# 포스트별 HTML 시각화

35개 시리즈의 416편마다 핵심 개념 하나를 골라 세 장면으로 구성했다. 배열·트리·네트워크·격자·흐름도·막대·꺾은선의 일곱 표현을 사용한다. 각 장면의 데이터와 설명은 글 주제에 맞춰 작성했으며, 전체 알고리즘이나 논문 실험을 재현하는 시뮬레이터는 아니다. 생략한 조건과 가상 수치는 해당 화면의 설명에 표시한다.

## 사용 방법

글 제목 아래 **이 글의 시각화 재생하기**를 누른다. 첫 화면에서는 자동재생하지 않는다.

- **재생 / 일시정지**: 현재 위치에서 재생하거나 멈춘다.
- **정지**: 첫 장면으로 돌아가 멈춘다.
- **처음부터 재생**: 첫 장면에서 다시 시작한다.
- **← / → / 단계 슬라이더**: 자동재생을 멈추고 원하는 단계를 고른다.
- **속도**: 0.5배·1배·2배 중 고른다.
- **이 HTML 저장**: 현재 시각화를 독립 HTML로 저장한다. 다시 열면 첫 장면에서 시작한다.

마지막 장면에서는 자동으로 멈춘다. 다른 탭으로 이동해 페이지가 숨겨질 때도 일시정지한다. 기본 HTML 버튼·슬라이더·선택 상자를 사용해 키보드로 조작할 수 있고, 모든 단계 설명을 텍스트로도 제공한다. 화면의 색과 함께 테두리·설명·단계 표시를 사용한다. 동작 감소 설정에서는 CSS 전환을 끈다.

저장한 개별 파일은 인터넷 없이 재생된다. 사이트의 글 목록과 본문으로 돌아가는 링크는 전체 사이트와 함께 열 때 사용하는 상대 경로다.

## 생성되는 파일

`npm run build -w @playground/demo`를 실행하면 다음 파일이 만들어진다.

```text
packages/demo/dist/
  visualizations/
    index.html          # 416개 검색 목록
    lang/1.html         # 언어 기초 1편
    techniques/3.html   # 이분 탐색
    attention/1.html    # 어텐션 점수와 가중치
    ...                 # 시리즈별 글 번호와 일치
```

시리즈 폴더 안에 416개 HTML이 있고 목록 HTML은 별도다. 각 HTML에 플레이어 코드·스타일·장면 데이터를 인라인으로 넣는다. 재생에 CDN·외부 라이브러리·fetch·iframe을 사용하지 않는다. 시각화 목록도 파일 구조를 유지해 내려받으면 로컬에서 열 수 있다.

GitHub Actions의 **post-visualizations** 아티팩트에는 이 폴더 전체가 들어간다. 압축을 풀고 `index.html`을 열거나 각 HTML을 직접 열면 된다. 시각화 스크린샷은 기존 **screenshots** 아티팩트의 `demo-mobile/visualization-*.png`에 들어간다. 아티팩트 보관 기간은 14일이다. 소스가 있으므로 이후에도 빌드로 다시 만들 수 있다.

## 원문과 장면의 대응

`packages/demo/src/visualizations/`의 각 모듈은 `시리즈 slug/글 번호`로 장면을 지정한다.

| 소스 | 시리즈 |
|---|---|
| foundations.ts | 언어·AI 기초, 이산수학, 확률, 통계, 선형대수, 미적분, 정보 이론 |
| algorithms.ts | 알고리즘 기법, DP, 고급 자료 구조, 그래프, 문자열, 수학·기하 |
| structures.ts | 심화 알고리즘, 추상 데이터 타입 심화 |
| hardware.ts | CPU, 메모리, GPU, 트랜지스터에서 자연어까지 |
| machine-learning.ts | 어텐션, 신경망 레이어, 오픈 웨이트 모델, 양자화 |
| games.ts | 게임 자원 관리, 게임 셰이더, 레벨 디자인 |
| development.ts | WSL, 도커, PostgreSQL, Git, GitHub, 컴퓨터와 AI의 첫걸음, AI 시대의 소프트웨어 부채, 웹 앱의 원리 |

`catalog.ts`가 장면 데이터를 모으고 `render.ts`가 각 HTML을 만든다. `player.ts`는 브라우저용으로 번들해 각 HTML에 넣는다. 글과 시각화가 1:1인지 빌드에서 대조한다. 새 포스트의 시각화 누락, 중복 키, 글 없이 남은 장면, 빈 장면, 차트의 잘못된 숫자는 실패로 처리한다.

장면 데이터에서 `!`로 시작하는 항목은 해당 단계의 강조 대상이다. 막대·꺾은선 값은 `라벨=숫자`, 네트워크 간선은 `출발>도착=설명`으로 적는다. 트리는 배열 인덱스 기준으로 왼쪽 `2i+1`, 오른쪽 `2i+2`이고 `·`는 빈 노드다.

차트는 장면 전체에서 같은 y축 범위를 쓴다. x축은 항목 순서이며 실제 수치 간격을 따르지 않는 표본에서는 그 조건을 설명에 쓴다. 서로 다른 단위의 단계는 해당 설명을 함께 읽어야 한다.

## 검증

- 단위 검사: 실제 416개 원문의 제목과 장면 키 대조, 독립 HTML 생성·링크·외부 의존 부재, 누락·중복·잘못된 데이터·HTML 이스케이프 검사.
- 브라우저 검사: 글에서 시각화 이동, 자동재생 없음, 재생·일시정지·정지·재시작·끝에서 멈춤, 재생 중 저장한 HTML의 오프라인 재실행, 키보드 슬라이더, 목록 검색.
- 전체 장면 검사: 416개 HTML을 모두 열고 세 단계를 넘기면서 SVG·스크립트 오류와 모바일 가로 넘침을 확인.
- 대표 화면 검사: 배열·트리·그래프·표·차트의 모바일 스크린샷.

GitHub E2E의 실행기는 Ubuntu 24.04로 고정했다. 기존 Playwright 1.56.1이 Ubuntu 26.04를 지원하지 않아 브라우저 설치에 실패하던 문제를 피하면서 Playwright 버전은 유지한다.

이 작업은 사용자 요청에 따라 `docs/renewal` 브랜치에서 계속한다. 코드가 포함되므로 저장소의 일반적인 `docs/*` 분류와는 다른 예외다. main 배포는 이 브랜치를 올리는 것만으로 수행되지 않는다.

최신 dev 통합 시 추가된 7개 시리즈·83편에도 장면을 추가했다. 이후 추가된 「웹 앱의 원리」 20편에도 장면을 추가했다. 초기 313편의 검토 기록은 당시 기준을 유지하며, 추가된 원문의 전면 감수를 의미하지 않는다.
