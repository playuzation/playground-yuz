## 트리의 정의
**트리**는 사이클이 없는 연결 무방향 그래프다(8편). 연결되어 있으니 어느 두 정점 사이에도 경로가 있고, 사이클이 없으니 그 경로는 **정확히 하나**뿐이다. 경로가 두 개라면 둘을 이어 붙여 사이클을 만들 수 있기 때문이다.

트리의 가장 중요한 성질은 정점이 n개면 간선이 정확히 n − 1개라는 것이다. 4편의 귀납법으로 보일 수 있다. 정점이 1개면 간선은 0개다. 정점이 2개 이상인 트리에는 차수가 1인 정점(**잎**)이 반드시 있다(가장 긴 경로의 끝 정점을 생각하면 된다). 잎과 거기 붙은 간선 하나를 떼어 내도 여전히 트리이므로, 귀납 가정에 따라 남은 n − 1개 정점에 간선이 n − 2개이고, 떼어 낸 간선을 더하면 n − 1개다.

그래서 트리는 "연결을 유지하는 최소한의 간선"만 가진 그래프다. 간선을 하나라도 빼면 끊어지고, 하나라도 더하면 사이클이 생긴다.

## 루트가 있는 트리
정점 하나를 **루트**로 정하면 위아래가 생긴다. 파일 시스템이 대표적이다.
```text
posts/                               루트, 깊이 0
├── lang/                            깊이 1, posts의 자식
│   ├── 1-programming-languages.md   잎, 깊이 2
│   └── 3-interpreted-languages.md   잎, 깊이 2
└── discrete/                        깊이 1
    └── 9-trees.md                   잎, 깊이 2
```
- **부모와 자식**: 루트 쪽으로 이웃한 정점이 부모, 반대쪽이 자식이다. 루트를 뺀 모든 정점은 부모가 정확히 하나다.
- **잎**: 자식이 없는 정점. 위 그림의 `.md` 파일들이다.
- **깊이**: 루트에서 그 정점까지의 간선 수. 트리의 **높이**는 가장 깊은 잎의 깊이다.
- **서브트리**: 한 정점과 그 아래 전부. "트리는 루트와 그 자식들을 루트로 하는 서브트리들"이라는 재귀적 정의가 가능해서, 트리를 다루는 코드는 대부분 재귀 함수다(4편).

## 이진 트리
모든 정점의 자식이 많아야 두 개(왼쪽, 오른쪽)인 루트 트리를 **이진 트리**라고 한다. 깊이 d에는 정점이 많아야 2ᵈ개이므로 높이가 h인 이진 트리의 정점은 많아야 `1 + 2 + … + 2ʰ = 2ʰ⁺¹ − 1`개다. 거꾸로 말하면 정점 n개를 담으려면 높이가 적어도 약 `log₂ n`이어야 하고, 고르게 채우면 그 정도 높이로 충분하다. 균형 잡힌 이진 탐색 트리에서 검색이 빠른 이유가 이것이며, 11편에서 `O(log n)`으로 다시 만난다.

## 식을 나타내는 트리
`(1 + 2) × 3` 같은 식은 연산자를 내부 정점, 숫자를 잎으로 하는 이진 트리로 나타낼 수 있다. 괄호는 트리 모양 속에 녹아 사라진다. `+`가 `×`보다 아래에 있으니 먼저 계산된다.
```text
      ×
     / \
    +   3
   / \
  1   2
```
파이썬도 소스 코드를 실행하기 전에 정확히 이런 모양의 **추상 구문 트리**(AST)를 만든다.
```python
import ast
print(ast.dump(ast.parse("(1 + 2) * 3", mode="eval").body, indent=1))
```
```text
BinOp(
 left=BinOp(
  left=Constant(value=1),
  op=Add(),
  right=Constant(value=2)),
 op=Mult(),
 right=Constant(value=3))
```

## 순회: 정점을 방문하는 세 가지 순서
트리의 모든 정점을 한 번씩 방문하는 것을 **순회**라고 한다. 루트를 언제 방문하느냐에 따라 세 가지가 있다.
- **전위 순회**: 루트 → 왼쪽 → 오른쪽
- **중위 순회**: 왼쪽 → 루트 → 오른쪽
- **후위 순회**: 왼쪽 → 오른쪽 → 루트

언어 기초 3편의 AST 표현을 그대로 써서 세 순회를 구현해 보자.
```python
tree = ("*", ("+", 1, 2), 3)          # 언어 기초 3편과 같은 AST: (1 + 2) * 3

def preorder(n):                      # 루트 → 왼쪽 → 오른쪽
    if isinstance(n, int):
        return [n]
    op, left, right = n
    return [op] + preorder(left) + preorder(right)

def inorder(n):                       # 왼쪽 → 루트 → 오른쪽 (괄호를 붙여야 뜻이 보존된다)
    if isinstance(n, int):
        return [n]
    op, left, right = n
    return ["("] + inorder(left) + [op] + inorder(right) + [")"]

def postorder(n):                     # 왼쪽 → 오른쪽 → 루트
    if isinstance(n, int):
        return [n]
    op, left, right = n
    return postorder(left) + postorder(right) + [op]

print(*preorder(tree))
print(*inorder(tree))
print(*postorder(tree))
```
```text
* + 1 2 3
( ( 1 + 2 ) * 3 )
1 2 + 3 *
```
중위 순회는 우리가 평소 쓰는 표기지만 괄호를 붙이지 않으면 `1 + 2 * 3`이 되어 뜻이 바뀐다. 전위(폴란드 표기법)와 후위(역폴란드 표기법)는 괄호 없이도 계산 순서가 하나로 정해진다.

## 후위 순회 = 스택 바이트코드
후위 순회 결과 `1 2 + 3 *`를 "숫자는 스택에 넣고, 연산자는 두 개를 꺼내 계산한 뒤 다시 넣는다"로 읽으면 그대로 언어 기초 3편의 스택 바이트코드가 된다. 앞 코드에 이어서 실행해 보자.
```python
# 앞 코드의 tree, postorder에 이어서
OPS = {"+": "ADD", "*": "MUL"}
code = [("PUSH", t) if isinstance(t, int) else (OPS[t], None) for t in postorder(tree)]
print(code)

stack = []
for op, arg in code:
    if op == "PUSH":
        stack.append(arg)
    else:
        b, a = stack.pop(), stack.pop()
        stack.append(a + b if op == "ADD" else a * b)
print(stack.pop())
```
```text
[('PUSH', 1), ('PUSH', 2), ('ADD', None), ('PUSH', 3), ('MUL', None)]
9
```
3편에서 손으로 적어 넣은 바이트코드와 순서가 똑같다. 자식을 먼저 계산해야 부모를 계산할 수 있으므로, 자식을 먼저 방문하는 후위 순회가 곧 계산 순서다. 바이트코드 컴파일러가 AST를 후위 순회하며 명령을 내보내는 이유가 이것이다.

## 어디에 쓰이나

## 정리
- 트리는 사이클 없는 연결 그래프로, 두 정점 사이의 경로가 유일하고 간선 수는 정점 수 − 1이다.
- 루트를 정하면 부모·자식·잎·깊이가 생기고, 트리는 재귀적으로 정의되어 재귀 함수로 다루기 좋다.
- 높이 h인 이진 트리는 정점을 많아야 2ʰ⁺¹ − 1개 담으므로, 균형 잡힌 트리의 높이는 약 log₂ n이다.
- 식 트리를 후위 순회하면 스택 바이트코드 순서가 되고, 이것이 컴파일러가 AST에서 바이트코드를 만드는 방법이다.
