## 도미노 원리
3편에서 보았듯 자연수 전체에 대한 ∀ 명제는 아무리 많이 확인해도 증명되지 않는다. **수학적 귀납법**은 이 문제를 두 단계로 해결한다.
1. **기초 단계**: `P(1)`이 참임을 보인다.
2. **귀납 단계**: 임의의 k에 대해 `P(k)`가 참이라고 가정하면 `P(k + 1)`도 참임을 보인다. 이 가정을 **귀납 가정**이라고 한다.

두 단계가 끝나면 `P(1)`에서 `P(2)`가, `P(2)`에서 `P(3)`이 나오는 식으로 모든 자연수에 대해 성립한다. 첫 도미노를 넘어뜨리고(기초), 어떤 도미노든 넘어지면 다음 도미노를 넘어뜨린다는 것(귀납)을 보이면 끝없이 늘어선 도미노가 전부 넘어지는 것과 같다. 귀납 단계는 "P(k)가 참이다"를 증명하는 것이 아니라 "P(k)이면 P(k + 1)"이라는 함의를 증명한다는 점에 주의하자.

## 예: 1부터 n까지의 합
`P(n)`: `1 + 2 + … + n = n(n + 1)/2`를 증명해 보자.
```text
기초 단계 (n = 1)
  왼쪽 = 1,  오른쪽 = 1 × 2 / 2 = 1  → 성립

귀납 단계 (P(k)를 가정하고 P(k + 1)을 보인다)
  1 + 2 + … + k + (k + 1)
  = k(k + 1)/2 + (k + 1)          ← 귀납 가정 사용
  = (k + 1)(k + 2)/2              ← (k + 1)로 묶기
  = (k + 1)((k + 1) + 1)/2        → P(k + 1)과 같은 꼴
```
따라서 모든 자연수 n에 대해 성립하고, n = 10이면 `10 × 11 / 2 = 55`다.

## 강한 귀납법
귀납 단계에서 바로 앞의 `P(k)` 하나가 아니라 `P(1), P(2), …, P(k)` 전부를 가정해도 된다. 이를 **강한 귀납법**이라 한다. 더 작은 경우 여러 개에 기대야 할 때 쓴다.

예: "2 이상의 모든 정수는 소수의 곱으로 쓸 수 있다." 기초 단계 2는 소수다. k + 1이 소수면 그 자체로 끝이다. 소수가 아니면 `k + 1 = a × b`(2 ≤ a, b ≤ k)로 쪼개지는데, a와 b는 k 이하이므로 귀납 가정에 따라 각각 소수의 곱이고, 둘을 곱하면 k + 1도 소수의 곱이다. 여기서 a, b는 k보다 한참 작을 수 있으므로 "바로 앞 하나"만 가정하는 보통 귀납법으로는 부족하다.

## 재귀 함수는 귀납법을 코드로 쓴 것
자기 자신을 호출하는 **재귀 함수**는 귀납법과 구조가 똑같다.

| 귀납법 | 재귀 함수 |
|---|---|
| 기초 단계 `P(1)` | 종료 조건 (`if n == 0`) |
| 귀납 가정 `P(k)` | 더 작은 입력에 대한 재귀 호출 |
| 귀납 단계 `P(k) → P(k + 1)` | 재귀 결과로 지금 답을 만드는 코드 |

```python
def sum_to(n):
    if n == 0:                 # 종료 조건 = 기초 단계
        return 0
    return sum_to(n - 1) + n   # 더 작은 문제는 맞게 풀린다고 믿는다 = 귀납 가정

print(sum_to(10), 10 * 11 // 2)                                 # 55 55
print(all(sum_to(n) == n * (n + 1) // 2 for n in range(500)))   # True (확인일 뿐, 증명은 아니다)
```
재귀 함수를 짤 때 "sum_to(n − 1)이 어떻게 계산되는지 끝까지 따라가 보는" 대신 "맞게 돌려준다고 믿고 그걸로 지금 답을 만든다"고 생각하면 쉬워진다. 그 믿음을 정당화하는 것이 귀납법이다. 종료 조건이 없으면 기초 단계 없는 귀납법처럼 아무것도 보장되지 않고, 실제로는 호출이 끝없이 쌓인다.
```python
def bad(n):
    return bad(n - 1) + n      # 종료 조건이 없다

try:
    bad(10)
except RecursionError as e:
    print("RecursionError:", e)  # RecursionError: maximum recursion depth exceeded
```

반복문도 같은 방식으로 증명한다. "i번째 반복이 끝나면 `total = 1 + … + i`"처럼 매 반복마다 유지되는 성질을 **루프 불변식**이라 하고, 처음에 성립하고(기초) 한 번 돌아도 유지됨(귀납)을 보이면 반복문이 끝났을 때의 결과가 보장된다.

## 피보나치 점화식
앞의 항들로 다음 항을 정의하는 식을 **점화식**이라 한다. 피보나치 수열은 `F(0) = 0`, `F(1) = 1`, `F(n) = F(n − 1) + F(n − 2)`다. 항 두 개에 기대므로 기초 단계도 두 개 필요하고, 성질을 증명할 때는 강한 귀납법을 쓴다. 예를 들어 `F(n) < 2ⁿ`은 `F(n) = F(n − 1) + F(n − 2) < 2ⁿ⁻¹ + 2ⁿ⁻² < 2ⁿ`으로 바로 나온다.
```python
from functools import lru_cache

calls = 0
def fib(n):
    global calls
    calls += 1
    if n < 2:                  # 기초 단계가 두 개: F(0) = 0, F(1) = 1
        return n
    return fib(n - 1) + fib(n - 2)

print(fib(20), calls)          # 6765 21891: 같은 값을 수없이 다시 계산한다

@lru_cache(maxsize=None)
def fib_memo(n):
    return n if n < 2 else fib_memo(n - 1) + fib_memo(n - 2)

print(fib_memo(20), fib_memo.cache_info().misses)  # 6765 21: 각 n을 한 번씩만 계산
```
점화식을 그대로 옮긴 재귀는 정확하지만 F(20) 하나에 함수를 21,891번 호출한다. 이미 계산한 값을 기억해 두는 **메모이제이션**을 쓰면 21번이면 된다. 이 차이를 수식으로 세는 법은 11편에서 다룬다.

## 정리
- 수학적 귀납법은 기초 단계 `P(1)`과 귀납 단계 `P(k) → P(k + 1)`로 모든 자연수에 대한 명제를 증명한다.
- 강한 귀납법은 k 이하 전부를 가정하며, 더 작은 여러 경우에 기댈 때 쓴다.
- 재귀 함수의 종료 조건은 기초 단계, 재귀 호출은 귀납 가정에 해당하고, 반복문은 루프 불변식으로 같은 방식으로 증명한다.
- 점화식을 그대로 옮긴 재귀는 같은 계산을 반복할 수 있어 메모이제이션이 필요하다.
