# [이산수학 11/12] 점근 표기법: 알고리즘의 비용 세기

> **한 줄 요약** — 점근 표기법은 입력 크기 n이 커질 때 비용이 "어떤 속도로" 늘어나는지만 남기고 상수와 작은 항을 버리는 표기로, O(n²)와 O(n log n)의 차이는 컴퓨터를 바꾸는 것보다 훨씬 큰 차이를 만든다.

## 이 글에서 다루는 것
- 왜 시간 대신 연산 횟수의 증가 속도를 세는가
- O, Ω, Θ의 정확한 정의: 상수 c와 n₀
- 대표적인 증가 속도와 n = 1,000일 때의 크기
- 반복문 세기와 이분 탐색이 O(log n)인 이유

## 무엇을 세는가
같은 코드라도 실행 시간은 컴퓨터, 언어, 그날의 부하에 따라 달라진다. 그래서 알고리즘을 비교할 때는 초 대신 "입력 크기 n에 대해 기본 연산을 몇 번 하는가"를 함수로 센다. 그리고 n이 충분히 클 때 무엇이 지배하는지만 본다. 연산 횟수가 `3n² + 5n + 2`라면 n = 1,000일 때 `3n²`이 3,000,000이고 나머지 `5n + 2`는 5,002라서 사실상 무시할 수 있다. 앞의 계수 3도 컴퓨터가 2배 빨라지면 바뀌는 값이므로, 결국 남는 것은 "n²에 비례해 늘어난다"는 사실이다.

## O, Ω, Θ의 정의
3편의 한정자로 정확히 쓰면 다음과 같다.
```text
f(n) = O(g(n))  ⇔  ∃ c > 0, ∃ n₀,  ∀ n ≥ n₀:  f(n) ≤ c · g(n)    (위로 막힌다)
f(n) = Ω(g(n))  ⇔  ∃ c > 0, ∃ n₀,  ∀ n ≥ n₀:  f(n) ≥ c · g(n)    (아래로 막힌다)
f(n) = Θ(g(n))  ⇔  O(g(n))이면서 Ω(g(n))                          (같은 속도로 자란다)
```
"상수배(c)를 허용하고, 처음 몇 개(n₀ 미만)는 봐준다"는 것이 핵심이다. `f(n) = 3n² + 5n + 2`가 `O(n²)`임은 c = 4, n₀ = 6으로 보일 수 있다. `4n² − f(n) = n² − 5n − 2`는 n ≥ 6에서 양수이기 때문이다(n = 5에서는 f(5) = 102 > 100이라 아직 아니다). 또 모든 n ≥ 1에서 `f(n) ≥ 3n²`이므로 `Ω(n²)`이고, 따라서 `Θ(n²)`이다.

O는 상한일 뿐이라 `3n² + 5n + 2 = O(n³)`도 틀린 말은 아니다. 다만 쓸모가 없을 뿐이다. 실무에서 "이 알고리즘은 O(n²)"이라고 하면 보통 "가장 정확한 상한이 n²", 즉 Θ의 뜻으로 쓴다. 또 O는 대개 **최악의 경우**를 기준으로 말한다.

## 대표적인 증가 속도
| 표기 | 이름 | n = 1,000일 때 | 예 |
|---|---|---|---|
| `O(1)` | 상수 | 1 | 배열 인덱스 접근, 딕셔너리 조회(평균) |
| `O(log n)` | 로그 | 약 10 | 이분 탐색 |
| `O(n)` | 선형 | 1,000 | 리스트 전체 훑기 |
| `O(n log n)` | 선형 로그 | 약 10,000 | 병합 정렬, 파이썬 `sorted` |
| `O(n²)` | 제곱 | 1,000,000 | 모든 쌍 비교 |
| `O(2ⁿ)` | 지수 | 약 1.07 × 10³⁰¹ | 부분집합 전부 나열 |

로그의 밑은 상수배 차이(`log₂ n = log₁₀ n × log₂ 10`)라서 점근 표기에서는 생략한다. 1초에 연산 10억 번을 한다고 하면, n = 1,000,000일 때 `n log n`은 약 0.02초, `n²`은 약 1,000초(17분 가량)다. `2ⁿ`은 n = 100이기만 해도 `2¹⁰⁰ ≈ 1.27 × 10³⁰`번이라 약 1.3 × 10²¹초, 우주의 나이(약 4 × 10¹⁷초)의 수천 배가 걸린다. 4편의 단순 재귀 피보나치가 지수 시간의 예이고, 메모이제이션은 이를 `O(n)`으로 바꾼다.

## 반복문 세기
대부분의 코드는 반복문이 몇 번 도는지만 세면 된다.
```python
def count_ops(n):
    single = sum(1 for i in range(n))                             # 반복문 하나
    nested = sum(1 for i in range(n) for j in range(n))           # 이중 반복문
    pairs = sum(1 for i in range(n) for j in range(i + 1, n))     # 모든 쌍 한 번씩
    halving, i = 0, n
    while i > 1:                                                  # 절반씩 줄이기
        i //= 2
        halving += 1
    return single, nested, pairs, halving

for n in [10, 100, 1000]:
    print(n, count_ops(n))
```
```text
10 (10, 100, 45, 3)
100 (100, 10000, 4950, 6)
1000 (1000, 1000000, 499500, 9)
```
- 반복문 하나는 `Θ(n)`, 이중 반복문은 `Θ(n²)`이다. 반복문 안에서 `O(n)`짜리 함수(예: 리스트의 `x in lst`)를 부르면 겉보기엔 한 겹이어도 `O(n²)`이 된다.
- "모든 쌍 한 번씩"은 `n(n − 1)/2`번으로 절반이지만 4편의 합 공식에서 보듯 여전히 `Θ(n²)`이다. 상수배는 증가 속도를 바꾸지 못한다.
- 매번 절반으로 줄이면 k번 뒤 `n/2ᵏ`이 1 이하가 될 때 멈추므로 `k ≈ log₂ n`이다. n이 1,000이면 9번이다(`log₂ 1000 ≈ 9.97`).

## 이분 탐색이 O(log n)인 이유
정렬된 목록에서 값을 찾을 때, 가운데 원소와 비교하면 찾는 값이 왼쪽 절반에 있는지 오른쪽 절반에 있는지 알 수 있다. 한 번 비교할 때마다 후보가 절반으로 줄어드는 것이 바로 위의 "절반씩 줄이기"다.
```python
def binary_search(xs, target):
    lo, hi, steps = 0, len(xs) - 1, 0
    while lo <= hi:
        steps += 1
        mid = (lo + hi) // 2
        if xs[mid] == target:
            return mid, steps
        if xs[mid] < target:
            lo = mid + 1                  # 왼쪽 절반을 버린다
        else:
            hi = mid - 1                  # 오른쪽 절반을 버린다
    return -1, steps

xs = list(range(0, 2_000_000, 2))         # 정렬된 짝수 100만 개
print(binary_search(xs, 1_234_568))       # (617284, 17): 있는 값
print(binary_search(xs, 7))               # (-1, 20): 없는 값
```
원소 100만 개에서 최악의 경우에도 20번이면 끝난다(`2²⁰ = 1,048,576`). 앞에서부터 하나씩 보는 선형 탐색은 최악의 경우 100만 번이다. 원소가 2배가 되어도 이분 탐색은 한 번만 더 비교하면 된다. 단, 이 속도는 "정렬되어 있다"는 조건 덕분이며, 정렬 자체에는 `O(n log n)`이 든다.

## 어디에 쓰이나
- AI 기초 4편 「컴퓨터 사이언스로 보는 AI 모델: 텐서, 연산, 메모리」: 어텐션이 `O(n²)`이라 입력 길이를 2배로 늘리면 비용이 4배가 되는 것이 이 글의 제곱 증가이고, 행렬 곱 연산량 `2·m·k·n` FLOPs는 상수까지 정확히 센 `Θ(mkn)`이다.
- 언어 기초 5편 「컴파일 언어: 실행 전에 번역하기」: 인라이닝이나 벡터화 같은 최적화는 주로 상수배를 줄이지만, 1~10 합 반복문을 상수 55로 접는 것처럼 반복문 자체를 없애면 실행 시점의 비용이 `O(n)`에서 `O(1)`로 바뀐다.
- 10편 「그래프 탐색: BFS, DFS, 위상 정렬」: BFS와 DFS가 인접 리스트에서 `O(V + E)`, 인접 행렬에서 `O(V²)`라는 것이 8편의 표현 선택을 결정하는 근거다.

## 정리
- 점근 표기법은 상수와 작은 항을 버리고 n이 커질 때의 증가 속도만 비교한다.
- `f = O(g)`는 "어떤 상수 c와 n₀가 있어 n ≥ n₀에서 `f(n) ≤ c·g(n)`"이고, Ω는 아래로, Θ는 양쪽으로 막힌다는 뜻이다.
- 반복문 하나는 n, 이중 반복문은 n², 절반씩 줄이면 log n이며, 이분 탐색은 100만 개에서도 20번이면 끝난다.
- n이 크면 알고리즘의 증가 속도 차이가 하드웨어 성능 차이보다 훨씬 크다.
