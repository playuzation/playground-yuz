## 정점과 간선
**그래프** `G = (V, E)`는 **정점**(vertex)의 집합 V와 정점 쌍을 잇는 **간선**(edge)의 집합 E로 이루어진다. 위치나 모양은 상관없고 "누가 누구와 이어져 있는가"만 중요하다.
- **무방향 그래프**: 간선에 방향이 없다. 친구 관계처럼 A와 B가 이어져 있으면 B와 A도 이어져 있다. 간선을 `{u, v}`로 쓴다.
- **방향 그래프**: 간선에 방향이 있다. "a가 b를 import한다", "a가 b를 팔로우한다"처럼 `u → v`가 `v → u`를 뜻하지 않는다. 간선을 순서쌍 `(u, v)`로 쓴다. 5편의 관계는 사실 방향 그래프와 같은 것이다.
- **가중치 그래프**: 간선마다 거리, 비용, 시간 같은 수가 붙어 있다. 지도 앱의 도로망이 대표적이다.

```text
A ─── B
 \   /
  \ /
   C ─── D
```
위 그래프는 정점 4개 `{A, B, C, D}`, 간선 4개 `{A,B}, {A,C}, {B,C}, {C,D}`로 된 무방향 그래프다.

## 차수와 악수 정리
정점에 붙은 간선의 수를 **차수**(degree)라고 한다. 위 그래프에서 C의 차수는 3, D의 차수는 1이다. 차수를 모두 더하면 `2 + 2 + 3 + 1 = 8`, 즉 간선 수 4의 두 배가 된다. 이것은 우연이 아니다.
```text
악수 정리:  모든 정점의 차수의 합 = 2 × 간선 수
```
간선 하나는 양 끝 정점에서 한 번씩, 정확히 두 번 세어지기 때문이다. 파티에서 모든 사람이 악수한 횟수를 더하면 악수 횟수의 두 배가 되는 것과 같다. 여기서 "차수가 홀수인 정점의 개수는 항상 짝수"라는 사실도 따라 나온다. 차수의 합이 짝수여야 하기 때문이다.

방향 그래프에서는 들어오는 간선 수(**진입 차수**)와 나가는 간선 수(**진출 차수**)를 나눠 센다. 간선 하나는 진출 차수 한 번, 진입 차수 한 번으로 세어지므로 두 합은 모두 간선 수와 같다. 이 플랫폼의 패키지 의존성으로 확인해 보자.
```python
# 이 플랫폼의 패키지 의존성: "a → b"는 a가 b를 import한다는 뜻
deps = {
    "server": ["api", "core", "web"],
    "demo":   ["api", "core", "web"],
    "api":    ["core"],
    "web":    ["core"],
    "core":   [],
}
out_deg = {v: len(ns) for v, ns in deps.items()}
in_deg = {v: 0 for v in deps}
for ns in deps.values():
    for n in ns:
        in_deg[n] += 1

E = sum(out_deg.values())
print("진출 차수", out_deg)
print("진입 차수", in_deg)
print("간선 수", E, "진입 차수 합", sum(in_deg.values()))
```
```text
진출 차수 {'server': 3, 'demo': 3, 'api': 1, 'web': 1, 'core': 0}
진입 차수 {'server': 0, 'demo': 0, 'api': 2, 'web': 2, 'core': 4}
간선 수 8 진입 차수 합 8
```
진입 차수가 가장 큰 `core`는 모두가 기대는 바닥이고, 진출 차수가 0이라 아무것에도 기대지 않는다.

## 경로, 사이클, 연결성
- **경로**: 간선을 따라 정점을 차례로 밟아 가는 길. 위 그래프의 A → C → D는 길이(간선 수) 2인 경로다.
- **사이클**: 출발한 정점으로 되돌아오는 경로. A → B → C → A가 사이클이다. 사이클이 없는 방향 그래프를 **DAG**(방향 비순환 그래프)라고 한다.
- **연결 그래프**: 어느 두 정점 사이에도 경로가 있는 무방향 그래프. 연결되지 않은 그래프는 서로 이어진 덩어리(**연결 요소**) 여러 개로 나뉜다.

이 플랫폼의 패키지 그래프는 DAG다. 각 패키지에 계층 번호(core 0, api·web 1, server·demo 2)를 매기고 "더 낮은 계층으로만 간선을 낼 수 있다"고 정했기 때문에, 간선을 따라가면 계층 번호가 계속 줄어들어 출발점으로 되돌아올 수 없다.

## 그래프를 메모리에 담는 두 가지 방법
**인접 행렬**은 V × V 표에 i와 j가 이어져 있으면 1, 아니면 0을 적는다. **인접 리스트**는 정점마다 이웃의 목록을 둔다.
```python
friends = [("A", "B"), ("A", "C"), ("B", "C"), ("C", "D")]
V = sorted({v for e in friends for v in e})

adj_list = {v: [] for v in V}
for u, w in friends:
    adj_list[u].append(w)
    adj_list[w].append(u)          # 무방향이므로 양쪽에 기록

idx = {v: i for i, v in enumerate(V)}
adj_matrix = [[0] * len(V) for _ in V]
for u, w in friends:
    adj_matrix[idx[u]][idx[w]] = adj_matrix[idx[w]][idx[u]] = 1

print(adj_list)
for v, row in zip(V, adj_matrix):
    print(v, row)
```
```text
{'A': ['B', 'C'], 'B': ['A', 'C'], 'C': ['A', 'B', 'D'], 'D': ['C']}
A [0, 1, 1, 0]
B [1, 0, 1, 0]
C [1, 1, 0, 1]
D [0, 0, 1, 0]
```
무방향 그래프의 인접 행렬은 대각선을 기준으로 대칭이고, 각 행의 합이 그 정점의 차수다.

| 항목 | 인접 행렬 | 인접 리스트 |
|---|---|---|
| 공간 | V² | V + E |
| u와 v가 이어졌나? | 칸 하나 확인 | u의 이웃 목록 훑기 |
| u의 이웃 전부 보기 | 행 전체(V칸) 훑기 | 차수만큼만 |
| 잘 맞는 그래프 | 간선이 빽빽할 때 | 간선이 드물 때 |

현실의 그래프는 대부분 간선이 드물다(**희소 그래프**). 사용자 1만 명이 평균 100명과 친구라면 간선은 50만 개다. 인접 행렬은 1억 칸이 필요하지만 인접 리스트는 1만 + 100만(간선마다 양쪽에 한 번씩) 정도면 된다. 그래서 탐색 알고리즘은 보통 인접 리스트를 쓴다. 인접 행렬은 행렬 연산과 바로 이어진다는 장점이 있는데, 행렬 자체는 선형대수 3편 「행렬과 행렬 곱」에서 다룬다.

## 정리
- 그래프는 정점과 간선으로 연결 구조만 나타내며, 방향과 가중치 유무로 종류가 나뉜다.
- 차수의 합은 간선 수의 두 배(악수 정리)이고, 방향 그래프에서는 진입·진출 차수의 합이 각각 간선 수와 같다.
- 경로, 사이클, 연결성은 그래프 문제의 기본 어휘이며, 사이클이 없는 방향 그래프를 DAG라고 한다.
- 인접 행렬은 V², 인접 리스트는 V + E의 공간을 쓰며, 대부분의 실제 그래프는 희소해서 인접 리스트가 유리하다.
