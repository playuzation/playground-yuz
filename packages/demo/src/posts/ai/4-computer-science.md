# [AI 기초 4/4] 컴퓨터 사이언스로 보는 AI 모델: 텐서, 연산, 메모리

> **한 줄 요약** — 컴퓨터 입장에서 AI 모델은 거대한 숫자 배열(텐서)과 그 위에서 도는 행렬 곱의 묶음이며, 모델의 속도와 비용은 대부분 연산량, 메모리 크기, 메모리 대역폭으로 결정된다.

## 이 글에서 다루는 것
- 모델의 정체: 파라미터와 계산 그래프
- 텐서와 행렬 곱, 연산량(FLOPs) 세기
- 숫자 표현: 부동소수점 정밀도와 양자화
- 메모리: 모델 크기와 학습에 필요한 메모리 계산
- GPU가 필요한 이유와 진짜 병목
- 자동 미분, 어텐션의 계산 복잡도

## 모델은 숫자 + 계산 순서
학습이 끝난 모델은 두 가지로 이루어진다.
1. **파라미터**: 학습으로 정해진 숫자들. 70억(7B) 파라미터 모델이라면 숫자가 70억 개다.
2. **계산 그래프**(아키텍처): 그 숫자들로 입력을 어떤 순서로 계산할지에 대한 정의. 보통 코드로 표현된다.

모델 파일을 열어 보면 대부분은 이름이 붙은 거대한 숫자 배열의 모음이다. 예를 들어 `layers.0.attention.wq.weight`라는 이름의 4096×4096 배열 같은 것들이 수백 개 들어 있다.

## 텐서와 행렬 곱
**텐서**는 다차원 배열이다. 숫자 하나(스칼라)는 0차원, 벡터는 1차원, 행렬은 2차원 텐서이고, 컬러 이미지 묶음은 (배치, 높이, 너비, 채널)의 4차원 텐서다.

신경망 계산의 대부분은 **행렬 곱**이다. 크기 4096인 입력 벡터에 4096×4096 가중치 행렬을 곱하는 것이 층 하나의 기본 동작이다.
```python
import numpy as np

x = np.random.rand(1, 4096)      # 입력 벡터 1개
W = np.random.rand(4096, 4096)   # 가중치 행렬 하나 (약 1,677만 개의 숫자)
y = x @ W                        # 곱셈과 덧셈이 각각 약 1,677만 번
```

(m×k) 행렬과 (k×n) 행렬의 곱에는 곱셈과 덧셈이 각각 약 m·k·n번 필요하므로, 연산량을 흔히 2·m·k·n **FLOPs**(부동소수점 연산 수)로 센다. 이를 바탕으로 한 어림 규칙이 있다.
- **추론**: 토큰 하나를 처리하는 데 약 2 × 파라미터 수 FLOPs
- **학습**: 토큰 하나당 약 6 × 파라미터 수 FLOPs (순전파 2 + 역전파 4)

7B 모델이 토큰 하나를 만들려면 약 140억 번, 즉 14 GFLOPs의 연산이 필요하다는 뜻이다.

## 숫자를 몇 비트로 저장하나
| 형식 | 비트 | 특징 | 주 용도 |
|---|---|---|---|
| FP32 | 32 | 정밀하지만 크다 | 예전의 학습 기본값, 누적 계산 |
| FP16 | 16 | 표현 범위가 좁아 넘침에 주의해야 한다 | 추론, 혼합 정밀도 학습 |
| BF16 | 16 | FP32와 같은 범위(지수 8비트)에 정밀도는 낮다 | 현대 학습의 기본 |
| INT8 / INT4 | 8 / 4 | 정수로 근사한다(양자화) | 추론 경량화 |

부동소수점은 실수를 근사한 값이라서, 계산 순서만 바뀌어도 결과가 미세하게 달라진다.
```python
>>> 0.1 + 0.2
0.30000000000000004
>>> (0.1 + 0.2) + 0.3 == 0.1 + (0.2 + 0.3)
False
```

GPU는 수천 개의 덧셈을 병렬로 처리하면서 더하는 순서가 실행마다 달라질 수 있다. 같은 입력에도 AI 모델의 출력이 비트 단위로 똑같이 재현되지 않는 흔한 원인이 이것이다.

**양자화**는 가중치를 INT8이나 INT4처럼 적은 비트로 근사해 저장하는 기법이다. 정확도를 조금 잃는 대신 메모리 사용량과 메모리에서 읽어야 할 데이터 양을 2~8배 줄인다.

## 모델 크기 계산하기
가중치에 필요한 메모리는 `파라미터 수 × 숫자 하나의 바이트 수`로 바로 계산할 수 있다.
| 모델 | FP32 (4바이트) | BF16 (2바이트) | INT4 (0.5바이트) |
|---|---|---|---|
| 7B | 28GB | 14GB | 3.5GB |
| 70B | 280GB | 140GB | 35GB |

이는 가중치만의 크기다. 추론할 때는 앞서 처리한 토큰들의 어텐션 정보(**KV 캐시**)가 추가로 필요하고, 학습할 때는 훨씬 더 많은 메모리가 든다. Adam 옵티마이저로 혼합 정밀도 학습을 하면 파라미터 하나당 가중치, 기울기, 옵티마이저 상태를 합쳐 약 16바이트가 필요하다. 그래서 7B 모델을 학습하려면 중간 계산값을 빼고도 100GB가 넘는 메모리가 든다.

## GPU가 필요한 이유
CPU는 복잡한 일을 빠르게 처리하는 소수의 강력한 코어로 이루어져 있고, GPU는 단순한 계산을 동시에 처리하는 수천 개의 코어로 이루어져 있다. 행렬 곱은 서로 독립적인 곱셈과 덧셈의 거대한 묶음이라 GPU 구조와 잘 맞는다. 최신 GPU에는 행렬 곱만 전담하는 **텐서 코어**까지 들어 있다.

그런데 연산 능력만으로 속도가 정해지지는 않는다. 계산하려면 먼저 데이터를 메모리에서 가져와야 하기 때문이다.
- **연산 병목**: 가져온 데이터로 해야 할 계산이 많은 경우. 큰 배치로 학습할 때가 그렇다.
- **메모리 대역폭 병목**: 계산은 적은데 옮길 데이터가 많은 경우. 언어 모델이 토큰을 하나씩 생성할 때가 대표적이다. 토큰 하나를 만들 때마다 가중치 전체를 메모리에서 한 번씩 읽어야 한다.

그래서 한 번에 한 요청만 처리할 때의 토큰 생성 속도는 대략 `메모리 대역폭 ÷ 모델 크기`로 어림할 수 있다. 대역폭이 1TB/s인 GPU에서 14GB(7B, BF16) 모델을 돌리면 초당 약 70토큰이 이론상 상한이다. 양자화로 모델 크기를 줄이면 생성 속도까지 빨라지는 이유가 여기에 있다.

## 자동 미분: 역전파를 대신 계산해 주는 기술
딥러닝 프레임워크는 순전파 계산을 기록해 **계산 그래프**를 만들고, 그 그래프를 거꾸로 따라가며 연쇄 법칙으로 기울기를 자동 계산한다(역방향 자동 미분). 출력은 손실 하나이고 입력인 파라미터는 수십억 개인 상황에서, 역방향 방식은 순전파의 몇 배 정도 비용으로 모든 기울기를 한 번에 구한다. 파라미터를 하나씩 조금 바꿔 보며 기울기를 재는 수치 미분이었다면 불가능했을 일이다.
```python
import torch

w = torch.tensor(3.0, requires_grad=True)
loss = (w * 2 - 4) ** 2   # 순전파: 계산 그래프가 기록된다
loss.backward()           # 역전파: 연쇄 법칙이 자동으로 적용된다
print(w.grad)             # tensor(8.)  ← d/dw (2w − 4)² = 4·(2w − 4) = 8
```

1편 「딥러닝」에서 손으로 짠 역전파 코드를 프레임워크가 이렇게 대신 처리해 준다.

## 어텐션의 계산 복잡도
트랜스포머의 셀프 어텐션은 모든 토큰이 다른 모든 토큰을 참조한다. 길이가 n인 입력이면 n×n 크기의 점수 행렬이 생기므로, 연산량과 메모리가 `O(n²)`으로 늘어난다. 입력 길이를 2배로 늘리면 어텐션 비용은 4배가 된다. 이것이 긴 문맥을 다루기 어려운 근본 원인이고, 이를 줄이려고 메모리 접근을 줄여 같은 계산을 빠르게 하는 FlashAttention, 일부 토큰만 참조하는 희소 어텐션이나 슬라이딩 윈도우 같은 기법이 연구되어 왔다. 생성할 때는 이전 토큰들의 키와 값을 KV 캐시에 저장해 같은 계산을 반복하지 않지만, 그만큼 메모리를 쓴다.

## 정리
- 컴퓨터 입장에서 모델은 파라미터(텐서)와 계산 그래프이며, 계산의 대부분은 행렬 곱이다.
- 비용은 연산량(토큰당 추론 약 2N, 학습 약 6N FLOPs, N은 파라미터 수), 메모리(파라미터 수 × 바이트 수), 메모리 대역폭으로 어림할 수 있다.
- 정밀도와 양자화, GPU, 자동 미분, 어텐션의 `O(n²)`은 모두 이 비용을 다루기 위한 컴퓨터 사이언스의 문제다.
