## 설계 철학: 가독성이 중요하다
파이썬 인터프리터에서 `import this`를 실행하면 파이썬의 설계 원칙인 「The Zen of Python」이 출력된다. 자주 인용되는 문장은 다음과 같다.
- *Beautiful is better than ugly.* — 아름다운 것이 추한 것보다 낫다.
- *Readability counts.* — 가독성은 중요하다.
- *There should be one-- and preferably only one --obvious way to do it.* — 명확한 방법이 하나, 가급적 딱 하나만 있어야 한다.

이 철학이 가장 잘 드러나는 부분은 **들여쓰기가 곧 문법**이라는 점이다. 중괄호 대신 들여쓰기로 코드 블록을 구분하기 때문에, 누가 작성해도 코드의 모양이 비슷해진다.

## 예제로 보는 핵심 문법
```python
from dataclasses import dataclass


@dataclass
class Post:
    title: str
    likes: int = 0


def popular(posts: list[Post], min_likes: int = 10) -> list[str]:
    """좋아요가 min_likes 이상인 포스트 제목을 좋아요 많은 순으로 돌려준다."""
    hits = [p for p in posts if p.likes >= min_likes]
    hits.sort(key=lambda p: p.likes, reverse=True)
    return [p.title for p in hits]


posts = [Post("파이썬 입문", 42), Post("러스트 입문", 7), Post("컴파일러 이야기", 15)]
print(popular(posts))  # ['파이썬 입문', '컴파일러 이야기']
```

짧은 코드에 파이썬다운 요소가 모여 있다.
- `@dataclass`: 데이터를 담는 클래스의 생성자와 비교 메서드 등을 자동으로 만들어 준다.
- `list[Post]`, `-> list[str]`: **타입 힌트**. 실행에는 영향을 주지 않고, mypy 같은 정적 분석 도구와 편집기가 오류를 미리 찾는 데 쓴다.
- `[p for p in posts if ...]`: **리스트 컴프리헨션**. 반복과 필터링을 한 줄로 표현한다.
- `"""..."""`: **독스트링**. 함수 설명이 코드와 함께 남고 `help(popular)`로 볼 수 있다.

## 동적 타입이란
변수에는 타입이 없고 **값**에 타입이 있다. 같은 변수에 다른 타입의 값을 넣을 수 있고, 타입이 맞지 않는 연산은 그 줄이 실제로 실행될 때 오류가 된다.
```python
x = 10        # int
x = "열"      # 이제 str — 문제없다
print(x + 1)  # TypeError: can only concatenate str (not "int") to str
```

자유도가 높은 대신 실수가 늦게 드러난다. 그래서 규모가 큰 프로젝트에서는 타입 힌트와 정적 분석 도구로 이 단점을 보완하는 것이 일반적이다.

## 파이썬 코드는 어떻게 실행되나
흔히 파이썬을 "인터프리터 언어"라고 부르지만, 공식 구현인 CPython은 소스 코드를 한 줄씩 그대로 해석하지 않는다.
1. **컴파일**: 소스(`.py`)를 파싱해 **바이트코드**로 바꾼다. 임포트한 모듈의 바이트코드는 `__pycache__/*.pyc`에 캐시되어 다음 실행이 빨라진다.
2. **실행**: CPython **가상 머신**이 바이트코드 명령을 하나씩 해석하며 실행한다.

표준 라이브러리의 `dis` 모듈로 바이트코드를 직접 볼 수 있다.
```python
import dis

def add(a, b):
    return a + b

dis.dis(add)
```
```text
RESUME        0
LOAD_FAST     0 (a)
LOAD_FAST     1 (b)
BINARY_OP     0 (+)
RETURN_VALUE
```
위 출력은 파이썬 3.12 기준으로 줄 번호와 오프셋을 생략한 것이다. 명령 이름은 버전마다 조금씩 다르다. 이 과정은 3편 「인터프리터 언어」에서 더 자세히 다룬다.

## 장점과 단점
| 장점 | 단점 |
|---|---|
| 문법이 간결해 배우기 쉽다 | 같은 일을 하는 C·Rust 코드보다 대체로 느리다 |
| 표준 라이브러리와 PyPI 생태계가 방대하다 | 타입 오류가 실행 시점에야 드러난다 |
| REPL·주피터 노트북으로 실험이 빠르다 | 배포할 때 인터프리터와 의존성을 함께 챙겨야 한다 |
| C로 작성된 라이브러리(NumPy 등)로 성능 문제를 우회할 수 있다 | GIL 때문에 스레드로 CPU 작업을 병렬화하기 어려웠다 (3.13부터 GIL 없는 빌드를 실험적으로 제공) |
