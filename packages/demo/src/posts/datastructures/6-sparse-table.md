# [고급 자료 구조 6/12] 희소 테이블: O(1) 구간 최솟값 질의

> **한 줄 요약** — 희소 테이블은 길이가 2의 거듭제곱인 모든 구간의 답을 O(n log n)에 미리 계산해 두고, 어떤 구간이든 서로 겹치는 두 조각으로 덮어 O(1)에 답하는 정적 자료 구조이며, 겹쳐 세도 답이 같은 멱등 연산(최솟값, 최댓값, gcd)에서만 이 속임수가 통한다.

## 이 글에서 다루는 것
- 배열이 바뀌지 않고 질의만 아주 많을 때
- 2ᵏ 길이 구간 표를 두 배씩 쌓아 만들기
- 겹치는 두 조각으로 O(1) 질의, 그리고 멱등 법칙
- 구간 합에는 왜 안 되나와 O(log n) 분해
- 구간 최솟값 질의(RMQ)가 쓰이는 곳

## 문제: 바뀌지 않는 배열, 아주 많은 질의
길이 n 배열이 한 번 주어진 뒤 바뀌지 않고, "l~r번째 최솟값" 질의가 q = 10⁶번 들어온다. 이것을 **구간 최솟값 질의**(range minimum query, RMQ)라고 한다. 질의마다 훑으면 O(n)이라 10¹¹ 근처다. 모든 (l, r)의 답을 표로 만들면 질의는 O(1)이지만 표가 n²/2칸이라 n = 10⁵이면 50억 칸이다. 3편 「세그먼트 트리: 구간 질의와 점 갱신」은 질의마다 O(log n)이다. 갱신이 없다는 점을 이용하면 질의를 O(1)로 만들 수 있다.

## 표 만들기: 2ᵏ 길이 구간만 저장한다
모든 구간 대신 길이가 1, 2, 4, 8, …인 구간만 저장한다. `sp[k][i]`는 i에서 시작하는 길이 2ᵏ 구간의 최솟값이다. 길이 2ᵏ 구간은 길이 2ᵏ⁻¹ 구간 둘을 이어 붙인 것이므로 바로 아래 층에서 계산한다.
```text
sp[0][i] = a[i]
sp[k][i] = min(sp[k−1][i],
               sp[k−1][i + 2ᵏ⁻¹])
```
층은 `⌊log₂ n⌋ + 1`개이고 층마다 n칸 이하라 표 전체가 O(n log n)이다. 이처럼 "모든 칸이 아니라 2의 거듭제곱 간격만" 저장하기 때문에 **희소 테이블**(sparse table)이라고 부른다.

## 질의: 겹치는 두 조각으로 덮기
구간 [l, r]의 길이를 L이라 하고 `2ᵏ ≤ L`인 가장 큰 k를 고른다. 그러면 왼쪽 끝에서 시작하는 길이 2ᵏ 조각과 오른쪽 끝에서 끝나는 길이 2ᵏ 조각 두 개가 [l, r]을 빈틈없이 덮는다. 2ᵏ⁺¹ > L이므로 두 조각을 합치면 구간을 넘치지 않으면서 전체를 덮고, 가운데는 겹친다. `a = [4, 6, 1, 5, 7, 3, 8, 2]`에서 [1, 6]을 보자.
```text
a      4 6 1 5 7 3 8 2
i      0 1 2 3 4 5 6 7
[1,6]    └─────────┘
[1,4]    └─────┘
[3,6]        └─────┘
```
길이 6이므로 k = 2이고, [1, 4]의 최솟값 1과 [3, 6]의 최솟값 3 중 작은 1이 답이다. 3, 4번 칸이 두 번 들어갔지만 최솟값은 같은 원소를 두 번 봐도 바뀌지 않는다. 연산이 `x ∘ x = x`를 만족하는 이 성질을 **멱등 법칙**(idempotence)이라고 한다. k는 L의 최상위 비트 위치라서 `L.bit_length() - 1`로 바로 구한다(로그 표를 미리 만들어 두는 방법도 흔하다).
```python
import random
from functools import reduce
from math import gcd

class SparseTable:
    def __init__(self, a, op):             # op: 결합 법칙 + 멱등 op(x, x) = x
        self.op, self.sp = op, [list(a)]   # sp[k][i] = a[i..i+2ᵏ−1]의 답
        k = 1
        while (1 << k) <= len(a):
            prev, half = self.sp[-1], 1 << (k - 1)
            self.sp.append([op(prev[i], prev[i + half])
                            for i in range(len(a) - (1 << k) + 1)])
            k += 1

    def query(self, l, r):                 # 닫힌 구간 [l, r]
        k = (r - l + 1).bit_length() - 1   # 2ᵏ ≤ 길이인 가장 큰 k
        row = self.sp[k]
        return self.op(row[l], row[r - (1 << k) + 1])   # 겹치는 두 조각

rng = random.Random(15)
for _ in range(500):
    a = [rng.randint(1, 60) for _ in range(rng.randint(1, 40))]
    tables = [(SparseTable(a, f), f) for f in (min, max, gcd)]
    for _ in range(30):
        l, r = sorted(rng.randrange(len(a)) for _ in range(2))
        for st, f in tables:
            assert st.query(l, r) == reduce(f, a[l:r + 1])
print("무작위 500개 비교(min, max, gcd): 모두 일치")

n = 100_000
st = SparseTable([rng.random() for _ in range(n)], min)
print("n =", n, " 층 수:", len(st.sp), " 칸 수:", sum(map(len, st.sp)))
```
```text
무작위 500개 비교(min, max, gcd): 모두 일치
n = 100000  층 수: 17  칸 수: 1568946
```
최솟값, 최댓값, gcd 세 연산 모두 정의대로 구한 값과 같다. n = 10만이면 층이 17개, 칸이 약 157만 개다. 위 층일수록 시작 위치가 줄어서 `n × 17`보다 조금 적다.

## 구간 합에는 왜 안 되나
합은 멱등이 아니다. 겹친 칸을 두 번 더하므로 틀린 답이 나온다. 앞 코드에 이어서 확인한다.
```python
from operator import add

a = [4, 6, 1, 5, 7, 3, 8, 2]
st = SparseTable(a, add)
print("겹치는 두 조각:", st.query(1, 6), " 실제 합:", sum(a[1:7]))

def query_disjoint(st, l, r, e):          # 겹치지 않는 2ᵏ 조각으로, O(log n)
    res = e
    for k in range(len(st.sp) - 1, -1, -1):
        if l + (1 << k) - 1 <= r:
            res = st.op(res, st.sp[k][l])
            l += 1 << k
    return res

rng = random.Random(16)
for _ in range(500):
    a = [rng.randint(-50, 50) for _ in range(rng.randint(1, 40))]
    st = SparseTable(a, add)
    for _ in range(30):
        l, r = sorted(rng.randrange(len(a)) for _ in range(2))
        assert query_disjoint(st, l, r, 0) == sum(a[l:r + 1])
print("겹치지 않는 분해, 무작위 500개 비교: 모두 일치")
```
```text
겹치는 두 조각: 42  실제 합: 30
겹치지 않는 분해, 무작위 500개 비교: 모두 일치
```
[1, 4]의 합 19와 [3, 6]의 합 23을 더하면 겹친 3, 4번 칸(5 + 7 = 12)이 두 번 들어가 42가 된다. 겹치지 않게 쓰려면 길이를 2진수로 쪼개 2의 거듭제곱 조각을 왼쪽부터 차례로 붙이면 되고, 그러면 결합 법칙만 있는 연산에도 맞지만 질의가 O(log n)으로 돌아간다. 구간 합이라면 그냥 누적 합으로 O(1)이니 희소 테이블을 쓸 이유가 없다. 정리하면 다음과 같다.
- O(1) 질의가 되는 연산: 최솟값, 최댓값, gcd, 비트 AND, 비트 OR(모두 결합 법칙 + 멱등)
- 안 되는 연산: 합, 곱, XOR, 최대 구간합(멱등이 아님)

배열이 바뀌면 표 전체를 다시 만들어야 하므로(O(n log n)) 갱신이 섞인 문제에는 세그먼트 트리를 쓴다. 변형으로는 2차원 희소 테이블(직사각형 최솟값, 메모리 `O(nm log n log m)`), 결합 법칙만 있으면 O(1) 질의를 주는 분리 희소 테이블(disjoint sparse table)이 있다. 흔한 실수는 층의 길이(`n − 2ᵏ + 1`)를 넘는 인덱스 접근과, 오른쪽 조각의 시작을 `r − 2ᵏ`로 잘못 쓰는 것(`r − 2ᵏ + 1`이 맞다)이다.

## RMQ가 쓰이는 곳
RMQ는 그 자체보다 다른 문제의 부품으로 자주 나온다. 트리의 두 정점의 최소 공통 조상은 오일러 투어 순서에서 두 정점 사이의 "깊이가 가장 얕은 정점"이고, 접미사 배열에서 두 접미사의 최장 공통 접두사는 LCP 배열의 구간 최솟값이다. 2000년 벤더(Bender)와 파라크-콜턴(Farach-Colton)의 논문 "The LCA Problem Revisited"는 이 둘이 사실상 같은 문제임을 이용해, 희소 테이블을 블록 분할과 엮어 전처리 O(n)·질의 O(1)인 간단한 방법으로 정리했다.

## 복잡도
| 방법 | 전처리 | 질의 |
|---|---|---|
| 매번 훑기 | 없음 | O(n) |
| 모든 구간 표 | O(n²) | O(1) |
| 세그먼트 트리 | O(n) | O(log n) |
| 희소 테이블 | O(n log n) | O(1) |

- 공간은 O(n log n)이고 갱신은 지원하지 않는다. 겹치지 않는 분해 질의는 O(log n)이다. q가 n보다 훨씬 클 때 희소 테이블이 가장 빛난다.

## 어디에 쓰이나
- 이산수학 7편 「비둘기집 원리와 포함·배제의 원리」: 합에서 겹친 부분이 두 번 세어지는 것은 `∣A ∪ B∣ = ∣A∣ + ∣B∣ − ∣A ∩ B∣`에서 교집합을 빼야 하는 이유와 같고, 멱등 연산은 그 빼기가 필요 없다.
- 10편 「최소 공통 조상: 희소 배열로 2의 거듭제곱씩 오르기」: 오일러 투어 + 희소 테이블로 LCA를 O(1)에 답하는 방식이 binary lifting과 비교된다.
- 문자열 알고리즘 5편 「접미사 배열과 LCP 배열」: 두 접미사의 최장 공통 접두사 길이가 LCP 배열의 구간 최솟값이라, 희소 테이블을 얹으면 임의의 두 접미사에 대해 이 값을 O(1)에 구한다.

## 정리
- 희소 테이블은 길이 2ᵏ 구간의 답을 `sp[k][i]`에 두 배씩 쌓아 O(n log n)에 만든다.
- 질의는 `2ᵏ ≤ L`인 가장 큰 k로 양 끝 두 조각을 겹쳐 덮어 O(1)에 답한다.
- 겹쳐 세도 되는 멱등 연산(최솟값·최댓값·gcd·AND·OR)에서만 O(1)이고, 합은 겹친 칸을 두 번 센다.
- 갱신이 없고 질의가 많은 RMQ에 쓰며, LCA와 LCP 같은 문제의 부품이 된다.
