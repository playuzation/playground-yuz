# [Redis 실무 3/10] 자료 구조: 리스트, 해시, 셋, 정렬된 셋

> **한 줄 요약** — 리스트는 양 끝에서 넣고 빼는 줄(큐·최근 목록), 해시는 필드 묶음(객체 하나), 셋은 중복 없는 모음(태그·교집합), 정렬된 셋은 점수로 늘 정렬된 모음(순위표·시간 창)이고, 연산을 서버 안에서 하므로 필요한 결과만 받아 온다.

## 이 글에서 다루는 것
- 리스트: 큐, 최근 N개 목록, 기다리며 꺼내기
- 해시: 사용자 한 명의 필드 묶음
- 셋: 중복 없는 모음과 교집합
- 정렬된 셋: 순위표와 시간 구간 질의
- 명령의 비용과 고르는 법

## 왜 값에 자료 구조를 두나
사용자 프로필을 JSON 문자열 하나로 저장하면, 나이 하나를 올리려 해도 전체를 읽어 와 고치고 다시 써야 한다. 그 사이에 다른 클라이언트가 이름을 바꾸면 한쪽의 변경이 사라진다. 값 자체가 해시라면 `HINCRBY user:42 age 1` 한 번이면 된다. 필요한 연산을 서버에 맡기면 왕복과 경쟁이 함께 준다. 실습 서버를 띄우고 하나씩 써 보자.
```bash
redis-server --port 6390 --save "" --appendonly no > redis.log 2>&1 &
until redis-cli -p 6390 ping > /dev/null 2>&1; do sleep 0.1; done
r() { redis-cli -p 6390 --no-raw "$@"; }
```

## 리스트: 양 끝이 열린 줄
리스트는 삽입 순서를 지키는 문자열 목록이다. 양 끝(`L`은 왼쪽, `R`은 오른쪽)에 넣고 빼는 것은 길이와 상관없이 빠르다. 작업 큐와 "최근 본 상품 5개" 같은 목록에 쓴다.
```bash
r rpush jobs email:1 email:2 email:3
r lpop jobs
r llen jobs
for item in p1 p2 p3 p4 p5 p6 p7; do r lpush recent:42 $item > /dev/null; r ltrim recent:42 0 4 > /dev/null; done
r lrange recent:42 0 -1
r blpop empty:queue 1
```
```text
(integer) 3
"email:1"
(integer) 2
1) "p7"
2) "p6"
3) "p5"
4) "p4"
5) "p3"
(nil)
```
`RPUSH`로 오른쪽에 넣고 `LPOP`으로 왼쪽에서 꺼내면 먼저 들어온 것이 먼저 나가는 큐다. 최근 목록은 `LPUSH`로 앞에 넣고 `LTRIM 0 4`로 다섯 개만 남긴다. 일곱 개를 넣었지만 최신 다섯 개만 남았다. `BLPOP`은 비어 있으면 값이 들어올 때까지(여기서는 최대 1초) 기다렸다 꺼낸다. 워커가 쉴 새 없이 묻지 않고 기다릴 수 있다. 다만 꺼낸 순간 리스트에서 사라지므로, 워커가 처리 중에 죽으면 그 일은 잃는다. 이 문제는 6편의 스트림이 푼다.

## 해시: 필드 묶음
해시는 키 하나 안에 필드와 값의 짝을 여러 개 둔다. 객체 하나를 표현하기 좋다.
```bash
r hset user:42 name minji city Seoul age 29
r hget user:42 city
r hincrby user:42 age 1
r hgetall user:42
r hdel user:42 city
r hlen user:42
r object encoding user:42
```
```text
(integer) 3
"Seoul"
(integer) 30
1) "name"
2) "minji"
3) "city"
4) "Seoul"
5) "age"
6) "30"
(integer) 1
(integer) 2
"listpack"
```
`HINCRBY`로 필드 하나만 원자적으로 올렸다. 필드가 적고 값이 짧은 해시는 `listpack`이라는 촘촘한 배열로 저장되어 메모리를 아낀다. 해시는 필드마다 따로 만료 시간을 줄 수 없다는 점(Redis 7.4부터 필드 만료가 생겼다)을 기억하자. 세션처럼 통째로 만료되는 묶음에는 잘 맞고, 필드마다 수명이 다른 값은 키를 나누는 편이 쉽다.

## 셋: 중복 없는 모음
셋은 순서 없이 중복을 허락하지 않는 모음이다. 들어 있는지 확인하는 것이 빠르고, 셋끼리 교집합·합집합·차집합을 서버 안에서 계산한다.
```bash
r sadd tags:post:1 redis cache db
r sadd tags:post:1 redis
r sismember tags:post:1 cache
r scard tags:post:1
r sadd follows:minji a b c d
r sadd follows:sora c d e
redis-cli -p 6390 sinter follows:minji follows:sora | sort
```
```text
(integer) 3
(integer) 0
(integer) 1
(integer) 3
(integer) 4
(integer) 3
c
d
```
이미 있는 `redis`를 다시 넣자 0이 돌아왔다(새로 추가된 개수). 두 사람이 함께 팔로우하는 사람은 `SINTER` 한 번으로 구했다. 셋에는 순서가 없어 출력 순서가 정해져 있지 않으므로, 여기서는 정렬해서 보였다. 좋아요를 누른 사람, 오늘 방문한 사용자 ID처럼 "들어 있나"와 "몇 명인가"가 중요한 데이터에 쓴다.

## 정렬된 셋: 점수로 늘 정렬된 모음
정렬된 셋은 멤버마다 점수(실수)를 붙이고 점수 순서를 항상 유지한다. 순위표, 우선순위 큐, 시간을 점수로 쓴 이벤트 목록에 쓴다.
```bash
r zadd board 120 minji 95 sora 150 jun 80 hana
r zincrby board 40 sora
r zrevrange board 0 2 withscores
r zrevrank board minji
r zcount board 100 200
r zadd events 1700000010 login 1700000070 buy 1700000130 logout
r zrangebyscore events 1700000000 1700000100
```
```text
(integer) 4
"135"
1) "jun"
2) "150"
3) "sora"
4) "135"
5) "minji"
6) "120"
(integer) 2
(integer) 3
(integer) 3
1) "login"
2) "buy"
```
`ZINCRBY`로 sora의 점수를 올리자 순위가 바로 바뀌었다. 상위 3명은 `ZREVRANGE` 한 번으로, minji의 순위(0부터 세어 2, 즉 3등)와 100~200점 사이의 인원도 각각 명령 하나로 나온다. 시각을 점수로 쓰면 "이 시간 구간의 이벤트"를 `ZRANGEBYSCORE`로 고를 수 있고, 5편의 슬라이딩 윈도 레이트 리밋이 이 방식을 쓴다. 안쪽은 스킵 리스트와 해시 테이블의 조합이라, 멤버 수가 n일 때 넣기와 순위 찾기가 대략 log n 단계에 끝난다(추상 데이터 타입 심화 10편의 스킵 리스트).

## 명령의 비용과 고르는 법
| 자료 구조 | 빠른 연산 | 조심할 연산 |
| --- | --- | --- |
| 리스트 | 양 끝 넣기·빼기 | 가운데 접근, 전체 읽기 |
| 해시 | 필드 하나 읽기·쓰기 | 큰 해시의 HGETALL |
| 셋 | 들어 있나, 넣기 | 큰 셋의 SMEMBERS |
| 정렬된 셋 | 넣기, 순위, 구간 | 전체 범위 읽기 |

"전체를 한 번에 돌려주는" 명령은 원소가 수십만 개로 커지면 1편에서 본 한 줄 실행을 오래 붙잡는다. 큰 컬렉션은 `HSCAN`, `SSCAN`, `ZSCAN`으로 나눠 읽고, 애초에 한 키가 끝없이 커지지 않게 설계한다(9편의 큰 키).
```bash
r shutdown nosave
```

## 흔한 오해
- "리스트로 만든 큐면 메시지 큐로 충분하다": 꺼낸 순간 사라지므로 처리 중 장애에 약하고, 여러 소비자가 같은 메시지를 나눠 읽는 그룹 개념이 없다. 그런 요구에는 스트림(6편)이나 전용 메시지 시스템을 쓴다.
- "셋의 출력 순서는 넣은 순서다": 셋에는 순서가 없다. 순서가 필요하면 리스트나 정렬된 셋을 쓴다.
- "정렬된 셋의 점수는 정수만 된다": 실수를 쓰므로 시각, 가중치, 확률도 점수가 된다. 다만 점수가 같으면 멤버 이름의 사전 순으로 정렬된다.

## 정리
- 리스트는 양 끝 넣기·빼기가 빠른 줄이라 큐와 최근 N개 목록에 맞는다. `BLPOP`으로 기다리며 꺼낸다.
- 해시는 객체 하나의 필드 묶음이다. 필드 하나를 원자적으로 고친다.
- 셋은 중복 없는 모음이다. 포함 여부와 교집합을 서버에서 계산한다.
- 정렬된 셋은 점수 순서를 늘 유지해 순위표와 시간 구간 질의에 쓴다.
- 전체를 돌려주는 명령은 큰 컬렉션에서 서버를 멈추게 한다. SCAN 계열로 나눠 읽는다.
