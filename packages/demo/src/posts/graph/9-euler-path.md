# [그래프 알고리즘 9/14] 오일러 경로: 모든 간선을 한 번씩 지나기

> **한 줄 요약** — 모든 간선을 정확히 한 번씩 지나는 경로는 간선이 한 덩어리로 이어져 있고 홀수 차수 정점이 0개 또는 2개일 때만 있으며, 히어홀저 알고리즘은 막힐 때까지 걷고 막힌 정점부터 답의 뒤쪽에 쌓는 스택 하나로 그 경로를 O(V + E)에 만든다.

## 이 글에서 다루는 것
- 쾨니히스베르크 다리 문제와 오일러 경로·회로의 존재 조건
- 그냥 걸으면 막히는 이유와 히어홀저 알고리즘의 "막힌 곳부터 쌓기"
- 무방향·방향 그래프를 함께 다루는 구현과 되추적 완전 탐색 대조
- 응용: 드 브루인 수열, 사전순 경로, 우편배달부 문제

## 예제 문제: 다리 일곱 개를 한 번씩
프로이센의 도시 쾨니히스베르크는 강으로 네 땅(섬 A, 북쪽 B, 남쪽 C, 동쪽 D)으로 나뉘고 다리 일곱 개로 이어져 있었다. 모든 다리를 한 번씩만 건너는 산책로가 있을까? 땅을 정점, 다리를 간선으로 놓으면 같은 두 정점 사이에 간선이 여러 개인 멀티그래프가 된다.

| 땅 | 다리로 이어진 땅 | 차수 |
|---|---|---|
| A (섬) | B, B, C, C, D | 5 |
| B (북쪽) | A, A, D | 3 |
| C (남쪽) | A, A, D | 3 |
| D (동쪽) | A, B, C | 3 |

다리는 A–B 2개, A–C 2개, A–D, B–D, C–D다. 레온하르트 오일러는 1735년 페테르부르크 학술원에서 이런 산책로가 없음을 보였고 이듬해 논문으로 정리했다.

모든 간선을 정확히 한 번씩 지나는 경로를 **오일러 경로**(Eulerian path), 출발점으로 돌아오면 **오일러 회로**(Eulerian circuit)라 한다. 정점을 한 번씩 지나는 해밀턴 경로는 NP-완전이라 동적 계획법 6편 「비트마스크 DP: 외판원 순회 문제」 같은 지수 시간 방법이 필요하지만, 간선 버전은 선형 시간에 풀린다.

## 존재 조건과 그 이유
- **무방향**: 간선이 있는 정점들이 모두 연결되어 있고, 홀수 차수 정점이 0개면 회로, 2개면 그 둘을 양 끝으로 하는 경로가 있다.
- **방향**: (나가는 수 − 들어오는 수)가 출발점에서 +1, 도착점에서 −1, 나머지에서 0이어야 한다(모두 0이면 회로). 연결성은 방향을 무시하고 본다.

필요한 이유는 간단하다. 경로가 중간 정점을 한 번 지날 때마다 들어오는 간선과 나가는 간선을 하나씩 쓰므로, 양 끝이 아닌 정점의 차수는 짝수여야 한다. 홀수 차수 정점이 1개일 수는 없다. 이산수학 8편의 악수 정리에 따라 홀수 차수 정점은 늘 짝수 개다. 쾨니히스베르크는 넷 모두 홀수라 불가능하다.

충분한 이유는 이산수학 4편 「수학적 귀납법과 재귀」 식의 간선 수 귀납이다. 회로 조건에서 아무 정점에서나 걷기 시작하면, 다른 정점에 들어갈 때마다 나갈 간선이 하나 남아 있으므로 막히는 곳은 출발점뿐이다. 그렇게 만든 닫힌 길을 지워도 남은 간선의 차수는 모두 짝수이므로, 남은 조각마다 귀납 가정으로 회로를 만들어 원래 길의 만나는 정점에 끼워 넣으면 된다. 오일러는 충분성을 증명 없이 적었고, 이 증명은 카를 히어홀저(Carl Hierholzer)가 세상을 떠난 뒤인 1873년에 출판되었다.

## 그냥 걸으면 막힌다
두 삼각형이 정점 2를 공유하는 나비넥타이 모양에서 0 → 1 → 2 → 0으로 걸으면 0에서 막힌다. 간선 2–3, 3–4, 4–2가 남았는데 돌아갈 길이 없다. 모든 경우를 되추적하면 답은 나오지만 최악에 간선 수의 계승만큼 걸린다. 히어홀저의 방법은 막혔을 때 되돌아가며, 막힌 정점을 **답의 맨 뒤**로 확정한다. 스택을 되감다가 아직 안 쓴 간선이 있는 정점(여기서는 2)을 만나면 거기서 다시 걸어 곁가지 회로를 만들고, 그 회로가 자연스럽게 중간에 끼워진다.

## 구현
```python
def euler_path(n, edges, directed=False):
    adj, deg = [[] for _ in range(n)], [0] * n
    for i, (u, v) in enumerate(edges):
        adj[u].append((v, i))
        if directed:
            deg[u] += 1; deg[v] -= 1      # 나가는 수 − 들어오는 수
        else:
            adj[v].append((u, i)); deg[u] += 1; deg[v] += 1
    if directed:
        odd = [v for v in range(n) if deg[v] != 0]
        if any(abs(deg[v]) > 1 for v in odd) or len(odd) > 2:
            return None
        start = [v for v in odd if deg[v] == 1]
    else:
        start = [v for v in range(n) if deg[v] % 2]
        if len(start) > 2:
            return None
    if not start:
        start = [next((v for v in range(n) if adj[v]), 0)]
    used, ptr = [False] * len(edges), [0] * n
    stack, path = [start[0]], []
    while stack:
        v = stack[-1]
        while ptr[v] < len(adj[v]) and used[adj[v][ptr[v]][1]]:
            ptr[v] += 1                   # 이미 쓴 간선은 다시 보지 않는다
        if ptr[v] == len(adj[v]):
            path.append(stack.pop())      # 막혔다: 답의 뒤쪽부터 확정
        else:
            w, i = adj[v][ptr[v]]
            used[i] = True
            stack.append(w)
    if len(path) != len(edges) + 1:       # 닿지 못한 간선 = 연결 안 됨
        return None
    return path[::-1]

A, B, C, D = range(4)                     # A = 크나이프호프 섬
bridges = [(A, B), (A, B), (A, C), (A, C), (A, D), (B, D), (C, D)]
print("쾨니히스베르크", euler_path(4, bridges))
print("B-C 추가", euler_path(4, bridges + [(B, C)]))
print("나비넥타이", euler_path(5, [(0, 1), (1, 2), (2, 0),
                                   (2, 3), (3, 4), (4, 2)]))
```
```text
쾨니히스베르크 None
B-C 추가 [0, 1, 0, 2, 0, 3, 1, 2, 3]
나비넥타이 [0, 1, 2, 3, 4, 2, 0]
```
다리 B–C를 하나 놓으면 B와 C가 짝수가 되어 홀수 정점 A에서 D로 가는 경로가 생긴다. 나비넥타이에서는 0 → 1 → 2 → 0이 막힌 뒤 2에서 2 → 3 → 4 → 2가 끼워졌다.

세 가지 장치가 중요하다. 무방향 간선은 양쪽 인접 리스트에 들어가므로 간선 번호로 `used`를 표시한다. `ptr`는 정점마다 다음에 볼 위치를 기억해 쓴 간선을 다시 훑지 않게 하며, 이것이 전체를 O(V + E)로 만든다. 연결성은 따로 검사하지 않고 결과 길이로 판정한다. 다른 덩어리에 있는 간선은 출발점에서 닿지 못해 경로에 빠지기 때문이다.

## 무작위 대조 검사
느린 쪽은 모든 출발점에서 간선을 하나씩 골라 되추적하는 완전 탐색이다. 구한 경로는 이웃한 정점 쌍의 중복 집합이 간선 목록과 같은지로 따로 검증한다. 앞 코드에 이어서 실행한다.
```python
import random
from collections import Counter

def brute_exists(n, edges, directed):
    used = [False] * len(edges)
    def go(v, k):                         # k개 간선을 썼고 지금 v에 있다
        if k == len(edges):
            return True
        for i, (a, b) in enumerate(edges):
            if not used[i] and (a == v or (not directed and b == v)):
                used[i] = True
                if go(b if a == v else a, k + 1):
                    return True
                used[i] = False
        return False
    return any(go(v, 0) for v in range(n))

def valid(path, edges, directed):
    key = (lambda e: e) if directed else (lambda e: tuple(sorted(e)))
    walk = Counter(key(e) for e in zip(path, path[1:]))
    return walk == Counter(key(e) for e in edges)

rng = random.Random(9)
found = 0
for _ in range(1000):
    directed = rng.random() < 0.5
    n = rng.randint(1, 5)
    E = [(rng.randrange(n), rng.randrange(n)) for _ in range(rng.randint(2, 8))]
    p = euler_path(n, E, directed)
    assert (p is not None) == brute_exists(n, E, directed), (E, directed)
    assert p is None or valid(p, E, directed)
    found += p is not None
print("무작위 1000개 비교: 모두 일치")
print("경로가 있던 입력:", found)
```
```text
무작위 1000개 비교: 모두 일치
경로가 있던 입력: 656
```
자기 루프, 평행 간선, 끊긴 그래프가 모두 섞인 입력에서 존재 여부와 경로가 맞았다.

## 응용: 드 브루인 수열
k자리 이진 문자열 2ᵏ개를 모두 부분 문자열로 품는 가장 짧은 문자열을 **드 브루인 수열**(de Bruijn sequence)이라 한다. (k−1)비트 문자열을 정점으로, 끝에 비트 하나를 붙여 옮겨 가는 것을 간선으로 놓으면 모든 정점의 나가는 수와 들어오는 수가 2로 같으므로 오일러 회로가 있다. 간선 하나가 k비트 문자열 하나이므로 회로를 따라 비트를 적으면 길이 2ᵏ + k − 1짜리 답이 된다. 앞 코드에 이어서 실행한다.
```python
def de_bruijn(k):
    m = 1 << (k - 1)                      # 정점 = (k−1)비트 문자열
    edges = [(x, (x << 1 | b) % m) for x in range(m) for b in (0, 1)]
    p = euler_path(m, edges, directed=True)
    return format(p[0], f"0{k - 1}b") + "".join(str(v & 1) for v in p[1:])

s = de_bruijn(3)
print(s, len(s), len({s[i:i + 3] for i in range(len(s) - 2)}))
for k in (4, 8, 12):
    s = de_bruijn(k)
    print(k, len(s), len({s[i:i + k] for i in range(len(s) - k + 1)}))
```
```text
0001011100 10 8
4 19 16
8 263 256
12 4107 4096
```
3자리 8가지가 10글자 안에 모두 들어 있고, k = 12에서도 4,107글자 안에 4,096가지가 빠짐없이 한 번씩 나온다. 같은 그래프를 DNA 조각에 쓰면, 짧은 조각들의 k-글자 부분을 간선으로 놓고 오일러 경로로 원래 서열을 이어 붙일 수 있다.

## 자주 하는 실수와 변형
- `adj[v].remove(...)`로 간선을 지우면 한 번에 O(차수)라 전체가 O(E²)까지 느려진다. 위처럼 포인터와 `used` 배열을 쓴다.
- 재귀로 쓰면 간선 수만큼 깊어진다. 간선이 10⁵개면 파이썬 재귀 한도를 넘으므로 명시적 스택이 안전하다.
- 출발점을 홀수 차수 정점(방향이면 +1인 정점)으로 고르지 않으면 존재하는 경로를 놓친다.
- **사전순으로 가장 앞선 경로**: 방향 그래프에서 인접 리스트를 도착 정점 순으로 정렬해 두면 위 알고리즘이 그대로 사전순 최소 경로를 낸다. 작은 무작위 그래프 523개에서 모든 경로를 열거해 확인했다.
- **플뢰리 알고리즘**(Fleury's algorithm): 단절선은 다른 길이 없을 때만 건너는 규칙으로 걷는다. 매 걸음 8편의 단절선 판정이 필요해 히어홀저보다 느리다.
- **우편배달부 문제**: 오일러 경로가 없으면 홀수 차수 정점들을 짝지어 그 사이 최단 경로를 한 번 더 걷는다. 짝짓는 비용을 최소화하는 것은 일반 그래프의 최소 가중치 완전 매칭 문제가 된다.

## 복잡도
| 방법 | 시간 | 공간 |
|---|---|---|
| 되추적 완전 탐색 | 최악 O(E!) 수준 | O(E) |
| 플뢰리 | O(E·(V + E)) | O(V + E) |
| 히어홀저 | O(V + E) | O(V + E) |

히어홀저는 간선마다 `used` 표시 한 번, 포인터 전진 한 번(무방향은 양쪽에서 두 번)이고 정점은 들어간 간선 수만큼 스택에 오르내린다.

- 유전체 조립: 퍼브즈너(Pavel Pevzner)·탱·워터먼의 2001년 논문은 DNA 조각 조립을 드 브루인 그래프 위의 오일러 경로 문제로 바꿔 반복 서열 문제를 다뤘다.

## 정리
- 오일러 경로는 간선이 한 덩어리이고 홀수 차수 정점이 0개(회로) 또는 2개(경로)일 때만 있고, 방향 그래프는 나가는 수와 들어오는 수의 차이로 판정한다.
- 그냥 걸으면 막히지만, 히어홀저는 막힌 정점을 답의 뒤에 쌓고 되돌아가며 곁가지 회로를 끼워 넣는다.
- 간선 번호 `used`와 정점별 포인터로 O(V + E)를 지키고, 결과 길이로 연결성까지 확인한다.
- 드 브루인 수열과 DNA 조립처럼 "조각을 한 줄로 잇기" 문제가 오일러 경로로 바뀐다.
