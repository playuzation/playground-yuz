# [동적 계획법 12/12] 부분집합 합 DP(SOS DP): 모든 부분집합에 대한 합을 빠르게

> **한 줄 요약** — 비트마스크를 n차원 정육면체(각 변의 길이 2)의 한 점으로 보면 "S의 모든 부분집합에 대한 합"은 n차원 누적 합이고, 차원(비트)을 하나씩 누적하면 2ⁿ개 집합 전부의 답을 3ⁿ이 아닌 n·2ⁿ에 구하며, 같은 방식으로 빼면 원래 값이 돌아온다.

## 이 글에서 다루는 것
- 모든 S에 대해 부분집합 합 구하기: 4ⁿ → 3ⁿ → n·2ⁿ
- 비트를 차원으로 보는 누적 합과 그 불변식
- 초집합 합과 되돌리기(뫼비우스 변환)
- 응용: AND가 0인 쌍 세기, OR·AND 합성곱
- 완전 탐색과의 무작위 대조

## 예제 문제: 가진 재료로 만들 수 있는 요리 수
재료가 n = 20종 있고, 요리마다 필요한 재료 집합이 비트마스크로 주어진다. `f[T]`를 "필요한 재료 집합이 정확히 T인 요리 수"라 하자. 이제 재료 조합 S 2ⁿ ≈ 100만 가지 **모두**에 대해 "S에 있는 재료만으로 만들 수 있는 요리 수"를 알고 싶다.
```text
g[S] = Σ f[T]    (T ⊆ S)
```
S마다 모든 T를 보며 부분집합인지 확인하면 4ⁿ ≈ 1.1 × 10¹²번이다. 알고리즘 기법 11편 「비트마스킹: 정수 하나로 집합 다루기」의 "부분집합의 부분집합 열거"(`T = (T - 1) & S`)를 쓰면 원소마다 "T에 있음 / S에만 있음 / S에도 없음" 세 경우라 정확히 3ⁿ ≈ 3.5 × 10⁹번이다. 줄긴 했지만 여전히 35억 번이다.

## 아이디어: 비트 하나가 차원 하나
T ⊆ S는 "모든 비트에서 T의 비트 ≤ S의 비트"와 같다. 마스크를 n차원 좌표 (b₀, b₁, …)로 보면 g는 n차원 **누적 합**이다. 알고리즘 기법 6편 「누적 합과 차분 배열: 구간 합과 구간 갱신을 O(1)로」의 2차원 누적 합을 가로로 한 번, 세로로 한 번 누적해 구할 수 있듯, n차원 누적 합도 차원마다 한 번씩 누적하면 된다. 각 차원의 길이가 2뿐이라 "차원 i 방향 누적"은 한 줄로 끝난다. 비트 i가 켜진 S에, 비트 i를 끈 마스크의 값을 더한다.
```text
n = 2, f = [a, b, c, d]
         (00, 01, 10, 11)
비트 0 후: [a, a+b, c, c+d]
비트 1 후: [a, a+b, a+c, a+b+c+d]
```
맞는 이유는 불변식으로 보인다. 비트 0~i−1을 처리한 뒤 `g[S]`는 "S의 부분집합이면서 비트 i 이상은 S와 똑같은 T"들의 합이다. 비트 i를 처리할 때 비트 i가 켜진 S에 비트 i를 끈 쪽의 값을 더하면, 비트 i가 0인 T들이 합류해 "비트 i + 1 이상이 같은 T"로 넓어진다. n개를 다 처리하면 조건이 사라져 모든 부분집합의 합이 된다. 비트 i를 처리하는 동안 값이 바뀌는 칸은 비트 i가 켜진 칸뿐이고 읽는 칸은 꺼진 칸이라, 배열 하나를 제자리에서 갱신해도 된다.
```python
def sum_naive(f, n):                   # 부분집합의 부분집합 열거 O(3ⁿ)
    g, ops = [0] * (1 << n), 0
    for S in range(1 << n):
        T = S
        while True:                    # S의 모든 부분집합 T
            ops += 1
            g[S] += f[T]
            if T == 0:
                break
            T = (T - 1) & S
    return g, ops

def sos(f, n):                         # 비트(차원)마다 한 번씩 O(n·2ⁿ)
    g, ops = f[:], 0
    for i in range(n):
        for S in range(1 << n):
            if S >> i & 1:             # 비트 i를 끈 쪽의 값을 더한다
                ops += 1
                g[S] += g[S ^ (1 << i)]
    return g, ops

print(sos([1, 10, 100, 1000], 2)[0])
for n in [8, 10, 12]:
    f = list(range(1 << n))
    a, x = sum_naive(f, n)
    b, y = sos(f, n)
    print(n, a == b, "열거:", x, "SOS:", y)
```
```text
[1, 11, 101, 1111]
8 True 열거: 6561 SOS: 1024
10 True 열거: 59049 SOS: 5120
12 True 열거: 531441 SOS: 24576
```
열거는 정확히 3ⁿ번, SOS는 n·2ⁿ⁻¹번 더한다. n = 12에서 이미 20배 넘게 차이 나고, n = 20이면 약 330배다. 바깥 반복이 비트, 안쪽 반복이 마스크라는 순서가 중요하다. 둘을 바꾸면 같은 T가 여러 경로로 두 번 이상 더해진다.

## 초집합 합과 되돌리기
"S를 포함하는 모든 T"의 합(초집합 합)은 방향만 뒤집는다. 비트 i가 꺼진 S에 비트 i를 켠 쪽의 값을 더한다. 거꾸로 g에서 f를 되찾으려면 같은 순서로 더하는 대신 빼면 된다. 차원마다 누적 합의 역연산이 차분이기 때문이다. 이를 **뫼비우스 변환**(Möbius transform)이라 하고, 풀어 쓰면 포함·배제의 원리 `f(S) = Σ (−1)^(∣S∣−∣T∣)·g(T)`다. 앞 코드에 이어서, 크기 0~8비트의 무작위 f 500개로 세 함수를 모두 정의 그대로의 계산과 비교한다.
```python
import random

def sup_sos(f, n):                     # 초집합 합: 비트 i를 켠 쪽을 더한다
    g = f[:]
    for i in range(n):
        for S in range(1 << n):
            if not S >> i & 1:
                g[S] += g[S | 1 << i]
    return g

def mobius(g, n):                      # 부분집합 합을 되돌린다
    f = g[:]
    for i in range(n):
        for S in range(1 << n):
            if S >> i & 1:
                f[S] -= f[S ^ (1 << i)]
    return f

rng = random.Random(12)
for t in range(500):
    n = rng.randint(0, 8)
    f = [rng.randint(-50, 50) for _ in range(1 << n)]
    g = sos(f, n)[0]
    assert g == sum_naive(f, n)[0]
    sup = [sum(f[T] for T in range(1 << n) if T & S == S)
           for S in range(1 << n)]
    assert sup_sos(f, n) == sup
    assert mobius(g, n) == f
print("무작위 500개 비교: 모두 일치")
```
```text
무작위 500개 비교: 모두 일치
```

## 응용: AND가 0인 쌍 세기
수 n개(각 16비트 이하) 중 `a_i & a_j == 0`인 쌍 (i < j)의 수를 세자. 모든 쌍을 보면 O(n²)이다. x와 AND가 0이라는 것은 y가 x의 여집합 `full ^ x`의 부분집합이라는 뜻이므로, 값별 개수 `cnt`의 부분집합 합 F를 한 번 구해 두면 x마다 `F[full ^ x]`가 짝의 수다. 이렇게 더하면 순서쌍을 세게 되고, x = 0은 자기 자신과도 짝이 되므로 0의 개수를 빼고 2로 나눈다. 앞 코드에 이어서 쓴다.
```python
def and_zero_pairs(a, bits):
    full = (1 << bits) - 1
    cnt = [0] * (1 << bits)
    for x in a:
        cnt[x] += 1
    F, ops = sos(cnt, bits)            # F[S] = S의 부분집합인 원소 수
    ordered = sum(F[full ^ x] for x in a)  # x와 겹치지 않는 원소 수
    self_pairs = cnt[0]                # x = 0은 자기 자신과도 AND가 0
    return (ordered - self_pairs) // 2, ops

def brute_pairs(a):
    return sum(a[i] & a[j] == 0
               for i in range(len(a)) for j in range(i + 1, len(a)))

rng = random.Random(1212)
for t in range(500):
    bits = rng.randint(1, 8)
    a = [rng.randrange(1 << bits) for _ in range(rng.randint(1, 60))]
    assert and_zero_pairs(a, bits)[0] == brute_pairs(a)
print("무작위 500개 비교: 모두 일치")

bits, n = 16, 100_000
a = [rng.randrange(1 << bits) & rng.randrange(1 << bits)
     for _ in range(n)]                # 켜진 비트가 적은 수가 많게
pairs, ops = and_zero_pairs(a, bits)
print("AND가 0인 쌍:", pairs)
print("쌍 전부 보기:", n * (n - 1) // 2, " SOS 덧셈:", ops)
```
```text
무작위 500개 비교: 모두 일치
AND가 0인 쌍: 1769419474
쌍 전부 보기: 4999950000  SOS 덧셈: 524288
```
50억 쌍을 보는 대신 덧셈 52만 번과 원소마다 조회 한 번으로 끝났다. 비용이 원소 수 n이 아니라 값의 비트 수에 달려 있으므로, 값의 범위가 작고 원소가 많을 때 특히 유리하다.

## 합성곱과 변형
- OR 합성곱 `h(S) = Σ f(A)·g(B)` (A ∪ B = S): "A ∪ B ⊆ S"는 "A ⊆ S 그리고 B ⊆ S"와 같으므로, f와 g의 부분집합 합을 칸별로 곱한 뒤 뫼비우스 변환으로 되돌리면 h가 나온다. AND 합성곱은 초집합 합으로 똑같이 한다. XOR 합성곱은 같은 나비 모양에서 a + b, a − b를 쓰는 월시-아다마르 변환(Walsh–Hadamard transform)으로 한다.
- 서로소인 두 집합으로 나누는 부분집합 합성곱(A ∩ B = ∅)은 집합 크기를 차원으로 하나 더 붙여 O(n²·2ⁿ)에 푼다. 비에르클룬드(Björklund), 후스펠트, 카스키, 코이비스토가 2007년 STOC에 발표한 방법이다.
- 합 대신 최댓값: max도 차원별 누적이 되므로 "S의 부분집합 중 가장 큰 값"을 같은 틀로 구한다. 다만 max는 되돌릴 수 없어 뫼비우스 변환은 없다.
- 자주 하는 실수: 바깥·안쪽 반복 순서 바꾸기, 여집합을 구할 때 비트 폭(`full`)을 틀리기, 2ⁿ 크기 배열의 메모리(파이썬 리스트로 n = 25면 3천만 칸이 넘는다).

## 복잡도
| 방법 | 연산 수 | n = 20일 때 |
|---|---|---|
| 모든 (S, T) 쌍 | 4ⁿ | 약 1.1 × 10¹² |
| 부분집합 열거 | 3ⁿ | 약 3.5 × 10⁹ |
| SOS DP | n·2ⁿ⁻¹ | 약 1.0 × 10⁷ |

- 공간은 세 방법 모두 2ⁿ칸이다. SOS DP는 차원 n개마다 칸의 절반을 한 번씩 갱신한다.
- 쌍 세기 응용은 O(bits·2^bits + n)으로, 원소 수 n에 대해 선형이다.

## 어디에 쓰이나
- 이산수학 7편 「비둘기집 원리와 포함·배제의 원리」: 부분집합 합을 되돌리는 뫼비우스 변환은 포함·배제의 원리를 2ⁿ개 집합 전체에 한꺼번에 적용한 것이다.
- 선형대수 5편 「연립일차방정식과 역행렬」: 부분집합 합 변환은 2ⁿ × 2ⁿ 하삼각 행렬을 곱하는 일이고, 그 행렬이 2 × 2 행렬 `[[1, 0], [1, 1]]`을 n번 크로네커 곱한 꼴이라 4ⁿ 대신 n·2ⁿ에 곱할 수 있다. 뫼비우스 변환은 그 역행렬(`[[1, 0], [-1, 1]]`의 크로네커 곱)이다.
- 알고리즘 기법 6편 「누적 합과 차분 배열: 구간 합과 구간 갱신을 O(1)로」: SOS DP는 각 변의 길이가 2인 n차원 누적 합이고, 뫼비우스 변환은 n차원 차분이다.
- 장바구니 분석: 상품 집합 S를 모두 포함하는 거래 수(지지도)를 모든 S에 대해 구하는 것은 거래별 상품 집합 빈도의 초집합 합이다.

## 정리
- 모든 S의 부분집합 합은 비트마다 한 번씩 누적하는 n차원 누적 합으로 n·2ⁿ⁻¹번의 덧셈에 구한다.
- 반복 순서는 바깥이 비트, 안쪽이 마스크다. 방향을 뒤집으면 초집합 합, 더하기를 빼기로 바꾸면 뫼비우스 변환이다.
- "AND가 0" 같은 조건은 여집합의 부분집합 개수로 바꿔 원소 수에 선형인 시간에 센다.
- 부분집합 합을 칸별로 곱하고 되돌리면 OR 합성곱이 되고, 같은 틀이 AND·XOR·부분집합 합성곱으로 이어진다.
