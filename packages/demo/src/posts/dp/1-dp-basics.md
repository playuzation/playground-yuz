# [동적 계획법 1/12] 동적 계획법의 기본: 부분 문제와 점화식

> **한 줄 요약** — 동적 계획법(DP)은 큰 문제의 답을 작은 부분 문제의 답으로 쓰는 점화식을 세우고 같은 부분 문제를 한 번만 풀어 표에 기억해 두는 방법이며, 상태·전이·초기값·답 네 가지를 정하면 대부분의 DP를 설계할 수 있다.

## 이 글에서 다루는 것
- 예제 "1로 만들기"와 탐욕이 틀리는 이유
- 피보나치 호출 수로 보는 겹치는 부분 문제와 최적 부분 구조

## 예제 문제: 1로 만들기
정수 n에 쓸 수 있는 연산은 세 가지다. 1을 빼거나, 2로 나누어떨어지면 2로 나누거나, 3으로 나누어떨어지면 3으로 나눈다. n을 1로 만드는 최소 연산 횟수는 얼마인가? 먼저 떠오르는 방법은 "나눌 수 있으면 나눈다"는 **탐욕**(greedy)이다. n = 10이면 10 → 5 → 4 → 2 → 1로 4번이다. 그런데 10 → 9 → 3 → 1이면 3번이다. 처음에 1을 빼는 손해가 3으로 두 번 나누는 이득으로 돌아왔다. 지금 좋아 보이는 선택이 전체 최선을 보장하지 않으면 가능한 선택을 모두 따져야 한다.

모두 따지는 방법을 식으로 쓰자. `f(n)`을 n을 1로 만드는 최소 횟수라 하면, 첫 연산 뒤에는 n − 1, n/2, n/3 중 하나가 남고 거기서부터는 다시 최소로 가면 된다.
```text
f(1) = 0
f(n) = 1 + min(f(n−1),f(n/2),f(n/3))
       (n/2, n/3은 나누어떨어질 때만)
```
"부분 문제의 최적해를 이어 붙이면 전체 최적해가 된다"는 이 성질을 **최적 부분 구조**(optimal substructure)라고 한다. 10에서 출발한 최선의 길은 9에서 출발한 최선의 길을 그대로 쓴다.

## 단순한 재귀는 왜 느린가
점화식을 그대로 재귀 함수로 옮기면 정확하지만 느리다. 이산수학 4편 「수학적 귀납법과 재귀」의 피보나치로 호출 수를 세어 보자.
```python
calls = 0
def fib(n):                          # 점화식을 그대로 옮긴 재귀
    global calls
    calls += 1
    return n if n < 2 else fib(n - 1) + fib(n - 2)

memo, computed = {}, 0
def fib_memo(n):                     # 한 번 계산한 값은 기억한다
    global computed
    if n not in memo:
        computed += 1
        memo[n] = n if n < 2 else fib_memo(n - 1) + fib_memo(n - 2)
    return memo[n]

for n in [10, 20, 30]:
    calls, computed = 0, 0
    memo.clear()
    f = fib(n)
    fib_memo(n)
    print(f"n={n} F={f} 재귀 {calls:,}번 / 메모 {computed}번")
```
```text
n=10 F=55 재귀 177번 / 메모 11번
n=20 F=6765 재귀 21,891번 / 메모 21번
n=30 F=832040 재귀 2,692,537번 / 메모 31번
```
단순 재귀의 호출 수는 `2·F(n+1) − 1`로, 약 1.618배씩 늘어나는 지수 시간이다(이산수학 11편 「점근 표기법: 알고리즘의 비용 세기」). `fib(30)` 안에서 `fib(2)`는 51만 4,229번 다시 계산된다. 서로 다른 부분 문제는 `fib(0)`~`fib(30)`의 31개뿐인데 같은 것을 되풀이해 푸는 것이다. 이 성질이 **겹치는 부분 문제**(overlapping subproblems)이고, 답을 기억해 두면 31번으로 끝난다.

최적 부분 구조와 겹치는 부분 문제가 함께 있을 때 **동적 계획법**(dynamic programming)을 쓴다. 부분 문제가 겹치지 않으면(병합 정렬의 두 절반처럼) 기억할 것이 없으니 알고리즘 기법 8편 「분할 정복: 나누고 풀고 합치기」가 된다. 이름은 리처드 벨먼이 1950년대 랜드(RAND) 연구소에서 다단계 결정 문제를 연구하며 붙였고, 1957년 같은 제목의 책을 냈다. programming은 코드 작성이 아니라 "계획표 짜기"라는 뜻이다. 벨먼은 자서전(1984)에서, 당시 국방 장관이 "연구"라는 말을 몹시 싫어해서 수학 연구로 보이지 않는 이름을 골랐다고 회고했다.

## 하향식과 상향식
DP를 구현하는 방법은 두 가지다. **하향식**(top-down)은 점화식 재귀에 기억(메모이제이션)만 더한 것이고, **상향식**(bottom-up)은 작은 부분 문제부터 표를 차례로 채우는 것이다. 1로 만들기를 두 방식으로 짜고, 상향식에서는 어느 쪽에서 왔는지(`prev`)도 적어 실제 경로를 복원한다.
```python
from functools import lru_cache

@lru_cache(maxsize=None)
def ops_top(n):                      # 하향식: 점화식 + 기억
    if n == 1:
        return 0
    best = ops_top(n - 1)
    if n % 2 == 0:
        best = min(best, ops_top(n // 2))
    if n % 3 == 0:
        best = min(best, ops_top(n // 3))
    return best + 1

def ops_bottom(n):                   # 상향식: 작은 수부터 표를 채운다
    dp, prev = [0] * (n + 1), [0] * (n + 1)
    for i in range(2, n + 1):
        dp[i], prev[i] = dp[i - 1] + 1, i - 1
        for d in (2, 3):
            if i % d == 0 and dp[i // d] + 1 < dp[i]:
                dp[i], prev[i] = dp[i // d] + 1, i // d
    path = [n]                       # prev를 따라가면 경로가 나온다
    while path[-1] != 1:
        path.append(prev[path[-1]])
    return dp[n], path

def greedy(n):                       # 나눌 수 있으면 무조건 나눈다
    steps = 0
    while n > 1:
        if n % 3 == 0: n //= 3
        elif n % 2 == 0: n //= 2
        else: n -= 1
        steps += 1
    return steps

print(ops_bottom(10), "탐욕:", greedy(10))
bad = sum(greedy(n) != ops_bottom(n)[0] for n in range(1, 1001))
print("1~1000 중 탐욕이 틀린 n:", bad, "개")
print(ops_top(400), ops_bottom(5000)[0])
try:
    ops_top(5000)
except RecursionError:
    print("ops_top(5000): RecursionError")
```
```text
(3, [10, 9, 3, 1]) 탐욕: 4
1~1000 중 탐욕이 틀린 n: 541 개
9 13
ops_top(5000): RecursionError
```
탐욕은 1~1000 중 541개에서 틀렸다. 같은 점화식이라도 두 DP의 성격은 다르다.
- 하향식은 점화식을 그대로 옮겨 짜기 쉽고, 실제로 필요한 상태만 계산한다. 대신 재귀 깊이가 상태 사슬 길이만큼 쌓인다. 파이썬의 기본 재귀 한도는 1000이고, `lru_cache`로 감싸면 한 단계에 두 칸씩 써서 이 환경(파이썬 3.11)에서는 n = 500 근처에서 멈춘다. `sys.setrecursionlimit`으로 한도를 올리면 C 스택이 넘쳐 프로세스가 죽을 수 있다.
- 상향식은 재귀가 없고 배열이라 빠르지만, "어떤 순서로 채워야 필요한 칸이 미리 차 있는가"를 직접 정해야 한다. 여기서는 `i // d`와 `i − 1`이 모두 i보다 작으므로 오름차순이면 된다.

## 설계 4단계: 상태, 전이, 초기값, 답
**계단 오르기 유형**으로 설계 순서를 연습하자. 계단마다 점수가 있고, 바닥에서 출발해 한 번에 한 칸이나 두 칸을 오른다. 연속한 세 계단을 모두 밟을 수는 없고(바닥은 계단이 아니다), 마지막 계단은 반드시 밟아야 한다. 밟은 계단 점수의 합을 최대로 만들자.
1. **상태**: 부분 문제를 무엇으로 구별하나? "i번 계단에 섰을 때의 최대 점수"만으로는 다음 칸을 밟아도 되는지 알 수 없다. 그래서 연속 몇 번째로 밟았는지를 상태에 넣는다. `one[i]`, `two[i]`는 i번 계단을 연속 1번째, 2번째로 밟고 섰을 때의 최대 점수다.
2. **전이**: 두 칸 뛰어 왔으면 연속이 끊기므로 `one[i] = max(one[i−2], two[i−2]) + s[i]`, 한 칸 올라왔으면 직전이 연속 1번째여야 하므로 `two[i] = one[i−1] + s[i]`다.
3. **초기값**: 점화식이 기댈 곳 없는 가장 작은 상태다. 바닥에서 바로 올라오는 `one[0] = s[0]`, `one[1] = s[1]`이고, 불가능한 상태는 0이 아니라 −∞로 둔다.
4. **답**: 마지막 계단을 밟아야 하므로 `max(one[n−1], two[n−1])`이다.

전이가 더 작은 i만 보므로 i 오름차순으로 채운다.
```python
NEG = float("-inf")

def stairs(s):                       # s[i]: i+1번 계단 점수
    n = len(s)
    one, two = [NEG] * n, [NEG] * n  # i를 연속 1번째·2번째로 밟음
    for i in range(n):
        if i <= 1:
            one[i] = s[i]            # 바닥에서 바로 올라옴
        else:
            one[i] = max(one[i - 2], two[i - 2]) + s[i]
        if i >= 1:
            two[i] = one[i - 1] + s[i]
    return max(one[-1], two[-1])

print(stairs([10, 20, 15, 25, 10, 20]))
```
```text
75
```
10 + 20 + 25 + 20 = 75로, 3번 계단(15)을 건너뛰어 세 칸 연속을 피했다.

## 무작위 대조 검사
DP의 버그는 상태 누락이나 초기값 실수처럼 "그럴듯한 틀린 숫자"로 나타나서 예제 몇 개로는 잘 안 잡힌다. 이 시리즈는 알고리즘 기법 1편 「입력 크기로 알고리즘 고르기: 복잡도 어림과 문제 읽기」에서 소개한 무작위 대조 검사로 모든 구현을 확인한다. 느리지만 정의 그대로인 방법을 짜서, 시드를 고정한 무작위 입력 수백 개에서 답을 비교하는 것이다. 1로 만들기는 "연산 하나 = 간선 하나"인 상태 그래프의 BFS 최단 거리(이산수학 10편 「그래프 탐색: BFS, DFS, 위상 정렬」)로, 계단은 밟을 계단 집합 2ⁿ개를 모두 시도해서 비교한다. 앞 코드에 이어서 실행한다(`ops_bottom`, `stairs`, `NEG` 사용).
```python
import random
from collections import deque

def ops_bfs(n):                      # 정의 그대로: 상태 그래프 최단 거리
    dist, q = {n: 0}, deque([n])
    while q:
        x = q.popleft()
        if x == 1:
            return dist[x]
        for y in (x - 1, x // 2 if x % 2 == 0 else 0,
                  x // 3 if x % 3 == 0 else 0):
            if y >= 1 and y not in dist:
                dist[y] = dist[x] + 1
                q.append(y)

def stairs_brute(s):                 # 밟을 계단 집합을 전부 시도
    n, best = len(s), NEG
    for mask in range(1 << n):
        on = [i for i in range(n) if mask >> i & 1]
        if not on or on[-1] != n - 1 or on[0] > 1:
            continue
        if any(b - a > 2 for a, b in zip(on, on[1:])):
            continue                 # 한 번에 세 칸 이상 건너뜀
        if any(on[k + 2] - on[k] == 2 for k in range(len(on) - 2)):
            continue                 # 세 계단 연속
        best = max(best, sum(s[i] for i in on))
    return best

rng = random.Random(1)
for _ in range(500):
    n = rng.randint(1, 3000)
    assert ops_bottom(n)[0] == ops_bfs(n)
    s = [rng.randint(1, 100) for _ in range(rng.randint(1, 12))]
    assert stairs(s) == stairs_brute(s), s
print("무작위 500개 비교: 모두 일치")
```
```text
무작위 500개 비교: 모두 일치
```
자주 하는 실수도 이 검사에 잘 걸린다. 최댓값 문제에서 불가능한 상태를 0으로 두면 "갈 수 없는 길"이 답에 섞이고, 상태에서 "연속 횟수"를 빼면 세 계단 연속이 몰래 허용된다. 아직 채우지 않은 칸을 읽는 계산 순서 실수도 흔하다.

## 복잡도
DP의 시간은 대개 `상태 수 × 상태 하나의 전이 비용`이고, 공간은 기억하는 상태 수다.

| 방법 | 시간 | 공간 |
|---|---|---|
| 피보나치 단순 재귀 | O(1.618ⁿ) | O(n) 스택 |
| 피보나치 메모 | O(n) | O(n) |
| 1로 만들기 DP | O(n) | O(n) |
| 계단 DP | O(n) | O(n), 줄이면 O(1) |
| 계단 완전 탐색 | O(n·2ⁿ) | O(n) |

계단 DP는 `i − 1`, `i − 2`만 보므로 변수 몇 개로 공간을 O(1)까지 줄일 수 있다(2편에서 본격적으로 쓰는 기법).

- AI 기초 2편 「강화학습: 보상으로 배우는 머신러닝」: 가치를 "지금 보상 + 다음 상태의 최선 가치"로 쓰는 목표값은 벨먼 방정식, 즉 최적 부분 구조를 확률적인 상태 전이로 넓힌 것이다.
- 확률과 분포 12편 「마르코프 연쇄: 현재만 기억하는 확률 과정」: 숨은 상태가 마르코프 연쇄를 따를 때 가장 그럴듯한 상태열을 찾는 비터비 알고리즘(1967년, 길쌈 부호 복호를 위해 발표)은 시각 × 상태 표를 채우는 DP이고, 통신 복호와 음성 인식에 쓰였다.

## 정리
- DP는 최적 부분 구조(부분 최적해로 전체 최적해를 만든다)와 겹치는 부분 문제(같은 부분 문제가 반복된다)가 있을 때 쓴다.
- 하향식은 재귀 + 메모라 짜기 쉽지만 재귀 깊이에 주의하고, 상향식은 계산 순서를 정해 표를 채운다.
- 설계는 상태·전이·초기값·답 네 가지를 정하는 일이고, 상태에 필요한 정보가 빠지면 틀린다.
- 모든 DP는 느린 완전 탐색과 무작위 대조 검사로 확인한다.
