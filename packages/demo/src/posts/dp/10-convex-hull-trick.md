# [동적 계획법 10/12] 볼록 껍질 트릭: 직선들의 최솟값으로 DP 가속하기

> **한 줄 요약** — `dp[i] = min(dp[j] + b_j·a_i)` 꼴의 전이는 j마다 직선 하나를 놓고 x = `a_i`에서 가장 낮은 직선을 찾는 문제로 바뀌며, 기울기와 질의가 모두 단조이면 쓸모없는 직선을 덱에서 버리는 것만으로 O(n²)이 O(n)이 된다.

## 이 글에서 다루는 것
- 연속 구간 나누기 DP와 O(n²) 전이
- 전이를 직선 집합의 최솟값으로 보기
- 아래 껍질(lower envelope)과 덱 구현: 정수만으로 판정
- O(n²) 버전과 무작위 대조, 연산 횟수 비교
- 단조가 아닐 때: 이분 탐색, 리차오 트리

## 예제 문제: 묶음 비용이 합의 제곱인 구간 나누기
양수 n개가 한 줄로 있다. 이를 연속된 묶음으로 나누는데, 묶음 하나의 비용이 (묶음 합)² + M이다. 묶음을 잘게 나누면 M이 여러 번 붙고, 크게 묶으면 제곱이 커진다. 총비용의 최솟값은? 누적 합 `S`(알고리즘 기법 6편 「누적 합과 차분 배열: 구간 합과 구간 갱신을 O(1)로」)를 쓰면 마지막 묶음이 j + 1번째부터 i번째까지일 때의 점화식이 바로 나온다.
```text
dp[i] = min (dp[j] + (S[i]−S[j])²)
        j<i
        + M
```
i마다 j를 모두 보면 전이가 n(n + 1)/2번, O(n²)이다.
```python
def naive(c, M):                       # 정의 그대로 O(n²)
    S = [0]
    for x in c:
        S.append(S[-1] + x)
    n, ops = len(c), 0
    dp = [0] + [None] * n
    for i in range(1, n + 1):
        best = None
        for j in range(i):             # 마지막 묶음 = j+1 … i
            ops += 1
            v = dp[j] + (S[i] - S[j]) ** 2 + M
            if best is None or v < best:
                best = v
        dp[i] = best
    return dp[n], ops

print(naive([3, 1, 4, 1, 5, 9, 2, 6], 20))
```
```text
(307, 36)
```

## 아이디어: j마다 직선 하나
제곱을 풀면 i에만 관계된 항과 j에만 관계된 항, 그리고 둘의 곱 하나로 갈라진다.
```text
dp[i] = S[i]² + M
      + min (−2·S[j]) · S[i]
             + (dp[j] + S[j]²)
```
j마다 기울기 `m_j = −2·S[j]`, 절편 `k_j = dp[j] + S[j]²`인 직선을 하나씩 두면, `dp[i]`는 x = `S[i]`에서 가장 낮은 직선의 높이다. 일반적으로 `dp[i] = min(dp[j] + b_j·a_i) + c_i` 꼴이면 모두 이렇게 바뀐다. 직선들의 최솟값을 그리면 아래로 꺾인 선, **아래 껍질**이 된다.

이 문제에는 단조성이 두 개 있다. 수가 양수라 `S[j]`가 커지므로 새로 들어오는 직선의 기울기는 점점 작아지고, 질의하는 x = `S[i]`도 점점 커진다. x가 커질수록 기울기가 작은 직선이 이기므로, 직선들은 덱에 기울기 순으로 쌓이고 차례로 최솟값 자리를 넘겨받는다.
```text
x가 커지면 기울기 작은 직선이 이긴다
  x ≤ x₁₂        → l1이 최소
  x₁₂ ≤ x ≤ x₂₃  → l2가 최소
  x ≥ x₂₃        → l3이 최소
x₁₃ ≤ x₁₂면 l2가 최소인 곳은 없다
```
xᵢⱼ는 두 직선의 교점이다. l1과 l3의 교점이 l1과 l2의 교점보다 왼쪽에 있으면, l2가 l1을 이기기 전에 l3이 이미 l1을 이기고 있으므로 l2는 어디에서도 최소가 아니다. 교점을 실수로 나눠 구하지 말고 양변에 (양수인) 기울기 차를 곱해 정수로 비교한다.
```text
(k3−k1)(m1−m2) ≤ (k2−k1)(m1−m3)
  ⇒ l2를 버린다
```

## 구현: 덱 하나로 O(n)
- 직선 추가(뒤): 새 직선이 들어올 때 맨 뒤 직선이 위 조건으로 쓸모없어지면 꺼낸다.
- 질의(앞): x가 커지기만 하므로, 맨 앞 직선이 둘째 직선보다 높아지면 다시는 이기지 못한다. 꺼낸다.
```python
from collections import deque

def bad(l1, l2, l3):
    """기울기 l1 > l2 > l3일 때 l2가 어디서도 최소가 아닌가"""
    (m1, k1, _), (m2, k2, _), (m3, k3, _) = l1, l2, l3
    return (k3 - k1) * (m1 - m2) <= (k2 - k1) * (m1 - m3)

def cht(c, M):
    S = [0]
    for x in c:
        S.append(S[-1] + x)
    n, ops = len(c), 0
    dp, prev = [0] * (n + 1), [0] * (n + 1)
    hull = deque()                     # (기울기, 절편, j), 기울기 감소 순

    def add(m, k, j):
        nonlocal ops
        line = (m, k, j)
        while len(hull) >= 2 and bad(hull[-2], hull[-1], line):
            ops += 1
            hull.pop()                 # 가운데 직선은 영영 쓸모없다
        hull.append(line)

    def val(line, x):
        return line[0] * x + line[1]

    add(0, 0, 0)                       # j = 0: 기울기 −2·S₀, 절편 dp₀ + S₀²
    for i in range(1, n + 1):
        x = S[i]                       # 질의 x도 증가한다
        while len(hull) >= 2 and val(hull[0], x) >= val(hull[1], x):
            ops += 1
            hull.popleft()             # 앞 직선은 이제 다시 안 이긴다
        ops += 1
        dp[i] = val(hull[0], x) + x * x + M
        prev[i] = hull[0][2]
        add(-2 * S[i], dp[i] + S[i] * S[i], i)
    groups, i = [], n
    while i > 0:                       # 마지막 묶음부터 거꾸로 복원
        groups.append(c[prev[i]:i])
        i = prev[i]
    return dp[n], groups[::-1], ops

print(cht([3, 1, 4, 1, 5, 9, 2, 6], 20))
```
```text
(307, [[3, 1], [4, 1], [5], [9], [2], [6]], 15)
```
직선에 j를 함께 넣어 두면 어느 j가 최소였는지 기록해 묶음을 복원할 수 있다. (3 + 1)² + 20 = 36부터 6² + 20 = 56까지 더하면 307이다. 9처럼 큰 수는 혼자 두고 작은 수끼리 묶는다. 직선은 덱에 한 번 들어가고 많아야 한 번 나오므로, 추가·삭제·질의를 모두 합쳐도 O(n)이다(분할 상환).

## 무작위 대조 검사
앞 코드에 이어서, 무작위 입력 500개에서 O(n²) 버전과 답을 비교하고, 복원한 묶음이 원래 수열을 순서대로 나눈 것이며 그 비용이 답과 같은지도 확인한다. 0도 넣어서 기울기가 같은 직선이 들어오는 경우까지 시험한다. 마지막으로 n = 3,000에서 연산 횟수를 센다.
```python
import random

rng = random.Random(10)
for t in range(500):
    n = rng.randint(1, 60)
    c = [rng.randint(0, 20) for _ in range(n)]   # 0이면 기울기가 같다
    M = rng.randint(0, 100)
    best, groups, _ = cht(c, M)
    assert best == naive(c, M)[0]
    assert sum(sum(g) ** 2 + M for g in groups) == best
    assert [x for g in groups for x in g] == c
print("무작위 500개 비교: 모두 일치")

c = [rng.randint(1, 1000) for _ in range(3000)]
print("O(n²) 전이:", naive(c, 10**6)[1])
print("CHT 연산  :", cht(c, 10**6)[2])
```
```text
무작위 500개 비교: 모두 일치
O(n²) 전이: 4501500
CHT 연산  : 5998
```
450만 번의 전이가 6천 번 정도의 덱 연산으로 줄었다. 질의 3,000번에 꺼내기가 3,000번 가까이 더해진 값이라 n의 두 배 안팎이다.

## 왜 "볼록 껍질"인가
직선 `y = m·x + k`를 점 (m, k)로 바꿔 보자. x에서의 높이는 벡터 (x, 1)과 점 (m, k)의 내적이므로, 가장 낮은 직선은 점들 중 (x, 1) 방향으로 가장 낮은 점, 즉 점 집합의 볼록 껍질 꼭짓점에서 나온다. 실제로 `bad`의 부등식을 정리하면 세 점 (m1, k1), (m2, k2), (m3, k3)의 외적 부호 검사와 같다. 덱 뒤에서 꺼내는 과정은 수학·기하 알고리즘 10편 「볼록 껍질: 모노톤 체인과 그레이엄 스캔」의 모노톤 체인이 스택에서 껍질 안쪽으로 들어간 점을 꺼내는 것과 같은 동작이다.

## 단조가 아닐 때와 자주 하는 실수
- 기울기는 단조인데 질의 x가 제멋대로면: 덱 앞에서 꺼내지 말고, 껍질의 교점들이 정렬되어 있으므로 이분 탐색으로 최소 직선을 찾는다. 질의마다 O(log n).
- 기울기도 단조가 아니면: x 범위 위에 세그먼트 트리를 만들어 노드마다 직선 하나를 두는 **리차오 트리**(Li Chao tree)를 쓴다. 직선 추가와 질의가 각각 O(log C)(C는 x 범위)다.
- 최댓값 문제는 직선의 부호를 뒤집어 최솟값으로 바꾸거나, 기울기 순서와 부등호 방향을 함께 뒤집는다. 방향 하나만 뒤집으면 조용히 틀린 답이 나온다.
- 기울기가 같은 직선은 절편이 작은 쪽만 남기도록 따로 처리하는 것이 안전하다. 교점을 실수로 계산하면 오차로 직선을 잘못 버릴 수 있으니 위처럼 곱셈 비교를 쓴다. 파이썬 정수는 커져도 되지만, 64비트 정수를 쓰는 언어에서는 이 곱이 넘칠 수 있다.

## 복잡도
| 방법 | 시간 | 공간 |
|---|---|---|
| 모든 j를 보는 DP | O(n²) | O(n) |
| 단조 덱 CHT | O(n) | O(n) |
| 껍질 + 이분 탐색 | O(n log n) | O(n) |
| 리차오 트리 | O(n log C) | O(n) 또는 O(C) |

- 덱 버전은 직선마다 넣기·빼기가 한 번씩이라 분할 상환 O(n)이다. 정렬이 필요하면 O(n log n)이 더해진다.
- 리차오 트리는 노드를 필요할 때만 만들면 직선 하나에 노드가 많아야 하나 생겨 O(n), 배열로 미리 잡으면 O(C) 공간이다.

## 어디에 쓰이나
- 미적분 9편 「최적화: 극값과 볼록 함수」: 일차 함수들의 최댓값은 언제나 볼록 함수이고 최솟값은 오목 함수다. 아래 껍질은 그 오목 함수의 꺾인 점들만 저장한 표현이다.
- 수학·기하 알고리즘 10편 「볼록 껍질: 모노톤 체인과 그레이엄 스캔」: 직선을 점 (기울기, 절편)으로 바꾸면 덱에서 직선을 버리는 조건이 그 글의 외적(CCW) 검사가 된다.
- 알고리즘 기법 5편 「슬라이딩 윈도우와 단조 덱: 구간 최솟값을 한 번에」: 다시는 답이 될 수 없는 원소를 덱 양 끝에서 버려 O(n)을 얻는 같은 패턴이다.
- 고급 자료 구조 3편 「세그먼트 트리: 구간 질의와 점 갱신」: 리차오 트리는 그 구조의 노드에 값 대신 직선을 저장한 변형이다.

## 정리
- `dp[j] + b_j·a_i` 꼴의 전이는 j마다 직선을 하나 두고 x = `a_i`에서 가장 낮은 직선을 찾는 문제다.
- 기울기와 질의가 모두 단조이면, 쓸모없는 직선을 덱 뒤(추가 때)와 앞(질의 때)에서 버려 전체 O(n)이다.
- 직선을 버리는 판정은 교점을 나누지 말고 곱셈으로 비교하며, 이는 볼록 껍질의 외적 검사와 같다.
- 질의만 제멋대로면 이분 탐색, 기울기까지 제멋대로면 리차오 트리를 쓴다.
