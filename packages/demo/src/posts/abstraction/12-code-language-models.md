## 코드도 토큰열이다
9편의 컴파일러는 문법이 정한 토큰(이름, 숫자, 기호)으로 소스를 잘랐다. 언어 모델은 문법을 모른 채 자주 함께 나오는 글자 조각을 토큰으로 삼는다. 널리 쓰이는 방식인 **바이트 쌍 인코딩**(BPE, byte pair encoding)은 가장 자주 이웃한 두 조각을 하나로 합치는 일을 반복한다. 파이썬 함수 다섯 개로 배워 보자.
```python
from collections import Counter

corpus = ["def add(a, b):\n    return a + b\n",
          "def sub(a, b):\n    return a - b\n",
          "def neg(x):\n    return 0 - x\n",
          "def total(xs):\n    s = 0\n    for x in xs:\n        s = s + x\n    return s\n",
          "def first(xs):\n    for x in xs:\n        return x\n"]

def merge(seq, a, b):                    # 이웃한 a, b를 한 토큰으로
    out, i = [], 0
    while i < len(seq):
        if seq[i:i + 2] == [a, b]: out.append(a + b); i += 2
        else: out.append(seq[i]); i += 1
    return out

def learn_bpe(texts, n_merges):          # 가장 잦은 이웃 쌍을 반복해서 합친다
    seqs, rules = [list(t) for t in texts], []
    for _ in range(n_merges):
        pairs = Counter(p for s in seqs for p in zip(s, s[1:]))
        a, b = pairs.most_common(1)[0][0]
        rules.append((a, b))
        seqs = [merge(s, a, b) for s in seqs]
    return rules

def encode(text, rules):
    seq = list(text)
    for a, b in rules: seq = merge(seq, a, b)
    return seq

rules = learn_bpe(corpus, 16)
print([a + b for a, b in rules])
code = "def mul(a, b):\n    return a * b\n"
print(len(code), "글자 →", encode(code, rules))
```
```text
['  ', '    ', '\n    ', ':\n    ', 'n ', 'de', 'def', 'def ', '):\n    ', 're', 'ret', 'retu', 'retur', 'return ', ' b', ' x']
32 글자 → ['def ', 'm', 'u', 'l', '(', 'a', ',', ' b', '):\n    ', 'return ', 'a', ' ', '*', ' b', '\n']
```
가장 먼저 합쳐진 것은 들여쓰기 공백이고, 이어서 `def `와 `return `이 한 토큰이 되었다. 처음 보는 이름 `mul`은 글자 단위로 쪼개진다. `'):\n    '`처럼 괄호, 콜론, 줄바꿈, 들여쓰기가 한 토큰이 되는 것은 문법 단위와 상관없이 빈도만 보기 때문이다. 실제 모델은 바이트 단위 BPE로 수만 개 이상의 어휘를 만들지만 원리는 같다.

## 다음 토큰 예측으로 코드 분포를 배운다
토큰열 x₁…xₙ의 확률은 연쇄 법칙으로 `p(x) = Π p(xᵢ ∣ x₁…xᵢ₋₁)`이고, 모델은 공개 저장소의 코드에서 다음 토큰의 교차 엔트로피를 줄이도록 학습한다(AI 기초 3편 「데이터 분포로 보는 AI 모델」). 코드는 자연어보다 규칙적이다. `def f(a, b):` 다음에는 들여쓰기가, 열린 괄호 뒤에는 언젠가 닫는 괄호가 온다. 앞에서 정의한 변수 이름을 뒤에서 다시 쓰려면 멀리 떨어진 토큰을 찾아봐야 하는데, 어텐션이 그 일을 한다(어텐션 1편 「어텐션의 기본: 쿼리, 키, 값」). 함수 이름과 독스트링 같은 자연어도 코드와 같은 토큰열에 섞여 있으므로, 모델은 "설명 다음에 오는 구현"의 분포를 함께 배운다.

## 결정적 변환과 확률적 변환
| 항목 | 컴파일러 (9편) | 언어 모델 |
|---|---|---|
| 입력 | 문법이 정해진 소스 | 모호한 자연어 명세 |
| 규칙 | 사람이 쓴 번역 규칙 | 데이터에서 배운 분포 |
| 같은 입력 | 늘 같은 출력 | 샘플마다 다른 출력 |
| 보장 | 의미 보존(버그 제외) | 없음, 테스트로 확인 |

컴파일러는 소스의 의미가 명세로 정해져 있으니 틀리면 컴파일러 버그다. 언어 모델은 명세 자체가 모호하고 출력은 분포에서 뽑은 표본이므로, 생성된 코드는 "그럴듯한 후보"일 뿐이다. 그래서 코드 생성의 평가는 실행해서 테스트를 통과하는지로 한다.

## 샘플링과 온도
모델은 다음 토큰마다 로짓 zᵢ를 내고 **온도** T로 `pᵢ ∝ exp(zᵢ/T)`를 만들어 뽑는다. T가 작으면 가장 그럴듯한 토큰에 몰리고, 크면 고르게 퍼진다. 정답이 1등 후보인 문제 둘, 2등·3등 후보인 문제 하나씩이 있는 장난감 모델로 온도와 성공률의 관계를 보자. 10번 독립으로 뽑아 하나라도 맞을 확률은 `1 − (1 − p)¹⁰`이다.
```python
import math

def softmax(logits, T):
    e = [math.exp(z / T) for z in logits]
    return [x / sum(e) for x in e]

logits = [2.0, 1.0, 0.0]                 # "return a" 다음: " +", " -", " *"
answers = [0, 0, 1, 2]                   # 문제 4개의 정답 후보 번호
for T in (0.2, 0.5, 1.0, 2.0):
    probs = softmax(logits, T)
    p1 = sum(probs[a] for a in answers) / 4
    p10 = sum(1 - (1 - probs[a]) ** 10 for a in answers) / 4
    print(f"T={T}: {[round(p, 2) for p in probs]} pass@1={p1:.3f} pass@10={p10:.3f}")
```
```text
T=0.2: [0.99, 0.01, 0.0] pass@1=0.498 pass@10=0.516
T=0.5: [0.87, 0.12, 0.02] pass@1=0.467 pass@10=0.715
T=1.0: [0.67, 0.24, 0.09] pass@1=0.416 pass@10=0.888
T=2.0: [0.51, 0.31, 0.19] pass@1=0.377 pass@10=0.961
```
한 번만 낼 수 있다면 낮은 온도가 낫고(0.498), 여러 번 뽑아 하나만 맞으면 된다면 다양성이 큰 높은 온도가 낫다(0.961). 낮은 온도에서는 열 번 뽑아도 거의 같은 답만 나오기 때문이다. 다음 절의 Codex 논문도 한 실험에서 pass@1은 T = 0.2, pass@100은 T = 0.8일 때 가장 좋았다고 보고했다.

## Codex와 HumanEval(2021)
2021년 OpenAI의 Chen 등은 GPT 계열 모델을 공개 GitHub 코드로 미세 조정한 Codex를 발표했다. 2020년 5월 공개 저장소 5,400만 개에서 모은 파이썬 파일을 걸러 159GB의 학습 데이터를 만들었다. 평가를 위해 사람이 직접 쓴 164개 문제의 HumanEval을 만들었다. 문제마다 함수 시그니처와 독스트링이 주어지고, 모델이 본문을 쓰면 평균 7.7개의 단위 테스트로 채점한다. 120억 파라미터 Codex는 한 번에 28.8%를 풀었고 같은 조건에서 GPT-3는 0%, GPT-J는 11.4%였다. 문제마다 100개를 뽑아 하나라도 통과하면 푼 것으로 치면 70.2%까지 올라갔다. 같은 해 6월 GitHub은 Codex 기반의 Copilot을 기술 미리보기로 공개했다.

## pass@k와 불편 추정식
pass@k는 "k개를 뽑았을 때 하나라도 테스트를 통과할 확률"이다. 문제마다 k개만 뽑아 재면 분산이 크므로, 논문은 n ≥ k개(논문에서는 n = 200)를 뽑아 정답 c개를 센 뒤 이렇게 추정한다.
```text
pass@k ≈ 1 − C(n−c, k) / C(n, k)
```
C(n−c, k)/C(n, k)는 n개 중 k개를 무작위로 골랐을 때 오답만 고를 확률이다(이산수학 6편 「경우의 수: 순열과 조합」). 정답률 p̂ = c/n을 `1 − (1 − p̂)ᵏ`에 넣는 단순한 방법과 비교해 보자.
```python
from math import comb

def pass_at_k(n, c, k):                  # n개 중 c개 정답일 때의 불편 추정
    if n - c < k: return 1.0
    return 1 - comb(n - c, k) / comb(n, k)

for c in (1, 10, 50):
    print(f"n=200, c={c}:", [round(pass_at_k(200, c, k), 3) for k in (1, 10, 100)])

p, n, k = 0.05, 20, 10                   # 참 정답률 5%, 샘플 20개, k = 10
pmf = [comb(n, c) * p**c * (1 - p) ** (n - c) for c in range(n + 1)]
print("참값      ", round(1 - (1 - p) ** k, 4))
print("불편 추정 ", round(sum(w * pass_at_k(n, c, k) for c, w in enumerate(pmf)), 4))
print("단순 추정 ", round(sum(w * (1 - (1 - c / n) ** k) for c, w in enumerate(pmf)), 4))
```
```text
n=200, c=1: [0.005, 0.05, 0.5]
n=200, c=10: [0.05, 0.409, 0.999]
n=200, c=50: [0.25, 0.948, 1.0]
참값       0.4013
불편 추정  0.4013
단순 추정  0.3365
```
200개 중 하나만 맞아도 pass@100은 0.5다. 100개를 고르면 그 하나가 들어 있을 확률이 절반이기 때문이다. 아래쪽은 c가 이항 분포를 따를 때의 기댓값을 정확히 계산한 것이다. 불편 추정식의 기댓값은 참값 0.4013과 같고, 단순 추정은 0.3365로 체계적으로 낮다. `1 − (1 − p̂)ᵏ`가 오목한 함수라서 p̂의 흔들림이 평균을 아래로 끌어내리기 때문이다(옌센 부등식). pass@1은 두 식이 같고 그냥 c/n이다.

## 모호한 자연어와 정확한 코드 사이
"리스트에서 중복을 없애라"라는 명세에 맞는 구현은 여러 개다.
```python
def dedup_a(xs): return list(set(xs))
def dedup_b(xs): return list(dict.fromkeys(xs))

xs = [3, 1, 3, 2, 1]
print(dedup_a(xs), dedup_b(xs))
for f in (dedup_a, dedup_b):
    print(f.__name__, f(xs) == [3, 1, 2])   # "처음 나온 순서를 지킨다"는 테스트
```
```text
[1, 2, 3] [3, 1, 2]
dedup_a False
dedup_b True
```
둘 다 중복을 없앴지만 순서가 다르다. 명세는 순서를 말하지 않았으므로 어느 쪽도 틀렸다고 할 수 없다. 원소가 문자열이면 `set`의 순서는 해시 무작위화 때문에 실행할 때마다 달라질 수도 있다. 사람의 의도("처음 나온 순서 유지")는 테스트 한 줄로 적었을 때 비로소 정확해진다. 자연어 명세에서 코드로 가는 변환에는 이렇게 명세가 정하지 않은 빈칸이 있고, 모델은 그 빈칸을 학습 데이터에서 흔했던 방식으로 채운다.

## 이 층의 변환
```text
입력: 자연어 명세(독스트링, 대화, 이슈)
출력: 코드 후보들(분포에서 뽑은 표본)
보존: 보장 없음, 테스트를 통과한 만큼만
숨김: 문법, API 이름, 관용구, 구현 세부
```
이 변환이 쓸 만한 것은 공개 코드의 방대한 분포에서 "이런 설명 다음에는 이런 구현"이라는 대응을 배웠기 때문이지만, 그 대응은 확률일 뿐 의미 보존의 증명이 아니다. 그래서 출력의 정확성은 생성 쪽이 아니라 검증 쪽(단위 테스트, 타입 검사, 사람의 리뷰)이 보장해야 하며, 여러 번 뽑고 테스트로 거르면 pass@k처럼 성공률이 올라간다. 그 고리를 자동으로 돌리는 것이 13편의 에이전트다.

## 어디에 쓰이나
- AI 기초 3편 「데이터 분포로 보는 AI 모델」: 언어 모델의 확률 연쇄 법칙과 온도가 이 글의 코드 생성과 샘플링에 그대로 쓰였다.
- 어텐션 1편 「어텐션의 기본: 쿼리, 키, 값」: 앞에서 정의한 변수 이름이나 열린 괄호를 찾아 다음 토큰을 정하는 장치가 어텐션이다.
- 이산수학 6편 「경우의 수: 순열과 조합」: pass@k 불편 추정식의 C(n−c, k)/C(n, k)는 오답만 고르는 조합의 수를 전체 조합의 수로 나눈 것이다.
- 9편 「컴파일러: 식과 문장을 명령어로 바꾸기」: 같은 입력에 늘 같은 출력을 내는 결정적 변환과 이 글의 확률적 변환을 나란히 놓고 비교했다.

## 정리
- 언어 모델에게 코드는 BPE 토큰열이고, 들여쓰기와 키워드처럼 잦은 조각이 토큰이 된다.
- 다음 토큰 예측으로 배운 모델은 자연어 명세를 받아 코드 분포에서 표본을 뽑는다. 결정적인 컴파일러와 달리 출력이 매번 다르고 의미 보존의 보장이 없다.
- 온도가 낮으면 pass@1, 높으면 pass@k(큰 k)에 유리하다. pass@k는 `1 − C(n−c, k)/C(n, k)`로 편향 없이 추정한다.
- 자연어 명세에는 빈칸이 있고, 그 빈칸은 테스트가 메운다.
