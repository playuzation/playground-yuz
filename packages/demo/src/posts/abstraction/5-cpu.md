# [트랜지스터에서 자연어까지 5/13] CPU의 구조: 명령어를 실행하는 기계

> **한 줄 요약** — CPU는 PC가 가리키는 명령어를 인출하고, 비트 필드를 해독해 제어 신호를 만들고, 그 신호대로 ALU·레지스터·메모리를 움직이는 일을 클록마다 되풀이하는 기계이며, 프로그램을 배선이 아니라 메모리 속 숫자로 두었기 때문에 회로를 바꾸지 않고도 다른 계산을 시킬 수 있다.

## 배선이 곧 프로그램이던 시절
1~4편에서 트랜지스터로 게이트를, 게이트로 ALU와 레지스터·메모리를 만들었다. 부품은 다 모였지만 아직 "무엇을 계산할지"를 정하는 방법이 없다. 초기 전자식 컴퓨터는 이것을 배선으로 정했다. 1946년 2월 공개된 ENIAC은 플러그보드 배선, 장치 사이를 잇는 케이블, 수많은 스위치를 손으로 바꿔서 프로그램했다. 종이 위에서 계산 절차를 다 짜 놓아도 그것을 기계에 옮기는 데 며칠이 걸릴 수 있었다.

ENIAC을 만들던 팀은 다음 기계 EDVAC을 구상하고 있었고, 여기에 참여한 존 폰 노이만이 쓴 「EDVAC에 관한 보고서 초안」(First Draft of a Report on the EDVAC)이 1945년 6월 30일 날짜로 허먼 골드스타인을 통해 배포되었다. 101쪽짜리 미완성 문서였지만, **프로그램 내장 방식**(stored-program) 컴퓨터의 논리 설계를 처음 공개적으로 기술한 문서로 꼽힌다. 핵심은 명령어도 숫자로 바꿔 데이터와 같은 메모리에 넣자는 것이다. 다만 ENIAC을 설계한 에커트와 모클리는 자신들의 아이디어가 먼저였다고 주장했고, 그래서 "폰 노이만 구조"라는 이름은 지금도 논란이 있다.

이 생각을 실제로 처음 돌린 기계는 1948년 6월 21일 첫 프로그램을 실행한 맨체스터 대학의 SSEM(맨체스터 베이비)이다. 1949년 5월 6일에는 케임브리지의 모리스 윌크스 팀이 만든 EDSAC이 제곱수 표를 출력하며 첫 프로그램을 돌렸고, 이후 실제 계산 업무에 쓰였다. ENIAC도 1948년부터는 배선을 고정해 두고 숫자로 된 명령을 스위치에 넣는 방식으로 바꿔 썼다.

프로그램이 메모리 속 숫자가 되면 두 가지가 바뀐다. 프로그램을 바꾸는 일이 배선 작업에서 숫자 쓰기로 바뀐다. 그리고 프로그램이 다른 프로그램을 데이터로 만들 수 있게 된다. 8편의 어셈블러와 9편의 컴파일러가 바로 "기계어를 출력하는 프로그램"이다. 이 시리즈의 위쪽 층은 모두 이 한 가지 결정 위에 서 있다.

## CPU의 부품
```text
┌────┐  ┌────────────┐  ┌────┐
│ PC ├─→│ instr. mem ├─→│ IR │
└─┬──┘  └────────────┘  └─┬──┘
  ↑                       │
  │      ┌─────────┐  op  │
  │      │ control │←─────┤
  │      └────┬────┘      │
  │           ↓ signals   │ rd rs imm
  │  ┌────────┴─────────┐ │
  │  │ reg file   ALU   │←┘
  │  │ data mem   out   │
  │  └────────┬─────────┘
  └───────────┘ next PC
```
- **프로그램 카운터**(PC, program counter): 다음에 실행할 명령어의 주소를 담은 레지스터다.
- **명령어 레지스터**(IR, instruction register): 방금 메모리에서 꺼낸 명령어 워드를 붙잡아 둔다.
- **레지스터 파일**(register file): R0~R3 네 개의 8비트 레지스터와, 어느 것을 읽고 쓸지 고르는 멀티플렉서다(4편의 레지스터 + 3편의 멀티플렉서).
- **ALU**: 3편에서 만든 연산 회로다. 결과가 0인지 알려 주는 제로 플래그 Z가 분기 판단에 쓰인다.
- **제어 장치**(control unit): opcode를 보고 "B 입력은 레지스터에서", "결과를 레지스터에 쓴다" 같은 제어 신호를 만든다.

이 글의 토이 CPU는 명령어 메모리와 데이터 메모리를 따로 둔다. 이런 배치를 하버드 구조(Harvard architecture)라고 부르는데, 명령은 천공 테이프에, 데이터는 계수기에 두었던 하버드 마크 I에서 온 이름이다. EDVAC 보고서의 설계는 둘을 한 메모리에 두는 쪽이다. 오늘날 CPU는 대부분 메모리는 하나로 두고 가장 가까운 캐시만 명령용과 데이터용으로 나누는 변형 하버드 구조를 쓴다(7편).

## 토이 ISA
5·6·8·9편은 같은 토이 명령어 집합(ISA)을 쓴다. 명령어는 16비트이고 `[15:12] opcode · [11:10] rd · [9:8] rs · [7:0] imm8`로 나뉜다. 산술은 8비트로 감기므로(mod 256) `ADDI R1, 255`는 R1에서 1을 빼는 것과 같다(이산수학 12편 「수 체계와 모듈러 연산: 2진수에서 해시까지」의 2의 보수). 비트 배치를 이렇게 정한 이유와 실제 ISA와의 비교는 6편에서 다룬다.

| op | 명령 | 동작 |
|---|---|---|
| 0 | `HALT` | 멈춤 |
| 1 | `LOADI rd, imm` | rd ← imm |
| 2 | `ADD rd, rs` | rd ← rd + rs, Z 갱신 |
| 3 | `SUB rd, rs` | rd ← rd − rs, Z 갱신 |
| 4 | `ADDI rd, imm` | rd ← rd + imm, Z 갱신 |
| 5 | `LOAD rd, [imm]` | rd ← mem[imm] |
| 6 | `STORE rd, [imm]` | mem[imm] ← rd |
| 7 | `JMP imm` | PC ← imm |
| 8 | `JZ imm` | Z면 PC ← imm |
| 9 | `JNZ imm` | Z가 아니면 PC ← imm |
| A | `OUT rd` | rd를 출력 |

## 인출-해독-실행 주기
CPU가 하는 일은 세 단계의 무한 반복이다.
1. **인출**(fetch): `IR ← imem[PC]`, 그리고 `PC ← PC + 1`.
2. **해독**(decode): IR의 비트를 잘라 opcode·rd·rs·imm을 얻고, 제어 장치가 opcode에 맞는 신호를 낸다.
3. **실행**(execute): 신호에 따라 ALU가 계산하고, 메모리를 읽거나 쓰고, 결과를 레지스터에 쓴다. 분기 명령이면 PC를 imm으로 덮어쓴다.

여기서는 명령 하나를 클록 한 번에 끝내는 단일 사이클 설계로 본다. 클록 에지 사이에 조합 회로(3편)가 다음 값을 계산하고, 상승 에지에서 PC·레지스터·메모리가 한꺼번에 새 값을 받는다(4편). 가장 느린 명령이 클록 주기를 정한다는 약점 때문에 실제 CPU는 이 단계를 여러 클록으로 나누고 겹쳐 실행한다. 그 이야기는 7편에서 한다.

## 파이썬으로 만든 토이 CPU
제어 장치는 opcode를 신호 묶음으로 바꾸는 표 그 자체다. 아래 코드는 그 표를 문자열로 적어 두고, 데이터 경로는 신호만 보고 움직이게 만든다.
```python
# 제어 신호표: opcode 순서대로 한 줄씩 (A = R[rd], B = R[rs] 또는 imm)
SIGNALS = """
op     alu  b  wb   z  mem  pc
HALT   -    -  -    0  -    stop
LOADI  B    I  alu  0  -    +1
ADD    A+B  R  alu  1  -    +1
SUB    A-B  R  alu  1  -    +1
ADDI   A+B  I  alu  1  -    +1
LOAD   -    -  mem  0  rd   +1
STORE  -    -  -    0  wr   +1
JMP    -    -  -    0  -    imm
JZ     -    -  -    0  -    z?imm
JNZ    -    -  -    0  -    nz?imm
OUT    -    -  -    0  out  +1
"""
rows = [r.split() for r in SIGNALS.strip().splitlines()]
NAMES = [r[0] for r in rows[1:]]                  # opcode = 줄 번호
CTRL = {r[0]: dict(zip(rows[0][1:], r[1:])) for r in rows[1:]}

def alu(fn, a, b):
    r = {"B": b, "A+B": a + b, "A-B": a - b}[fn] & 0xFF   # 8비트로 감김
    return r, r == 0

def run(imem, show=()):
    R, dmem, pc, z, out = [0] * 4, [0] * 256, 0, False, []
    for cycle in range(1, 1000):
        at, ir = pc, imem[pc]                  # 인출
        pc = (pc + 1) & 0xFF
        op, rd = ir >> 12, (ir >> 10) & 3      # 해독
        rs, imm = (ir >> 8) & 3, ir & 0xFF
        s = CTRL[NAMES[op]]                    # 제어 장치
        if s["pc"] == "stop":
            return out, cycle
        b = R[rs] if s["b"] == "R" else imm    # 실행
        if s["alu"] != "-":
            val, zero = alu(s["alu"], R[rd], b)
        if s["mem"] == "rd": val = dmem[imm]
        if s["mem"] == "wr": dmem[imm] = R[rd]
        if s["mem"] == "out": out.append(R[rd])
        if s["wb"] != "-": R[rd] = val         # 쓰기
        if s["z"] == "1": z = zero
        if (s["pc"] == "imm" or (s["pc"] == "z?imm" and z)
                or (s["pc"] == "nz?imm" and not z)):
            pc = imm
        if cycle in show:
            print(f"{cycle:2} pc={at} {ir:04X} {NAMES[op]:5}"
                  f" R={R} Z={int(z)}")

prog = [0x1000, 0x140A, 0x2100, 0x44FF, 0x9002, 0xA000, 0x0000]
print(run(prog, show=[1, 2, 3, 4, 5, 6, 31, 32, 33]))
```
```text
 1 pc=0 1000 LOADI R=[0, 0, 0, 0] Z=0
 2 pc=1 140A LOADI R=[0, 10, 0, 0] Z=0
 3 pc=2 2100 ADD   R=[10, 10, 0, 0] Z=0
 4 pc=3 44FF ADDI  R=[10, 9, 0, 0] Z=0
 5 pc=4 9002 JNZ   R=[10, 9, 0, 0] Z=0
 6 pc=2 2100 ADD   R=[19, 9, 0, 0] Z=0
31 pc=3 44FF ADDI  R=[55, 0, 0, 0] Z=1
32 pc=4 9002 JNZ   R=[55, 0, 0, 0] Z=1
33 pc=5 A000 OUT   R=[55, 0, 0, 0] Z=1
([55], 34)
```

`prog`는 언어 기초 1편의 "1부터 10까지 더하기"를 토이 ISA의 기계어로 쓴 것이다. 5번째 사이클의 `JNZ`는 Z가 0이라 PC를 2로 덮어쓰고, 그래서 6번째 사이클에 다시 주소 2의 `ADD`를 인출한다. 31번째 사이클에서 R1이 0이 되어 Z가 1이 되면 `JNZ`는 뛰지 않고, `OUT`이 55를 내보낸 뒤 34번째 사이클의 `HALT`에서 멈춘다. 실행한 명령은 2 + 3 × 10 + 2 = 34개다.

회로를 그대로 두고 메모리 속 숫자만 바꾸면 전혀 다른 계산이 된다. 프로그램 내장 방식의 핵심이 이것이다. 앞 코드에 이어서 실행한다.
```python
# 같은 CPU, 다른 숫자: 6 × 7을 덧셈 반복으로 계산하고 메모리를 거쳐 출력
mul = [0x1000, 0x1406, 0x1807,      # R0 = 0, R1 = 6, R2 = 7
       0x2100, 0x48FF, 0x9003,      # loop: R0 += R1; R2 -= 1; JNZ loop
       0x6010, 0x5C10, 0xAC00,      # mem[16] = R0; R3 = mem[16]; OUT R3
       0x0000]
print(run(mul))
```
```text
([42], 28)
```

## 제어 신호표 읽기
`SIGNALS`의 각 열이 데이터 경로의 스위치 하나다.
- `alu`: ALU가 할 일. `B`는 B 입력을 그대로 통과시킨다. 그래서 `LOADI`는 "imm을 ALU에 통과시켜 레지스터에 쓰는 명령"이 된다.
- `b`: ALU의 B 입력을 레지스터 `R[rs]`에서 가져올지(`R`), 명령어 안의 imm에서 가져올지(`I`) 고르는 멀티플렉서 선택 신호다. `ADD`와 `ADDI`는 이 신호 하나만 다르고 나머지 회로는 공유한다.
- `wb`: 레지스터 rd에 ALU 결과를 쓸지, 메모리에서 읽은 값을 쓸지, 아무것도 쓰지 않을지.
- `z`: 이번 결과로 Z 플래그를 갱신할지. `LOADI`는 갱신하지 않는다.
- `mem`: 데이터 메모리 읽기·쓰기, 그리고 출력 포트.
- `pc`: 다음 PC를 PC + 1로 할지, imm으로 할지, Z에 따라 고를지.

하드웨어에서 이 표는 opcode 4비트를 입력으로, 신호 비트들을 출력으로 하는 진리표이고, 2편의 게이트로 그대로 만들 수 있다. 이렇게 게이트로 굳힌 방식을 하드와이어드(hardwired) 제어라고 한다. 다른 길도 있다. 모리스 윌크스는 1951년, 제어 신호의 순서를 빠른 메모리에 넣은 작은 프로그램으로 표현하자는 **마이크로프로그래밍**(microprogramming)을 제안했다. 표를 회로 대신 메모리에 두는 셈이라, 같은 명령어 집합을 서로 다른 회로로 구현하기 쉬워진다. 이 성질이 6편의 IBM System/360에서 중요한 역할을 한다.

## 이 층의 변환
```text
입력: 게이트·ALU·레지스터·메모리
출력: 명령어를 하나씩 실행하는 기계
보존: 명령마다 정해진 상태 변화
숨김: 제어 신호, MUX 선택, 타이밍
```
이 변환이 성립하는 것은 제어 장치가 결정적이기 때문이다. 같은 상태에서 같은 명령 워드를 실행하면 언제나 같은 다음 상태가 나온다. 또 모든 상태 변화가 클록 에지에서 한꺼번에 일어나므로(4편), 에지 사이에서 신호가 어떤 순서로 출렁이든 위 층에는 "명령 하나 = 상태 전이 하나"로만 보인다. 프로그램을 메모리 속 숫자로 두었기 때문에 회로는 한 번만 만들면 된다.

## 어디에 쓰이나
- 언어 기초 3편 「인터프리터 언어: 실행하면서 번역하기」: 바이트코드 VM의 루프(명령 읽기 → 종류 판별 → 실행)는 이 글의 인출-해독-실행 주기를 소프트웨어로 옮긴 것이다.
- 언어 기초 6편 「어셈블리와 컴파일·링크: 소스 코드가 실행 파일이 되기까지」: 거기서 본 `mov`, `add`, `jmp`가 이 글의 레지스터 파일 쓰기, ALU, PC 덮어쓰기로 실행된다.
- 6편 「명령어 집합: 하드웨어와 소프트웨어의 약속」: 이 글의 opcode 표가 회로와 프로그램 사이의 계약이 되는 이야기다.
- 7편 「빠르게 만드는 기술: 파이프라인, 캐시, 병렬성」: 인출·해독·실행을 겹쳐서 명령을 더 빨리 끝내는 방법을 다룬다.

## 정리
- 1945년 EDVAC 보고서가 기술한 프로그램 내장 방식은 프로그램을 배선이 아니라 메모리 속 숫자로 만들었다.
- CPU는 PC, IR, 레지스터 파일, ALU, 제어 장치로 이루어지고, 인출-해독-실행을 클록마다 반복한다.
- 제어 장치는 opcode를 제어 신호로 바꾸는 표이며, 게이트로 굳히거나(하드와이어드) 메모리에 둘 수 있다(마이크로프로그래밍).
- 파이썬 토이 CPU는 기준 프로그램을 34개 명령 만에 실행해 55를 출력했고, 회로를 바꾸지 않고 숫자만 바꿔 42도 계산했다.
