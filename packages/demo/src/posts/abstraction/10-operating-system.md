# [트랜지스터에서 자연어까지 10/13] 운영체제: 기계를 나눠 쓰게 하는 층

> **한 줄 요약** — 운영체제는 CPU 시간, 물리 메모리, 장치를 여러 프로그램에 나눠 주면서 각 프로그램에게는 "기계를 혼자 쓴다"는 착각을 만들어 주는 층이고, 그 착각은 사용자·커널 모드, 타이머 인터럽트와 문맥 교환, 페이지 테이블 주소 변환이라는 하드웨어 장치 위에서 지켜진다.

## 이 글에서 다루는 것
- 운영체제가 생기기까지: 일괄 처리, 시분할, 유닉스
- 사용자 모드와 커널 모드, 시스템 호출
- 인터럽트와 시분할 스케줄링: 토이 CPU 하나에서 두 프로그램 돌리기
- 가상 메모리: 페이지 테이블 주소 변환과 페이지 폴트 시뮬레이션
- 파일과 장치 추상화

## 프로그램은 기계를 혼자 쓴다고 믿는다
9편까지의 프로그램은 PC가 0번지에서 시작하고, 레지스터 네 개와 데이터 메모리 256바이트가 모두 자기 것이라고 가정했다. 실제 컴퓨터에서는 브라우저, 편집기, 음악 앱이 CPU 하나와 메모리 하나를 동시에 쓴다. 그런데도 각 프로그램은 다른 프로그램의 존재를 모른 채 그 가정대로 짜여 있다. 그 가정을 참으로 만들어 주는 층이 **운영체제**(operating system)다. 운영체제는 세 가지 착각을 만든다. 내 CPU(시분할), 내 메모리(가상 메모리), 내 장치(파일). 실행 중인 프로그램 하나를 **프로세스**(process)라 하고, 운영체제는 프로세스마다 저장된 레지스터와 주소 공간, 열린 파일 목록을 따로 들고 있다.

## 운영체제가 생기기까지
초기 컴퓨터는 한 번에 한 프로그램만 돌았다. 1950년대에는 작업을 모아 차례로 실행하는 일괄 처리(batch) 모니터가 운영자의 손일을 덜었지만, 사람은 결과를 받기까지 오래 기다려야 했다. 1961년 11월 MIT의 페르난도 코르바토 팀은 IBM 709에서 CTSS를 처음 시연했다. 여러 사용자가 단말기로 한 컴퓨터를 동시에 쓰는 **시분할**(time-sharing)이다. 1962년 영국 맨체스터 대학의 Atlas는 페이징으로 작은 코어 메모리와 드럼을 하나의 큰 메모리처럼 보이게 했다. 가상 메모리의 시작이다. 1964년 MIT, GE, 벨 연구소가 Multics를 시작했고, 1969년 벨 연구소가 빠진 뒤 켄 톰프슨과 데니스 리치가 PDP-7에서 유닉스를 만들었다. 1973년 유닉스 커널은 C로 다시 쓰였다(C는 11편). 리눅스는 1991년 8월 리누스 토르발스가 처음 발표했다.

## 사용자 모드와 커널 모드
아무 프로그램이나 디스크를 직접 제어하거나 다른 프로세스의 메모리를 읽으면 착각은 깨진다. 그래서 CPU에는 모드 비트가 있다. **커널 모드**(kernel mode)에서만 입출력 장치 제어, 페이지 테이블 교체, 인터럽트 끄기 같은 특권 명령이 허용되고, 일반 프로그램은 **사용자 모드**(user mode)에서 돈다. 사용자 프로그램이 파일을 쓰려면 **시스템 호출**(system call)로 커널에 부탁한다. x86-64의 `syscall`, ARM의 `svc`, RISC-V의 `ecall` 명령은 모드를 커널로 바꾸면서 커널이 미리 정해 둔 입구로만 점프한다. 원하는 곳으로 뛰어들 수 없다는 것이 핵심이다. 파이썬의 `os.write`가 실제로 무엇이 되는지 `strace`로 보자.
```python
# hello.py
import os
os.write(1, b"hello\n")                      # 1번 = 표준 출력
fd = os.open("out.txt", os.O_WRONLY | os.O_CREAT | os.O_TRUNC, 0o644)
os.write(fd, b"hello\n")                     # 같은 write, 대상만 파일
os.close(fd)
```
```text
$ strace -e trace=openat,write,close -o trace.txt python3 hello.py
hello
$ tail -5 trace.txt
write(1, "hello\n", 6)                  = 6
openat(AT_FDCWD, "out.txt", O_WRONLY|O_CREAT|O_TRUNC|O_CLOEXEC, 0644) = 3
write(3, "hello\n", 6)                  = 6
close(3)                                = 0
+++ exited with 0 +++
```
파이썬 한 줄이 시스템 호출 하나가 되었다. 커널은 파일을 열고 번호 3을 돌려줬고(0·1·2는 표준 입력·출력·오류), 프로그램은 그 번호로만 파일을 가리킨다(`O_CLOEXEC`는 파이썬이 기본으로 붙이는 플래그다). 터미널에 쓰는 것과 파일에 쓰는 것이 같은 `write`라는 점은 아래 파일 추상화에서 다시 본다.

## 인터럽트와 시분할
커널이 CPU를 되찾는 방법은 **인터럽트**(interrupt)다. 키보드, 디스크, 네트워크 카드 같은 장치가 신호를 보내면 CPU는 하던 명령을 마치고 커널의 처리 루틴으로 점프한다. 그중 타이머 인터럽트가 시분할의 열쇠다. 일정 시간마다 커널이 깨어나 지금 프로세스의 레지스터를 저장하고 다음 프로세스의 레지스터를 복원한다. 이것이 **문맥 교환**(context switch)이고, 순서대로 같은 시간씩 돌리는 방식을 라운드 로빈 스케줄링이라 한다. 토이 CPU 하나에서 두 프로그램을 8개 명령마다 번갈아 돌려 보자. A는 1~10의 합, B는 3, 2, 1을 출력하는 기계어다. 이 두 프로그램은 메모리 명령을 쓰지 않으므로 그 부분은 생략했다.
```python
cpu = {"pc": 0, "R": [0] * 4, "z": False}     # 실제 레지스터는 한 벌뿐

def step(code, out):                          # 토이 ISA 명령 하나
    w = code[cpu["pc"]]; cpu["pc"] += 1
    op, d, s, imm, R = w >> 12, w >> 10 & 3, w >> 8 & 3, w & 255, cpu["R"]
    if op == 1: R[d] = imm
    if 2 <= op <= 4:
        R[d] = (R[d] + [R[s], -R[s], imm][op - 2]) & 255; cpu["z"] = R[d] == 0
    if op == 7 or op == 8 and cpu["z"] or op == 9 and not cpu["z"]:
        cpu["pc"] = imm
    if op == 10: out.append(R[d])
    return op != 0                            # HALT면 False

def make(name, code):                         # 프로세스 = 코드 + 저장된 문맥
    return {"name": name, "code": code, "pc": 0, "R": [0] * 4, "z": False,
            "out": [], "steps": 0}

A = make("A", [0x1000, 0x140A, 0x2100, 0x44FF, 0x9002, 0xA000, 0x0000])
B = make("B", [0x1003, 0xA000, 0x40FF, 0x9001, 0x0000])
ready, timeline, QUANTUM = [A, B], [], 8
while ready:
    p = ready.pop(0)
    cpu.update(pc=p["pc"], R=p["R"][:], z=p["z"])          # 문맥 복원
    for n in range(1, QUANTUM + 1):
        p["steps"] += 1
        if not step(p["code"], p["out"]): break            # 프로그램 끝
    else:                                                  # 타이머 인터럽트
        p.update(pc=cpu["pc"], R=cpu["R"][:], z=cpu["z"])  # 문맥 저장
        ready.append(p)
    timeline.append(f"{p['name']}{n}")
print(" ".join(timeline))
for p in (A, B): print(p["name"], p["out"], p["steps"], "명령")
```
```text
A8 B8 A8 B3 A8 A8 A2
A [55] 34 명령
B [3, 2, 1] 11 명령
```
A는 8개 명령을 돌다 세 번이나 중간에 끊겼지만 출력은 혼자 돌 때와 같은 55, 실행 명령도 똑같이 34개다(5·8편의 기준 프로그램). 끊긴 순간의 PC, 레지스터, Z 플래그를 전부 저장했다가 그대로 되돌려 놓았기 때문이다. 프로그램 입장에서 끊긴 시간은 존재하지 않는다. 실제 운영체제는 이 간격을 밀리초 단위로 잡고, 입출력을 기다리는 프로세스는 건너뛰고, 우선순위를 섞는 등 스케줄링 정책을 훨씬 정교하게 다룬다.

## 가상 메모리: 페이지 테이블
두 프로그램이 모두 16번지에 변수를 둔다면 어떻게 될까. 운영체제는 프로세스마다 **가상 주소 공간**을 주고, 하드웨어(MMU)가 매 메모리 접근마다 가상 주소를 물리 주소로 바꾼다. 주소를 **페이지**(page) 번호와 페이지 안 위치(오프셋)로 나누고, 프로세스별 **페이지 테이블**에서 페이지가 놓인 물리 프레임을 찾는다. 테이블에 없으면 **페이지 폴트**(page fault)가 나서 커널이 빈 프레임을 마련하고(없으면 다른 페이지를 디스크로 내보내고) 접근을 다시 시킨다. 16바이트 페이지, 물리 프레임 4개로 흉내 내 보자.
```python
import random

PAGE, FRAMES = 16, 4                  # 16바이트 페이지, 물리 프레임 4개
tables = {"A": {}, "B": {}}           # 프로세스별 페이지 테이블: 페이지 → 프레임
free, loaded, faults = list(range(FRAMES)), [], 0

def translate(proc, vaddr):
    global faults
    page, offset = divmod(vaddr, PAGE)
    table = tables[proc]
    if page not in table:             # 페이지 폴트 → 운영체제가 처리
        faults += 1
        if not free:                  # 빈 프레임이 없으면 가장 먼저 온 것을 내보냄
            p, pg = loaded.pop(0)
            free.append(tables[p].pop(pg))
        table[page] = free.pop(0)
        loaded.append((proc, page))
    return table[page] * PAGE + offset

for proc, va in [("A", 0x13), ("B", 0x13), ("A", 0x14), ("B", 0x80),
                 ("A", 0x42), ("A", 0xF0), ("A", 0x13)]:
    pa = translate(proc, va)
    print(f"{proc} 가상 0x{va:02X} → 물리 0x{pa:02X}  폴트 누적 {faults}")
```
```text
A 가상 0x13 → 물리 0x03  폴트 누적 1
B 가상 0x13 → 물리 0x13  폴트 누적 2
A 가상 0x14 → 물리 0x04  폴트 누적 2
B 가상 0x80 → 물리 0x20  폴트 누적 3
A 가상 0x42 → 물리 0x32  폴트 누적 4
A 가상 0xF0 → 물리 0x00  폴트 누적 5
A 가상 0x13 → 물리 0x13  폴트 누적 6
```
A와 B가 같은 가상 주소 0x13을 써도 서로 다른 물리 주소로 가므로, B는 A의 메모리를 볼 방법이 없다. 이것이 격리다. 0x14는 0x13과 같은 페이지라 폴트 없이 번역되었다. 프레임 4개가 다 찬 뒤 A가 0xF0을 읽자 가장 오래된 A의 1번 페이지가 밀려났고, 다시 0x13을 읽자 이번에는 B의 페이지를 밀어내고 다른 프레임(0x13)에 올라왔다. A가 쓰는 주소는 그대로인데 물리 위치는 바뀌었고, 프로그램은 그 사실을 모른다.

페이지 단위로 옮기는 방식이 통하는 이유는 지역성이다.
```python
def count_faults(addresses):
    global free, loaded, faults
    tables["A"], free, loaded, faults = {}, list(range(FRAMES)), [], 0
    for va in addresses: translate("A", va)
    return faults

random.seed(0)
print("순서대로 256번:", count_faults(range(256)))
print("무작위로 256번:", count_faults(random.randrange(256) for _ in range(256)))
```
```text
순서대로 256번: 16
무작위로 256번: 202
```
순서대로 읽으면 페이지마다 한 번, 16번만 폴트가 나지만, 무작위로 읽으면 256번 중 202번이 폴트다. 실제 페이지 폴트는 디스크를 읽어야 하므로 메모리 접근보다 훨씬 느리다. 실제 x86-64는 4KiB 페이지와 4단계 테이블(48비트 가상 주소 = 9비트 × 4 + 오프셋 12비트)을 쓰고, 최근 번역 결과를 TLB라는 작은 캐시에 둔다. 7편의 캐시와 같은 지역성의 원리다.

## 파일과 장치 추상화
운영체제의 셋째 착각은 장치다. 디스크의 섹터, SSD의 블록, 터미널, 네트워크 소켓은 제어 방법이 전혀 다르지만, 유닉스 계열은 이들을 모두 열고(`open`) 읽고(`read`) 쓰고(`write`) 닫는(`close`) 바이트의 흐름으로 보이게 한다. 위의 strace에서 터미널과 파일이 같은 `write`였던 이유다. 이름 붙은 바이트열인 파일, 계층 디렉터리, 숫자 하나로 가리키는 파일 디스크립터가 디스크 컨트롤러의 명령을 숨긴다. 장치 드라이버가 장치별 차이를 커널 안에 가둔다.

## 이 층의 변환
```text
입력: 여러 프로그램, CPU, 메모리, 장치
출력: 프로세스별 CPU·주소 공간·파일
보존: 각 프로그램의 명령어 의미와 결과
숨김: 물리 주소, 장치 제어, 끊긴 시점
```
이 변환은 소프트웨어만으로는 지킬 수 없다. 특권 명령을 막는 모드 비트, 커널이 CPU를 되찾게 하는 타이머 인터럽트, 모든 접근을 가로채는 MMU라는 하드웨어 장치가 있어야 사용자 프로그램이 약속을 어길 수 없다. 그 위에서 커널이 문맥을 빠짐없이 저장·복원하고 페이지 테이블을 관리하기 때문에, A는 몇 번을 끊겨도 55를 출력한다.

## 정리
- 운영체제는 CPU·메모리·장치를 나눠 쓰게 하면서 각 프로세스에게 기계를 혼자 쓴다는 착각을 준다.
- 사용자·커널 모드와 시스템 호출은 정해진 입구로만 커널에 들어가게 한다.
- 타이머 인터럽트와 문맥 교환 덕분에 끊겨도 결과가 같고(A는 여전히 55), 페이지 테이블 덕분에 같은 가상 주소가 서로 다른 물리 주소로 간다.
- 파일 추상화는 서로 다른 장치를 같은 `read`·`write`로 다루게 한다.
