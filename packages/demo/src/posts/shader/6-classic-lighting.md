# [게임 셰이더 6/16] 고전 조명 모델: 램버트, 퐁, 블린-퐁, 툰 셰이딩

> **한 줄 요약** — 법선과 빛 방향의 내적 하나(램버트)가 면의 밝기를, 반사 벡터나 하프 벡터의 거듭제곱(퐁·블린-퐁, 블린 지수는 퐁의 약 4배)이 하이라이트를 만들고, 그 내적을 계단으로 자르면 툰 셰이딩이 되며, 이 모든 것의 입력인 법선은 모델 행렬이 아니라 그 역전치 행렬로 옮겨야 비균일 스케일에서도 면에 수직으로 남는다.

## 이 글에서 다루는 것
- 램버트 확산(코사인 법칙)과 주변광 항
- 퐁 반사와 블린-퐁, 하프 벡터 각과 지수 4배 관계의 파이썬 확인
- 법선을 역전치 행렬로 변환하는 이유(무작위 행렬 300개로 확인)
- 툰 셰이딩과 림 라이트, 세 구를 GLSL로 렌더링하고 파이썬으로 대조

## 문제: 단색으로 칠한 구는 원판이다
구를 한 색으로 칠하면 원판과 구별되지 않는다. 우리 눈은 면이 빛을 향한 정도로 입체를 읽는다. 그래서 조명에는 세 단위 벡터가 필요하다. 표면에 수직인 **법선**(normal) N, 표면에서 빛을 향하는 L, 눈을 향하는 V다. 이 글의 모델은 모두 이 셋의 내적(두 단위 벡터 사이 각의 코사인, 선형대수 2편)으로 밝기를 정한다.

## 램버트 확산: 코사인 법칙
단면적 A인 빛줄기가 각 θ로 기운 면에 닿으면 A / cos θ 넓이에 퍼지므로, 면의 단위 넓이가 받는 빛은 cos θ = N·L에 비례한다(람베르트 1760, 그래픽스에서는 영어식으로 '램버트'라 부른다). 무광 표면은 받은 빛을 모든 방향으로 고르게 내보내므로 어디서 봐도 밝기가 같고, V는 식에 들어가지 않는다. 등 뒤의 빛(N·L < 0)은 0으로 자른다. 그림자 쪽이 완전히 검으면 어색하므로 간접광을 상수로 대신하는 **주변광**(ambient) 항 ka를 더한다. 이 상수를 주변 환경에서 구한 값으로 바꾸는 것이 9편의 이미지 기반 조명이다. 이 글의 식을 한데 모으면 다음과 같다.
```text
c = ka + kd·max(N·L, 0)
  + ks·max(R·V, 0)ⁿ    (Phong 1975)
  + ks·max(N·H, 0)ⁿ    (Blinn 1977)
R = reflect(-L, N) = 2(N·L)N - L
H = normalize(L + V)
```

## 퐁과 블린-퐁: 하이라이트
반짝이는 표면은 빛을 거울 반사 방향 R 근처로 몰아 보낸다. **퐁 반사 모델**(Phong reflection model, 퐁 1975)은 R과 V가 가까울수록 밝은 `pow(max(dot(R, V), 0.0), n)`을 더하고, 지수 n이 클수록 하이라이트가 작고 날카롭다. 블린(1977)은 R 대신 L과 V의 중간 방향인 **하프 벡터**(half vector) H를 쓰고 N·H를 거듭제곱했다. 빛과 눈이 충분히 멀면 H는 프레임마다 상수라 정점마다 R을 구하는 것보다 쌌고, OpenGL 1.x의 고정 기능 조명(`GL_SHININESS`는 0~128)도 이 블린-퐁을 정점마다 계산했다. 두 식의 관계는 각으로 보인다. N, L, V가 한 평면 위에 있으면 ∠(R, V) = 2∠(N, H)이므로, 같은 크기의 하이라이트를 얻으려면 블린 지수가 약 4배여야 한다. 하이라이트 밝기가 절반이 되는 각(반폭)을 맞춰 확인한다.
```python
import math, random

def dot(a, b): return sum(x * y for x, y in zip(a, b))
def cross(a, b):
    return (a[1] * b[2] - a[2] * b[1], a[2] * b[0] - a[0] * b[2],
            a[0] * b[1] - a[1] * b[0])
def mul(M, v): return tuple(dot(r, v) for r in M)
def norm(v): return tuple(x / math.sqrt(dot(v, v)) for x in v)
def angle(a, b, line=False):           # 두 벡터 사이 각(도)
    c = dot(norm(a), norm(b))          # line=True면 앞뒤 무시(법선 방향만)
    return math.degrees(math.acos(max(-1, min(1, abs(c) if line else c))))
def reflect(i, n):                     # GLSL reflect(i, n) = i - 2(n·i)n
    k = 2 * dot(n, i)
    return tuple(x - k * y for x, y in zip(i, n))

rng, N = random.Random(6), (0.0, 0.0, 1.0)
for coplanar in (True, False):
    dev = 0.0
    for _ in range(300):
        if coplanar:                   # N, L, V가 한 평면(xz) 위
            a, b = [math.radians(rng.uniform(-80, 80)) for _ in range(2)]
            L, V = (math.sin(a), 0, math.cos(a)), (math.sin(b), 0, math.cos(b))
        else:
            L, V = [norm((rng.uniform(-1, 1), rng.uniform(-1, 1),
                          rng.uniform(0.2, 1))) for _ in range(2)]
        R = reflect(tuple(-x for x in L), N)
        H = norm(tuple(x + y for x, y in zip(L, V)))
        dev = max(dev, abs(angle(R, V) - 2 * angle(N, H)))
    name = "한 평면" if coplanar else "3차원"
    print(f"{name}: ∣∠(R,V) - 2∠(N,H)∣ 최대 {dev:.6f}도")

for n in (8, 32, 128):
    a = math.acos(0.5 ** (1 / n))      # 퐁: (R·V)ⁿ = 0.5가 되는 각
    m = math.log(0.5) / math.log(math.cos(a / 2))   # 같은 폭의 블린 지수
    print(f"퐁 n={n:3d}: 반폭 {math.degrees(a):5.2f}도"
          f" → 블린 {m:6.1f} ({m / n:.3f}배)")
```
```text
한 평면: ∣∠(R,V) - 2∠(N,H)∣ 최대 0.000000도
3차원: ∣∠(R,V) - 2∠(N,H)∣ 최대 53.071905도
퐁 n=  8: 반폭 23.51도 → 블린   32.7 (4.089배)
퐁 n= 32: 반폭 11.88도 → 블린  128.7 (4.022배)
퐁 n=128: 반폭  5.96도 → 블린  512.7 (4.005배)
```
한 평면에서는 반각 관계가 정확하고, n이 클수록 비가 4에 다가간다. 3차원에서는 관계가 성립하지 않아 모양도 다르다. 퐁 하이라이트는 둥글고 블린-퐁은 비스듬한 시선에서 길쭉해지는데, 젖은 도로의 길쭉한 반사에 더 가까운 쪽은 블린-퐁이다. 퐁 재질을 블린-퐁으로 옮기며 지수를 그대로 두면 하이라이트가 두 배쯤 넓어진다.

## 법선은 역전치 행렬로 옮긴다
2편에서 넘긴 문제다. 법선을 위치처럼 모델 행렬 M으로 옮기면 틀린다. x로 2배, y로 0.5배 늘이는 M에서 45도 경사면의 접선 t = (1, −1, 0)은 (2, −0.5, 0)이 되는데, 법선 (1, 1, 0)은 (2, 0.5, 0)이 되어 내적이 4 − 0.25 = 3.75로 더는 수직이 아니다. 법선은 접선과의 내적 0을 지켜야 하는 벡터라, `nᵀt = 0`이 변환 뒤에도 유지되려면 `(M⁻¹)ᵀ`로 옮겨야 한다. 삼각형 두 변의 외적으로 법선을 다시 구한 값(정의)과 비교한다(앞 코드에 이어서).
```python
def inv_t(M):                          # (M⁻¹)ᵀ = 여인수 행렬 / det
    r0, r1, r2 = M
    c = (cross(r1, r2), cross(r2, r0), cross(r0, r1))
    return tuple(tuple(x / dot(r0, c[0]) for x in row) for row in c)

worst = {"M": 0.0, "(M⁻¹)ᵀ": 0.0}
for _ in range(300):
    M = [[rng.uniform(-2, 2) for _ in range(3)] for _ in range(3)]
    a, b = [[rng.uniform(-1, 1) for _ in range(3)] for _ in range(2)]
    n = cross(a, b)                    # 삼각형 두 변의 외적 = 법선
    true = cross(mul(M, a), mul(M, b)) # 변환한 삼각형에서 다시 구한 법선
    worst["M"] = max(worst["M"], angle(mul(M, n), true, True))
    worst["(M⁻¹)ᵀ"] = max(worst["(M⁻¹)ᵀ"], angle(mul(inv_t(M), n), true, True))
for k, v in worst.items():
    print(f"법선 변환 {k}: 최대 오차 {v:.6f}도 (무작위 300개)")
```
```text
법선 변환 M: 최대 오차 89.892676도 (무작위 300개)
법선 변환 (M⁻¹)ᵀ: 최대 오차 0.000001도 (무작위 300개)
```
회전과 균일 스케일만 있으면 `(M⁻¹)ᵀ`가 M의 상수배라 M으로 옮긴 뒤 정규화해도 된다. 역행렬은 비싸므로 GLSL에서 `transpose(inverse(mat3(uModel)))`을 정점마다 부르기보다 CPU에서 물체마다 한 번 구해 유니폼으로 넘긴다. 유니티 빌트인 파이프라인의 `UnityObjectToWorldNormal`은 역행렬 `unity_WorldToObject`를 법선의 오른쪽에서 곱하는(`mul(n, M⁻¹)` = `(M⁻¹)ᵀn`) 방식으로 같은 일을 한다.

## 툰 셰이딩과 림 라이트
N·L을 연속값 대신 몇 단계로 자르면 만화 같은 **툰 셰이딩**(toon shading, 셀 셰이딩)이 된다. 경계를 1차원 램프 텍스처로 정하면 아티스트가 색 띠를 직접 고른다. 실루엣에서 N이 시선과 거의 수직(1 − N·V가 큼)인 곳을 밝히는 **림 라이트**(rim light)를 더하면 캐릭터가 배경에서 떨어져 보인다. 세 모델을 같은 빛으로 비춘 구를 하네스(WebGL2의 GLSL ES 3.00)로 렌더링한다. UV에서 단위 구의 법선 `(x, y, √(1 − x² − y²))`를 만든다.
```glsl
#version 300 es
precision highp float;
// render 36x7
in vec2 vUV;
out vec4 fragColor;
const vec3 L = vec3(-0.48, 0.6, 0.64);   // 빛 방향(단위 벡터)
const vec3 V = vec3(0.0, 0.0, 1.0);      // 시선 방향
void main() {
    float k = floor(vUV.x * 3.0);        // 0 램버트, 1 블린-퐁, 2 툰
    vec2 p = vec2(fract(vUV.x * 3.0) * 2.0 - 1.0,
                  (vUV.y * 2.0 - 1.0) * 1.1);
    float r2 = dot(p, p);
    if (r2 > 1.0) { fragColor = vec4(0.0, 0.0, 0.0, 1.0); return; }
    vec3 N = vec3(p, sqrt(1.0 - r2));    // 단위 구의 법선
    float ndl = max(dot(N, L), 0.0);
    float c;
    if (k < 0.5) {
        c = 0.1 + 0.9 * ndl;
    } else if (k < 1.5) {
        vec3 H = normalize(L + V);
        c = 0.1 + 0.5 * ndl + 0.5 * pow(max(dot(N, H), 0.0), 32.0);
    } else {
        c = ndl > 0.6 ? 0.9 : (ndl > 0.2 ? 0.5 : 0.2);   // 3단계
        c += 1.0 - N.z > 0.7 ? 0.3 : 0.0;                // 림 라이트
    }
    fragColor = vec4(vec3(c), 1.0);
}
```

```text
=+*+++=-:...------::....#+++++++...+

```
램버트 구는 왼쪽 위에서 부드럽게 어두워지고, 블린-퐁 구는 빛과 시선의 중간 방향에 하이라이트(`%@#`)가 맺히며, 툰 구는 `%`, `+`, `.` 세 띠로 끊기고 가장자리에 림 라이트가 더해진다. 같은 식을 파이썬으로 계산하면 GPU 출력과 글자 하나까지 같다(앞 코드에 이어서).
```python
Lt, RAMP = (-0.48, 0.6, 0.64), " .:-=+*#%@"
Ht = norm((Lt[0], Lt[1], Lt[2] + 1))   # H = normalize(L + V), V = (0,0,1)

def sphere(x, y):                      # 셰이더와 같은 식, 픽셀 (x, y)
    u, v = (x + 0.5) / 36, (y + 0.5) / 7
    k, f = math.floor(u * 3), u * 3 - math.floor(u * 3)
    p = (f * 2 - 1, (v * 2 - 1) * 1.1)
    if dot(p, p) > 1: return 0.0
    n = (*p, math.sqrt(1 - dot(p, p)))
    ndl = max(dot(n, Lt), 0)
    if k == 0: return 0.1 + 0.9 * ndl
    if k == 1: return 0.1 + 0.5 * ndl + 0.5 * max(dot(n, Ht), 0) ** 32
    c = 0.9 if ndl > 0.6 else 0.5 if ndl > 0.2 else 0.2
    return c + (0.3 if 1 - n[2] > 0.7 else 0)

for y in range(6, -1, -1):             # 회색이라 밝기 = 8비트 값
    c8 = [round(min(max(sphere(x, y), 0), 1) * 255) for x in range(36)]
    print("".join(RAMP[min(9, c * 10 // 256)] for c in c8).rstrip())
```

고정 기능 시절에는 이 계산을 정점에서 하고 색을 보간해(구로 셰이딩, 1971) 큰 삼각형 한가운데의 하이라이트가 사라졌다. 프래그먼트 셰이더에서는 법선을 보간해 픽셀마다 계산하는 것(퐁 셰이딩)이 기본이다.

## 어디에 쓰이나
- 선형대수 2편 「내적과 코사인 유사도」: N·L은 두 단위 벡터의 코사인 유사도이고, 램버트 확산은 그 값을 그대로 밝기로 쓴다.
- 선형대수 5편 「연립일차방정식과 역행렬」: 법선 행렬 `(M⁻¹)ᵀ`는 여인수 행렬을 행렬식으로 나눈 역행렬 공식에서 바로 나온다.
- 8편 「물리 기반 렌더링: 마이크로패싯 BRDF와 GGX」: 블린-퐁의 (N·H)ⁿ은 미세면 법선이 H 근처에 몰린 정도를 나타내는 법선 분포 함수의 조상이다.

## 정리
- 램버트 확산은 `max(N·L, 0)`, 주변광은 간접광을 대신하는 상수다.
- 퐁은 (R·V)ⁿ, 블린-퐁은 (N·H)ⁿ이며, 한 평면에서 ∠(R, V) = 2∠(N, H)라 같은 하이라이트에 블린 지수가 약 4배 든다(n = 32에서 4.022배).
- 법선은 `(M⁻¹)ᵀ`로 옮겨야 한다. 무작위 행렬 300개에서 M은 최대 89.9도 틀렸고 역전치는 0.000001도였다.
- 툰 셰이딩은 N·L을 계단으로 자르고, 림 라이트는 1 − N·V로 실루엣을 밝힌다. 세 구의 GPU 렌더링은 파이썬 계산과 글자 하나까지 같았다.
