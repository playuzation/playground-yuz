# [게임 셰이더 3/16] 래스터화와 보간: 무게중심 좌표와 원근 보정

> **한 줄 요약** — 래스터라이저는 픽셀 중심마다 에지 함수 세 개의 부호로 안팎을 가르고, 경계 위 픽셀은 위-왼쪽 규칙으로 한 삼각형에만 주며, 정점 값을 무게중심 좌표로 섞되 속성/w와 1/w를 따로 보간해 나눠야 원근에서 맞고, 2×2 쿼드 단위로 실행해 셰이더가 이웃과의 차이(미분)를 공짜로 얻는다.

## 이 글에서 다루는 것
- 에지 함수로 픽셀이 삼각형 안에 있는지 판정하기(스캔라인 방식과 대조)
- 위-왼쪽 규칙: 공유 변 위의 픽셀을 한 번만 칠하기
- 무게중심 좌표로 속성 보간하기, GLSL 렌더링과 파이썬 재현
- 원근 보정 보간과 플레이스테이션 1의 텍스처 일그러짐

## 문제: 정점 셋에서 픽셀 수천 개로
2편의 변환을 거치면 삼각형은 화면 위의 점 셋과 각 점의 깊이·w·속성(UV, 법선, 색)이 된다. 래스터라이저는 어느 픽셀이 이 삼각형에 속하는지, 그 픽셀에서 속성 값이 얼마인지를 정해야 하고, 둘 다 픽셀 **중심**에서 판단한다.

## 에지 함수: 안인가 밖인가
변 a→b의 **에지 함수**(edge function) `E(p) = (b − a) × (p − a)`(2차원 외적의 z 성분)는 p가 변의 왼쪽이면 양수, 오른쪽이면 음수, 변 위면 0이다. 반시계 방향 삼각형이면 세 값이 모두 0 이상인 점이 안쪽이다. 픽셀마다 독립인 곱셈 몇 번이라 병렬 하드웨어에 맞고, 한 픽셀 옆으로 가면 E가 상수만큼 변해 덧셈으로 갱신된다. 옛 소프트웨어 렌더러의 스캔라인 방식과 무작위 삼각형 300개에서 픽셀 집합을 비교한다(실제 GPU는 화면 전체가 아니라 경계 상자나 타일 안만 본다).
```python
import math, random

def edge(a, b, p):          # (b - a) × (p - a): 왼쪽이면 양수
    return (b[0] - a[0]) * (p[1] - a[1]) - (b[1] - a[1]) * (p[0] - a[0])

def raster_edge(a, b, c):   # 픽셀 중심마다 에지 함수 셋의 부호(GPU 방식)
    if edge(a, b, c) < 0: b, c = c, b                  # 반시계로 맞춘다
    return {(x, y) for x in range(64) for y in range(64)
            if min(edge(a, b, (x + .5, y + .5)), edge(b, c, (x + .5, y + .5)),
                   edge(c, a, (x + .5, y + .5))) >= 0}

def raster_scanline(a, b, c):   # 옛 방식: 행마다 변과의 교점 사이를 칠한다
    out = set()
    for y in range(64):
        yc, xs = y + 0.5, []
        for p, q in ((a, b), (b, c), (c, a)):
            if (p[1] <= yc) != (q[1] <= yc):           # 변이 이 행을 가로지르면
                xs.append(p[0] + (yc - p[1]) * (q[0] - p[0]) / (q[1] - p[1]))
        if xs:
            out |= {(x, y) for x in range(64) if min(xs) <= x + 0.5 <= max(xs)}
    return out

rng, same = random.Random(3), 0
for _ in range(300):
    tri = [(rng.uniform(0, 64), rng.uniform(0, 64)) for _ in range(3)]
    same += raster_edge(*tri) == raster_scanline(*tri)
print(f"무작위 삼각형 300개: 에지 함수 = 스캔라인 {same}/300")
```
```text
무작위 삼각형 300개: 에지 함수 = 스캔라인 300/300
```
실제 GPU는 정점 좌표를 고정소수점으로 바꿔 계산한다(Direct3D 11은 서브픽셀 8비트, 픽셀당 256단계). 그래서 에지 함수가 정확히 0이 되는 일이 실제로 생긴다.

## 위-왼쪽 규칙: 공유 변은 한 번만
픽셀 중심이 두 삼각형의 공유 변 위에 놓이면 E = 0이다. "0 이상이면 안"이면 둘 다 칠해 반투명 물체가 그 줄만 진해지고, "0보다 커야 안"이면 둘 다 빠뜨려 틈이 생긴다. Direct3D는 **위-왼쪽 규칙**(top-left rule)으로, E = 0인 픽셀은 그 변이 위쪽 수평 변이거나 왼쪽 변일 때만 칠한다. OpenGL 명세도 공유 변 위의 프래그먼트를 정확히 한 다각형만 만들라고 요구한다. 꼭짓점이 모두 픽셀 중심 위에 오는 격자 메시로 비교한다(앞 코드에 이어서, y가 위로 커지는 좌표).
```python
from collections import Counter

def top_left(a, b):          # 반시계·y 위쪽 좌표에서 위 변 또는 왼쪽 변인가
    return (a[1] == b[1] and b[0] < a[0]) or b[1] < a[1]

rules = {">= 0": lambda e, tl: e >= 0, "> 0": lambda e, tl: e > 0,
         "위-왼쪽 규칙": lambda e, tl: e > 0 or (e == 0 and tl)}
tris = []                    # 4×4칸을 대각선으로 나눈 32개, 꼭짓점이 픽셀 중심 위
for i in range(4):
    for j in range(4):
        x0, y0, x1, y1 = 4 * i + 0.5, 4 * j + 0.5, 4 * i + 4.5, 4 * j + 4.5
        tris += [((x0, y0), (x1, y0), (x1, y1)), ((x0, y0), (x1, y1), (x0, y1))]
for name, ok in rules.items():
    cnt = Counter((x, y) for t in tris for x in range(18) for y in range(18)
                  if all(ok(edge(u, v, (x + .5, y + .5)), top_left(u, v))
                         for u, v in zip(t, t[1:] + t[:1])))
    inner = [cnt[(x, y)] for x in range(1, 16) for y in range(1, 16)]
    print(f"{name}: 안쪽 225픽셀 중 중복 {sum(k > 1 for k in inner)}"
          f"(최대 {max(inner)}번), 빠짐 {inner.count(0)}")
```
```text
>= 0: 안쪽 225픽셀 중 중복 129(최대 6번), 빠짐 0
> 0: 안쪽 225픽셀 중 중복 0(최대 1번), 빠짐 129
위-왼쪽 규칙: 안쪽 225픽셀 중 중복 0(최대 1번), 빠짐 0
```
여섯 삼각형이 만나는 꼭짓점은 포함 규칙에서 여섯 번 칠해진다. 위-왼쪽 규칙만 중복도 빠짐도 없다.

## 무게중심 좌표로 보간하기
에지 함수를 삼각형 전체의 값 `S = E_ab(c)`(넓이의 두 배)로 나눈 `λa = E_bc(p)/S`, `λb = E_ca(p)/S`, `λc = E_ab(p)/S`가 **무게중심 좌표**(barycentric coordinates)다. 합은 1이고, p가 꼭짓점 a에 있으면 (1, 0, 0)이다. 정점 속성은 `λa·Aa + λb·Ab + λc·Ac`로 섞으니 판정과 보간이 한 계산이다. 프래그먼트 셰이더에서 같은 계산을 해 (λa, λb, λc)를 (R, G, B)로 내보낸다. A는 왼쪽 아래, B는 위, C는 오른쪽이다.
```glsl
#version 300 es
precision highp float;
// render 28x12
in vec2 vUV;
out vec4 fragColor;
float edgeFn(vec2 a, vec2 b, vec2 p) {          // (b - a) × (p - a)
    return (b.x - a.x) * (p.y - a.y) - (b.y - a.y) * (p.x - a.x);
}
void main() {
    const vec2 A = vec2(0.02, 0.0), B = vec2(0.4, 1.0), C = vec2(0.98, 0.2);
    float area = edgeFn(A, B, C);
    vec3 l = vec3(edgeFn(B, C, vUV), edgeFn(C, A, vUV), edgeFn(A, B, vUV)) / area;
    bool inside = all(greaterThanEqual(l, vec3(0.0)));
    fragColor = inside ? vec4(l, 1.0) : vec4(0.0, 0.0, 0.0, 1.0);  // R=A, G=B, B=C
}
```
```text
           *
          ****
         *+++++
        +++++++==
       +++=========
      =========------
     =====----------::
     ----------:::::::::
    ------::::::::::......
   --::::::::::..........
  :::::::........
 :::..
```
밝기 `0.2126λa + 0.7152λb + 0.0722λc`도 λ의 일차식이라 등고선이 곧은 평행선이고, G를 받은 B 쪽이 가장 밝다. 이 삼각형은 시계 방향이라 넓이가 음수지만 나눗셈에서 부호가 상쇄된다. 파이썬으로 비교한다(앞 코드에 이어서).
```python
RAMP = " .:-=+*#%@"
gpu = """\
           *
          ****
         *+++++
        +++++++==
       +++=========
      =========------
     =====----------::
     ----------:::::::::
    ------::::::::::......
   --::::::::::..........
  :::::::........
 :::..""".split("\n")
A, B, C = (0.02, 0.0), (0.4, 1.0), (0.98, 0.2)
rows, area = [], edge(A, B, C)
for y in reversed(range(12)):
    s = ""
    for x in range(28):
        p = ((x + 0.5) / 28, (y + 0.5) / 12)              # 픽셀 중심의 vUV
        l = [edge(B, C, p) / area, edge(C, A, p) / area, edge(A, B, p) / area]
        r, g, b = [round(v * 255) for v in l] if min(l) >= 0 else [0, 0, 0]
        s += RAMP[min(9, int((0.2126 * r + 0.7152 * g + 0.0722 * b) * 10 / 256))]
    rows.append(s.rstrip())
print("GPU 렌더링과 일치:", rows == gpu)
```

## 원근 보정: 속성/w와 1/w를 보간한다
화면의 λ로 UV를 바로 섞으면 틀린다. 원근은 먼 쪽을 줄이므로 화면의 같은 간격이 3차원에서는 같은 간격이 아니다. 3차원에서 일차인 속성 a에 대해 `a/w`와 `1/w`는 **화면에서** 일차이므로, 둘을 각각 λ로 보간한 뒤 나누면 정확하다. 하드웨어가 `in` 변수마다 기본으로 해 주는 일이다. 3차원 삼각형 위의 점을 먼저 골라 정답을 정의대로 구한 뒤 화면에서 두 방식으로 보간한 값과 비교한다(앞 코드에 이어서).
```python
def project(P):              # 뷰 공간 → 화면(초점 거리 1), w = -z
    return (P[0] / -P[2], P[1] / -P[2]), -P[2]

def interp(s, S, W, u):      # 화면 무게중심 좌표로 두 가지 보간
    A = edge(S[0], S[1], S[2])
    l = [edge(S[1], S[2], s) / A, edge(S[2], S[0], s) / A, edge(S[0], S[1], s) / A]
    affine = sum(l[i] * u[i] for i in range(3))
    persp = (sum(l[i] * u[i] / W[i] for i in range(3))
             / sum(l[i] / W[i] for i in range(3)))
    return affine, persp

# 바닥 띠: 가까운 끝 w=1(u=0), 먼 끝 w=9(u=1). 화면 중간 높이의 점
S, W = [(0, -1), (1, -1), (0, -1 / 9)], [1, 1, 9]
print("화면 중간: 선형 %.3f, 보정 %.3f, 정답 0.100"
      % interp((0, -5 / 9), S, W, [0, 0, 1]))

rng, e_aff, e_per = random.Random(7), 0.0, 0.0
for _ in range(300):
    P = [(rng.uniform(-3, 3), rng.uniform(-3, 3), -rng.uniform(1, 20))
         for _ in range(3)]
    u = [rng.random() for _ in range(3)]
    b = [rng.random() for _ in range(3)]
    b = [x / sum(b) for x in b]                  # 삼각형 위의 3차원 점 X
    X = [sum(b[i] * P[i][k] for i in range(3)) for k in range(3)]
    ref = sum(b[i] * u[i] for i in range(3))     # 정의대로의 정답
    S, W = zip(*(project(p) for p in P))
    aff, per = interp(project(X)[0], S, W, u)
    e_aff, e_per = max(e_aff, abs(aff - ref)), max(e_per, abs(per - ref))
print(f"무작위 300점 최대 오차(256텍셀 텍스처): 선형 {e_aff * 256:.1f}텍셀,"
      f" 보정 {e_per * 256:.0e}텍셀")
```
```text
화면 중간: 선형 0.500, 보정 0.100, 정답 0.100
무작위 300점 최대 오차(256텍셀 텍스처): 선형 93.6텍셀, 보정 1e-12텍셀
```
가까운 끝 1m, 먼 끝 9m인 바닥에서 화면의 중간 높이는 1.8m 지점이라 u = 0.1이 맞는데, 화면 선형 보간은 0.5를 준다. 1994년 나온 플레이스테이션 1은 이 보정 없이 화면에서 선형으로(아핀) 텍스처를 입혀 바닥과 벽의 무늬가 카메라를 따라 휘고 출렁였고, 개발자들은 큰 다각형을 잘게 나눠 오차를 줄였다.

## 2×2 쿼드와 미분
GPU는 프래그먼트 셰이더를 2×2 **쿼드**(quad) 단위로 실행한다. 삼각형이 쿼드의 한 픽셀만 덮어도 나머지 셋을 결과를 버리는 **도우미 호출**(helper invocation)로 함께 돌린다. 덕분에 셰이더는 어떤 값이든 옆 픽셀과의 차이를 얻는데, 이것이 `dFdx`·`dFdy`(HLSL의 `ddx`·`ddy`)이고 5편에서 밉 레벨을 고르는 근거다. `f = x²`의 `dFdx`를 렌더링한다.
```glsl
#version 300 es
precision highp float;
// render 4x1 rgba
out vec4 fragColor;
void main() {
    float x = gl_FragCoord.x;           // 픽셀 중심: 0.5, 1.5, 2.5, 3.5
    float f = x * x;                    // 픽셀마다 다른 값
    fragColor = vec4(dFdx(f) / 8.0, 0.0, 0.0, 1.0);   // 쿼드 안 이웃과의 차
}
```
```text
(0,0) 64 0 0 255
(1,0) 64 0 0 255
(2,0) 191 0 0 255
(3,0) 191 0 0 255
```
손으로 확인하면 첫 쿼드는 `1.5² − 0.5² = 2`(2/8 × 255 ≈ 64), 둘째 쿼드는 `3.5² − 2.5² = 6`(191)이다. 픽셀마다 중심 차분을 했다면 1, 3, 5, 7로 모두 달랐을 것이다. 쿼드 안의 두 픽셀이 값을 공유하는 것이 쿼드 실행의 증거다. 그 대가로 몇 픽셀짜리 작은 삼각형에서는 쿼드의 상당 부분이 도우미 호출로 낭비된다(16편).

## MSAA는 짧게
중심 하나로만 판정하면 경계가 계단이 된다. **MSAA**(multisample anti-aliasing)는 픽셀 안 여러 샘플 위치에서 에지 함수와 깊이를 판정하되 셰이더는 픽셀당 한 번만 돌려 덮인 샘플에 같은 색을 쓰고 나중에 평균 낸다. 셰이더 비용은 거의 그대로지만 메모리는 샘플 수만큼 늘어난다.

## 숫자로 보기
| 항목 | 값 | 근거 |
|---|---|---|
| 서브픽셀 정밀도 | 8비트(1/256픽셀) | Direct3D 11 |
| 1080p 쿼드 수 | 518,400개 | 960×540 |
| 1080p 색+깊이 | 16.6MB | RGBA8 + 32비트 깊이 |
| 같은 버퍼 4×MSAA | 66.4MB | 샘플 4개 |

## 어디에 쓰이나
- 수학·기하 알고리즘 9편 「계산 기하 기초: CCW와 선분 교차」: 에지 함수는 세 점의 방향을 판정하는 CCW 그 자체다.
- 미적분 2편 「미분: 순간 변화율」: `dFdx`는 한 픽셀 간격의 차분으로 근사한 미분이라 값이 급히 변하면 거칠어진다.
- 5편 「텍스처 샘플링: 필터링, 밉맵, 이방성 필터링」: 원근 보정된 UV의 화면 미분이 텍셀 발자국이 되어 밉 레벨을 정한다.

## 정리
- 에지 함수 셋의 부호로 픽셀 중심의 안팎을 가르며, 무작위 300개에서 스캔라인 방식과 같았다.
- 공유 변 위의 픽셀은 위-왼쪽 규칙으로 정확히 한 번 칠한다. 포함 규칙은 129픽셀을 중복, 제외 규칙은 129픽셀을 빠뜨렸다.
- 무게중심 좌표는 에지 함수를 넓이로 나눈 것이고, 원근에서는 속성/w와 1/w를 보간해 나눈다. 화면 선형 보간은 최대 93.6텍셀 틀렸다.
- 프래그먼트는 2×2 쿼드로 실행되고, `dFdx`는 쿼드 안 이웃과의 차이다.
