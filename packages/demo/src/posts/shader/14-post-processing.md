# [게임 셰이더 14/16] 포스트 프로세싱: 분리 가능한 블러, 블룸, 외곽선

> **한 줄 요약** — 다 그린 장면을 텍스처로 읽어 화면 전체에 셰이더를 한 번 더 돌리는 것이 포스트 프로세싱이고, 가우시안 블러는 가로·세로 두 번으로 나눠 81탭을 18탭(쌍선형 읽기면 10번)으로 줄이며, 블룸은 절반씩 줄인 사슬로 넓은 번짐을 원본 3분의 1 메모리로 만들고, 외곽선은 깊이와 법선에 소벨 필터를 건다.

## 화면 전체 패스
장면을 다 그린 결과는 렌더 타깃이라는 텍스처일 뿐이다. 이것을 입력으로 화면을 덮는 삼각형 하나를 그리면 프래그먼트 셰이더가 픽셀마다 한 번 돌며 이웃 픽셀을 읽어 흐리게 하거나 번지게 하거나 경계를 찾는다. 이것이 **포스트 프로세싱**(post-processing)이다. 결과를 다른 렌더 타깃에 쓰고 다음 패스가 다시 읽는 식으로 효과를 잇는다. 계산은 단순하고 비용은 대부분 대역폭이다. 10편의 HDR 형식 RGBA16F는 픽셀당 8바이트라 1080p 한 장이 15.8MiB이고, 한 번 읽고 쓰는 패스 하나가 60fps에서 초당 1.85GiB를 쓴다(아래 계산).

## 가우시안 블러를 두 번으로 나누기
9×9 블러는 픽셀마다 이웃 81개를 가중합한다. 가우시안은 `G(x, y) = g(x)·g(y)`로 갈라지므로 가로로 9탭 블러한 결과를 세로로 다시 9탭 블러하면 2차원 합성곱과 같고, 읽기는 18번이다. 탭 수가 n²에서 2n으로 준다. 여기에 GPU의 쌍선형 필터링을 끼우면 더 준다. 위치 a, a + 1의 두 탭(가중치 wa, wb)을 그 사이 `(a·wa + (a + 1)·wb)/(wa + wb)`에서 한 번 읽어 wa + wb를 곱하면 하드웨어 선형 보간이 같은 가중합을 내준다. 9탭이 5번 읽기가 된다. 둘 다 정의대로의 계산과 비교한다.
```python
import math, random

def gauss(n, sigma):                   # 합이 1인 1차원 가우시안 n탭
    w = [math.exp(-i*i / (2*sigma*sigma)) for i in range(-(n//2), n//2 + 1)]
    return [x / sum(w) for x in w]

g, N = gauss(9, 2.0), 24
rng = random.Random(5)
img = [[rng.random() for _ in range(N)] for _ in range(N)]
cl = lambda v: min(max(v, 0), N - 1)   # 가장자리는 clamp
full = [[sum(g[j] * g[i] * img[cl(y+j-4)][cl(x+i-4)]       # 81탭
             for j in range(9) for i in range(9)) for x in range(N)] for y in range(N)]
row = [[sum(g[i] * img[y][cl(x+i-4)] for i in range(9)) for x in range(N)]
       for y in range(N)]                                   # 가로 9탭
sep = [[sum(g[j] * row[cl(y+j-4)][x] for j in range(9)) for x in range(N)]
       for y in range(N)]                                   # 세로 9탭
err = max(abs(a - b) for r1, r2 in zip(full, sep) for a, b in zip(r1, r2))
print(f"9×9 합성곱 대 가로·세로 두 번: 최대 차 {err:.1e}")

# 쌍선형 샘플 하나로 이웃 두 탭을 합친다: 오프셋 (a·wa + b·wb)/(wa + wb)
taps = [(0, g[4])] + [((a*g[4+a] + (a+1)*g[5+a]) / (g[4+a] + g[5+a]), g[4+a] + g[5+a])
                      for a in (1, 3)]
def lerp_fetch(s, x):                  # GPU의 선형 필터링을 흉내 낸다
    i = math.floor(x); f = x - i
    return s[i] * (1 - f) + s[i+1] * f
s, worst = [rng.random() for _ in range(308)], 0.0
for x in range(4, 304):
    exact = sum(g[i] * s[x+i-4] for i in range(9))
    fast = taps[0][1] * s[x] + sum(w * (lerp_fetch(s, x+o) + lerp_fetch(s, x-o))
                                   for o, w in taps[1:])
    worst = max(worst, abs(exact - fast))
print("쌍선형 오프셋", [round(o, 3) for o, _ in taps])
print(f"9탭 대 5번 읽기, 무작위 300점: 최대 차 {worst:.1e}")
```
```text
9×9 합성곱 대 가로·세로 두 번: 최대 차 4.4e-16
쌍선형 오프셋 [0, 1.407, 3.294]
9탭 대 5번 읽기, 무작위 300점: 최대 차 1.1e-14
```

두 결과 모두 반올림 오차 수준에서 같다. 가로 패스 결과를 중간 렌더 타깃에 한 번 쓰고 읽어야 하지만, 81 대 10번 읽기의 차이가 훨씬 크다. 이렇게 정확히 갈라지는 것은 커널을 행렬로 볼 때 랭크가 1인 경우뿐이다. 가우시안과 상자 필터는 되고, 원형 커널은 안 된다.

## 블룸: 밝은 곳만 넓게 번지게
태양이나 불꽃처럼 1보다 밝은 HDR 픽셀은 렌즈와 눈에서처럼 주변으로 번져야 밝게 느껴진다. **블룸**(bloom)은 ① 밝기가 문턱값을 넘는 부분만 남기고 ② 해상도를 절반씩 줄이며(1/2, 1/4, …, 1/64) 단계마다 작은 필터로 흐린 뒤 ③ 거꾸로 두 배씩 키우며 앞 단계에 더해 장면에 조금 섞는다. 1/64 해상도의 텍셀 하나는 원본 64×64 픽셀을 덮으므로 작은 필터로도 반지름 수십 픽셀의 번짐이 나오고, 단계를 모두 더하면 밝은 점 근처는 날카롭고 멀리는 부드러운 꼬리가 생긴다. 콜 오브 듀티: 어드밴스드 워페어(지메네즈, SIGGRAPH 2014)가 이런 피라미드 구조를 시간적 안정성과 함께 정리했다. 사슬의 메모리를 계산하고 등비급수와 비교한다.
```python
MiB = 2**20
for name, w, h in (("1080p", 1920, 1080), ("4K", 3840, 2160)):
    one = w * h * 8 / MiB                    # RGBA16F: 픽셀당 8바이트
    chain = sum((w >> k) * (h >> k) * 8 for k in range(1, 7)) / MiB
    print(f"{name}: 한 장 {one:.1f}MiB, 읽고 쓰는 패스 하나 {2*one*60/1024:.2f}GiB/s")
    print(f"  블룸 사슬(1/2~1/64) {chain:.1f}MiB = {chain/one:.3f}장")
print(f"공식 Σ 4^-k (k=1..6) = {sum(4**-k for k in range(1, 7)):.3f}")
```
```text
1080p: 한 장 15.8MiB, 읽고 쓰는 패스 하나 1.85GiB/s
  블룸 사슬(1/2~1/64) 5.3MiB = 0.333장
4K: 한 장 63.3MiB, 읽고 쓰는 패스 하나 7.42GiB/s
  블룸 사슬(1/2~1/64) 21.1MiB = 0.333장
공식 Σ 4^-k (k=1..6) = 0.333
```

사슬 전체가 원본의 3분의 1이다. 다운샘플을 2×2 평균으로만 하면 작은 밝은 점이 카메라가 움직일 때 어느 텍셀에 걸리느냐에 따라 깜박이므로, 실무에서는 더 넓은 탭으로 줄이고 업샘플도 텐트 같은 부드러운 필터로 한다.

## 외곽선: 깊이와 법선에 소벨
외곽선은 15편의 G-버퍼에 있는 깊이와 법선에서 찾는다. 사이토·다카하시(SIGGRAPH 1990)가 깊이·법선을 픽셀마다 담은 버퍼에 2차원 영상 처리를 해 윤곽을 그린 것이 이 방식의 출발이다. **소벨 필터**(Sobel filter)는 3×3 가중치로 가로·세로 기울기를 재는 합성곱이다.
```text
Gx: -1 0 1    Gy:  1  2  1
    -2 0 2         0  0  0
    -1 0 1        -1 -2 -1
```
깊이 기울기가 크면 실루엣이고, 깊이는 이어지는데 법선이 꺾이는 곳(지붕 능선, 상자 모서리)은 법선 기울기로 잡는다. 아래 셰이더는 원판(깊이 0.1), 깊이가 비스듬하고 가운데 능선에서 법선이 꺾이는 지붕, 배경을 절차적으로 만들고, 이웃 9곳에서 장면을 다시 계산해 소벨을 건다. 깊이 경계는 `@`, 법선 경계만 걸린 곳은 `+`, 물체 안은 `.`이다.
```glsl
#version 300 es
precision highp float;
// render 36x14
in vec2 vUV;
out vec4 fragColor;
vec4 scene(vec2 p) {          // 픽셀 p의 (법선 xyz, 깊이 w)
    if (length(p - vec2(13, 7)) < 6.5) return vec4(0, 0, 1, 0.1);  // 원판
    if (p.x > 19.0 && p.x < 33.0 && p.y > 1.0 && p.y < 13.0)        // 지붕
        return vec4(sign(p.x - 26.0) * 0.7071, 0, 0.7071,
                    0.3 + 0.02 * abs(p.x - 26.0));
    return vec4(0, 0, 1, 1);  // 배경
}
void main() {
    vec2 p = floor(vUV * vec2(36, 14)) + 0.5;
    vec4 gx = vec4(0), gy = vec4(0);
    for (int j = -1; j <= 1; j++)
        for (int i = -1; i <= 1; i++) {        // 소벨 3×3
            vec4 v = scene(p + vec2(i, j));
            gx += float(i) * (j == 0 ? 2.0 : 1.0) * v;
            gy += float(j) * (i == 0 ? 2.0 : 1.0) * v;
        }
    float dz = length(vec2(gx.w, gy.w));       // 깊이의 경사
    float dn = length(gx.xyz) + length(gy.xyz); // 법선의 변화
    float c = dz > 0.3 ? 1.0 : dn > 0.5 ? 0.55 : scene(p).w < 1.0 ? 0.15 : 0.0;
    fragColor = vec4(vec3(c), 1);
}
```
```text
         @@@@@@@@ @@@@@@@@@@@@@@@@
       @@@@@@@@@@@@@@@@@@@@@@@@@@@
       @@@@....@@@@@.....++.....@@
      @@@........@@@.....++.....@@
      @@@........@@@.....++.....@@
      @@..........@@.....++.....@@
      @@..........@@.....++.....@@
      @@..........@@.....++.....@@
      @@..........@@.....++.....@@
      @@@........@@@.....++.....@@
      @@@........@@@.....++.....@@
       @@@@....@@@@@.....++.....@@
       @@@@@@@@@@@@@@@@@@@@@@@@@@@
         @@@@@@@@ @@@@@@@@@@@@@@@@
```
실루엣은 깊이로, 지붕 능선은 법선으로만 잡혔다. 같은 계산을 파이썬으로 해 GPU 출력과 줄마다 비교하고, 깊이 문턱값을 0.15로 낮춘 경우도 센다.
```python
import math
def scene(x, y):                      # 셰이더와 같은 장면: (법선 xyz, 깊이)
    if math.hypot(x - 13, y - 7) < 6.5: return (0, 0, 1, 0.1)
    if 19 < x < 33 and 1 < y < 13:
        return (math.copysign(0.7071, x - 26), 0, 0.7071, 0.3 + 0.02*abs(x - 26))
    return (0, 0, 1, 1)

def outline(th):                      # 밝기 1 → @, 0.55 → +, 0.15 → .
    rows = []
    for py in range(13, -1, -1):      # 위쪽 행부터
        s = ""
        for px in range(36):
            x, y, gx, gy = px + 0.5, py + 0.5, [0]*4, [0]*4
            for j in (-1, 0, 1):
                for i in (-1, 0, 1):
                    for k, v in enumerate(scene(x + i, y + j)):
                        gx[k] += i * (2 if j == 0 else 1) * v
                        gy[k] += j * (2 if i == 0 else 1) * v
            dz, dn = math.hypot(gx[3], gy[3]), math.hypot(*gx[:3]) + math.hypot(*gy[:3])
            s += "@" if dz > th else "+" if dn > 0.5 else "." if scene(x, y)[3] < 1 else " "
        rows.append(s.rstrip())
    return rows

GPU = """         @@@@@@@@ @@@@@@@@@@@@@@@@
       @@@@@@@@@@@@@@@@@@@@@@@@@@@
       @@@@....@@@@@.....++.....@@
      @@@........@@@.....++.....@@
      @@@........@@@.....++.....@@
      @@..........@@.....++.....@@
      @@..........@@.....++.....@@
      @@..........@@.....++.....@@
      @@..........@@.....++.....@@
      @@@........@@@.....++.....@@
      @@@........@@@.....++.....@@
       @@@@....@@@@@.....++.....@@
       @@@@@@@@@@@@@@@@@@@@@@@@@@@
         @@@@@@@@ @@@@@@@@@@@@@@@@"""
same = sum(a == b for a, b in zip(outline(0.3), GPU.split("\n")))
print(f"GPU 렌더링과 같은 줄: {same}/14")
for th in (0.3, 0.15):
    t = "".join(outline(th))
    print(f"깊이 문턱값 {th}: @ {t.count('@')}개, + {t.count('+')}개, . {t.count('.')}개")
```
```text
GPU 렌더링과 같은 줄: 14/14
깊이 문턱값 0.3: @ 180개, + 20개, . 180개
깊이 문턱값 0.15: @ 280개, + 20개, . 80개
```

지붕은 깊이가 픽셀마다 0.02씩 변하는 비탈이라 깊이 소벨이 0.02 × 2 × 4 = 0.16을 낸다. 문턱값 0.3에서는 칠해지지 않지만 0.15로 낮추면 비탈 100픽셀이 모두 선이 된다. 문턱값을 낮추면 비스듬한 바닥이 온통 선이 되고, 높이면 가까이 붙은 물체 사이의 경계를 놓친다. 그래서 깊이를 선형 거리로 바꿔 거리에 비례한 문턱값을 쓰거나 법선 조건과 합친다.

## 깊이 기반 안개
깊이 버퍼 값은 2편에서 본 것처럼 비선형이라, 먼저 뷰 공간 거리 d로 되돌린 뒤 `f = exp(−density·d)`로 남는 비율을 정하고 `mix(fogColor, color, f)`로 섞는다. 거리 1/density에서 원래 색이 e⁻¹ ≈ 37% 남는다. 포스트 패스로 하면 물체 셰이더마다 안개 코드를 넣지 않아도 되지만, 깊이를 쓰지 않는 반투명 물체(12편)는 따로 처리해야 한다.

## 어디에 쓰이나
- 신경망 레이어 2편 「합성곱 층: 가까운 것끼리 보는 레이어」: 블러와 소벨은 학습하지 않고 정해 둔 합성곱 커널이다.
- 선형대수 10편 「특이값 분해(SVD)」: 커널이 가로·세로로 정확히 갈라지는 것은 커널 행렬의 랭크가 1일 때이고, SVD의 첫 성분이 가장 가까운 분리 가능 근사다.
- 게임 자원 관리 1편 「프레임 예산: 16.67ms 안에 모든 일을 끝내기」: 포스트 패스는 해상도에 비례하는 고정 비용이라, 저사양 설정은 블룸·외곽선을 절반 해상도로 돌려 예산을 맞춘다.

## 정리
- 포스트 프로세싱은 렌더 타깃을 읽어 화면 전체 삼각형으로 픽셀마다 셰이더를 돌리는 패스이고, 비용은 해상도 × 바이트 × 패스 수의 대역폭이다.
- 가우시안 블러는 가로·세로로 나눠도 2차원 합성곱과 같고 탭은 n²에서 2n으로, 쌍선형 읽기로 다시 절반 가까이 준다.
- 블룸은 밝은 부분을 절반씩 줄인 사슬에서 흐려 더해, 원본 3분의 1 메모리로 넓은 번짐을 만든다.
- 외곽선은 깊이 소벨로 실루엣을, 법선 소벨로 접힌 모서리를 찾는다.
