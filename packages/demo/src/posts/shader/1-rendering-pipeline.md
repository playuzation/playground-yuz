# [게임 셰이더 1/16] 셰이더와 렌더링 파이프라인: GPU가 삼각형을 픽셀로 바꾸는 길

> **한 줄 요약** — GPU는 정점마다 정점 셰이더를 돌려 위치를 정하고, 고정 하드웨어가 삼각형을 픽셀 조각으로 자른 뒤, 조각마다 프래그먼트 셰이더를 돌려 색을 정하는데, 정점은 메시마다 수백~수만 번이지만 프래그먼트는 1080p 60fps 한 겹만으로 초당 1억 2천만 번이라 비용의 무게는 대개 픽셀 쪽에 실린다.

## 이 글에서 다루는 것
- 렌더링 파이프라인의 단계와, 그중 프로그램할 수 있는 두 단계
- 고정 기능에서 프로그래머블 셰이더, 통합 셰이더로 온 길
- 가장 단순한 셰이더를 WebGL2에서 렌더링하고 파이썬으로 같은 그림 재현하기
- 구 하나를 그릴 때 정점·프래그먼트 셰이더 실행 횟수와 오버드로 세기
- 드로 콜과 상태, 엔진(Unity·Unreal·Godot)에서 셰이더가 보이는 모습

## 문제: 16.67ms 안에 픽셀 2백만 개
게임 화면 한 장은 삼각형 수십만~수백만 개짜리 장면을 1920×1080 = 2,073,600개 픽셀의 색으로 바꾼 결과다. 60fps라면 게임 자원 관리 1편 「프레임 예산: 16.67ms 안에 모든 일을 끝내기」의 예산 안에 끝내야 하므로, 같은 계산을 수많은 데이터에 동시에 적용하는 처리량 기계인 GPU가 맡는다. 그 기계 위에서 "이 정점을 어디에 놓을까", "이 픽셀을 무슨 색으로 칠할까"를 정하는 작은 프로그램이 **셰이더**(shader)다. 첫 글은 셰이더가 끼워지는 자리, 곧 **렌더링 파이프라인**(rendering pipeline)의 지도를 그린다.

## 파이프라인 한눈에 보기
```text
vertex + index buffers (VRAM)
            ↓
1 input assembly         fixed
            ↓
2 vertex shader          PROGRAM
            ↓
3 clip, divide by w,
  viewport, cull         fixed
            ↓
4 rasterizer             fixed
            ↓
5 fragment shader        PROGRAM
            ↓
6 depth test, blending   settings
            ↓
framebuffer (color + depth)
```
- 1 입력 조립(input assembly): 정점·인덱스 버퍼에서 정점을 읽어 삼각형으로 묶는다.
- 2 **정점 셰이더**(vertex shader): 정점마다 한 번, 위치를 클립 공간 좌표 `gl_Position`으로 바꾸고 보간할 값을 내보낸다(2편).
- 3 클리핑·원근 나눗셈·뷰포트: 시야 밖을 잘라 내고 w로 나눈 뒤 픽셀 좌표로 늘린다. 뒷면 컬링도 여기서 한다.
- 4 래스터화(rasterization): 삼각형이 덮는 픽셀 중심마다 **프래그먼트**(fragment, 픽셀 하나에 대한 후보 조각)를 만들고 정점 값을 보간해 붙인다(3편).
- 5 **프래그먼트 셰이더**(fragment shader, Direct3D에서는 픽셀 셰이더): 프래그먼트마다 한 번 색을 계산한다. 텍스처(5편)와 조명(6~9편)이 여기 있다.
- 6 깊이 테스트·블렌딩: 가려진 조각을 버리고 남은 색을 쓰거나 섞는다(12편). 프로그램이 아니라 설정이다.

## 고정 기능에서 프로그래머블로
1990년대 GPU의 파이프라인은 **고정 기능**(fixed function)이었다. 변환과 조명 식이 칩에 박혀 있어 행렬, 광원 색 같은 매개변수만 고를 수 있었다. 2000년 11월 DirectX 8.0이 정점 셰이더와 픽셀 셰이더를 API에 처음 넣었고, 2001년 2월 나온 엔비디아 GeForce 3가 이를 지원한 첫 GPU였다(셰이더 모델 1.1, 명령어 수가 엄격히 제한된 어셈블리). OpenGL은 2004년 OpenGL 2.0에서 C를 닮은 GLSL을 표준에 넣었다. 다음 전환은 **통합 셰이더**(unified shader)다. 그전에는 정점용과 픽셀용 장치가 따로 있어 한쪽이 놀기 쉬웠는데, 2005년 Xbox 360의 ATI Xenos와 2006년 11월 GeForce 8800(G80, DirectX 10·셰이더 모델 4.0)부터 같은 연산 장치가 어느 셰이더든 돌린다. 오늘날 GPU의 SM이 그 통합 장치이고, 셰이더 호출은 CUDA 스레드처럼 워프로 묶여 실행된다.

## 가장 단순한 셰이더 한 쌍
이 시리즈의 GLSL은 모두 OpenGL ES 3.0·WebGL2의 **GLSL ES 3.00**이고, 헤드리스 Chromium의 WebGL2(SwiftShader)에서 실제로 컴파일했다. 먼저 정점 셰이더다. `in`은 정점마다 다른 입력, `uniform`은 드로 콜 하나 동안 모든 정점이 같이 보는 값, `out`은 래스터라이저가 보간해 프래그먼트 셰이더에 넘길 값이다.
```glsl
#version 300 es
layout(location = 0) in vec3 aPos;     // 정점 버퍼에서 온 위치
uniform mat4 uMVP;                     // 드로 콜마다 CPU가 넣는 행렬
out vec2 vUV;                          // 래스터라이저가 보간할 값
void main() {
    vUV = aPos.xy * 0.5 + 0.5;
    gl_Position = uMVP * vec4(aPos, 1.0);   // 클립 공간 좌표
}
```
프래그먼트 셰이더는 보간된 `vUV`를 색으로 바꾼다. 렌더링 결과는 화면 전체를 덮는 삼각형 하나로 그린 뒤, 픽셀 밝기(0.2126R + 0.7152G + 0.0722B)를 열 단계 문자 ` .:-=+*#%@`로 바꿔 위쪽 행부터 보인다.
```glsl
#version 300 es
precision mediump float;
// render 20x6
in vec2 vUV;              // 래스터라이저가 보간해 준 값
out vec4 fragColor;       // 이 픽셀의 색
void main() {
    fragColor = vec4(vUV.x, vUV.y, 0.0, 1.0);   // R = 가로, G = 세로
}
```
```text
****##########%%%%%%
++++++**********####
========+++++++++***
----------=========+
..:::::::::---------
    .........:::::::
```
같은 계산을 파이썬으로 하고 GPU 출력과 글자 하나까지 비교한다. 프래그먼트 셰이더가 픽셀의 **중심** `((x + 0.5)/W, (y + 0.5)/H)`에서 계산되고, 결과가 8비트로 반올림되어 저장된다는 점을 그대로 흉내 낸다.
```python
RAMP = " .:-=+*#%@"
W, H = 20, 6
gpu = """\
****##########%%%%%%
++++++**********####
========+++++++++***
----------=========+
..:::::::::---------
    .........:::::::""".split("\n")

def shade(x, y):                            # 프래그먼트 셰이더 한 번
    u, v = (x + 0.5) / W, (y + 0.5) / H     # 픽셀 중심의 vUV
    return round(u * 255), round(v * 255)   # 8비트 프레임 버퍼에 저장

rows = []
for y in reversed(range(H)):                # 위쪽 행부터
    s = ""
    for x in range(W):
        r, g = shade(x, y)
        s += RAMP[min(9, int((0.2126 * r + 0.7152 * g) * 10 / 256))]
    rows.append(s.rstrip())
print("GPU 렌더링과 일치:", rows == gpu, "/ 왼쪽 아래 (R, G):", shade(0, 0))
```
```text
GPU 렌더링과 일치: True / 왼쪽 아래 (R, G): (6, 21)
```

## 몇 번 도나: 정점 대 프래그먼트
위도 12칸·경도 24칸 구를 +z 위에서 직교 투영으로 그리며 두 셰이더의 실행 횟수를 센다. 래스터화는 3편의 에지 함수로 하고, 뒷면 컬링을 켠 경우와 끈 경우를 비교한다. 대조로, 컬링한 프래그먼트 수를 구의 윤곽(적도 24각형) 안의 픽셀 중심을 직접 센 값과 비교한다.
```python
import math
from collections import Counter

def uv_sphere(S=12, L=24):
    """위도 S칸·경도 L칸 구를 +z에서 내려다본 (x, y). 극의 퇴화 삼각형은 뺀다."""
    vs = [(math.sin(math.pi * i / S) * math.cos(2 * math.pi * j / L + 0.1),
           math.sin(math.pi * i / S) * math.sin(2 * math.pi * j / L + 0.1))
          for i in range(S + 1) for j in range(L + 1)]
    tris = []
    for i in range(S):
        for j in range(L):
            a = i * (L + 1) + j
            if i > 0: tris.append((a, a + L + 1, a + 1))
            if i < S - 1: tris.append((a + 1, a + L + 1, a + L + 2))
    return vs, tris

def edge(a, b, p):           # 에지 함수: p가 a→b의 왼쪽이면 양수
    return (b[0] - a[0]) * (p[1] - a[1]) - (b[1] - a[1]) * (p[0] - a[0])

def draw(vs, tris, r, cull):
    scr = [(r + 2 + r * x, r + 2 + r * y) for x, y in vs]   # 정점 셰이더
    cover = Counter()
    for t in tris:
        a, b, c = (scr[k] for k in t)
        if edge(a, b, c) < 0:
            if cull: continue                # 뒷면(시계 방향)은 버린다
            b, c = c, b
        for y in range(int(min(a[1], b[1], c[1])), int(max(a[1], b[1], c[1])) + 1):
            for x in range(int(min(a[0], b[0], c[0])), int(max(a[0], b[0], c[0])) + 1):
                p = (x + 0.5, y + 0.5)       # 픽셀 중심
                if min(edge(a, b, p), edge(b, c, p), edge(c, a, p)) >= 0:
                    cover[(x, y)] += 1       # 프래그먼트 셰이더 한 번
    return cover

def in_silhouette(r, L=24):  # 대조: 적도 다각형 안의 픽셀 중심을 직접 센다
    ring = [(r + 2 + r * math.cos(2 * math.pi * j / L + 0.1),
             r + 2 + r * math.sin(2 * math.pi * j / L + 0.1)) for j in range(L)]
    return sum(all(edge(ring[j], ring[(j + 1) % L], (x + 0.5, y + 0.5)) >= 0
                   for j in range(L))
               for x in range(2 * r + 5) for y in range(2 * r + 5))

vs, tris = uv_sphere()
used = len({k for t in tris for k in t})               # 인덱스가 가리키는 정점
print(f"정점 {len(vs)}(쓰이는 것 {used}), 삼각형 {len(tris)},"
      f" 인덱스 없이 {3 * len(tris)}")
for r in (4, 28, 100):
    f, b = draw(vs, tris, r, True), draw(vs, tris, r, False)
    print(f"반지름 {r}px: 컬링 {sum(f.values())}·최대 {max(f.values())}겹"
          f"·직접 세기 {sum(f.values()) == in_silhouette(r)}"
          f" / 끄면 {sum(b.values())}·최대 {max(b.values())}겹")
```
```text
정점 325(쓰이는 것 323), 삼각형 528, 인덱스 없이 1584
반지름 4px: 컬링 52·최대 1겹·직접 세기 True / 끄면 104·최대 2겹
반지름 28px: 컬링 2448·최대 1겹·직접 세기 True / 끄면 4896·최대 2겹
반지름 100px: 컬링 31040·최대 1겹·직접 세기 True / 끄면 62080·최대 2겹
```
정점 캐시가 이상적이면 정점 셰이더는 인덱스가 가리키는 정점마다 한 번(323번), 인덱스 없이 보내면 1,584번 돈다. 프래그먼트 셰이더는 화면 넓이에 비례해 52번에서 31,040번까지 변한다. 컬링을 끄면 뒤쪽 반구도 래스터화되어 모든 픽셀이 두 번 칠해진다. 한 픽셀에 프래그먼트가 여러 번 생기는 이것이 **오버드로**(overdraw)이고, 깊이 테스트가 뒤쪽 조각을 버려도 셰이더를 돌린 뒤면 비용은 이미 냈다(16편). 반지름 4픽셀이면 정점이 프래그먼트보다 여섯 배 많다. 먼 물체에 LOD를 쓰는 이유다.

## 드로 콜과 상태
"이 셰이더, 이 텍스처, 이 블렌드·깊이 설정으로 인덱스 n개를 그려라"라는 명령 하나가 **드로 콜**(draw call)이다. 그 사이에 셰이더나 텍스처를 바꾸는 상태 변경은 드라이버 검증과 파이프라인 전환을 부르므로, 엔진은 그릴 목록을 셰이더 → 머티리얼 → 메시 순으로 정렬하고 인스턴싱과 텍스처 아틀라스로 드로 콜을 합친다. Direct3D 12와 Vulkan은 셰이더와 고정 기능 설정을 파이프라인 상태 객체(PSO) 하나로 묶어 컴파일하는데, 이를 실행 중에 만들 때의 끊김은 16편에서 다룬다.

## 엔진에서의 모습
- Unity: ShaderLab 파일이 패스와 렌더 상태(블렌드, 깊이 쓰기, 컬링)를 적고, 그 안의 `HLSLPROGRAM` 블록에 HLSL로 정점·프래그먼트 함수를 쓴다.
- Unreal Engine: 머티리얼 에디터의 노드 그래프로 표면 속성을 만들면 엔진이 HLSL로 바꿔 자신의 셰이더 틀에 끼운다.
- Godot: GLSL ES 3.0을 닮은 자체 셰이딩 언어로 `shader_type spatial;` 아래에 `vertex()`와 `fragment()` 함수를 쓴다.

## 어디에 쓰이나
- GPU와 CUDA 3편 「SIMT와 워프: 32개 스레드가 함께 걷는 법」: 프래그먼트 셰이더 호출도 워프로 묶여 함께 실행되므로 분기 비용이 CUDA 커널과 같은 원리로 생긴다(16편).
- 게임 자원 관리 9편 「컬링과 LOD: 안 보이는 것은 그리지 않고 먼 것은 덜 그리기」: 반지름 4픽셀 구에서 정점 셰이더 323번이 프래그먼트 52개보다 많았던 것이 먼 물체를 거친 모델로 바꾸는 이유다.
- 게임 자원 관리 12편 「텍스처 아틀라스와 사각형 빈 패킹」: 텍스처를 한 장에 모으면 상태 변경 없이 여러 물체를 드로 콜 하나로 합칠 수 있다.

## 정리
- 파이프라인에서 프로그램하는 곳은 정점 셰이더와 프래그먼트 셰이더이고, 나머지는 고정 하드웨어와 설정이다.
- DirectX 8.0(2000)과 GeForce 3(2001)가 프로그래머블 셰이더를, Xenos(2005)와 G80(2006)이 통합 셰이더를 열었다.
- 프래그먼트 셰이더는 픽셀 중심에서 실행되고, 파이썬 재현이 GPU 렌더링과 글자 하나까지 같았다.
- 정점 수는 메시가, 프래그먼트 수는 화면 넓이와 오버드로가 정한다. 컬링을 끄면 프래그먼트가 정확히 두 배가 됐다.
