## 문제: 플레이어는 지도를 모른다
디자이너는 레벨을 위에서 내려다보며 만들지만 플레이어는 눈높이에서 앞만 본다. 순진한 해결은 화면에 화살표나 목표 표시를 띄우는 것이다. 길은 잃지 않지만 플레이어는 공간 대신 표시를 따라간다. 아무것도 없으면 헤맨다. 목표는 공간이 스스로 길을 말하게 하는 것이다.

## 공간의 문법
- **랜드마크**(landmark): 멀리서도 보이는 고유한 기준점(탑, 큰 나무)으로, 방향과 현재 위치를 알려 준다.
- 빛과 색: 시선은 밝고 채도 높은 곳으로 간다. 미러스 엣지(2008)의 러너 비전(Runner Vision)은 문·난간·파이프처럼 진행에 필요한 물체를 빨갛게 칠해 질주 중에도 길을 읽게 하고, 높은 난이도에서는 끌 수 있다(위키백과와 리뷰들의 설명).
- 모이는 선: 길, 난간, 전선이 모이는 구도는 시선을 소실점으로 보낸다. 그 끝에 목표를 둔다.
- 열린 문과 닫힌 문: 열린 문과 빛이 새는 문은 초대이고, 닫힌 문은 "나중에"라는 신호다(4편의 게이팅).
- **리빌**(reveal): 시야를 막았다가 한 걸음에 연다. 닌텐도 개발진은 CEDEC 2017 강연에서 젤다의 전설 브레스 오브 더 와일드의 "삼각형 법칙"을 소개했다. 언덕 같은 장애물을 삼각형으로 두면 넘을지 돌아갈지 고르게 되고, 삼각형이 시야를 가려 너머가 궁금해진다(강연을 옮긴 보도 기준).
- 막다른 길과 보상: 막다른 길에는 시간을 쓴 대가(아이템, 경치, 지름길)를 둔다. 빈 막다른 길은 탐험을 벌한다.

이 장치들은 모두 "어디에서 무엇이 보이는가"에 달려 있다. 걸어 보며 확인하는 것이 기본이지만, 격자 모델로 계산하면 배치 후보를 숫자로 비교할 수 있다.

## 순진한 시야: 브레젠험 직선
흔한 방법은 두 칸 사이에 **브레젠험 직선**(Bresenham's line)을 그어 벽이 하나도 없으면 보인다고 치는 것이다. 문제는 A에서 B로 그은 칸들과 B에서 A로 그은 칸들이 다를 수 있다는 점이다. 그러면 A에서는 B가 보이는데 B에서는 A가 안 보인다. 그래서 두 칸의 중심을 잇는 선분이 어떤 벽 칸의 내부도 지나지 않으면 보인다고 정한다. 선분에는 방향이 없으니 대칭이다. 정의 그대로의 계산은 모든 벽과 교차를 검사한다. 선분의 매개변수 t가 두 축 모두에서 벽의 열린 구간 안에 드는 범위가 남는지를 분수로 계산해, 모서리를 스치는 경우도 정확히 가른다.
```python
import random
from fractions import Fraction as F

def bresenham(a, b):                     # a에서 b로 가며 지나는 칸
    (r, c), (r1, c1) = a, b
    dr, dc = abs(r1 - r), -abs(c1 - c)
    sr, sc, err, out = (r1 > r) * 2 - 1, (c1 > c) * 2 - 1, dr + dc, []
    while (r, c) != (r1, c1):
        e2 = 2 * err
        if e2 >= dc: err, r = err + dc, r + sr
        if e2 <= dr: err, c = err + dr, c + sc
        out.append((r, c))
    return out[:-1]                      # 끝점 제외

def see_bres(g, a, b):
    return all(g[r][c] != "#" for r, c in bresenham(a, b))

def crosses(a, b, w):                    # 중심-중심 선분이 벽 w 내부를 지나나
    lo, hi = F(0), F(1)                  # 매개변수 t의 열린 구간
    for p, q, s in zip(a, b, w):         # 행 축, 열 축
        p, q = p + F(1, 2), q + F(1, 2)
        if p == q:
            if not s < p < s + 1:
                return False
            continue
        t1, t2 = (s - p) / (q - p), (s + 1 - p) / (q - p)
        lo, hi = max(lo, min(t1, t2)), min(hi, max(t1, t2))
    return lo < hi

def see_exact(g, a, b):                  # 정의 그대로: 모든 벽과 검사
    return not any(crosses(a, b, (r, c))
                   for r, row in enumerate(g) for c, ch in enumerate(row)
                   if ch == "#" and (r, c) not in (a, b))
```

## 섀도캐스팅: 그림자를 한 번만 만든다
**섀도캐스팅**(shadowcasting)은 로그라이크에서 널리 쓰는 시야 알고리즘 계열이다. 시작점 둘레를 8개 분면으로 나누고, 거리 d인 줄 단위로 바깥쪽으로 훑는다. 줄의 k번째 칸 중심은 기울기 k/d에 있다. 정사각형은 볼록하므로 선분이 벽 칸 (d, k)의 내부를 지나는 것은 목표가 더 먼 줄에 있고 목표 중심의 기울기가 그 벽의 모서리 기울기 (2k − 1)/(2d + 1)과 (2k + 1)/(2d − 1) 사이에 엄밀히 들어갈 때뿐이다. 벽마다 이 열린 구간을 그림자로 한 번 만들어 합쳐 두면, 칸은 그림자 목록과만 비교하면 된다. 앞 코드에 이어서, 무작위 지도 300개에서 정의대로의 계산과 비교한다.
```python
# 앞 코드에 이어서
def merge(iv):                           # 겹치는 열린 구간 합치기
    out = []
    for lo, hi in sorted(iv):
        if out and lo < out[-1][1]:
            out[-1] = (out[-1][0], max(hi, out[-1][1]))
        else:
            out.append((lo, hi))
    return out

def fov(g, o):                           # 섀도캐스팅: 8분면을 줄 단위로
    R, C, seen = len(g), len(g[0]), {o}
    for sr, sc, swap in [(a, b, s) for a in (1, -1) for b in (1, -1)
                         for s in (0, 1)]:
        shadows = []                     # 기울기의 열린 구간들
        for d in range(1, max(R, C)):
            new = []
            for k in range(d + 1):       # 거리 d 줄의 k번째 칸
                dr, dc = (k, d) if swap else (d, k)
                r, c = o[0] + sr * dr, o[1] + sc * dc
                if not (0 <= r < R and 0 <= c < C):
                    continue
                if not any(lo < F(k, d) < hi for lo, hi in shadows):
                    seen.add((r, c))     # 중심 기울기가 그림자 밖
                if g[r][c] == "#":       # 모서리 기울기 사이가 그림자
                    new.append((F(2*k - 1, 2*d + 1), F(2*k + 1, 2*d - 1)))
            shadows = merge(shadows + new)
    return seen

rng, same, asym, total = random.Random(2), 0, 0, 0
for _ in range(300):
    R, C = rng.randint(3, 8), rng.randint(3, 8)
    g = ["".join(rng.choice("..#") for _ in range(C)) for _ in range(R)]
    cells = [(r, c) for r in range(R) for c in range(C)]
    o = rng.choice(cells)
    exact = {b for b in cells if b == o or see_exact(g, o, b)}
    same += fov(g, o) == exact
    asym += sum(see_bres(g, o, b) != see_bres(g, b, o) for b in cells)
    total += len(cells)
print("무작위 300개 지도, 섀도캐스팅 = 정의대로:", same, "/ 300")
print(f"브레젠험이 비대칭인 쌍: {asym} / {total}")
```
```text
무작위 300개 지도, 섀도캐스팅 = 정의대로: 300 / 300
브레젠험이 비대칭인 쌍: 798 / 9136
```
섀도캐스팅은 300개 모두 정의와 같았다. 브레젠험은 9%의 쌍에서 한쪽만 다른 쪽을 본다. "여기서 탑이 보이나"와 "탑에서 여기가 보이나"가 달라지고, 전투에서는 내가 못 보는 적이 나를 쏘는 불공정이 된다(7편).

## 지도로 보기: 꺾인 복도와 리빌
앞 코드에 이어서, 시작 방 S에서 꺾인 복도를 지나 홀로 나가는 레벨이다. 범례: `#` 벽, `.` K에서 보이는 바닥, 공백은 안 보이는 바닥, `K` 복도가 꺾이는 곳, `a b c` 랜드마크 후보.
```python
# 앞 코드에 이어서
MAP = ["##############################",
       "#....#.......................#",
       "#.S..#..........###..b.......#",
       "#....#..........###..........#",
       "##.###.......................#",
       "##.###.......................#",
       "##K.........................a#",
       "######..........##...........#",
       "######..........##...........#",
       "######.....######...##########",
       "     #######    #.c.#",
       "                #####"]
g = [row.ljust(30).replace(" ", "#") for row in MAP]
spot = {ch: (r, c) for r, row in enumerate(MAP)
        for c, ch in enumerate(row) if ch.isalpha()}
floor = {(r, c) for r in range(len(g)) for c in range(30) if g[r][c] != "#"}

def show(vis):                           # 보이는 바닥만 . 으로
    for r, row in enumerate(MAP):
        print("".join(ch if ch in "# " or ch.isalpha() else
                      "." if (r, c) in vis else " "
                      for c, ch in enumerate(row)).rstrip())

show(fov(g, spot["K"]))
path = [(r, 2) for r in range(2, 6)] + [(6, c) for c in range(2, 9)]
print("S부터 한 칸씩:", *[len(fov(g, p) & floor) for p in path])
```
```text
##############################
#... #                       #
# S  #          ###  b       #
# .  #          ###    ......#
##.###          .............#
##.###   ....................#
##K.........................a#
######   .......##           #
######          ##           #
######     ######   ##########
     #######    # c #
                #####
S부터 한 칸씩: 15 15 14 11 80 84 94 125 140 141 143
```
복도에서는 보이는 바닥이 15칸 안팎이다가, K로 꺾는 한 걸음에 11칸에서 80칸으로 뛴다. 꺾인 복도가 리빌을 한 순간에 모은 것이다. 곧은 복도였다면 홀이 조금씩 새어 보여 놀람이 흩어진다. K에서는 복도 축을 따라 펼쳐진 부채꼴이 보이고, 그 끝에 a가 있다.

랜드마크 후보 셋을 비교한다. 시야가 대칭이므로 "a가 보이는 칸 전체"는 a에서 시야를 한 번 계산하면 되고, 칸마다 따로 계산한 결과와 대조한다.
```python
# 앞 코드에 이어서
show(fov(g, spot["a"]))                  # a가 보이는 곳 = a에서 보이는 곳
for ch in "abc":
    v = fov(g, spot[ch]) & floor
    each = {x for x in floor if x == spot[ch] or see_exact(g, x, spot[ch])}
    print(f"{ch}: 바닥의 {len(v) / len(floor):.0%}에서 보임,",
          "K에서", "보임," if spot["K"] in v else "안 보임,",
          "따로 계산과 일치", v == each)
```
```text
##############################
#    #            ...........#
# S  #...       ###..b.......#
#    #........  ###..........#
## ###.......................#
## ###.......................#
##K.........................a#
######          ##...........#
######          ##...........#
######     ######.  ##########
     #######    # c #
                #####
a: 바닥의 68%에서 보임, K에서 보임, 따로 계산과 일치 True
b: 바닥의 51%에서 보임, K에서 안 보임, 따로 계산과 일치 True
c: 바닥의 27%에서 보임, K에서 안 보임, 따로 계산과 일치 True
```
a는 복도 축의 끝에 있어 리빌 순간(K)에 보이고 홀 바닥의 68%에서 보인다. 방향을 잡는 랜드마크로 좋다. b는 홀 가운데라 51%에서 보이지만 K에서는 기둥에 가려, 걸어 들어가며 발견하는 보상 자리에 어울린다. c는 막다른 방이라 27%에서만 보이므로, 들어가 본 사람에게 주는 보상 자리다. 같은 숫자라도 목적에 따라 좋고 나쁨이 갈린다.

## 모델이 말해 주지 않는 것
- 2D 격자는 높이를 모른다. 진짜 랜드마크는 벽 너머로도 보이고, 3D 엔진에서는 레이캐스트나 미리 구운 가시성 데이터로 같은 질문에 답한다.
- 보인다고 본다는 보장은 없다. 시선은 밝기, 대비, 움직임, 카메라 방향에 끌리므로 플레이테스트에서 실제 움직임을 확인한다.
- 유도가 강할수록 탐험의 재미는 준다. 얼마나 이끌지는 게임의 목표로 정한다.

## 정리
- 랜드마크, 빛과 색, 모이는 선, 열린 문은 표시 없이 갈 곳을 알려 주고, 리빌은 시야를 막았다 열어 호기심을 만든다.
- 브레젠험 판정은 방향에 따라 결과가 달라 비대칭이다. 중심을 잇는 선분으로 정의하면 대칭이 된다.
- 섀도캐스팅은 벽마다 그림자 구간을 한 번 만들고, 무작위 지도 300개에서 정의대로의 계산과 일치했다.
- 대칭 시야 덕분에 랜드마크가 보이는 영역을 한 번에 구해 후보를 비교한다. 꺾인 복도는 리빌을 한 걸음에 모은다.
