## 같은 전투가 누구에게는 지옥, 누구에게는 산책
기획자가 1분마다 같은 자리에서 적 30마리가 몰려오게 배치했다고 하자. 중간 실력의 테스터에게 맞춰 다듬은 배치다. 그런데 서툰 플레이어는 앞 무리를 다 처리하기도 전에 다음 무리를 맞아 내내 몰리고, 능숙한 플레이어는 몇 초 만에 정리하고 나머지 시간을 빈 복도에서 보낸다. 순진한 해결책도 둘 다 실패한다. 강도를 일정하게 유지하면 사람은 같은 자극에 금방 무뎌지고, 끝까지 올리기만 하면 중반에 지친다. 페이싱(pacing)은 긴장을 언제 올리고 언제 풀지 정하는 일이다.

## 강도 곡선과 톱니 모양
레벨을 따라가며 예상 긴장도를 그린 것을 **강도 곡선**(intensity curve)이라 한다. 흔히 권하는 모양은 전체적으로는 오르되 구간마다 정점과 골이 있는 톱니다. 전투나 추격으로 정점에 오른 뒤 탐색·이야기·보급 구간으로 내려오고, 다음 정점은 조금 더 높다. 이완이 있어야 다음 고조가 대비로 크게 느껴지고, 플레이어가 방금 배운 것을 정리하고 자원을 채울 시간이 생긴다는 것이 흔히 알려진 설명이다.

## 몰입 채널: 실력과 도전 사이
심리학자 미하이 칙센트미하이는 『몰입』(Flow, 1990)에서 도전이 실력보다 너무 높으면 불안, 너무 낮으면 지루함이 생기고 둘이 맞을 때 몰입(flow)이 일어난다고 설명했다. 제노바 첸은 2007년 『Communications of the ACM』 글 「Flow in Games (and Everything Else)」에서 이 틀을 게임에 적용해, 잘 만든 게임은 플레이어를 각자의 몰입 영역(Flow Zone)으로 데려간다고 썼다.
```text
challenge
  ^             /     /
  |    A      /     /
  |         /     /
  |       /  F  /
  |     /     /     B
  |   /     /
  +----------------------> skill
```
A는 불안(anxiety), F는 몰입 채널, B는 지루함(boredom)이다. 실력은 플레이하며 오르므로 도전도 올라야 하고, 채널 안에서 위아래로 오가는 것이 톱니 모양이다. 문제는 채널의 위치가 사람마다 다르다는 점이다. 고정된 곡선 하나는 한 사람에게만 맞는다.

## AI 디렉터: 긴장도를 읽고 배치하기
밸브의 『레프트 4 데드』(2008)는 이 문제를 **AI 디렉터**로 풀었다. 마이크 부스가 AIIDE 2009에서 발표한 「The AI Systems of Left 4 Dead」는 AI의 목표 중 하나로 "극적인 게임 페이싱 생성"을 꼽는다. 밸브 개발자 위키의 디렉터 스크립트 문서(레프트 4 데드 2 기준)는 무리(mob)의 출현을 고조(build up) → 정점 유지(sustain peak) → 이완(relax)의 반복으로 설명하고, 무리는 고조 단계에서만 나오며, 정점에서 이완으로 넘어가려면 모든 생존자의 강도(intensity)가 문턱 아래로 내려가야 한다고 적는다.

이를 단순화해 모델을 만든다. 1초마다 강도 I가 5%씩 줄고, 적에게 맞으면 6, 적을 처치하면 1 오른다(상한 100). 디렉터는 고조 단계에서 출현 수를 점점 늘리다 I ≥ 70이면 5초간 유지하고, I < 25가 될 때까지 출현을 멈춘 뒤(감쇠), 30초 쉬고 다시 고조로 간다. 이 값들은 모델에서 고른 것이지 밸브의 수치가 아니다. 실력은 1초에 적 하나를 처치할 확률로 둔다.
```python
import random

D, PEAK, CALM = 0.95, 70, 25          # 감쇠율, 정점 문턱, 이완 문턱

def tick(I, foes, skill, rng):
    """1초: 적마다 skill 확률로 처치, 살아남은 적은 0.3 확률로 명중."""
    kills = sum(rng.random() < skill for _ in range(foes))
    foes -= kills
    hits = sum(rng.random() < 0.3 for _ in range(foes))
    return min(100.0, I * D + 6 * hits + 1 * kills), foes

def run(skill, mode, seed, T=600):
    rng, I, foes, trace = random.Random(seed), 0.0, 0, []
    phase, timer = "BUILD", 0
    for t in range(T):
        if mode == "fixed":              # 60초마다 같은 자리에서 30마리
            spawn = 30 if t % 60 == 30 else 0
        else:                            # 단순화한 디렉터
            if phase == "BUILD":
                timer += 1
                if I >= PEAK:
                    phase, timer = "SUSTAIN", 5
            elif phase == "SUSTAIN":
                timer -= 1
                if timer == 0:
                    phase = "FADE"
            elif phase == "FADE" and I < CALM:
                phase, timer = "RELAX", 30
            elif phase == "RELAX":
                timer -= 1
                if timer == 0:
                    phase, timer = "BUILD", 0
            spawn = {"BUILD": 1 + timer // 10, "SUSTAIN": 1}.get(phase, 0)
        I, foes = tick(I, foes + spawn, skill, rng)
        trace.append(I)
    return trace

def stats(tr):
    peaks = sum(a < PEAK <= b for a, b in zip([0] + tr, tr))
    return (sum(x >= PEAK for x in tr) / len(tr),
            sum(x < 20 for x in tr) / len(tr), peaks)

for mode in ("fixed", "director"):
    for skill in (0.25, 0.4, 0.6):
        s = [stats(run(skill, mode, seed)) for seed in range(40)]
        hi, calm, pk = (sum(v) / 40 for v in zip(*s))
        print(f"{mode:8} 실력 {skill}: 고조 {hi:.0%} 한산 {calm:.0%}"
              f" 정점 {pk:.1f}회")

def strip(tr):                         # 20초마다 최댓값을 한 글자로
    return "".join("_.-=#"[sum(max(tr[i:i + 20]) >= c
                               for c in (20, 40, 55, 70))]
                   for i in range(0, len(tr), 20))

for mode in ("fixed", "director"):
    for skill in (0.25, 0.6):
        print(mode[0].upper(), f"{skill:.2f}", strip(run(skill, mode, 1)))
```
```text
fixed    실력 0.25: 고조 27% 한산 33% 정점 10.1회
fixed    실력 0.4: 고조 14% 한산 43% 정점 9.3회
fixed    실력 0.6: 고조 2% 한산 59% 정점 2.7회
director 실력 0.25: 고조 19% 한산 38% 정점 9.0회
director 실력 0.4: 고조 12% 한산 41% 정점 9.5회
director 실력 0.6: 고조 6% 한산 43% 정점 8.5회
F 0.25 _##.##.##-##.##.##.##-##.##.##
F 0.60 _=-_#-_=-_#=.=-_-._#=.#-_=-_=-
D 0.25 ##..##..#=..##..##._##.-#=.-#=
D 0.60 .##._#=..=#-_.##._-#-_-##..##.
```
고조는 I ≥ 70인 시간, 한산은 I < 20인 시간의 비율이고, 아래 띠는 10분을 20초 칸으로 나눠 칸마다 최고 강도를 `_ . - = #`(20 미만, 40, 55, 70 미만, 70 이상)로 찍은 것이다(F는 고정, D는 디렉터). 중간 실력(0.4)에 맞춘 고정 배치는 그 사람에게는 디렉터와 비슷하지만, 서툰 사람은 무리마다 정점에 오르고 강도가 40 아래인 칸이 1분에 하나뿐이며(`##.`의 반복), 능숙한 사람은 10분 동안 정점이 2.7번뿐이고 59%를 한산하게 보낸다. 디렉터에서는 세 실력 모두 한산한 시간이 38~43%, 정점이 8.5~9.5번으로 비슷하고, D 띠는 고조와 이완이 번갈아 오는 톱니가 된다. 고조 비율이 여전히 19%와 6%로 다른 것은 이미 나온 적이 사라지지 않기 때문이다. 이 디렉터는 새 출현만 조절한다.

## 감쇠의 닫힌 식으로 휴식 길이 정하기
강도 갱신은 선형 점화식이라 닫힌 식이 있다. 매초 같은 이득 g를 받으면 다음과 같고, 상한 100은 마지막에 min으로 씌우면 된다(수열이 한 방향으로만 움직이기 때문이다).
```text
I_t = I₀·dᵗ + g·(1 − dᵗ)/(1 − d)
평형값 = g/(1 − d)
반감기 = ln 0.5 / ln d
```
앞 코드에 이어서, 1초씩 갱신한 값과 닫힌 식을 무작위 300개로 대조하고, 정점(100)에서 이완 문턱(25)까지 걸리는 시간을 식과 시뮬레이션으로 각각 구한다.
```python
import math

def simulate(I, d, g, t):             # 정의 그대로: 1초씩 갱신
    for _ in range(t):
        I = min(100.0, I * d + g)
    return I

def closed(I0, d, g, t):              # 등비급수의 합 + 상한
    return min(100.0, I0 * d**t + g * (1 - d**t) / (1 - d))

rng, ok = random.Random(5), 0
for _ in range(300):
    d, g = rng.uniform(0.8, 0.99), rng.uniform(0, 6)
    t, I0 = rng.randint(1, 200), rng.uniform(0, 100)
    ok += abs(simulate(I0, d, g, t) - closed(I0, d, g, t)) < 1e-9
print(f"무작위 300개 비교: {ok}개 일치")

I, t = 100.0, 0                       # 정점에서 이완 문턱까지
while I >= CALM:
    I, t = I * D, t + 1
print("식:", math.ceil(math.log(CALM / 100) / math.log(D)), "초",
      " 시뮬레이션:", t, "초")
print("반감기", round(math.log(0.5) / math.log(D), 1), "초,",
      "초당 이득 3.5의 평형", round(3.5 / (1 - D), 1))
```
```text
무작위 300개 비교: 300개 일치
식: 28 초  시뮬레이션: 28 초
반감기 13.5 초, 초당 이득 3.5의 평형 70.0
```
설계에 바로 쓰이는 숫자가 나온다. 감쇠율 0.95에서 강도가 상한 100까지 올랐다면 출현을 멈춰도 이완 문턱 아래로 내려가는 데 28초가 걸린다. 감쇠 단계를 시간으로 정한다면 그보다 짧게 잡을 때 플레이어는 아직 긴장한 채로 다음 고조를 맞는다. 그리고 평형값이 g/(1 − d) = 20g이므로, 초당 이득 3.5만큼 꾸준히 흘러드는 적은 플레이어를 정점 문턱 70에 계속 붙잡아 둔다. 큰 무리가 없어도 끊이지 않는 잔챙이가 휴식을 지운다는 뜻이다. 이완 구간은 "적을 줄이는 것"이 아니라 "출현을 멈추는 것"으로 만들어야 한다.

## 휴식 구간: 세이브 룸이 하는 일
시간으로 정하는 이완 대신 공간으로 이완을 보장하는 방법이 **휴식 구간**이다. 『레프트 4 데드』에서는 안전실(safe room)이 챕터 사이를 잇는다. 한 챕터는 안전실에 들어가며 끝나고, 다음 챕터는 그 안전실의 문을 열며 시작한다. 휴식 구간은 몇 가지 일을 한꺼번에 한다.
- 적이 들어오지 않는 공간이라 강도가 확실히 0 쪽으로 내려간다(모델의 이완 30초를 공간으로 바꾼 것).
- 저장이나 체크포인트가 있으면 실패의 비용이 줄어서, 다음 구간의 정점을 더 높게 잡아도 플레이어가 받아들인다.
- 보급으로 자원을 채워 다음 고조를 준비하게 하고, 문을 여는 순간이 다음 고조의 신호가 된다.

## 모델이 말해 주지 않는 것
- 강도 I는 피격과 처치 횟수로 만든 대리 지표일 뿐이다. 실제 긴장은 소리, 조명, 시야, 불확실성, 이야기에서도 온다. 가중치 6과 1, 감쇠율 0.95는 모델에서 고른 값이고 플레이테스트로 다시 맞춰야 한다.
- 모델에서는 디렉터가 실력 차이를 상당 부분 흡수했지만, 이미 나온 적, 보스, 손으로 짠 연출 구간은 조절하지 못한다. 실무에서는 손으로 만든 장면과 동적 배치를 섞는다.
- 조절이 눈에 띄면 "게임이 봐준다"는 느낌을 준다. 숨김 조절의 장단점은 8편에서 다룬다.
- 시뮬레이션은 리듬의 모양을 비교하게 해 줄 뿐 재미를 증명하지 않는다.

## 정리
- 페이싱은 고조와 이완이 번갈아 오며 전체적으로 오르는 톱니 모양으로 설계하고, 이완은 출현을 멈춰서 만든다.
- 몰입 채널은 사람마다 위치가 달라서 고정 배치는 한 실력에만 맞는다. 모델에서 고정 배치는 능숙한 플레이어에게 10분간 정점 2.7번, 디렉터는 실력과 관계없이 8.5~9.5번을 줬다.
- 강도 갱신의 닫힌 식은 시뮬레이션과 300개 모두 일치했고, 상한에서 이완 문턱까지 걸리는 시간(28초)과 플레이어를 정점에 묶어 두는 평형값(20g)을 알려 준다.
