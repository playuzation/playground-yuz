# [레벨 디자인과 콘텐츠 제공 7/16] 전투 공간 설계: 엄폐, 고저차, 스폰 배치

> **한 줄 요약** — 전투 공간의 질은 "여기 서면 몇 곳에서 보이는가"로 잴 수 있어서, 칸마다 노출도를 계산해 히트맵으로 보면 엄폐물과 고지대가 선택지를 만드는지, 스폰 지점이 안전하고 공정한지를 숫자로 점검할 수 있다.

## 이 글에서 다루는 것
- 트인 들판과 일자 복도가 둘 다 나쁜 전투 공간인 이유
- 엄폐물·고저차·측면 우회로가 만드는 선택지와 교전 거리
- 칸마다 노출도 계산: 무차별 시야 판정 대 상대 위치별 배열 계산, ASCII 히트맵
- 스폰 지점의 안전 점수와 스폰 킬, 대칭 맵 대 비대칭 맵

## 들판과 복도 사이
아무것도 없는 들판에서는 먼저 본 쪽이 이기고, 어디에 설지 고민할 이유가 없으니 조준 실력만 남는다. 반대로 일자 복도에서는 앞으로 가거나 물러나는 것 말고 할 일이 없고, 한쪽이 입구를 지키면 교착된다. 좋은 전투 공간은 서 있을 자리마다 득실이 다르다. **엄폐물**(cover) 뒤는 안전하지만 시야가 좁고, **고지대**(high ground)는 멀리 보지만 오르는 길이 드러나고, **측면 우회로**(flank route)는 길지만 상대의 엄폐물이 막지 못하는 방향으로 데려간다. 공간의 크기는 무기의 **교전 거리**(engagement distance)와 함께 정한다. 사거리보다 넓게 트인 곳은 저격전이 되고, 사거리보다 좁은 방은 근접전이 된다.

## 노출도: 몇 곳에서 보이는가
이런 득실을 숫자로 보려고 칸 c의 **노출도**(exposure)를 "교전 거리 R 안에서 c를 볼 수 있는 칸의 수"로 정의한다. 반대로 c에서 볼 수 있는 칸의 수는 시야라고 부른다. 지도는 가로 30, 세로 11이고 `#`은 벽, `o`는 낮은 엄폐물(설 수 없음), `^`는 고지대, `A`·`B`는 두 팀의 스폰, `.`은 바닥이다. 180° 돌리면 같은 점대칭 맵이다. 시선은 두 칸 중심을 잇는 단순한 DDA 직선으로 긋는다(브레젠험과 섀도캐스팅의 비교는 2편에서 다룬다). 규칙은 둘이다. 벽은 모든 시선을 막는다. 표적 바로 앞의 낮은 엄폐물은 평지에서 보는 시선을 막지만, 고지대에서는 넘겨 본다.

무차별 방법은 칸 쌍마다 선을 긋고 지나는 칸을 하나씩 확인한다. 빠른 방법은 상대 위치가 같은 시선은 모양도 같다는 점을 쓴다. 상대 위치 (dr, dc)마다 선을 한 번만 긋고, 그 상대 위치에 있는 모든 (시점, 표적) 쌍을 배열을 밀어 겹치는 연산으로 한꺼번에 판정한다. 이 블록은 numpy를 쓴다.
```python
import numpy as np

MAP = """\
....#....^^^o............#....
....#....^^^o....o...#........
..o......oooo........#.....o..
........o.............o.......
A..#.......##....##.......#..B
A..#...o....#....#....o...#..B
A..#.......##....##.......#..B
.......o.............o........
..o.....#........oooo......o..
........#...o....o^^^....#....
....#............o^^^....#....""".split("\n")
H, W, R = len(MAP), len(MAP[0]), 8     # R: 교전 거리
LINES = [0]

def mid(dr, dc):                       # 시선이 지나는 중간 칸(상대 좌표)
    LINES[0] += 1
    n = max(abs(dr), abs(dc))
    return [(round(i * dr / n), round(i * dc / n)) for i in range(1, n)]

def cell(m, r, c):
    return m[r][c] if 0 <= r < H and 0 <= c < W else "#"

def sees(m, v, t):                     # 정의 그대로: v에서 t가 보이나
    dr, dc = t[0] - v[0], t[1] - v[1]
    if dr * dr + dc * dc > R * R:
        return False
    path = [cell(m, v[0] + a, v[1] + b) for a, b in mid(dr, dc)]
    if "#" in path:
        return False                   # 벽은 모든 시선을 막는다
    low = path and path[-1] == "o"     # 표적 바로 앞의 낮은 엄폐물
    return not (low and cell(m, *v) != "^")    # 고지대는 넘겨 본다

def stand(m):
    return [(r, c) for r in range(H) for c in range(W) if m[r][c] not in "#o"]

def brute(m):                          # 칸 쌍마다 선을 긋는다
    cells = stand(m)
    return {t: sum(sees(m, v, t) for v in cells if v != t) for t in cells}

def fast(m):                           # 상대 위치마다 격자 전체를 한 번에
    g = np.array([list(row) for row in m])
    wall = np.pad(g == "#", R, constant_values=True)
    low = np.pad(g == "o", R, constant_values=False)
    high = np.pad(g == "^", R, constant_values=False)
    ok = ~wall & ~low
    at = lambda M, a, b: M[R + a:R + a + H, R + b:R + b + W]
    exp = np.zeros((H, W), int)
    for dr in range(-R, R + 1):
        for dc in range(-R, R + 1):
            if (dr, dc) == (0, 0) or dr * dr + dc * dc > R * R:
                continue               # 시점은 표적에서 (-dr, -dc)
            vis = at(ok, 0, 0) & at(ok, -dr, -dc)
            ks = mid(dr, dc)
            for a, b in ks:
                vis &= ~at(wall, a - dr, b - dc)
            if ks:
                a, b = ks[-1]
                vis &= ~(at(low, a - dr, b - dc) & ~at(high, -dr, -dc))
            exp += vis
    return exp

B = brute(MAP)
n_brute = LINES[0]
F = fast(MAP)
print("무차별과 일치:", all(F[t] == e for t, e in B.items()),
      f"(선 계산 {n_brute}번 대 {LINES[0] - n_brute}번)")
for r in range(H):
    print("".join(ch if ch in "#o" else str(min(9, F[r, c] // 10))
                  for c, ch in enumerate(MAP[r])))
```

두 방법은 모든 칸에서 같은 값을 냈다. 선은 27,772번 대 196번 긋고, 이 환경에서 재 보면 약 0.07초 대 0.003초다. 맵 에디터에서 벽을 옮길 때마다 히트맵을 다시 그리려면 이 차이가 중요하다.

히트맵의 숫자는 노출도를 10으로 나눈 몫(0~9)이다. 트인 중앙은 7~9가 이어지고, 구석과 벽 뒤쪽은 3~5, 고지대에서 난간(`o`) 바로 안쪽 칸은 2까지 떨어진다. 플레이어는 이 숫자를 모르지만 몸으로 느낀다. 8~9가 넓게 이어진 곳은 "건너야 하는 사선"이고, 그 사이사이의 낮은 숫자가 다음 엄폐물까지 뛰어갈 징검다리가 된다. 징검다리 간격은 1편의 이동 속도로 정한다.

## 고지대, 스폰, 대칭
앞 코드에 이어서, 고지대와 평지의 시야·노출도를 비교하고, 스폰 후보 다섯 곳(S1 기본 스폰, S2·S3 구석, S4 고지대, S5 중앙 쪽)을 적 위치 두 가지에서 평가한다. 안전 점수는 `가장 가까운 적까지 걸음 수 − 10 × 나를 보는 적 수`로 두고, 점수 순으로 `후보(나를 보는 적 수, 걸음 수)`를 찍는다. 마지막으로 맵의 대칭을 확인하고, B팀 난간 한 줄만 지운 비대칭 맵과 비교한다.
```python
from collections import deque

def avg(xs):
    return round(sum(xs) / len(xs), 1)

cells = stand(MAP)
for name, g in (("고지대", [t for t in cells if MAP[t[0]][t[1]] == "^"]),
                ("평지", [t for t in cells if MAP[t[0]][t[1]] != "^"])):
    see = avg([sum(sees(MAP, v, t) for t in cells if t != v) for v in g])
    print(f"{name}: 보는 칸 {see}, 보이는 칸 {avg([F[t] for t in g])}")

def bfs(m, s):                         # 걸어서 가는 거리
    d, q = {s: 0}, deque([s])
    while q:
        r, c = q.popleft()
        for nr, nc in ((r + 1, c), (r - 1, c), (r, c + 1), (r, c - 1)):
            if cell(m, nr, nc) not in "#o" and (nr, nc) not in d:
                d[nr, nc] = d[r, c] + 1
                q.append((nr, nc))
    return d

spawns = {"S1": (5, 0), "S2": (0, 0), "S3": (10, 0), "S4": (1, 10),
          "S5": (8, 5)}
for name, foes in (("중앙 대치", [(3, 15), (7, 16), (5, 20), (9, 19), (0, 18)]),
                   ("A 진영 압박", [(2, 6), (7, 4), (5, 9), (9, 10), (0, 14)])):
    dist = [bfs(MAP, f) for f in foes]
    rank = []
    for s, p in spawns.items():
        seen = sum(sees(MAP, f, p) for f in foes)   # 나를 보는 적 수
        near = min(d[p] for d in dist)              # 가장 가까운 적
        rank.append((near - 10 * seen, s, seen, near))
    print(name + ":", " ".join(f"{s}({k},{d})"
                               for _, s, k, d in sorted(rank, reverse=True)))

def high_exposure(m, Fm):
    hs = [t for t in stand(m) if m[t[0]][t[1]] == "^"]
    return avg([Fm[t] for t in hs if t[1] < W // 2]), \
        avg([Fm[t] for t in hs if t[1] >= W // 2])

print("점대칭 맵의 노출도도 점대칭:", bool((F == F[::-1, ::-1]).all()))
print("고지대 노출 A, B:", *high_exposure(MAP, F))
M2 = MAP[:8] + [MAP[8][:17] + "...." + MAP[8][21:]] + MAP[9:]
print("B 난간 제거 후:", *high_exposure(M2, fast(M2)))
```
```text
고지대: 보는 칸 82.2, 보이는 칸 53.8
평지: 보는 칸 66.5, 보이는 칸 67.7
중앙 대치: S3(0,21) S2(0,20) S1(0,19) S5(0,14) S4(1,15)
A 진영 압박: S2(0,8) S3(1,7) S1(1,6) S4(2,5) S5(3,2)
점대칭 맵의 노출도도 점대칭: True
고지대 노출 A, B: 53.8 53.8
B 난간 제거 후: 53.8 77.0
```
**고저차의 이점**이 숫자로 보인다. 고지대는 평균 82.2칸을 보면서 53.8칸에서만 보인다(1.5배). 평지는 보는 칸과 보이는 칸이 거의 같다. 이 이점은 "위에서는 난간 너머를 보고, 아래에서는 난간에 가려 안 보인다"는 비대칭 규칙에서 나온다. 그래서 고지대는 공짜로 주면 안 된다. 오르는 길을 드러나게 하거나 길게 만들고, 고지대를 옆에서 칠 수 있는 측면 우회로를 둔다.

스폰 순위는 적 위치에 따라 바뀐다. 적이 중앙에 있을 때는 S1~S3가 모두 안전하지만, 적이 A 진영으로 밀고 들어오면 안전한 곳은 S2 하나뿐이고 S5는 적 3명에게 보이고 두 걸음 거리다. 여기서 되살아나면 움직이기도 전에 죽는 **스폰 킬**(spawn kill)이 된다. 그래서 많은 멀티플레이어 게임은 스폰 지점을 고정하지 않고 후보마다 점수를 매겨 고른다는 것이 흔히 알려진 설명이다. 디자이너가 그 점수에 손을 대게 하는 도구도 있다. 서튼 어피니티(Certain Affinity)가 『헤일로 2 애니버서리』의 맵 편집 도구 포지(Forge)로 게임 모드를 만드는 법을 설명한 글에는, 리스폰 금지 구역(anti-respawn zone)을 놓아 건물 안이나 난간, 점령 지점 위에서 되살아나지 않게 하는 예가 나온다.

대칭 맵에서는 노출도도 정확히 점대칭이 됐다. 시선을 긋는 반올림이 0을 중심으로 대칭이라(`round(−x) = −round(x)`) 180° 돌린 시선이 돌린 칸들을 그대로 지나기 때문이다. 두 팀이 같은 기회를 가진다는 것이 계산으로 확인된다. 반면 B팀 고지대의 난간 한 줄(4칸)을 지우자 B 고지대의 노출도만 53.8에서 77.0으로 뛰었다. 작은 수정 하나가 한쪽만 약하게 만든다. 공격과 수비가 나뉜 모드처럼 일부러 비대칭으로 만드는 맵도 있는데, 그때는 이런 진영별 수치와 실제 승률로 균형을 따로 확인해야 한다.

## 실무에서의 의미와 한계
- 모델은 2D 격자에 높이가 두 단계뿐이다. 실제 3D 맵에는 부분 엄폐, 앉기, 머리만 내미는 자리, 시야각과 소리가 있다.
- 노출도는 모든 칸을 같은 무게로 센다. 실제 위협은 적이 자주 서는 곳에서 오므로, 15편의 텔레메트리(사망 위치 히트맵)로 무게를 매기는 편이 낫다.
- 스폰 점수의 가중치 10은 모델에서 고른 값이다. 실제 시스템은 아군과의 거리, 목표 지점, 직전 스폰 위치 같은 항목도 함께 본다.
- 숫자는 공간의 득실을 비교하게 해 줄 뿐, 그 전투가 재미있는지는 플레이테스트로만 알 수 있다.

## 정리
- 전투 공간은 칸마다 노출도(몇 곳에서 보이는가)와 시야를 계산하면 들판·복도·엄폐 지대를 숫자로 구별할 수 있다.
- 상대 위치별 배열 계산은 무차별 시야 판정과 모든 칸에서 일치했고, 선 계산은 27,772번에서 196번으로 줄었다.
- 모델에서 고지대는 보는 칸이 보이는 칸의 1.5배였고, 스폰의 안전 순위는 적 위치에 따라 바뀌었다.
- 점대칭 맵은 노출도도 점대칭이었고, 난간 한 줄을 지우자 한쪽 고지대의 노출도만 77.0으로 올랐다.
