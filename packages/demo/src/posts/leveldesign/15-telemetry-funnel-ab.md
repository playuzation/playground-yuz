# [레벨 디자인과 콘텐츠 제공 15/16] 데이터로 판단하기: 텔레메트리, 퍼널, 히트맵, A/B 테스트

> **한 줄 요약** — 질문에 필요한 플레이 이벤트만 최소한으로 기록하면 레벨 퍼널과 사망 히트맵으로 어디서 막히는지 볼 수 있고, 레벨을 고친 효과는 A/B 테스트로 판단하되 집계와 검정은 정답·정확 검정·A/A 실험과 맞춰 보아야 하며, 왜 막히는지는 플레이테스트 관찰로만 알 수 있다.

## 이 글에서 다루는 것
- 이벤트 로그 설계: 무엇을 기록하고 무엇을 기록하지 않나
- 가상 플레이 로그로 만드는 레벨 퍼널과 사망 위치 히트맵
- 중복 전송을 지우지 않으면 퍼널이 부푼다: 정답·공식과 대조
- 레벨 변경의 A/B 테스트: 정규 근사 대 정확 검정, A/A 300번
- 데이터가 말해 주지 않는 것

## 문제: 출시 후에는 플레이어 옆에 앉을 수 없다
개발 중에는 플레이테스터 옆에서 어디서 헤매는지 볼 수 있지만, 출시 후에는 수만 명이 각자 집에서 논다. 리뷰와 커뮤니티 글은 목소리 큰 일부의 의견이다. **텔레메트리**(telemetry)는 게임이 플레이 중 일어난 일을 이벤트로 기록해 서버로 보내는 것이고, 이것으로 "몇 명이 어디까지 갔고 어디서 죽었나"를 셀 수 있다. 5편의 긴장 곡선, 6편의 학습 곡선, 7편의 노출도가 설계 단계의 모델이었다면, 텔레메트리는 모델이 실제와 맞는지 확인하는 수단이다.

## 이벤트 로그 설계
질문을 먼저 정하고 답에 필요한 이벤트만 기록한다. "어느 방에서 그만두나"와 "어디서 죽나"가 질문이라면 필드 몇 개면 된다.

| 필드 | 내용 |
|---|---|
| sid, seq | 가명 세션 ID, 세션 안 순번 |
| ev | start, death, clear |
| room, x, y | 방 번호와 칸 좌표 |

- 이름·이메일·기기 고유 번호 같은 개인정보는 넣지 않는다. 분석에는 계정과 분리된 가명 ID로 충분하다. 유럽 GDPR 5조 1항 (c)의 데이터 최소화 원칙은 개인 데이터가 처리 목적에 비추어 적절하고 관련 있으며 필요한 범위로 제한되어야 한다고 정한다(영국 ICO 안내). 법적 판단은 관할 규정과 전문가의 몫이고, 설계 습관으로는 "질문에 필요 없는 필드는 모으지 않고, 보관 기간을 정한다"면 된다.
- 클라이언트는 이벤트를 모아 보내고 네트워크가 끊기면 다시 보내므로, 같은 이벤트가 두 번 오고 도착 순서도 섞인다. 세션 안 순번이 있어야 중복을 지울 수 있다.
- 패치로 방 번호가 바뀌면 이전 데이터와 섞이지 않게 이벤트에 버전을 붙인다.

## 가상 플레이 로그 만들기
방 네 개짜리 레벨을 4,000 세션이 플레이한다. 방마다 위험 지점과 실패 확률이 있고, 죽으면 20% 확률로 그만둔다. 이벤트는 3% 확률로 두 번 전송되고 순서가 뒤섞인다. 생성기는 세션마다 실제로 통과한 방 수(정답)를 따로 돌려준다.
```python
import random
W, H, WX = 36, 9, (0, 9, 18, 27, 35)             # WX: 바깥벽과 방 사이 벽의 x
WALL = {(x, y) for x in range(W) for y in range(H)
        if y in (0, H - 1) or x in WX}
WALL -= {(9, 2), (18, 6), (27, 3)}               # 문
ROOMS = [(6, 2, 0.10), (13, 5, 0.30), (23, 4, 0.45), (31, 4, 0.35)]
QUIT = 0.2                                       # 죽은 뒤 그만둘 확률

def play(sid, rng, rooms, dup=0.03):
    """한 세션의 이벤트 로그와 정답(통과한 방 수)을 함께 돌려준다"""
    log, seq = [], 0
    def emit(ev, **kw):
        nonlocal seq
        e = dict(sid=sid, seq=seq, ev=ev, **kw)
        seq += 1
        log.extend([e] * (2 if rng.random() < dup else 1))  # 중복 전송
    emit("start")
    for room, (hx, hy, fail) in enumerate(rooms):
        while rng.random() < fail:               # 이번 시도에서 죽음
            x, y = 0, 0
            while not (WX[room] < x < WX[room + 1] and 0 < y < H - 1):
                x, y = round(rng.gauss(hx, 1.2)), round(rng.gauss(hy, 1.0))
            emit("death", room=room, x=x, y=y)   # 위험 지점 근처
            if rng.random() < QUIT:
                rng.shuffle(log)                 # 도착 순서는 뒤섞인다
                return log, room
        emit("clear", room=room)
    rng.shuffle(log)
    return log, len(rooms)

rng = random.Random(15)
logs, truth = [], []
for sid in range(4000):
    lg, cleared = play(sid, rng, ROOMS)
    logs += lg
    truth.append(cleared)
print("이벤트", len(logs), "개, 예:", logs[0])
```
```text
이벤트 23981 개, 예: {'sid': 0, 'seq': 1, 'ev': 'death', 'room': 0, 'x': 6, 'y': 1}
```

## 퍼널과 히트맵
**퍼널**(funnel)은 단계마다 남은 인원을 센 것이다. 앞 코드에 이어서 방마다 통과한 세션을 중복을 지우기 전과 후로 세어 정답, 공식과 비교한다. 실패 확률 f, 그만둘 확률 Q일 때 한 방에서 그만둘 확률은 죽고 다시 하는 시도를 등비급수로 더한 `Qf / (1 − (1 − Q)f)`다. 이어서 사망 위치를 칸별로 세어 히트맵을 그린다. `#`은 벽, `.`은 사망이 없는 바닥, 숫자 1~9는 가장 많이 죽은 칸을 9로 둔 사망 밀도다.
```python
uniq = list({(e["sid"], e["seq"]): e for e in logs}.values())  # 중복 제거

def funnel(events):                              # 방마다 통과한 세션 수
    c = [0] * len(ROOMS)
    for e in events:
        if e["ev"] == "clear":
            c[e["room"]] += 1
    return c

naive, dedup, reach = funnel(logs), funnel(uniq), 4000
for r, (_, _, f) in enumerate(ROOMS):
    reach *= 1 - QUIT * f / (1 - (1 - QUIT) * f)   # 방에서 그만둘 확률
    print(f"방{r + 1} 통과: 단순 {naive[r]}, 중복 제거 {dedup[r]},",
          f"정답 {sum(t > r for t in truth)}, 공식 {reach:.0f}")
cnt = {}
for e in uniq:
    if e["ev"] == "death":
        cnt[e["x"], e["y"]] = cnt.get((e["x"], e["y"]), 0) + 1
top = max(cnt.values())
for y in range(H):                               # 1~9 = 사망 밀도(9가 최대)
    print("".join("#" if (x, y) in WALL else "." if (x, y) not in cnt
                  else str(-(-9 * cnt[x, y] // top)) for x in range(W)))
```

방4 통과: 단순 2848, 중복 제거 2765, 정답 2765, 공식 2796

#..112221...111...#11122211#1112111#
#.1111121#.11211..#.1256521.1134321#

단순 집계는 정답보다 2.5~3.4% 많다. 이 오차는 방 사이의 실제 차이와 섞여 판단을 흐린다. 중복을 지운 집계는 네 방 모두 정답과 정확히 같고, 공식과는 표본 오차 수준(최대 1.3%)으로 맞는다. 가장 크게 빠지는 곳은 방3(3,591 → 3,057, 15% 이탈)이고 히트맵에서도 방3 가운데가 9로 가장 진하다. 퍼널은 "어느 단계"를, 히트맵은 "그 단계의 어디"를 알려 준다. 마이크로소프트의 사용자 연구팀이 헤일로 3 개발 중 플레이테스터의 이동 경로를 지도에 모아 본 일은 와이어드의 2007년 기사(클라이브 톰프슨)로 알려졌고, NPR 보도에 따르면 이 팀은 고속도로 구간 밖으로 날아가 죽는 플레이어가 너무 많자 방벽을 세웠다.

## A/B 테스트로 변경 효과 판단하기
방3에 엄폐물을 더해 실패 확률을 0.45에서 0.38로 낮춘 변경안 B를 생각하자. 통계학 7편처럼 세션을 무작위로 나누고 지표는 "방3에 들어온 세션 중 거기서 그만둔 비율"로 미리 정한다. 앞 코드에 이어서, 차이를 정규 근사 z 검정과 초기하 분포를 그대로 더한 정확 검정(피셔의 정확 검정)으로 따로 계산하고, 차이가 없는 A/A 실험 300번에서 거짓 양성이 5% 근처인지 본다.
```python
from math import comb, erfc, sqrt

def room3(rooms, n, seed):                       # 방3에 들어온 세션, 거기서 그만둔 세션
    rng, came, quit = random.Random(seed), 0, 0
    for sid in range(n):
        ev = {(e["ev"], e.get("room")) for e in play(sid, rng, rooms)[0]}
        came += ("clear", 1) in ev
        quit += ("clear", 1) in ev and ("clear", 2) not in ev
    return quit, came

def ztest(a, na, b, nb):                         # 정규 근사, 양측 p값
    p = (a + b) / (na + nb)
    z = (a / na - b / nb) / sqrt(p * (1 - p) * (1 / na + 1 / nb))
    return erfc(abs(z) / sqrt(2))

def exact(a, na, b, nb):                         # 초기하 분포로 정확한 양측 p값
    k = a + b
    pr = [comb(na, x) * comb(nb, k - x) / comb(na + nb, k)
          for x in range(k + 1)]
    return sum(q for q in pr if q <= pr[a] * (1 + 1e-9))

B = ROOMS[:2] + [(23, 4, 0.38)] + ROOMS[3:]     # 변경안: 방3에 엄폐물 추가
a, na = room3(ROOMS, 1500, 1)
b, nb = room3(B, 1500, 2)
print(f"방3 이탈 A {a}/{na} = {a / na:.1%}, B {b}/{nb} = {b / nb:.1%}")
print(f"z 검정 p = {ztest(a, na, b, nb):.4f},",
      f"정확 검정 p = {exact(a, na, b, nb):.4f}")
rng, hits = random.Random(3), [0, 0]
for _ in range(300):                             # A/A: 둘 다 이탈률 14%
    x, y = (sum(rng.random() < 0.14 for _ in range(1000)) for _ in "ab")
    hits[0] += ztest(x, 1000, y, 1000) < 0.05
    hits[1] += exact(x, 1000, y, 1000) < 0.05
print(f"A/A 300번 중 p < 0.05: z 검정 {hits[0]}번, 정확 검정 {hits[1]}번")
```
```text
방3 이탈 A 186/1333 = 14.0%, B 148/1352 = 10.9%
z 검정 p = 0.0183, 정확 검정 p = 0.0193
A/A 300번 중 p < 0.05: z 검정 19번, 정확 검정 19번
```
이탈률이 14.0%에서 10.9%로 줄었고 두 검정의 p값은 0.018과 0.019로 거의 같다. 이 정도 표본이면 정규 근사로 충분하고, 표본이 작거나 이탈이 드문 단계라면 정확 검정을 쓴다. A/A에서는 300번 중 19번(6.3%)이 우연히 유의해, 약속한 5%와 표본 오차(±1.3%p) 안에서 맞는다. 검정 코드를 믿기 전에 A/A로 확인하는 습관은 실제 실험 파이프라인에서도 유용하다.

## 데이터가 말해 주지 않는 것
- 왜 그만뒀는지는 로그에 없다. 어려워서인지, 길을 못 찾아서인지, 저녁을 먹으러 간 것인지가 같은 이벤트로 남는다. 플레이테스트에서 직접 관찰하고, 생각을 말하며 플레이하게(think-aloud) 하고, 끝난 뒤 물어야 안다.
- 많이 죽는 곳이 나쁜 곳은 아니다. 보스방의 높은 사망률은 의도일 수 있다. 기준은 사망 수가 아니라 의도한 난이도와 이탈의 관계다.
- 측정한 것만 좋아진다. 이탈률만 보고 방3을 계속 쉽게 만들면 퍼널은 좋아져도 긴장이 사라질 수 있다(5편). 완료 시간이나 재도전 비율 같은 보조 지표를 함께 본다.
- 모델의 플레이어는 실력이 모두 같지만 실제로는 다르고, 남은 사람만 다음 방에 오므로 뒤쪽 방의 지표는 걸러진 집단의 것이다(14편의 잔존율과 같은 이유).

## 정리
- 질문을 먼저 정하고, 답에 필요한 이벤트만 가명 ID로 기록하며 보관 기간을 정한다.
- 퍼널은 어느 단계에서, 히트맵은 그 단계의 어디에서 막히는지 보여 주고, 중복 전송을 지우지 않으면 수치가 부푼다.
- 레벨 변경 효과는 A/B 테스트로 판단하고, 검정 계산은 정확 검정과 A/A 실험으로 따로 확인한다.
- 데이터는 무엇이 일어났는지를, 플레이테스트 관찰은 왜 일어났는지를 알려 준다.
