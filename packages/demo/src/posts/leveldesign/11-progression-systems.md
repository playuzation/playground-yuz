## 진행 시스템이 푸는 문제
1부의 레벨 디자인이 공간 속의 경험을 설계했다면, **진행 시스템**(progression system)은 시간 속의 경험을 설계한다. 플레이어는 "지금 무엇을 향해 가고 있나"를 알아야 계속하고, 그 목표가 너무 가까우면 의미가 없고 너무 멀면 지친다. 순진한 방법은 레벨마다 같은 경험치를 요구하는 것인데, 그러면 후반의 적과 보상이 커질수록 레벨업이 점점 빨라져 성장이 싱거워진다. 반대로 감으로 "레벨마다 조금씩 더"를 정하면, 50레벨이 30레벨보다 몇 배 먼지 아무도 모른 채 출시된다. 곡선은 숫자 몇 개로 미리 계산할 수 있다.

## 경험치 곡선: 선형, 제곱, 지수
레벨 L에서 L + 1로 가는 데 필요한 경험치를 `need(L)`이라 하면, n레벨에 닿기까지의 누적 경험치는 그 합이다. 다항 곡선의 대표로 제곱을 쓰면, 세 가지 모양의 합에는 모두 닫힌 식이 있다.
```text
S(n) = need(1) + … + need(n − 1)
m = n − 1이라 두면
선형 need = a·L
  S = a·m(m + 1)/2
제곱 need = a·L²
  S = a·m(m + 1)(2m + 1)/6
지수 need = a·r^(L − 1)
  S = a·(rᵐ − 1)/(r − 1)
```
아래 코드는 분수로 정확히 계산해 닫힌 식과 정의대로의 합을 비교한다. 그다음 세 곡선 모두 "30레벨까지 20시간"이 되도록 a를 맞추고(경험치 획득 속도는 일정하다고 둔다), 레벨별 도달 시간과 레벨업 간격을 본다. 지수 곡선의 r은 1.1이다.
```python
from fractions import Fraction as F

def need(kind, L):                         # L → L+1에 필요한 경험치(a = 1)
    return {"선형": F(L), "제곱": F(L * L), "지수": F(11, 10) ** (L - 1)}[kind]

def total_loop(kind, n):                   # 정의대로: n레벨까지의 누적
    return sum(need(kind, L) for L in range(1, n))

def total_closed(kind, n):                 # 닫힌 식
    m = n - 1
    if kind == "선형":
        return F(m * (m + 1), 2)
    if kind == "제곱":
        return F(m * (m + 1) * (2 * m + 1), 6)
    r = F(11, 10)
    return (r ** m - 1) / (r - 1)          # 등비수열의 합

kinds = ["선형", "제곱", "지수"]
print("닫힌 식과 일치:", all(total_loop(k, n) == total_closed(k, n)
                         for k in kinds for n in range(1, 80)))
HOURS = 20                                 # 30레벨까지 20시간이 되도록 맞춘다
hours = lambda k, n: float(HOURS * total_closed(k, n) / total_closed(k, 30))
print("열: 레벨, 도달 시간(시간) 선형·제곱·지수")
for n in (5, 10, 20, 30, 40, 50):
    print(f"{n:>3}", *(f"{hours(k, n):6.1f}" for k in kinds))
for k in kinds:                            # 한 레벨에 걸리는 분
    m = [round(60 * (hours(k, n + 1) - hours(k, n))) for n in (2, 29, 49)]
    print(f"{k} 레벨업 간격(분): 2→3 {m[0]}, 29→30 {m[1]}, 49→50 {m[2]}")
```
```text
닫힌 식과 일치: True
열: 레벨, 도달 시간(시간) 선형·제곱·지수
  5    0.5    0.1    0.6
 10    2.1    0.7    1.8
 20    8.7    5.8    6.9
 30   20.0   20.0   20.0
 40   35.9   48.0   54.0
 50   56.3   94.5  142.3
선형 레벨업 간격(분): 2→3 6, 29→30 80, 49→50 135
제곱 레벨업 간격(분): 2→3 1, 29→30 118, 49→50 337
지수 레벨업 간격(분): 2→3 9, 29→30 116, 49→50 783
```
세 곡선은 30레벨에서 만나지만 그 앞뒤는 딴판이다. 제곱 곡선은 초반 레벨업이 1분 간격이라 첫 한 시간 안에 10레벨을 넘고, 지수 곡선은 50레벨까지 142시간으로 선형의 2.5배다. 지수 곡선의 레벨업 간격은 매 레벨 10%씩 늘어 49→50에 13시간이 걸린다. "레벨 상한을 10 올리는" 업데이트가 지수 곡선에서는 플레이 시간을 몇 배로 늘린다는 뜻이다. 실제 게임은 높은 레벨일수록 적이 주는 경험치도 늘리므로, 체감되는 곡선은 `need(L) ÷ 시간당 획득량(L)`이다. 둘의 증가율이 같으면 레벨업 간격은 평평해진다.

## 실제 곡선 하나: 룬스케이프
룬스케이프(RuneScape)의 기술 레벨은 지수 곡선의 유명한 예다. 커뮤니티 위키의 경험치 표에 따르면 2레벨은 83, 99레벨은 13,034,431이고, 92레벨(6,517,253)이 99레벨의 거의 절반이다. 위키에 실린 공식으로 계산해 표의 값과 맞춰 본다.
```python
import math

def rs_xp(L):                              # 룬스케이프 위키에 실린 경험치 공식
    return sum(math.floor(l + 300 * 2 ** (l / 7)) for l in range(1, L)) // 4

table = {2: 83, 50: 101_333, 92: 6_517_253, 99: 13_034_431}  # 위키의 표
print("표와 일치:", all(rs_xp(L) == v for L, v in table.items()))
print("92레벨 / 99레벨 =", round(rs_xp(92) / rs_xp(99), 4))
d = lambda L: rs_xp(L + 1) - rs_xp(L)      # L → L+1에 필요한 경험치
print("한 레벨 사이 증가율 d(98)/d(97) =", round(d(98) / d(97), 4),
      "/ 2^(1/7) =", round(2 ** (1 / 7), 4))
```
```text
표와 일치: True
92레벨 / 99레벨 = 0.5
한 레벨 사이 증가율 d(98)/d(97) = 1.1041 / 2^(1/7) = 1.1041
```
공식의 핵심 항은 `300·2^(L/7)`로, 7레벨마다 필요 경험치가 두 배가 된다. 레벨당 약 10.4%씩 늘어나므로 마지막 7레벨이 전체의 절반을 차지한다. 이렇게 극단적인 곡선은 "99레벨"을 최상위 목표로 만들려는 선택이고, 그만큼 대부분의 플레이어는 거기에 닿지 않는다는 뜻이기도 하다. 그 비율을 세는 것이 다음 절이다.

## 해금: 시스템을 하나씩 열기
상점, 제작, 길드, 대전 같은 시스템을 처음부터 다 열면 플레이어는 무엇부터 할지 모른다. 6편의 튜토리얼처럼 하나씩 여는 **해금**(unlock)은 배울 것을 나눠 준다. 그런데 해금 레벨은 곧 "그 시스템을 보는 플레이어 비율"이다. 앞 코드에 이어서, 총 플레이 시간이 중앙값 10시간인 로그정규 분포(가정한 값)를 따른다고 두고, 지수 곡선에서 각 레벨에 닿는 비율을 정확한 식과 2만 명 모의로 구한다.
```python
# 앞 코드에 이어서
import math, random

MED, SIG = 10, 1.0                         # 총 플레이 시간: 중앙값 10시간
def reach(t):                              # 정확: P(플레이 시간 ≥ t), 로그정규
    return 0.5 * math.erfc((math.log(t) - math.log(MED)) / (SIG * math.sqrt(2)))

rng = random.Random(11)
play = [rng.lognormvariate(math.log(MED), SIG) for _ in range(20000)]
print("열: 해금 레벨, 도달 시간(시간), 도달 비율 정확, 모의")
worst = 0
for n in (3, 5, 10, 20, 30, 40):
    t = hours("지수", n)
    sim = sum(p >= t for p in play) / len(play)
    worst = max(worst, abs(sim - reach(t)))
    print(f"{n:>3} {t:6.1f} {reach(t):6.3f} {sim:6.3f}")
print(f"정확 대 모의 최대 차이 {worst:.3f}")
```
```text
열: 해금 레벨, 도달 시간(시간), 도달 비율 정확, 모의
  3    0.3  1.000  1.000
  5    0.6  0.997  0.997
 10    1.8  0.955  0.955
 20    6.9  0.646  0.641
 30   20.0  0.244  0.242
 40   54.0  0.046  0.045
정확 대 모의 최대 차이 0.004
```
10레벨에 여는 시스템은 95%가 보지만, 30레벨이면 24%, 40레벨이면 5%만 본다. 게임의 핵심 재미를 담은 시스템을 30레벨에 두면 플레이어 넷 중 셋은 그것을 모른 채 떠난다. 그래서 핵심 시스템은 앞쪽에, 깊이를 더하는 시스템은 뒤쪽에 둔다. 여기서 분포는 가정이고, 실제 분포는 15편의 텔레메트리로 잰다.

## 보상 일정: 같은 평균, 다른 경험
행동 심리학은 보상을 주는 규칙을 **강화 계획**(schedule of reinforcement)이라 부른다. 퍼스터와 스키너의 1957년 책 『Schedules of Reinforcement』가 정리한 고전 개념이다. 정해진 횟수마다 주는 고정 비율(FR, fixed ratio)과 평균만 정해 두고 매번 무작위로 주는 변동 비율(VR, variable ratio)을 같은 평균 10으로 비교한다.
```python
import random

def gaps(rewarded, n):                     # 보상 사이의 행동 수 목록
    out, last = [], 0
    for i in range(1, n + 1):
        if rewarded(i):
            out.append(i - last)
            last = i
    return out

rng, N = random.Random(4), 200_000
fr = gaps(lambda i: i % 10 == 0, N)        # 고정 비율 FR-10: 10번째마다
vr = gaps(lambda i: rng.random() < 0.1, N) # 변동 비율 VR-10: 매번 10%
for name, g in (("FR-10", fr), ("VR-10", vr)):
    print(f"{name}: 행동당 보상 {len(g) / N:.3f}, 간격 평균 "
          f"{sum(g) / len(g):.1f}, 최장 {max(g)}")
long = sum(x > 30 for x in vr) / len(vr)
print(f"VR-10 간격 > 30: 모의 {long:.4f}, 공식 0.9³⁰ = {0.9 ** 30:.4f}")
```
```text
FR-10: 행동당 보상 0.100, 간격 평균 10.0, 최장 10
VR-10: 행동당 보상 0.099, 간격 평균 10.1, 최장 105
VR-10 간격 > 30: 모의 0.0425, 공식 0.9³⁰ = 0.0424
```
기댓값은 둘 다 행동당 0.1이지만 VR의 간격은 기하 분포라서, 4% 넘는 경우에 30번 넘게 보상이 없고 최장 가뭄은 105번이었다. 교과서적 설명으로는 FR에서는 보상 직후 잠깐 쉬었다가 다시 반응하는 패턴이, VR에서는 쉬는 틈이 거의 없는 높고 꾸준한 반응이 나타난다. 게임 쪽에서 읽으면 FR의 "보상 직후"는 자연스러운 멈춤 지점이고, VR은 다음 보상이 언제 올지 몰라 멈출 지점이 사라진다.

이 차이가 남용의 출발점이다. 변동 비율을 유료 뽑기와 묶거나, 접속하지 않으면 연속 출석 보상이 처음부터 다시 시작되게 만드는 식으로 "그만둘 이유"를 지우는 설계는 플레이어의 시간과 돈을 소모시키고 신뢰를 잃는다. 반대로 진행 막대처럼 남은 양이 보이는 보상, 하루 분량이 끝났음을 알려 주는 멈춤 지점, 불운이 계속될 때 보장해 주는 장치는 플레이어가 스스로 판단할 여지를 남긴다. 무작위 보상의 확률과 보장 장치는 12편에서 수식으로 다룬다.

## 실무에서의 의미와 한계
- 곡선은 한 장의 표로 먼저 본다. 레벨 상한, 레벨업 간격, 경험치 획득량이 한 표에 있으면 업데이트가 플레이 시간을 얼마나 늘리는지 출시 전에 보인다.
- 모델의 플레이 시간 분포와 획득 속도는 가정이다. 실제 값은 텔레메트리로 다시 맞추고, 지루함은 플레이테스트에서 확인한다.
- 시즌마다 정해진 기간에 단계를 채우는 배틀 패스는 이 곡선의 특수한 경우로, 14편에서 다룬다.

## 어디에 쓰이나
- 미적분 4편 「지수 함수와 로그 함수」: 지수 곡선에서 n레벨에 닿는 시간은 대략 rⁿ에 비례하므로, 거꾸로 시간 t에 닿는 레벨은 log t에 비례한다.
- 확률과 분포 8편 「정규 분포: 종 모양 곡선의 정체」: 로그정규 플레이 시간의 로그가 정규 분포라서 도달 비율을 정규 누적 분포로 계산했다.
- 확률과 분포 6편 「이산 분포: 베르누이, 이항, 기하, 포아송」: 변동 비율 보상의 간격은 기하 분포이고, 30번 넘게 못 받을 확률이 0.9³⁰인 것도 그 꼬리다.
- 6편 「튜토리얼과 온보딩: 레벨이 가르치게 하기」: 해금은 레벨 단위로 시스템을 하나씩 가르치는 온보딩의 연장이다.

## 정리
- 같은 "30레벨까지 20시간"이라도 곡선 모양에 따라 50레벨은 56시간도, 142시간도 된다. 닫힌 식으로 미리 계산한다.
- 룬스케이프의 공식은 7레벨마다 두 배가 되는 지수 곡선이고, 92레벨이 99레벨의 절반이다.
- 해금 레벨은 플레이 시간 분포를 거쳐 그 시스템을 보는 비율이 된다. 핵심 시스템은 앞에 둔다.
- 고정 비율과 변동 비율은 평균이 같아도 경험이 다르다. 멈출 지점을 지우는 쪽으로 쓰지 않는다.
