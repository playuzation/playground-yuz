# [레벨 디자인과 콘텐츠 제공 12/16] 확률형 보상: 기댓값, 천장, 확률 공개

> **한 줄 요약** — 확률 1%짜리 보상은 평균 100번이지만 100번 해도 37%는 못 얻고, 천장과 확률 상승 장치는 이 긴 꼬리를 잘라 실제 획득률(종합 확률)을 표기 확률보다 크게 바꾸므로, 정확한 분포를 계산해 기댓값·최악의 경우·종합 확률을 함께 알려야 플레이어가 판단할 수 있고, 한국은 2024년 3월부터 이런 확률 정보의 표시를 법으로 의무화했다.

## 이 글에서 다루는 것
- 기하 분포로 보는 확률형 보상: 기댓값, n번 안에 얻을 확률, 필요한 횟수
- 천장(pity)과 확률 상승이 분포를 어떻게 바꾸나: 동적 계획법과 몬테카를로 대조
- 공개된 숫자 읽기: 기본 확률과 종합 확률
- 확률 공개 의무화와 규제 동향(확인된 사실만)
- 오해하기 쉬운 지점: 독립 시행과 도박사의 오류

## 무엇이 문제인가
**확률형 보상**(randomized reward)은 정해진 확률로 결과가 갈리는 보상이다. 상자를 열거나 장비를 강화하는 것처럼 무료 보상에도, 돈을 내는 확률형 아이템에도 쓰인다. 11편에서 본 변동 비율 보상과 같은 구조라서, 다음 보상이 언제 올지 예측할 수 없고 평균보다 훨씬 긴 가뭄이 생긴다. 이 글은 그 수학을 정확히 계산하는 데 초점을 둔다. 목적은 플레이어가 표기된 숫자로 실제 비용을 판단할 수 있게 하는 것이고, 지출을 늘리는 방법은 다루지 않는다.

## 기하 분포: 1%는 100번이 아니다
매번 확률 p로 독립적으로 나오면 처음 얻을 때까지의 횟수는 기하 분포를 따른다(확률과 분포 6편). 평균은 `1/p`이고 n번 안에 한 번 이상 얻을 확률은 `1 − (1 − p)ⁿ`이다. 이를 뒤집으면 확률 q로 얻는 데 필요한 횟수는 `⌈ln(1 − q) / ln(1 − p)⌉`다. 공식과 10만 명 모의를 맞춰 본다.
```python
import math, random

p = 0.01                                   # 한 번에 1%
within = lambda n: 1 - (1 - p) ** n        # n번 안에 한 번 이상
need = lambda q: math.ceil(math.log(1 - q) / math.log(1 - p))
print(f"기댓값 {1 / p:.0f}번, 100번 안에 {within(100):.3f}, 10번 안에 {within(10):.4f}")
print("50%·90%·99%에 필요한 횟수:", [need(q) for q in (0.5, 0.9, 0.99)])

rng = random.Random(12)
def first_success():                       # 정의대로: 나올 때까지 뽑기
    n = 1
    while rng.random() >= p:
        n += 1
    return n

ts = sorted(first_success() for _ in range(100_000))
print(f"모의 10만 명: 평균 {sum(ts) / len(ts):.1f}, "
      f"100번 안에 {sum(t <= 100 for t in ts) / len(ts):.3f}")
print("모의 50%·90%·99% 지점:",
      [ts[int(q * len(ts))] for q in (0.5, 0.9, 0.99)])
late = [t for t in ts if t > 50]           # 50번 연속 실패한 사람들
print(f"50번 실패 뒤 51번째에 나올 확률: {sum(t == 51 for t in late) / len(late):.4f}")
```
```text
기댓값 100번, 100번 안에 0.634, 10번 안에 0.0956
50%·90%·99%에 필요한 횟수: [69, 230, 459]
모의 10만 명: 평균 99.8, 100번 안에 0.635
모의 50%·90%·99% 지점: [69, 230, 459]
50번 실패 뒤 51번째에 나올 확률: 0.0105
```
1%를 100번 하면 "반드시"가 아니라 63%다. 10번에 한 번 이상은 10%가 아니라 9.56%다. 절반은 69번 안에 얻지만, 운이 나쁜 1%는 459번을 넘긴다. 같은 표기 확률 아래에서 플레이어마다 비용이 6배 넘게 벌어지는 셈이다. 마지막 줄은 **도박사의 오류**(gambler's fallacy)를 확인한다. 50번 연속 실패한 사람도 51번째 확률은 여전히 약 1%다. 독립 시행에서는 "이제 나올 때가 됐다"가 성립하지 않는다.

## 천장과 확률 상승: 분포를 정확히 계산하기
긴 꼬리를 자르는 장치가 **천장**(pity)이다. 정해진 횟수 안에 얻지 못하면 다음 번은 확정이다. 천장에 가까워질수록 확률을 조금씩 올리는 장치를 더하기도 한다. 이런 장치가 있으면 확률이 "마지막 획득 이후 몇 번째인가"에 따라 달라지므로 기하 분포 공식은 더 쓸 수 없다. 대신 k번째 뽑기의 확률을 `h(k)`라 두고, k − 1번 동안 못 얻었을 확률 S를 한 칸씩 이어 가는 동적 계획법으로 정확한 분포를 구한다.
```text
S(0) = 1
P(T = k) = S(k − 1) · h(k)
S(k) = S(k − 1) − P(T = k)
기댓값 E[T] = Σ k · P(T = k)
```
오래 뽑으면 얻는 횟수 ÷ 뽑은 횟수는 `1/E[T]`로 수렴한다(재생 과정의 성질). 이 값을 **종합 확률**이라 부르고, 카운터를 들고 100만 번 뽑는 모의로 대조한다. 모델은 기본 확률 0.6%에 A는 장치 없음, B는 90번째 확정, C는 B에 71번째부터 매번 5%p씩 오르는 상승을 더한 가정이다.
```python
import random

P = 0.006                                  # 기본 확률 0.6%
MODELS = {                                 # k번째 뽑기(마지막 획득 이후)의 확률
    "A": lambda k: P,                                      # 천장 없음
    "B": lambda k: 1.0 if k >= 90 else P,                  # 90번째 확정
    "C": lambda k: 1.0 if k >= 90 else                     # 71번째부터
         min(1.0, P + 0.05 * (k - 70)) if k > 70 else P,   # 5%p씩 상승
}

def exact(h, kmax=3000):                   # DP: 생존 확률을 한 칸씩 이어 간다
    surv, mean, cdf, q99 = 1.0, 0.0, 0.0, None
    for k in range(1, kmax + 1):
        hit = surv * h(k)                  # P(T = k)
        mean, cdf = mean + k * hit, cdf + hit
        surv -= hit
        if q99 is None and cdf >= 0.99:
            q99 = k
    return mean, q99

def simulate(h, draws, rng):               # 정의대로: 카운터를 들고 계속 뽑기
    got, k = 0, 0
    for _ in range(draws):
        k += 1
        if rng.random() < h(k):
            got, k = got + 1, 0
    return got / draws

rng = random.Random(7)
print("열: 모델, 기댓값, 종합 확률(정확 1/기댓값), 모의, 99% 지점")
for name, h in MODELS.items():
    mean, q99 = exact(h)
    sim = simulate(h, 1_000_000, rng)
    print(f"{name} {mean:6.1f} {1 / mean:7.3%} {sim:7.3%} {q99:4d}")
closed = (1 - (1 - P) ** 90) / P           # B의 기댓값 닫힌 식
print(f"B 닫힌 식 (1 − 0.994⁹⁰)/0.006 = {closed:.1f}")
```
```text
열: 모델, 기댓값, 종합 확률(정확 1/기댓값), 모의, 99% 지점
A  166.7  0.600%  0.605%  766
B   69.7  1.435%  1.436%   90
C   60.7  1.647%  1.655%   81
B 닫힌 식 (1 − 0.994⁹⁰)/0.006 = 69.7
```
같은 "0.6%"라도 기댓값은 167번에서 70번, 61번으로 바뀌고 종합 확률은 2.7배까지 오른다. 더 중요한 것은 꼬리다. 장치가 없으면 1%의 플레이어가 766번을 넘기지만, 천장이 있으면 누구도 90번을 넘지 않는다. 천장은 최악의 비용에 상한을 두는 **플레이어 보호 장치**이고, 그 상한은 "천장 횟수 × 1회 가격"으로 누구나 계산할 수 있어야 한다. B의 기댓값은 닫힌 식 `(1 − (1 − p)ᴺ)/p`와 일치하고, 세 모델 모두 종합 확률이 모의와 0.01%p 단위로 맞는다.

## 공개된 숫자 읽기
원신(호요버스)의 기원 안내는 5성 기본 확률 0.6%, 보장을 포함한 종합 확률 1.6%, 최대 90번 안에 확정이라고 밝힌다(커뮤니티 위키가 옮긴 게임 내 안내 기준). 위 모델 B가 바로 "0.6%와 90번 천장만" 있는 경우인데 종합 확률은 1.435%다. 그러므로 공개된 1.6%에 맞으려면 90번 전에 확률이 오르는 구간이 있어야 한다는 계산이 나온다. 그 상승 곡선의 정확한 모양은 공식적으로 공개되지 않았고, 모델 C는 그런 장치가 종합 확률을 얼마나 바꾸는지 보이려고 가정한 예일 뿐이다. 이 사례가 말해 주는 것은 하나다. **기본 확률만으로는 실제 비용을 알 수 없고**, 천장·상승·보장의 규칙과 카운터가 다음 기간으로 이어지는지까지 알아야 기댓값을 계산할 수 있다.

## 확률 공개 의무화와 규제 동향
아래는 시행일과 대상 같은 확인된 사실만 옮긴 것이고 법률 해석이 아니다. 정확한 조문은 국가법령정보센터 같은 공식 출처에서 확인해야 한다.
- 한국: 개정 게임산업진흥에 관한 법률이 2024년 3월 22일 시행되어, 2015년부터 업계 자율 규약으로 하던 확률 공개가 법적 의무가 됐다. 확률형 아이템을 캡슐형·강화형·합성형으로 나눠 종류와 종류별 공급 확률을 게임 화면, 홈페이지, 광고·선전물에 표시해야 하고, 연평균 매출 1억 원 이하 중소기업 등 일부는 제외된다. 게임물관리위원회가 점검하며 위반하면 시정 요청, 문화체육관광부의 시정 권고·시정 명령 순으로 이어진다.
- 한국(2025년 개정): 보도에 따르면 2025년 8월부터 확률 정보를 표시하지 않거나 거짓으로 표시해 손해를 입힌 사업자의 배상 책임이 법에 명시됐고(제33조의2), 고의이면 손해의 3배 범위에서 배상액을 정할 수 있으며, 고의·과실이 없음은 사업자가 입증해야 한다.
- 중국: 문화부 규정으로 2017년 5월 1일부터 온라인 게임 운영자가 뽑기 아이템의 이름·내용과 확률을 공개해야 한다는 보도가 나왔다.
- 애플: 2017년 12월 App Store 심사 지침을 고쳐, 무작위 아이템을 파는 앱은 구매 전에 아이템 종류별 확률을 공개하도록 했다.
- 벨기에: 2018년 게임위원회가 현금으로 사는 루트 박스를 도박으로 본다는 판단을 내놓았다.

## 오해하기 쉬운 지점
- "1%면 100번이면 나온다": 100번 안에 63%다. 공개 화면에 기댓값과 함께 90% 지점(1%면 230번)을 보여 주면 오해가 준다.
- "많이 실패했으니 곧 나온다": 독립 시행에서는 틀린 생각이다. 반대로 천장이 있는 시스템에서는 카운터가 실제로 확률을 바꾼다. 그래서 카운터를 화면에 보여 주는 것이 공정하다.
- "종합 확률 1.6%면 매번 1.6%": 종합 확률은 긴 기간의 평균이다. 한 번 한 번의 확률은 카운터에 따라 0.6%에서 100%까지 움직인다.
- 모델은 기댓값과 꼬리를 정확히 계산해 줄 뿐, 지출이 플레이어에게 적절한지는 말해 주지 않는다. 미성년자 보호, 지출 상한, 거의 당첨될 뻔한 것처럼 보이는 연출 같은 문제는 수학 밖의 판단이다.

## 숫자로 보기
| 확률 1%일 때 | 값 | 계산 |
|---|---|---|
| 기댓값 | 100번 | 1/p |
| 100번 안에 얻을 확률 | 63.4% | 1 − 0.99¹⁰⁰ |
| 절반이 얻는 횟수 | 69번 | ln 0.5 / ln 0.99 |
| 99%가 얻는 횟수 | 459번 | ln 0.01 / ln 0.99 |

## 어디에 쓰이나
- 확률과 분포 6편 「이산 분포: 베르누이, 이항, 기하, 포아송」: 천장 없는 확률형 보상은 기하 분포 그대로이고, 무기억성이 도박사의 오류를 반박한다.
- 동적 계획법 9편 「확률과 기댓값 DP」: 카운터 상태를 따라 생존 확률을 이어 가는 계산이 그 글의 확률 DP다.
- 확률과 분포 12편 「마르코프 연쇄: 현재만 기억하는 확률 과정」: 천장 카운터는 마르코프 연쇄이고, 종합 확률은 그 연쇄를 오래 돌렸을 때의 획득 빈도다.
- 11편 「진행 시스템: 경험치 곡선, 해금, 보상 일정」: 변동 비율 보상의 가뭄을 천장이 어떻게 자르는지가 이 글의 주제였다.

## 정리
- 확률 p의 기댓값은 1/p이지만 그만큼 해도 얻을 확률은 63%뿐이고, 꼬리는 평균의 몇 배까지 길다.
- 천장과 확률 상승이 있으면 생존 확률 DP로 정확한 분포를 구하고, 종합 확률 = 1/기댓값을 몬테카를로로 대조한다.
- 기본 확률만으로는 비용을 알 수 없다. 천장, 상승, 카운터 이월 규칙까지 공개되어야 계산할 수 있다.
- 한국은 2024년 3월 22일부터 확률 정보 표시를 의무화했고, 2025년에는 위반 시 배상 책임을 강화했다.
