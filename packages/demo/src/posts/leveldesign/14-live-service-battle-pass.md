## 문제: 콘텐츠 트레드밀
새 던전 하나를 기획·아트·테스트까지 몇 주 걸려 만들어도, 열심히 하는 플레이어는 며칠 만에 다 보고 다음을 기다린다. 소비가 제작보다 빠른 이 상황을 흔히 **콘텐츠 트레드밀**(content treadmill)이라 부른다. 러닝머신처럼 계속 달려야 제자리라는 뜻이다. 순진한 대응은 더 많이 만드는 것이지만 팀 크기는 쉽게 늘지 않는다. 그래서 라이브 서비스는 두 종류를 섞는다.
- 일회성 콘텐츠(스토리, 새 지역, 이벤트 연출): 만들기 비싸고 한 번 보면 끝나지만 시즌의 얼굴이 된다.
- 반복 콘텐츠(대전, 랭크, 9편·10편의 절차적 생성 던전, 수집): 시스템을 한 번 만들면 오래 쓰지만, 같은 것을 또 할 이유가 필요하다.

**시즌**(season)은 몇 주에서 몇 달마다 새 일회성 콘텐츠를 내고 일부 진행을 초기화하는 주기이고, **배틀 패스**(battle pass)는 반복 플레이로 쌓은 경험치에 단계별 보상을 붙인 시즌 한정 진행 트랙이다. 반복 콘텐츠에 "이번 시즌 안에 어디까지 갈까"라는 목표를 주는 장치다.

## 사례: 도타 2의 컴펜디움과 포트나이트
밸브는 2013년 디 인터내셔널(The International) 대회에 맞춰 도타 2의 인터랙티브 컴펜디움을 팔고 구매액의 25%를 대회 상금에 더했다. 밸브의 컴펜디움 페이지와 ESPN 보도에 따르면 기본 상금 160만 달러가 약 287만 달러로 늘었다. 컴펜디움은 해마다 이어지다 2016년부터 "배틀 패스"라는 이름으로 팔렸다(밸브의 2016년 배틀 패스 페이지). 포트나이트 배틀로얄은 시즌 2에서 70단계 배틀 패스를 처음 도입했고 시즌 3에서 100단계로 늘렸다(당시 보도).

## 배틀 패스 완주율: 플레이 패턴별로 계산하기
10주 시즌, 100단계 × 1,000XP짜리 패스를 생각하자. 플레이한 날마다 경험치를 받고, 주간 과제 한 세트를 끝내면 7,000XP를 더 받는다(최대 10세트). 매일형은 날마다 70% 확률로 짧게 놀아 800XP, 주말형은 토·일에 90% 확률로 길게 놀아 3,500XP, 드문드문형은 날마다 20% 확률로 놀아 1,500XP를 번다. 과제 조건 두 가지를 비교한다. 규칙 A는 "그 주에 3일 이상 플레이", 규칙 B는 "시즌 누적 3일 플레이마다 한 세트"로, 밀린 과제를 나중에 몰아서 할 수 있는 셈이다. 각 경우를 2만 명 몬테카를로와, 확률을 정확히 합성곱한 분포로 따로 계산해 맞춘다.
```python
import random
from math import comb

WEEKS, PER_TIER, SET_XP = 10, 1000, 7000   # 10주, 단계당 1,000XP, 주간 과제
PATTERNS = {"매일형": (7, 0.7, 800),       # (주당 놀 수 있는 날, 확률, 하루 XP)
            "주말형": (2, 0.9, 3500),
            "드문드문형": (7, 0.2, 1500)}

def season_xp(played, xp, rule):
    """played: 주마다 논 날 수. A: 그 주에 3일 이상 놀아야 과제 한 세트,
    B: 시즌 누적 3일마다 한 세트(밀린 과제 몰아 하기). 둘 다 최대 10세트"""
    total = sum(played)
    sets = (sum(n >= 3 for n in played) if rule == "A"
            else min(WEEKS, total // 3))
    return total * xp + sets * SET_XP

def monte_carlo(k, p, xp, rule, tiers=100, n=20000, seed=14):
    rng, done, reach = random.Random(seed), 0, 0
    for _ in range(n):
        played = [sum(rng.random() < p for _ in range(k)) for _ in range(WEEKS)]
        x = season_xp(played, xp, rule)
        done += x >= tiers * PER_TIER
        reach += min(tiers, x // PER_TIER)
    return done / n, reach / n

def binom(k, p):
    return [comb(k, i) * p**i * (1 - p)**(k - i) for i in range(k + 1)]

def exact(k, p, xp, rule, tiers=100):
    """A: 한 주의 XP 분포를 10번 합성곱. B: 시즌 전체 논 날 수의 이항 분포"""
    if rule == "A":
        dist = {0: 1.0}
        for _ in range(WEEKS):
            new = {}
            for x, q in dist.items():
                for n, r in enumerate(binom(k, p)):
                    y = x + season_xp([n], xp, "A")
                    new[y] = new.get(y, 0) + q * r
            dist = new
    else:
        dist = {season_xp([n], xp, "B"): r
                for n, r in enumerate(binom(k * WEEKS, p))}
    done = sum(q for x, q in dist.items() if x >= tiers * PER_TIER)
    reach = sum(q * min(tiers, x // PER_TIER) for x, q in dist.items())
    return done, reach

for rule in "AB":
    print("규칙", rule, "(몬테카를로/정확)")
    for name, (k, p, xp) in PATTERNS.items():
        (d1, t1), (d2, t2) = monte_carlo(k, p, xp, rule), exact(k, p, xp, rule)
        print(f"  {name}: 완주 {d1:.1%}/{d2:.1%}, 평균 {t1:.1f}/{t2:.1f}단계")
```
```text
규칙 A (몬테카를로/정확)
  매일형: 완주 86.7%/86.5%, 평균 99.5/99.4단계
  주말형: 완주 0.0%/0.0%, 평균 62.8/62.8단계
  드문드문형: 완주 0.0%/0.0%, 평균 31.1/31.1단계
규칙 B (몬테카를로/정확)
  매일형: 완주 99.8%/99.8%, 평균 100.0/100.0단계
  주말형: 완주 68.1%/67.7%, 평균 97.4/97.4단계
  드문드문형: 완주 0.0%/0.0%, 평균 51.0/51.1단계
```
두 방법이 0.4%p 안에서 맞는다(완주율 68%에서 몬테카를로의 표준 오차가 약 0.3%p다). 규칙 A에서 주말형은 일주일에 이틀밖에 놀 수 없어 주간 과제를 한 세트도 받지 못하고, 완주율이 정확히 0이다. 주말형이 하루 보상으로 버는 경험치(평균 63,000)가 매일형(평균 39,200)보다 많은데도 그렇다. 규칙 B로 바꾸면 매일형은 거의 모두 완주하고 주말형 완주율이 68%로 오른다. 조건 문구 하나가 특정 생활 패턴을 구조적으로 배제하고 있었던 것이다.

단계 수도 민감하다. 앞 코드에 이어서, 규칙 B에서 단계 수만 바꿔 정확한 완주율을 본다(매일형 / 주말형 / 드문드문형 순서).
```python
for tiers in (80, 90, 100, 110, 120):          # 규칙 B에서 단계 수를 바꾸면
    row = [exact(k, p, xp, "B", tiers)[0] for k, p, xp in PATTERNS.values()]
    print(f"{tiers}단계: " + " / ".join(f"{d:.0%}" for d in row))
```
```text
80단계: 100% / 99% / 3%
90단계: 100% / 96% / 0%
100단계: 100% / 68% / 0%
110단계: 46% / 12% / 0%
120단계: 0% / 0% / 0%
```
100단계에서 110단계로 10%만 늘려도 매일형 완주율이 100%에서 46%로 떨어진다. 완주율은 평균 근처에서 계단처럼 급하게 변하므로 "평균 경험치로 단계 수를 정하는" 계산은 위험하다. 분포 전체를 보고, 패턴마다 목표 완주율을 정한 뒤 역산해야 한다. 드문드문형은 어떤 설정에서도 완주하지 못하는데, 이들에게는 완주보다 몇 단계마다 의미 있는 보상이 있는지가 중요하다.

## 잔존율 곡선: 왜 처음에 가파른가
라이브 서비스는 **잔존율**(retention)로 건강을 잰다. 여기서 Dn 잔존율은 설치한 사람 중 n일째에도 떠나지 않은 비율이다(n일째에 실제로 접속한 비율로 세는 정의도 흔하다). 플레이어마다 하루 이탈 확률 h가 다르다고 두면 전체 곡선은 유형별 지수 곡선의 혼합 `R(n) = Σ w·(1 − h)ⁿ`이다. 5만 명 시뮬레이션을 공식과 맞추고, 남은 사람들의 하루 이탈률을 본다.
```python
import random
MIX = [(0.6, 0.5), (0.3, 0.06), (0.1, 0.01)]     # (비율, 하루 이탈 확률)

def retention(n):                                # R(n) = Σ w·(1 − h)ⁿ
    return sum(w * (1 - h) ** n for w, h in MIX)

rng, alive = random.Random(7), [0] * 31
for _ in range(50000):
    u = rng.random()
    h = 0.5 if u < 0.6 else 0.06 if u < 0.9 else 0.01
    for day in range(31):                        # 0일 = 설치한 날
        if day and rng.random() < h:
            break
        alive[day] += 1
for n in (1, 7, 30):
    print(f"D{n}: 시뮬 {alive[n] / 50000:.1%} 공식 {retention(n):.1%},",
          f"남은 사람의 하루 이탈률 {1 - retention(n + 1) / retention(n):.1%}")
```
```text
D1: 시뮬 68.0% 공식 68.1%, 남은 사람의 하루 이탈률 24.7%
D7: 시뮬 29.4% 공식 29.2%, 남은 사람의 하루 이탈률 5.1%
D30: 시뮬 12.2% 공식 12.1%, 남은 사람의 하루 이탈률 2.9%
```
시뮬레이션과 공식이 표본 오차 안에서 맞는다. 눈여겨볼 것은 남은 사람의 하루 이탈률이 25%에서 3%로 떨어진다는 점이다. 모델에서 개인의 이탈 확률은 하나도 바뀌지 않았다. 떠나기 쉬운 사람이 먼저 빠져 남은 집단의 구성이 바뀐 것이다. 그래서 "한 달 넘게 남은 사람은 충성도가 높아졌다"고 읽으면 안 된다. 시즌 콘텐츠의 주 소비자는 이렇게 걸러진 핵심 플레이어이고, 이들이 가장 빨리 소비한다는 점을 제작 일정에 반영해야 한다.

## 플레이어 보호와 한계
- 기간 한정 패스는 "놓치면 끝"이라는 압박을 만든다. 매일 접속해야만 완주되는 설계는 놀이를 의무로 바꾼다. 규칙 B처럼 밀린 과제를 몰아서 할 수 있게 하거나, 지난 시즌 보상을 나중에 얻을 길을 두는 따라잡기 장치가 압박을 줄인다.
- 완주율을 일부러 낮게 맞춰 단계 구매를 유도하는 설계는 신뢰를 잃는다. 완주율 계산은 "의도한 플레이어가 무리 없이 완주하는가"를 확인하는 데 쓴다.
- 모델의 접속 확률은 시즌 내내 일정하지만, 실제로는 시즌 초에 몰리고 보상이 접속 자체를 바꾸며 도중에 이탈도 일어난다. 모델은 규칙의 구조적 문제(주말형 배제 같은)를 찾는 데 강하고, 실제 완주율은 15편의 텔레메트리로 확인해야 한다.
- 반복 콘텐츠도 결국 질린다. 배틀 패스는 반복할 동기를 빌려 줄 뿐, 반복하는 핵심 플레이가 재미없으면 버티지 못한다.

## 어디에 쓰이나
- 확률과 분포 6편 「이산 분포: 베르누이, 이항, 기하, 포아송」: 한 주나 한 시즌에 논 날 수가 이항 분포이고, 완주율은 그 꼬리 확률이다.
- 동적 계획법 9편 「확률과 기댓값 DP」: 주 단위 분포를 차례로 합성곱한 정확한 계산은 "지금까지 모은 XP"를 상태로 둔 확률 DP다.
- 11편 「진행 시스템: 경험치 곡선, 해금, 보상 일정」: 배틀 패스는 시즌마다 초기화되는 경험치 곡선이라 레벨 도달 시간 계산을 시즌 길이 안에서 그대로 쓴다.
- 13편 「게임 경제: 재화의 원천과 소모처, 인플레이션」: 패스 보상으로 재화를 준다면 시즌마다 원천이 하나 더 생기므로 경제 장부에 넣어야 한다.

## 정리
- 소비가 제작보다 빠른 트레드밀 때문에 라이브 서비스는 일회성 콘텐츠와 반복 콘텐츠를 섞고, 시즌과 배틀 패스가 반복에 목표를 준다.
- 완주율은 단계 수와 과제 조건에 매우 민감하므로 평균이 아니라 분포로 계산하고, 정확한 분포와 몬테카를로를 맞춰 계산 자체를 검증한다.
- "주 3일" 같은 조건은 특정 생활 패턴을 구조적으로 배제할 수 있고, 누적 조건과 따라잡기 장치가 이를 고친다.
- 잔존 곡선이 처음에 가파르고 나중에 평평한 것은 개인의 변화가 아니라 남은 집단의 구성 변화일 수 있다.
