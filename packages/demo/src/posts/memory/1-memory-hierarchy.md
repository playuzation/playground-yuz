# [메모리 시스템 1/10] 메모리 계층 지도: 레지스터에서 SSD까지 지연과 대역폭

> **한 줄 요약** — 코어는 0.2ns마다 명령을 끝내는데 DRAM은 값 하나에 70ns 넘게 걸리므로, 작고 빠른 저장소를 크고 느린 저장소 앞에 겹겹이 두고 지역성에 기대 대부분의 접근을 앞쪽에서 끝내며, 그 효과는 평균 메모리 접근 시간 AMAT = 적중 시간 + 미스율 × 미스 비용으로 잰다.

## 이 글에서 다루는 것
- 왜 한 가지 메모리로 만들지 않는가: 빠름·큼·쌈은 동시에 안 된다
- 계층 그림과 단계별 크기·지연(젠 4, DDR5 기준)
- 4단 계층 시뮬레이터로 접근 패턴별 평균 지연 재기
- AMAT 공식, 트레이스 합계와 대조, 미스율 1%의 무게
- 지연과 대역폭은 다르다: 리틀의 법칙으로 본 동시 미스 수

## 병목: 코어는 빨라졌고 메모리는 멀다
5GHz 코어의 한 사이클은 0.2ns다. 데스크톱 DDR5에서 캐시를 모두 놓친 적재 하나가 70ns쯤 걸리니 350사이클, 그동안 코어는 명령 수백 개를 끝낼 수 있었다. 이 격차가 트랜지스터에서 자연어까지 7편 「빠르게 만드는 기술: 파이프라인, 캐시, 병렬성」에서 본 **메모리 장벽**(memory wall)이다.

그럼 전부 빠른 메모리로 만들면 되지 않을까. 두 가지가 막는다. 첫째는 **밀도**다. 캐시에 쓰는 SRAM은 비트마다 트랜지스터 6개가 필요하고(2편), DRAM은 트랜지스터 1개와 축전기 1개다(5편). 게다가 TSMC N5와 N3E의 고밀도 SRAM 비트셀은 둘 다 0.021µm²로, 최근 공정에서는 SRAM이 거의 줄지 않는다. 기가바이트를 SRAM으로 채울 수는 없다. 둘째는 **거리**다. 배열이 커지면 워드선·비트선이 길어지고 주소 해독 단계가 늘어 한 번 읽는 데 더 오래 걸린다. 큰 메모리는 본질적으로 느리다.

그래서 작고 빠른 것을 코어 바로 옆에, 크고 느린 것을 멀리 두고 층을 쌓는다.
```text
 ┌──────────────┐
 │ registers    │  0 cycle
 ├──────────────┤
 │ L1D 32KiB    │  4 cycles
 ├──────────────┤
 │ L2  1MiB     │  14 cycles
 ├──────────────┤
 │ L3  32MiB    │  ~50 cycles
 └──────┬───────┘
        │ memory controller
 ┌──────┴───────┐
 │ DRAM  GBs    │  ~70 ns
 └──────┬───────┘
        │ PCIe + NVMe
 ┌──────┴───────┐
 │ SSD   TBs    │  tens of us
 └──────────────┘
```
캐시 크기·지연은 AMD 젠 4 코어 기준이다(L3는 CCD 하나에 공유). 캐시는 한 단계 내려갈 때마다 3~4배씩 느려지고 DRAM에서 다시 7배, SSD에서는 천 배쯤 느려진다. 레지스터는 컴파일러가, 캐시는 하드웨어가 채우고, DRAM과 SSD 사이(스왑, 파일 캐시)는 운영체제가 관리한다.

## 계층이 통하는 이유: 지역성
계층은 "곧 쓸 데이터가 위층에 있다"는 내기다. 내기가 맞는 근거가 **지역성**(locality)이다. 방금 쓴 주소를 곧 다시 쓰는 **시간 지역성**(반복문 변수, 작은 표), 방금 쓴 주소 근처를 곧 쓰는 **공간 지역성**(배열 순회)이다. 캐시는 64바이트 **캐시 줄**(cache line) 단위로 가져오므로 공간 지역성은 줄 하나에 든 이웃을 공짜로 얻는 효과로 나타난다. 피터 데닝(Peter Denning)이 1968년 작업 집합(working set) 모델로 프로그램의 이런 성질을 정리했다.

L1·L2·L3를 줄 단위 LRU 캐시로, DRAM을 350사이클(70ns × 5GHz, 가정)로 둔 4단 계층에 네 가지 접근 패턴을 흘려 보자. 접근은 하나씩 순서대로 기다린다고 가정한다.
```python
import random
from collections import OrderedDict

LINE = 64
LEVELS = [("L1", 512, 4), ("L2", 16384, 14), ("L3", 524288, 50)]
MEM = 350                        # DRAM 70ns × 5GHz (가정)

def run(trace):
    """L1→L2→L3→DRAM을 차례로 찾는다. 단계마다 줄 단위 LRU"""
    caches = [OrderedDict() for _ in LEVELS]
    acc, hit, total = [0] * 4, [0] * 4, 0
    for addr in trace:
        b = addr // LINE
        for k, (name, cap, lat) in enumerate(LEVELS):
            acc[k] += 1
            total += lat
            c = caches[k]
            if b in c:
                hit[k] += 1
                c.move_to_end(b)
                break
            c[b] = True                 # 채워 넣기
            if len(c) > cap:
                c.popitem(last=False)
        else:
            acc[3] += 1
            total += MEM
    return acc, hit, total

rng = random.Random(1)
N = 1 << 17                          # 접근 131,072번, 원소 8바이트
traces = {
    "순차 1MiB": [8 * i for i in range(N)],
    "16KiB 반복": [8 * (i % 2048) for i in range(N)],
    "무작위 256KiB": [8 * rng.randrange(32768) for _ in range(N)],
    "무작위 64MiB": [8 * rng.randrange(1 << 23) for _ in range(N)],
}
res = {}
for name, tr in traces.items():
    acc, hit, total = res[name] = run(tr)
    r = [f"{h / a:.1%}" for a, h in zip(acc[:3], hit[:3])]
    print(f"{name}: 평균 {total / N:.1f}사이클")
    print(f"  적중 L1 {r[0]} L2 {r[1]} L3 {r[2]}")
```
```text
순차 1MiB: 평균 55.8사이클
  적중 L1 87.5% L2 0.0% L3 0.0%
16KiB 반복: 평균 4.8사이클
  적중 L1 99.8% L2 0.0% L3 0.0%
무작위 256KiB: 평균 28.7사이클
  적중 L1 12.6% L2 96.4% L3 0.0%
무작위 64MiB: 평균 396.4사이클
  적중 L1 0.0% L2 1.4% L3 4.6%
```
같은 횟수의 8바이트 적재인데 평균 지연이 4.8사이클에서 396사이클까지 80배 벌어진다. 순차 순회는 처음 보는 데이터라 L2·L3에서는 다 놓치지만 줄 하나에 원소 8개가 들어 L1 적중률이 정확히 7/8이다. 16KiB 반복은 L1에 통째로 들어가 처음 256줄만 놓친다. 256KiB 무작위는 L1(512줄)이 4,096줄 중 12.5%만 담으므로 L1 적중률이 그 근처이고 나머지는 L2가 받는다. 64MiB 무작위는 거의 모든 접근이 DRAM까지 간다. 순차와 반복에서 L2·L3 적중률이 0%인 것은 그 단계까지 내려온 접근이 모두 처음 보는 줄이기 때문이다.

## AMAT 공식과 대조
단계 하나라면 평균 메모리 접근 시간은 다음과 같다(헤네시·패터슨 교과서의 표기).
```text
AMAT = 적중 시간 + 미스율 × 미스 비용
```
미스 비용 자리에 다음 단계의 AMAT를 넣으면 다단계가 된다. 이때 미스율은 그 단계에 **들어온** 접근 중 놓친 비율, 곧 **지역 미스율**(local miss rate)이다. 앞 코드에 이어서, 시뮬레이터가 접근마다 더한 총 사이클이 측정한 지역 미스율을 넣은 공식과 분수로 정확히 같은지 확인하고, 적중률 몇 %p가 평균을 얼마나 바꾸는지 계산한다.
```python
from fractions import Fraction as F

def amat(t, m, mem):
    """AMAT = t1 + m1·(t2 + m2·(t3 + m3·mem))"""
    x = mem
    for ti, mi in zip(t[::-1], m[::-1]):
        x = ti + mi * x
    return x

ok = True
for acc, hit, total in res.values():
    m = [F(a - h, a) for a, h in zip(acc[:3], hit[:3]) if a]
    m += [F(1)] * (3 - len(m))
    ok &= amat([4, 14, 50], m, MEM) * N == total
print("트레이스 합계 = 접근 수 × AMAT:", ok)
acc, hit, _ = res["순차 1MiB"]
print("순차 L1 적중 = 1 − 8/64:", F(hit[0], acc[0]) == 1 - F(8, 64))
acc, hit, _ = res["16KiB 반복"]
print("반복 L1 미스 = 256줄:", acc[0] - hit[0] == 16384 // LINE)
for h in (0.999, 0.99, 0.98, 0.95, 0.90):
    print(f"L1 적중 {h:.1%}: AMAT {amat([4], [1 - h], 414):5.1f}사이클")
```
```text
트레이스 합계 = 접근 수 × AMAT: True
순차 L1 적중 = 1 − 8/64: True
반복 L1 미스 = 256줄: True
L1 적중 99.9%: AMAT   4.4사이클
L1 적중 99.0%: AMAT   8.1사이클
L1 적중 98.0%: AMAT  12.3사이클
L1 적중 95.0%: AMAT  24.7사이클
L1 적중 90.0%: AMAT  45.4사이클
```
마지막 다섯 줄은 L1을 놓치면 L2·L3도 놓치고 DRAM까지 간다고 둔 경우다(벌점 14 + 50 + 350 = 414사이클). 적중률 99%와 98%는 1%p 차이지만 평균은 8.1에서 12.3사이클로 50% 늘고, 90%면 적중 시간의 11배다. 미스 비용이 적중 시간의 100배쯤 되면 **미스율 1%가 적중 시간 하나만큼 무겁다**. 캐시 최적화를 적중률이 아니라 미스율의 배수로 생각해야 하는 이유다.

## 지연과 대역폭은 다르다
지연은 요청 하나가 돌아오는 시간이고 대역폭은 초당 옮기는 양이다. DDR5-4800 DIMM 하나는 64비트(32비트 서브채널 두 개, 6편)로 초당 4,800M번 전송한다. 앞 코드에 이어서 계산해 보자.
```python
bw = 4800e6 * 8                  # DDR5-4800, 64비트 폭: 초당 바이트
lat = 70e-9                      # 적재 한 번의 지연(가정)
print(f"DDR5-4800 DIMM 하나: {bw / 1e9:.1f} GB/s")
print(f"한 번에 한 줄씩 기다리면: {LINE / lat / 1e9:.2f} GB/s")
print(f"대역폭을 채우는 동시 미스: {bw * lat / LINE:.0f}개")
```
```text
DDR5-4800 DIMM 하나: 38.4 GB/s
한 번에 한 줄씩 기다리면: 0.91 GB/s
대역폭을 채우는 동시 미스: 42개
```
한 줄씩 기다리면 38.4GB/s 중 1GB/s도 못 쓴다. 대역폭을 채우려면 **리틀의 법칙**(동시 요청 수 = 처리량 × 지연)대로 64바이트 미스 42개가 동시에 날아가야 한다. 비순차 실행 코어는 독립적인 미스를 여럿 겹치고(CPU 마이크로아키텍처 4편 「비순차 실행: 레지스터 이름 바꾸기와 토마술로 알고리즘」), 하드웨어 프리페처는 미리 요청을 낸다(4편). 그래서 위 시뮬레이터처럼 하나씩 기다리는 AMAT는 의존 사슬(연결 리스트 따라가기)에는 맞고, 독립 접근이 많은 순차 순회에서는 비관적인 어림이다. GPU가 스레드 수만 개로 같은 문제를 푸는 방식은 GPU와 CUDA 1편 「GPU는 왜 다르게 생겼나: 지연을 숨기는 처리량 기계」에서 다룬다.

## 코드에 주는 의미
- 작업 집합을 위층 크기에 맞춘다. 같은 계산이라도 16KiB에 머물면 4.8사이클, 64MiB를 무작위로 돌면 396사이클이다.
- 포인터를 따라가는 자료 구조(연결 리스트, 노드가 흩어진 트리)는 미스가 의존 사슬이 되어 겹칠 수 없다. 배열에 연속으로 담으면 공간 지역성과 동시 미스를 함께 얻는다.
- 적중률 99%를 "충분하다"고 보지 않는다. 남은 1%가 평균 시간의 절반을 차지할 수 있다.

## 숫자로 보기
| 단계 | 크기 | 지연 |
|---|---|---|
| L1D (젠 4) | 32KiB | 4사이클 |
| L2 (젠 4) | 1MiB | 14사이클 |
| L3 (젠 4) | 32MiB/CCD | 약 50사이클 |
| DRAM (젠 5, DDR5-6000 측정) | GB 단위 | 70ns 남짓 |
| NVMe SSD (TLC) | TB 단위 | 수십~100µs대 |

- 대역폭: DDR5-4800 DIMM 하나는 4,800MT/s × 8바이트 = 38.4GB/s, PCIe 4.0 x4 NVMe 링크는 16GT/s × 4레인 × 128/130 ÷ 8 ≈ 7.9GB/s(PCIe 5.0은 두 배)다. 지연과 대역폭은 제품·세대·측정 방법마다 다르므로 표는 자릿수를 익히는 용도로 본다.
- 캐시 줄은 x86 CPU에서 64바이트다. 인텔 골든 코브(P 코어)는 L1D가 48KiB에 5사이클로, 같은 세대라도 회사마다 크기와 지연을 다르게 고른다.

## 어디에 쓰이나

- 추상 데이터 타입 심화 9편 「B-트리와 B+트리: 디스크 블록 하나에 키 수백 개」: 노드를 블록 크기로 키우는 설계는 계층의 아래쪽(SSD·디스크)에서 미스 횟수를 줄이는 같은 계산이다.
- 양자화 15편 「CPU 오프로드: GPU 메모리보다 큰 모델 돌리기」: GPU 메모리, CPU DRAM, SSD 순으로 가중치를 내려놓을 때 속도를 정하는 것이 이 글의 대역폭 표다.

## 정리
- 큰 메모리는 밀도와 배선 거리 때문에 느리므로, 작고 빠른 층을 앞에 쌓고 지역성으로 대부분의 접근을 위층에서 끝낸다.
- 같은 적재 131,072번이 접근 패턴에 따라 평균 4.8~396사이클로 80배 갈렸다.
- 다단계 AMAT는 지역 미스율로 `t1 + m1·(t2 + m2·(…))`이고, 미스 비용이 크면 미스율 1%p가 평균을 수십 % 바꾼다.
- 대역폭을 쓰려면 미스를 겹쳐야 한다. DDR5-4800 DIMM 하나를 채우려면 70ns 지연에서 동시 미스 42개가 필요하다.
