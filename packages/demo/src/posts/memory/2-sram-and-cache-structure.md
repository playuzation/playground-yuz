# [메모리 시스템 2/10] SRAM과 캐시의 구조: 6T 셀, 태그·인덱스·오프셋

> **한 줄 요약** — 캐시는 6T SRAM 셀 배열에 데이터와 함께 주소의 윗부분(태그)을 저장해 두고, 주소를 오프셋·인덱스·태그로 잘라 인덱스로 집합 하나를 고른 뒤 그 집합의 웨이 수만큼 태그를 동시에 비교하는 장치이며, 연관도를 올리면 충돌 미스가 줄지만 비교기와 읽는 양이 웨이 수에 비례해 는다.

## 이 글에서 다루는 것
- 6T SRAM 셀의 읽기·쓰기와 셀 배열
- 캐시 줄과 태그, 주소를 태그·인덱스·오프셋으로 나누기
- 직접 사상·집합 연관·완전 연관을 시뮬레이터로 비교하기
- LRU의 정의 그대로 센 결과와 무작위 대조
- 태그 비교 회로의 비용, L1이 32KiB 8웨이인 이유

## 병목: 주소 하나로 어느 칸을 볼까
1편에서 본 대로 L1은 4~5사이클 안에 답해야 한다. 그런데 48비트 주소 공간은 256TiB이고 L1은 64바이트 줄 512개뿐이다. 캐시는 두 질문에 동시에 답해야 한다. 이 주소의 데이터가 여기 있나, 있다면 어느 칸인가. 512칸을 하나씩 뒤지면 늦고, 모든 칸을 동시에 비교하면 회로가 커진다. 그 사이의 타협이 이 글의 주제다. 먼저 칸 하나를 이루는 셀부터 보자.

## 6T SRAM 셀
트랜지스터에서 자연어까지 4편 「순차 회로: 클록, 플립플롭, 메모리」에서 본 SRAM 셀은 인버터 두 개를 엇갈려 이은 고리(트랜지스터 4개)에 접근 트랜지스터 2개를 더한 것이다.
```text
 BL ─[A1]─ Q ──►INV──► QB ─[A2]─ BLB
            ▲               │
            └─────INV◄──────┘
 A1, A2 gate = WL (word line)
```
고리는 Q와 QB(반대 값)를 서로 붙잡아 전원이 있는 한 값을 지킨다. 같은 행의 셀은 **워드선**(word line, WL)을 공유하고, 같은 열의 셀은 **비트선** 쌍(BL, BLB)을 공유한다.
- **읽기**: BL과 BLB를 둘 다 전원 전압으로 미리 충전(precharge)한 뒤 WL을 켠다. 0을 쥔 쪽이 자기 비트선을 조금 끌어내린다. 비트선은 셀 수백 개가 매달려 무겁기 때문에 끝까지 내려가길 기다리지 않고, **감지 증폭기**(sense amplifier)가 두 선의 작은 차이를 0·1로 키운다. 읽는 동안 셀이 뒤집히지 않도록 고리 쪽 트랜지스터를 접근 트랜지스터보다 강하게 만든다.
- **쓰기**: 쓰기 회로가 BL과 BLB를 반대 값으로 세게 몰고 WL을 켠다. 비트선 쪽이 고리를 이겨 상태가 뒤집힌다.

셀이 행과 열로 늘어선 배열 앞에 행 해독기가, 뒤에 감지 증폭기와 열 선택기가 붙는다. 캐시는 이런 배열 두 종류로 이뤄진다. 데이터를 담는 **데이터 배열**과, 그 데이터가 어느 주소의 것인지 적는 **태그 배열**이다.

## 캐시 줄과 주소 나누기
캐시는 64바이트 **줄**(line) 단위로 데이터를 옮긴다. 줄 안의 위치가 **오프셋**(offset), 줄을 넣을 **집합**(set)의 번호가 **인덱스**(index), 나머지 윗비트가 **태그**(tag)다. 한 집합에 줄이 들어갈 자리가 w개면 w-**웨이**(way) **집합 연관**(set-associative) 캐시다. w = 1이면 **직접 사상**(direct-mapped), 집합이 하나뿐이면 **완전 연관**(fully associative)이다.

32KiB, 8웨이, 64바이트 줄이면 집합은 32768 ÷ (64 × 8) = 64개다.
```text
 47           12 11     6 5      0
 ┌──────────────┬────────┬────────┐
 │     tag      │ index  │ offset │
 └──────────────┴────────┴────────┘
     36 bits      6 bits   6 bits
```
찾기는 세 걸음이다. 인덱스로 집합 하나의 행을 읽고, 그 집합의 태그 8개를 요청 주소의 태그와 **동시에** 비교하고, 일치한 웨이의 데이터에서 오프셋 위치의 바이트를 고른다. 일치가 없으면 미스다. 태그에는 유효 비트(valid)와, 고쳐 쓴 줄인지 표시하는 더티 비트(dirty, 3편)가 붙는다.

주소 나누기와 집합별 LRU 캐시를 구현하고, 벡터 덧셈 `c[k] = a[k] + b[k]`를 돌려 보자. 세 배열이 64KiB의 배수 주소에서 시작한다고 하자. 캐시는 모두 4KiB(64줄)로 같고 웨이 수만 다르다.
```python
def split(addr, size, ways, line=64):
    sets = size // (line * ways)
    ob, ib = line.bit_length() - 1, sets.bit_length() - 1
    return addr >> (ob + ib), (addr >> ob) & (sets - 1), addr & (line - 1)

class Cache:
    def __init__(self, size, ways, line=64):
        self.size, self.ways, self.line = size, ways, line
        self.sets = [[] for _ in range(size // (line * ways))]
        self.miss = 0

    def access(self, addr):
        tag, idx, _ = split(addr, self.size, self.ways, self.line)
        s = self.sets[idx]                # 앞쪽이 오래된 것
        if tag in s:                      # 웨이 수만큼 태그 비교
            s.remove(tag)
        else:
            self.miss += 1
            if len(s) == self.ways:
                s.pop(0)                  # LRU 교체
        s.append(tag)

t, i, o = split(0x7FFD12345678, 32 * 1024, 8)
print(f"tag {t:#x}, index {i}, offset {o}")    # 32KiB 8웨이

A, B, C = 0x10000, 0x20000, 0x30000      # 64KiB 배수에 놓인 배열
trace = []
for k in range(512):                     # c[k] = a[k] + b[k], 8바이트
    trace += [A + 8 * k, B + 8 * k, C + 8 * k]
for ways in (1, 2, 4, 8, 64):            # 모두 4KiB = 64줄
    c = Cache(4096, ways)
    for a in trace:
        c.access(a)
    print(f"{ways:2}웨이: 미스 {c.miss:4}/{len(trace)}"
          f" = {c.miss / len(trace):.1%}")
```
```text
tag 0x7ffd12345, index 25, offset 56
 1웨이: 미스 1536/1536 = 100.0%
 2웨이: 미스 1536/1536 = 100.0%
 4웨이: 미스  192/1536 = 12.5%
 8웨이: 미스  192/1536 = 12.5%
64웨이: 미스  192/1536 = 12.5%
```
세 배열의 k번째 원소는 주소의 아래 16비트가 같아서 어떤 구성에서든 같은 집합에 떨어진다. 직접 사상은 a, b, c가 한 자리를 번갈아 빼앗아 모든 접근이 미스다. 2웨이도 100%인 것이 눈여겨볼 점이다. 세 줄이 두 자리를 LRU로 돌면 늘 방금 쫓아낸 줄을 다음에 찾게 된다. 4웨이부터는 세 줄이 함께 들어가 줄마다 처음 한 번만 놓친다(192 = 3배열 × 4KiB ÷ 64B). 캐시는 텅 비어 있는데 한 집합만 붐벼서 생긴 미스가 **충돌 미스**이고, 3편에서 시뮬레이터로 따로 떼어 센다. 첫 줄의 태그 `0x7ffd12345`는 주소에서 아래 12비트를 뗀 값, 곧 4KiB 페이지 번호와 같다. 이 우연이 아닌 일치는 아래에서 다시 나온다.

## 정의 그대로 센 결과와 대조
LRU 캐시에서 줄 x가 남아 있을 조건은 이렇게 정의할 수 있다. "x를 마지막으로 쓴 뒤 같은 집합에서 x 아닌 줄이 w개 미만 쓰였다." 앞 코드에 이어서, 이 정의대로 과거 접근을 거꾸로 훑어 미스를 세는 느린 함수를 만들고 무작위 트레이스로 시뮬레이터와 비교한다.
```python
import random

def by_definition(trace, size, ways):
    """LRU의 정의: x를 마지막으로 쓴 뒤 같은 집합의
    다른 줄이 ways개 미만 쓰였으면 x는 아직 있다"""
    miss = 0
    for n, a in enumerate(trace):
        tag, idx, _ = split(a, size, ways)
        others, hit = set(), False
        for b in reversed(trace[:n]):
            tb, ib, _ = split(b, size, ways)
            if ib == idx:
                if tb == tag:
                    hit = len(others) < ways
                    break
                others.add(tb)
        miss += not hit
    return miss

rng, same = random.Random(2), 0
for _ in range(300):
    size = rng.choice([256, 512, 1024])
    ways = rng.choice([w for w in (1, 2, 4, 8, 16) if w * 64 <= size])
    tr = [rng.randrange(4096) for _ in range(150)]
    c = Cache(size, ways)
    for a in tr:
        c.access(a)
    same += c.miss == by_definition(tr, size, ways)
print(f"무작위 300개 비교: {same}개 일치")
```
```text
무작위 300개 비교: 300개 일치
```

## 태그 비교 회로의 값
w웨이 캐시는 찾을 때마다 비교기 w개가 태그 비트를 동시에 맞춰 보고, 일치 신호 w개로 w:1 멀티플렉서를 움직인다. 지연을 줄이려고 태그와 데이터를 함께 읽으면 쓰지도 않을 줄 w − 1개까지 매번 읽는다. 완전 연관은 모든 줄의 태그를 비교하는 **내용 주소 메모리**(CAM)가 된다. 앞 코드에 이어서, 32KiB 캐시에서 웨이 수를 바꾸며 태그 비트 수, 찾기 한 번에 비교하는 비트 수, 태그 저장 비율(48비트 주소, 유효·더티 비트 포함, LRU 비트 제외)을 계산한다.
```python
meta = []
for ways in (1, 2, 8, 64, 512):          # 32KiB, 64바이트 줄 512개
    sets = 32768 // (64 * ways)
    tagb = 48 - 6 - (sets.bit_length() - 1)
    meta.append(512 * (tagb + 2) / (32768 * 8))  # 태그 + 유효·더티
    print(f"{ways:3}웨이: 집합 {sets:3}, 태그 {tagb}, 비교 {ways * tagb:5}")
print(f"태그 저장 비율: {meta[0]:.1%} ~ {meta[-1]:.1%}")
```
```text
  1웨이: 집합 512, 태그 33, 비교    33
  2웨이: 집합 256, 태그 34, 비교    68
  8웨이: 집합  64, 태그 36, 비교   288
 64웨이: 집합   8, 태그 39, 비교  2496
512웨이: 집합   1, 태그 42, 비교 21504
태그 저장 비율: 6.8% ~ 8.6%
```
태그 저장은 웨이 수와 거의 무관하게 7~9%지만, 찾기 한 번에 맞춰 보는 비트는 웨이 수에 정비례해 완전 연관에서 2만 비트가 넘는다. 비교기 출력을 모으는 OR 트리와 멀티플렉서도 깊어져 지연이 늘고, 매 접근의 전력도 커진다. 그래서 수 사이클 안에 답해야 하는 L1은 8~12웨이에 머물고, 완전 연관은 항목이 수십 개인 작은 구조(일부 TLB 등)에만 쓴다. 지연을 더 허용하는 L2·L3는 태그를 먼저 비교한 뒤 일치한 웨이의 데이터만 읽는 식으로 전력을 아끼기도 한다. 웨이 수는 제품마다 다르다(젠 4 L2는 8웨이, 아래 표의 제온 L2는 16웨이).

## L1이 32KiB 8웨이인 이유
앞에서 태그가 4KiB 페이지 번호와 같았다. 32KiB ÷ 8웨이 = 4KiB이므로 인덱스와 오프셋이 주소의 아래 12비트, 곧 페이지 안 위치에 다 들어간다. 이 12비트는 가상 주소와 물리 주소가 같으므로, L1은 가상 주소로 집합을 고르는 동안 TLB가 물리 주소를 계산하고, 태그 비교는 물리 태그로 한다. 이것이 **VIPT**(virtually indexed, physically tagged)이고, 같은 물리 줄이 두 집합에 들어가는 별칭 문제도 없다(TLB는 7편). 이 조건을 지키며 L1을 키우려면 웨이를 늘려야 한다. 인텔 골든 코브의 48KiB 12웨이 L1D도 웨이 하나가 4KiB다. L1 용량이 오랫동안 32~48KiB에 머문 데에는 이런 구조적 이유가 있다.

## 코드에 주는 의미
- 2의 큰 거듭제곱 간격으로 놓인 배열이나 행(예: 폭 4,096바이트인 행렬의 열)을 함께 훑으면 같은 집합에 몰린다. 위 예처럼 웨이 수보다 하나만 많아도 미스가 100%로 뛴다. 배열 시작에 64바이트쯤 덧대거나 행 폭을 2의 거듭제곱에서 비켜 놓으면 풀린다.
- 캐시는 줄 단위다. 1바이트를 읽어도 64바이트를 가져오므로, 함께 쓰는 필드를 한 줄에 모으면 이득이다(4편의 AoS·SoA).

## 숫자로 보기
이 글을 쓴 컨테이너의 CPU(인텔 제온, 캐스케이드 레이크 계열)를 `getconf`로 확인한 값이다. 줄은 모두 64바이트다.

| 캐시 | 크기·연관도 | 집합 수 |
|---|---|---|
| L1D | 32KiB, 8웨이 | 64 |
| L2 | 1MiB, 16웨이 | 1,024 |
| L3 | 33MiB, 11웨이 | 49,152 |

- L3의 집합 수가 2의 거듭제곱이 아니다. 이 세대 제온의 L3는 코어마다 1.375MB 조각(slice)으로 나뉘고 주소 해시로 조각을 고르므로, 조각 하나 안에서만 2의 거듭제곱 인덱스를 쓴다.
- 비교: AMD 젠 4 L1D는 32KiB 8웨이, 인텔 골든 코브 L1D는 48KiB 12웨이다.
- SRAM 비트셀 면적: TSMC N5와 N3E 고밀도 셀 모두 0.021µm²(IEDM 2022 발표 기준). 로직은 줄어드는데 SRAM이 그대로라 같은 용량의 캐시가 다이에서 차지하는 비율이 커진다.

## 어디에 쓰이나
- 트랜지스터에서 자연어까지 4편 「순차 회로: 클록, 플립플롭, 메모리」: 그 글의 SR 래치 되먹임이 이 글 6T 셀의 엇갈린 인버터 고리다.
- 추상 데이터 타입 심화 16편 「해시 테이블 깊이 보기: 개방 주소법, 로빈 후드, 뻐꾸기 해싱」: 인덱스 비트로 집합을 고르는 캐시는 주소의 아래 비트를 해시로 쓰는 버킷 w칸짜리 해시 테이블이다.
- 7편 「가상 메모리 하드웨어: 페이지 테이블 워크와 TLB」: VIPT L1이 TLB와 나란히 동작하는 조건이 이 글의 "웨이 하나 = 4KiB"다.

## 정리
- 6T SRAM 셀은 엇갈린 인버터로 값을 붙잡고, 읽을 때는 미리 충전한 비트선의 작은 차이를 감지 증폭기가 키운다.
- 주소는 오프셋(줄 안 위치)·인덱스(집합)·태그(나머지)로 나뉘고, 찾기는 집합 하나의 태그 w개를 동시에 비교한다.
- 같은 4KiB 캐시에서 64KiB 간격 배열 셋은 1·2웨이에서 미스 100%, 4웨이 이상에서 12.5%였다.
- 웨이가 늘면 비교 비트와 읽는 양이 정비례해 늘어나므로, L1은 4KiB × 웨이 수(VIPT 조건) 안에서 8~12웨이를 고른다.
