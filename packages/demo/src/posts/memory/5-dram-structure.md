# [메모리 시스템 5/10] DRAM의 구조: 1T1C 셀, 뱅크, 행 버퍼, 리프레시

> **한 줄 요약** — DRAM은 트랜지스터 하나와 축전기 하나로 1비트를 담아 촘촘하지만, 읽기가 전하를 비트선과 나눠 갖는 파괴적 동작이라 행 하나를 통째로 감지 증폭기(행 버퍼)에 올려야 하므로, 열린 행을 다시 읽으면 tCL만, 다른 행이면 tRP + tRCD + tCL이 걸리고, 새는 전하를 채우는 리프레시가 시간의 몇 %를 떼어 간다.

## 이 글에서 다루는 것
- 1T1C 셀과 감지 증폭기: 전하 나눠 갖기와 파괴적 읽기
- 채널·랭크·칩·뱅크 그룹·뱅크·행·열의 계층
- ACT·RD·PRE 명령과 tRCD·tCL·tRP, 행 버퍼 적중·빈 뱅크·충돌
- 파이썬 타이밍 모델로 순차·무작위·뱅크 충돌 접근의 평균 지연, 공식과 대조
- 리프레시의 비용(DDR5 16Gb 기준)

## 병목: 촘촘하게 만들면 읽기가 어려워진다
1편에서 본 대로 SRAM은 비트마다 트랜지스터 6개라 기가바이트를 담을 수 없다. DRAM 셀은 트랜지스터 1개와 축전기 1개(1T1C)뿐이다. 트랜지스터에서 자연어까지 4편 「순차 회로: 클록, 플립플롭, 메모리」에서 본 대로 IBM의 로버트 데나드가 고안해 1968년 특허를 받은 구조다. 대가는 읽기다. SRAM 셀은 스스로 비트선을 끌어내릴 힘이 있지만, DRAM 셀은 작은 축전기에 담긴 전하가 전부다.
```text
 word line ───────┬────────
                  │ gate
 bit line ────── [T] ── C ── plate
```
워드선이 켜지면 트랜지스터 T가 열려 축전기 C가 비트선과 이어진다. 비트선은 미리 전압의 절반(V/2)으로 충전해 둔다. 셀의 전하가 비트선과 **나눠지면서** 비트선 전압이 아주 조금 오르거나 내린다.
```text
ΔV = (V_cell − V/2) × Cs / (Cs + Cb)
   = ±0.5V × 10fF / (10fF + 40fF)
   = ±0.1V
```
숫자는 설명용 가정이다(V = 1.0V, 셀 용량 Cs = 10fF, 비트선 용량 Cb = 40fF). 비트선에는 셀 수백 개가 매달려 Cb가 Cs보다 몇 배 크므로 신호가 작다. 엇갈린 인버터 한 쌍인 **감지 증폭기**(sense amplifier)가 이 작은 차이를 기준 비트선과 비교해 0V나 V까지 키운다. 그런데 나눠 가진 순간 셀의 전하는 이미 망가졌다. **파괴적 읽기**(destructive read)다. 다행히 감지 증폭기가 키운 전압이 아직 열린 트랜지스터를 통해 셀을 다시 채워 준다.

## 행 버퍼: 한 번 열면 한 행을 통째로
워드선 하나에는 셀 수천 개가 매달려 있어 켜는 순간 행 전체가 비트선으로 나온다. 그래서 감지 증폭기 줄은 행 하나를 통째로 붙잡는 **행 버퍼**(row buffer)가 되고, 이후의 읽기·쓰기는 행 버퍼에서 일부 열만 골라 한다. DDR5 16Gb x8 칩이라면 행 하나가 1KB다.
```text
channel
└ rank (chips in lockstep)
  └ chip (x8: 8 data pins)
    └ bank group x 8
      └ bank x 4
        └ row x 65,536
          └ 1KB row → row buffer
```
뱅크마다 행 버퍼가 따로 있어서 뱅크는 서로 독립적으로 행을 열고 닫는다. 16Gb x8 DDR5는 뱅크 그룹 8개 × 뱅크 4개 = 32뱅크다. 랭크는 같은 명령을 동시에 받는 칩 묶음이고, 64바이트 캐시 줄 하나는 여러 칩이 몇 비트씩 나눠 낸다. DDR5의 32비트 서브채널과 버스트 길이, 여러 채널에 주소를 흩는 방식은 6편에서 다룬다.

## 명령과 타이밍: tRCD, tCL, tRP
메모리 컨트롤러는 세 가지 명령으로 뱅크를 움직인다.
- **ACT**(activate): 행을 열어 행 버퍼에 올린다. 열 명령을 내리려면 **tRCD**(RAS-to-CAS delay)를 기다린다.
- **RD/WR**: 행 버퍼의 열을 읽거나 쓴다. 읽기 명령부터 데이터가 나오기까지가 **tCL**(CAS latency)이다.
- **PRE**(precharge): 행을 닫고 비트선을 다시 V/2로 충전한다. 같은 뱅크에 다음 ACT를 내리려면 **tRP**를 기다린다. 행은 최소 tRAS 동안 열려 있어야 닫을 수 있다.

그래서 요청 하나의 지연은 그 뱅크의 상태로 정해진다. 원하는 행이 이미 열려 있으면 **행 버퍼 적중**으로 tCL, 뱅크가 닫혀 있으면(빈 뱅크, 흔히 행 버퍼 미스라 부른다) tRCD + tCL, 다른 행이 열려 있으면 **행 충돌**로 tRP + tRCD + tCL이다. 메모리 컨트롤러가 읽은 행을 열어 두는 **열린 페이지 정책**(open-page)은 다음 요청이 같은 행이라는 데 거는 내기다.

JEDEC DDR5-4800B 타이밍(CL 40, tRCD 39, tRP 39클록)으로 세 경우를 계산하고, 뱅크 32개에 행 하나가 4KiB(x8 칩 4개가 1KB씩, 가정)인 타이밍 모델로 접근 패턴별 평균 지연을 잰다. 주소는 4KiB마다 다음 뱅크로 넘어가게 사상했고, 버스·컨트롤러 시간과 tRAS는 뺐으며, 요청은 하나씩 차례로 처리한다.
```python
import random
from fractions import Fraction as F

TCK = F(5, 12)                       # ns, DDR5-4800의 클록 2400MHz
CL, RCD, RP = 40, 39, 39             # JEDEC DDR5-4800B, 클록 수
COST = (CL, RCD + CL, RP + RCD + CL)  # 적중, 빈 뱅크, 행 충돌
for name, c in zip(("행 버퍼 적중", "빈 뱅크", "행 충돌"), COST):
    print(f"{name}: {c}클록 = {float(c * TCK):.2f}ns")

BANKS, ROW_LINES = 32, 64            # 뱅크 32개, 행 하나에 64바이트 줄 64개

def where(addr):                     # 주소 → (뱅크, 행). 4KiB마다 다음 뱅크
    line = addr // 64
    return line // ROW_LINES % BANKS, line // (ROW_LINES * BANKS)

def run(addrs):
    """열린 페이지 정책: 읽은 행을 열어 둔다. 요청은 하나씩 차례로"""
    opened, cyc, kind = [None] * BANKS, 0, [0, 0, 0]
    for a in addrs:
        b, r = where(a)
        k = 0 if opened[b] == r else 1 if opened[b] is None else 2
        kind[k] += 1
        cyc += COST[k]
        opened[b] = r
    return cyc, kind

N, rng = 16384, random.Random(6)
far = 1 << 20                        # 1MiB 떨어지면 같은 뱅크, 다른 행
pats = {
    "순차 1MiB": [64 * i for i in range(N)],
    "무작위 1GiB": [64 * rng.randrange(1 << 24) for _ in range(N)],
    "a·b 같은 뱅크": [64 * (i // 2) + i % 2 * far for i in range(N)],
    "a·b 다른 뱅크":
        [64 * (i // 2) + i % 2 * (far + 4096) for i in range(N)],
}
res = {}
for name, tr in pats.items():
    cyc, kind = res[name] = run(tr)
    print(f"{name}: 평균 {float(cyc * TCK / N):.2f}ns,"
          f" 적중 {kind[0] / N:.1%}")
```
```text
행 버퍼 적중: 40클록 = 16.67ns
빈 뱅크: 79클록 = 32.92ns
행 충돌: 118클록 = 49.17ns
순차 1MiB: 평균 17.14ns, 적중 98.4%
무작위 1GiB: 평균 49.13ns, 적중 0.0%
a·b 같은 뱅크: 평균 49.13ns, 적중 0.0%
a·b 다른 뱅크: 평균 17.14ns, 적중 98.4%
```
DRAM 칩 안에서만 같은 64바이트를 읽는 데 16.7ns에서 49.2ns까지 세 배 차이가 난다. 순차 접근은 행 하나에서 64줄 중 63줄이 적중이다. 무작위 접근은 거의 늘 다른 행이 열려 있어 행 충돌 비용을 다 낸다. 마지막 두 줄이 눈여겨볼 점이다. 두 배열을 번갈아 읽는 같은 코드인데, 두 배열이 같은 뱅크의 다른 행에 놓이면 서로의 행을 닫아 매번 충돌이고, 4KiB만 비켜 다른 뱅크에 놓이면 각자 행을 열어 둔 채 적중한다. 1편의 70ns 남짓한 메모리 지연 중 나머지는 캐시 계층을 거치는 시간, 코어와 메모리 컨트롤러 사이의 연결망, 컨트롤러 대기열, 데이터 전송 시간이다.

앞 코드에 이어서, 순차 접근은 손으로 센 공식(처음 32행은 빈 뱅크, 나머지 224행은 충돌, 나머지는 적중)과 정확히 같은지, 무작위 접근은 "같은 뱅크의 같은 행일 확률 1/8192"로 계산한 기댓값과 가까운지 확인한다.
```python
rows = N // ROW_LINES                     # 순차가 지나간 행 256개
want = (N - rows) * CL + BANKS * COST[1] + (rows - BANKS) * COST[2]
print("순차 = 손으로 센 공식:", res["순차 1MiB"][0] == want)
p = F(1, (1 << 30) // (4096 * BANKS))     # 무작위: 같은 행일 확률 1/8192
approx = (p * CL + (1 - p) * COST[2]) * TCK
print("무작위 ≈ 확률 계산(0.1ns 안):",
      abs(res["무작위 1GiB"][0] * TCK / N - approx) < F(1, 10))
```
```text
순차 = 손으로 센 공식: True
무작위 ≈ 확률 계산(0.1ns 안): True
```

## 리프레시의 비용
축전기의 전하는 새어 나가므로 주기적으로 읽어서 다시 써야 한다. 리프레시는 결국 행을 열었다 닫는 일이다. DDR5는 32ms 안에 모든 행을 리프레시하고, 컨트롤러는 평균 tREFI마다 REF 명령을 내린다. 일반 리프레시 동안 tRFC만큼 그 랭크의 뱅크는 다른 일을 못 한다. 16Gb DDR5의 tRFC는 295ns다. 앞 코드에 이어서, 리프레시가 떼어 가는 시간과, 아무 때나 도착한 요청이 리프레시에 걸려 더 기다리는 평균 시간을 계산한다.
```python
tREFI, tRFC = 32e6 / 8192, 295            # ns. 32ms에 REF 8192번, 16Gb
print(f"tREFI = {tREFI:.1f}ns")
print(f"REF 한 번에 뱅크마다 {65536 // 8192}행")
print(f"리프레시가 랭크를 막는 시간: {tRFC / tREFI:.2%}")
M = 100000                                # 한 주기 안에 고르게 도착한 요청
waits = [max(0, tRFC - (k + 0.5) * tREFI / M) for k in range(M)]
formula = tRFC ** 2 / (2 * tREFI)         # 막힐 확률 × 평균 남은 시간
print(f"추가 대기: 모의 {sum(waits) / M:.2f}ns,"
      f" 공식 {formula:.2f}ns")
```
```text
tREFI = 3906.2ns
REF 한 번에 뱅크마다 8행
리프레시가 랭크를 막는 시간: 7.55%
추가 대기: 모의 11.14ns, 공식 11.14ns
```
3.9µs마다 0.3µs, 시간의 7.5%를 리프레시가 가져가고, 무작위 시각의 요청은 평균 11ns를 더 기다린다(뱅크마다 65,536행이라 보면 REF 한 번에 8행씩이라는 단순 계산). 칩 용량이 커질수록 행이 많아져 tRFC가 길어지고, 85°C를 넘으면 누설이 빨라져 tREFI가 절반이 된다. 그래서 DDR5는 뱅크 그룹마다 같은 번호의 뱅크만 리프레시하는 동일 뱅크 리프레시(same-bank refresh)도 두어, 나머지 뱅크가 그동안 요청을 받게 한다. 이웃 행을 너무 자주 열면 리프레시 전에 전하가 새어 비트가 뒤집히는 로우해머는 10편에서 다룬다.

## 코드에 주는 의미
- DRAM에서도 순차 접근이 이긴다. 같은 행의 연속 줄은 행 버퍼 적중이라 무작위 접근의 3분의 1 지연이다. 프리페처와 버스트가 이 효과를 더 키운다.
- 여러 배열을 동시에 훑을 때, 배열 시작이 큰 2의 거듭제곱 간격이면 같은 뱅크의 다른 행에 몰려 행 충돌이 날 수 있다. 실제 컨트롤러는 주소 비트를 XOR로 섞어 뱅크를 고르므로 효과는 제품마다 다르지만, 원리는 2편의 캐시 집합 충돌과 같다.
- CL 같은 클록 수는 세대마다 커졌지만 클록이 빨라져 ns로는 비슷하다. 램 사양의 숫자는 ns로 바꿔 비교한다.

## 정리
- DRAM 셀은 1T1C라 촘촘하지만, 읽기가 전하를 나눠 갖는 파괴적 동작이라 감지 증폭기가 키우고 다시 채워야 한다.
- 행을 열면 행 전체가 행 버퍼에 올라오고, 지연은 적중(tCL)·빈 뱅크(tRCD + tCL)·충돌(tRP + tRCD + tCL)로 갈린다. DDR5-4800B에서 16.67·32.92·49.17ns다.
- 같은 코드도 두 배열이 같은 뱅크에 있으면 평균 49ns, 다른 뱅크에 있으면 17ns였다.
- 16Gb DDR5의 리프레시는 시간의 7.55%를 가져가고 요청 하나에 평균 11ns를 더한다.
