# [메모리 시스템 8/10] HBM과 GDDR: 넓게 쌓은 메모리와 빠르게 달리는 메모리

> **한 줄 요약** — GPU 메모리 대역폭은 핀 수 × 핀당 속도이고, GDDR은 32비트 칩의 핀을 PAM4·PAM3 신호로 수십 Gb/s까지 달려 이 곱을 키우며, HBM은 DRAM 다이를 TSV로 쌓고 실리콘 인터포저 위에서 스택당 1024개 선을 GPU에 바로 이어 폭으로 키운다.

## 이 글에서 다루는 것
- GPU가 대역폭에 굶주리는 이유: H100의 FLOP/바이트
- GDDR의 신호 방식: NRZ, PAM4(GDDR6X), PAM3(GDDR7)를 부호화해 보기
- HBM의 구조: 적층 다이, TSV, 실리콘 인터포저, 스택당 1024비트
- 세대·제품별 대역폭 계산과 용량·전력·비용의 맞바꿈

## 병목: GPU는 대역폭에 굶주린다
GPU는 연산 장치 수만 개를 동시에 돌리므로(GPU와 CUDA 2편 「GPU 하드웨어 구조: GPC, SM, 워프 스케줄러, 텐서 코어」) 데이터를 대 주는 속도도 CPU와 자릿수가 다르게 필요하다. H100 SXM5는 FP16 텐서 연산이 밀집 기준 989TFLOPS인데 HBM3 대역폭은 3.35TB/s다. 메모리에서 1바이트를 읽을 때마다 연산을 300번 가까이 하지 않으면 연산 장치가 논다. 언어 모델의 토큰 생성처럼 가중치를 한 번 읽어 한두 번만 쓰는 일은 대역폭이 속도를 거의 다 정한다. 6편 「DDR 메모리와 메모리 컨트롤러: 채널, 버스트, 스케줄링」의 공식이 여기서도 출발점이다.
```text
대역폭 = 핀 수 × 핀당 속도 ÷ 8
```
DDR5 DIMM은 64핀에 핀당 수 Gb/s다. 이 곱을 수십 배 키우는 길은 둘이다. 핀을 빠르게(GDDR), 핀을 많이(HBM).

## GDDR: 핀을 빠르게
**GDDR**(graphics DDR)은 그래픽 카드 기판에 GPU를 둘러싸고 납땜하는 DRAM이다. 칩 하나가 32비트 폭이고, 칩을 여러 개 나란히 붙여 버스를 넓힌다. RTX 4090은 칩 12개로 384비트다.
```text
     [G][G][G][G]
  [G]┌──────────┐[G]
     │   GPU    │
  [G]└──────────┘[G]
     [G][G][G][G]
 G = 32-bit GDDR chip on PCB
```
기판 위 배선은 길고 가닥 수에 한계가 있으니 핀당 속도를 극한까지 올린다. 기존 방식인 **NRZ**는 전압 준위 두 개로 기호 하나에 1비트를 보낸다. 마이크론과 엔비디아의 **GDDR6X**는 준위 네 개인 **PAM4**로 기호 하나에 2비트를, 2024년 3월 JEDEC 표준이 된 **GDDR7**은 준위 세 개인 **PAM3**로 기호 두 개에 3비트를 싣는다(3² = 9가지로 2³ = 8가지를 담는다). 같은 비트 속도를 더 낮은 기호 속도로 내는 대신, 같은 전압 폭을 잘게 나누므로 준위 사이 간격(눈 높이)이 줄어 잡음에 약해진다. 부호화와 복호화를 직접 해 보자. PAM3 표는 설명용이며 실제 GDDR7 부호표와는 다르다.
```python
import math, random

def pam4(bits):                   # 2비트 → 4준위 기호 하나
    return [2 * a + b for a, b in zip(bits[::2], bits[1::2])]

def un_pam4(sym):
    return [x for v in sym for x in (v >> 1, v & 1)]

def pam3(bits):                   # 3비트(8가지) → 3준위 기호 2개(9가지)
    out = []
    for i in range(0, len(bits), 3):
        v = 4 * bits[i] + 2 * bits[i + 1] + bits[i + 2]
        out += [v // 3, v % 3]
    return out

def un_pam3(sym):
    out = []
    for a, b in zip(sym[::2], sym[1::2]):
        v = 3 * a + b
        out += [v >> 2, v >> 1 & 1, v & 1]
    return out

rng = random.Random(1)
ok = True
for _ in range(300):              # 무작위 96비트를 부호화했다가 되돌리기
    bits = [rng.randrange(2) for _ in range(96)]
    ok &= un_pam4(pam4(bits)) == bits and un_pam3(pam3(bits)) == bits
print("무작위 300개 왕복:", "모두 일치" if ok else "불일치")

for name, enc, lv in [("NRZ ", list, 2), ("PAM3", pam3, 3), ("PAM4", pam4, 4)]:
    per = 96 / len(enc(bits))     # 기호 하나에 실리는 비트
    eye = 1 / (lv - 1)            # 같은 전압 폭에서 준위 사이 간격
    print(f"{name}: 기호당 {per:.2f}비트, 32Gb/s → {32 / per:4.1f}GBd,",
          f"눈 높이 {eye:.2f} ({20 * math.log10(eye):5.1f}dB)")
```
```text
무작위 300개 왕복: 모두 일치
NRZ : 기호당 1.00비트, 32Gb/s → 32.0GBd, 눈 높이 1.00 (  0.0dB)
PAM3: 기호당 1.50비트, 32Gb/s → 21.3GBd, 눈 높이 0.50 ( -6.0dB)
PAM4: 기호당 2.00비트, 32Gb/s → 16.0GBd, 눈 높이 0.33 ( -9.5dB)
```
같은 32Gb/s를 NRZ는 32GBd(초당 기호 320억 개)로, PAM4는 16GBd로 낸다. 기호 속도가 반이면 선이 견뎌야 할 주파수도 반이다. 대신 눈 높이가 1/3로 줄어 9.5dB를 잃는다. PAM3는 그 중간으로 기호당 1.5비트에 6dB 손실이다. GDDR7은 PAM4보다 덜 잘게 나눠 잡음 여유를 지키면서 NRZ보다 기호 속도를 낮춘 절충이다.

## HBM: 핀을 많이
**HBM**(high bandwidth memory)은 반대로 간다. DRAM 다이 여러 장을 수직으로 쌓고, 다이를 관통하는 구리 기둥 **TSV**(through-silicon via)로 위아래를 이은 뒤, 맨 아래 베이스(로직) 다이가 바깥과 통신한다. 이 스택을 GPU 바로 옆, 같은 **실리콘 인터포저** 위에 올린다. 인터포저는 반도체 공정으로 배선을 새긴 실리콘 판이라 기판보다 훨씬 촘촘한 선을 수천 가닥 깔 수 있고, 그래서 스택 하나가 1024비트 폭으로 GPU와 직접 이어진다. TSMC의 CoWoS가 이 패키징의 대표 공정이다.
```text
 ┌────────┐
 │ DRAM 3 │  ← dies stacked,
 │ DRAM 2 │    linked by TSVs
 │ DRAM 1 │
 │ DRAM 0 │
 │ base   │      ┌────────┐
 └───┬────┘      │  GPU   │
 ════╧═══════════╧════════╧═══
   silicon interposer
   (1024 wires per stack)
 ═════════════════════════════
   package substrate
```
선이 짧고 많으니 핀 하나는 느려도 된다. 첫 HBM(JEDEC 2013년 10월, 첫 제품은 2015년 AMD 라데온 R9 퓨리 X)은 핀당 1Gb/s였다. 스택의 1024비트는 독립 채널로 나뉘는데, HBM3는 64비트 채널 16개다. 2025년 4월 표준이 된 HBM4는 인터페이스를 2048비트로 넓히고 채널도 32개로 늘렸다.

## 세대별 대역폭
앞 코드에 이어서, 칩·스택 하나의 대역폭과 제품 전체의 대역폭을 계산한다. 핀 속도가 공개된 제품은 버스 폭 × 핀 속도가 발표 대역폭과 맞는지 보고, HBM 제품은 거꾸로 발표 대역폭에서 핀 속도를 구한다.
```python
def gbs(pins, gbps):              # 대역폭(GB/s) = 핀 수 × 핀당 속도 ÷ 8
    return pins * gbps / 8

for name, pins, rate in [("GDDR6X 칩", 32, 21), ("GDDR7 칩", 32, 32),
                         ("HBM2 스택", 1024, 2.0), ("HBM3 스택", 1024, 6.4),
                         ("HBM3E 스택", 1024, 9.2), ("HBM4 스택", 2048, 8.0)]:
    print(f"{name}: {pins}핀 × {rate}Gb/s = {gbs(pins, rate):.1f}GB/s")

print("제품: 버스 폭 × 핀 속도 = 발표 대역폭?")
for name, width, rate, bw in [("R9 Fury X, HBM", 4096, 1.0, 512),
                              ("RTX 4090, GDDR6X", 384, 21, 1008),
                              ("RTX 5090, GDDR7", 512, 28, 1792)]:
    print(f"  {name}: {gbs(width, rate):.0f}GB/s, 일치 {gbs(width, rate) == bw}")
print("제품: 발표 대역폭 ÷ 버스 폭 = 핀 속도")
for name, width, bw in [("A100 40GB, HBM2", 5120, 1555),
                        ("H100 SXM5, HBM3", 5120, 3350)]:
    print(f"  {name}: {bw * 8 / width:.2f}Gb/s")
print(f"H100 연산 ÷ 대역폭: {989e12 / 3.35e12:.0f} FLOP/바이트")
print(f"8B 모델 FP16(16GB) 토큰 상한: {3350 / 16:.0f}개/초")
```
```text
GDDR6X 칩: 32핀 × 21Gb/s = 84.0GB/s
GDDR7 칩: 32핀 × 32Gb/s = 128.0GB/s
HBM2 스택: 1024핀 × 2.0Gb/s = 256.0GB/s
HBM3 스택: 1024핀 × 6.4Gb/s = 819.2GB/s
HBM3E 스택: 1024핀 × 9.2Gb/s = 1177.6GB/s
HBM4 스택: 2048핀 × 8.0Gb/s = 2048.0GB/s
제품: 버스 폭 × 핀 속도 = 발표 대역폭?
  R9 Fury X, HBM: 512GB/s, 일치 True
  RTX 4090, GDDR6X: 1008GB/s, 일치 True
  RTX 5090, GDDR7: 1792GB/s, 일치 True
제품: 발표 대역폭 ÷ 버스 폭 = 핀 속도
  A100 40GB, HBM2: 2.43Gb/s
  H100 SXM5, HBM3: 5.23Gb/s
H100 연산 ÷ 대역폭: 295 FLOP/바이트
8B 모델 FP16(16GB) 토큰 상한: 209개/초
```
GDDR7 칩 하나(128GB/s)는 HBM2 스택의 절반이고, HBM3E 스택 하나는 GDDR7 칩 9개 분량이다. RTX 5090은 512비트를 28Gb/s로 달려 1.8TB/s를 내고, H100은 5120비트를 5.23Gb/s로 천천히 돌려 3.35TB/s를 낸다. 핀 수가 10배라 핀 속도가 1/5이어도 대역폭이 두 배다. H100은 HBM3 핀 상한(6.4Gb/s)보다 낮게 돈다. 마지막 줄은 배치 1에서 토큰마다 가중치 16GB를 한 번씩 읽는다고 둔 상한이다. 연산이 아무리 빨라도 초당 209개를 넘지 못한다.

## 맞바꿈: 용량·전력·비용
- **용량**: GDDR7 칩은 2GB급이라 512비트 카드가 칩 16개로 32GB다. HBM은 스택 하나에 다이를 8~12장 쌓아 HBM3E 스택이 24~36GB이고, HBM4 표준은 16장까지 쌓아 64GB를 정의한다. 데이터센터 GPU가 HBM을 쓰는 이유의 절반은 용량이다.
- **전력**: HBM은 선이 짧고 느리게 돌아 비트당 에너지가 작다. GDDR은 긴 기판 선을 빠르게 구동하느라 비트당 에너지가 크다.
- **비용**: HBM은 TSV 공정, 다이 적층, 인터포저 패키징이 모두 비싸고 단계마다 수율 위험이 쌓인다. AI 가속기 수요가 몰린 2023년 이후로는 HBM과 인터포저 패키징의 생산 능력이 공급 병목으로 꼽혔다.
- **확장**: GDDR은 칩을 더 붙이면 버스가 넓어지지만 기판 배선이 한계다. HBM은 인터포저 면적이 스택 수를 제한한다. H100은 스택 5개, H200은 HBM3E로 141GB·4.8TB/s다.

그래서 소비자 그래픽 카드는 GDDR, 데이터센터 가속기는 HBM으로 갈렸다.

## 코드에 주는 의미
- GPU 커널의 속도는 대개 바이트로 정해진다. 같은 계산을 더 적은 바이트로 하는 것(재사용, 타일링, 저정밀도)이 연산을 줄이는 것보다 효과가 크다.
- 옮길 바이트 ÷ 대역폭이 커널 시간의 하한이다. 측정값이 이에 가까우면 더 줄일 곳은 바이트뿐이다. 이 판단을 일반화한 것이 GPU와 CUDA 13편 「루프라인 모델과 프로파일링: 계산이 한계인가 메모리가 한계인가」다.
- 가중치를 FP16에서 4비트로 줄이면 토큰 생성 상한이 4배 가까이 오른다. 양자화가 추론을 빠르게 하는 주된 이유다.

- GPU와 CUDA 2편 「GPU 하드웨어 구조: GPC, SM, 워프 스케줄러, 텐서 코어」: SM과 L2 아래에 붙은 메모리 컨트롤러와 HBM 스택이 이 글의 구조다.
- 어텐션 7편 「플래시 어텐션: 메모리 계층을 아는 정확한 어텐션」: HBM이 아무리 넓어도 칩 안 SRAM보다 한 자릿수 느리므로 HBM 왕복을 줄이는 타일링이 빨라진다.
- AI 기초 4편 「컴퓨터 사이언스로 보는 AI 모델: 텐서, 연산, 메모리」: 토큰 생성 속도 ≈ 메모리 대역폭 ÷ 모델 크기라는 그 글의 어림을 위에서 H100 숫자로 계산했다.
- 양자화 12편 「KV 캐시·활성값·FP8: 추론과 학습의 저정밀화」: 읽는 바이트를 줄이는 저정밀화는 대역폭이 한계인 GPU에서 곧 속도다.

## 정리
- GPU 메모리 대역폭은 핀 수 × 핀당 속도이고, H100은 바이트당 약 300 FLOP를 해야 연산 장치를 채울 만큼 대역폭이 귀하다.
- GDDR은 32비트 칩의 핀을 PAM4(GDDR6X)·PAM3(GDDR7)로 빠르게 달린다. 기호당 비트를 늘리면 기호 속도는 줄지만 눈 높이도 준다.
- HBM은 다이를 TSV로 쌓고 인터포저 위에서 스택당 1024비트(HBM4는 2048비트)를 GPU에 바로 잇는다. 핀은 느려도 폭이 대역폭을 만든다.
- HBM은 용량·전력에서 앞서고 비용·공급에서 뒤져, 데이터센터는 HBM, 소비자 카드는 GDDR을 쓴다.
