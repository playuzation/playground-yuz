# [메모리 시스템 6/10] DDR 메모리와 메모리 컨트롤러: 채널, 버스트, 스케줄링

> **한 줄 요약** — DDR은 느린 셀 배열에서 한 번에 여러 비트를 꺼내 클록의 양쪽 에지에 버스트로 실어 핀 속도를 올리고, 메모리 컨트롤러는 주소를 채널·뱅크로 흩고 열린 행에 맞는 요청을 먼저 처리하는 FR-FCFS로 같은 요청을 몇 배 빨리 끝낸다.

## 이 글에서 다루는 것
- "두 번 전송"과 프리페치: 느린 셀 배열로 빠른 핀을 채우는 법
- 버스트 길이와 DDR4·DDR5의 차이(32비트 서브채널 두 개, BL16)
- 대역폭 = 전송률 × 버스 폭, CL을 나노초로 바꾸기
- 주소 사상과 FR-FCFS 스케줄링을 FCFS와 비교하는 시뮬레이션

## 병목: 셀 배열은 빨라지지 않았다
5편 「DRAM의 구조: 1T1C 셀, 뱅크, 행 버퍼, 리프레시」에서 본 대로 DRAM 읽기는 행 활성화(tRCD), 열 읽기(tCL), 프리차지(tRP)를 거치고, 이 시간은 세대가 바뀌어도 십몇 ns 근처에 머문다. 셀 배열이 도는 속도도 수백 MHz 수준이다. 그런데 CPU는 초당 수십 GB를 원한다. 해법은 배열을 빠르게 만드는 대신 **한 번에 많이 꺼내서 빠른 핀으로 줄 세워 내보내는** 것이다.

## 두 번 전송, 프리페치, 버스트
**DDR**(double data rate)은 클록의 상승 에지와 하강 에지에서 모두 데이터를 보낸다. 그래서 DDR4-3200의 3200은 클록 주파수가 아니라 초당 전송 횟수(MT/s)이고 실제 클록은 1600MHz다. 핀 속도와 배열 속도의 차이를 메우는 장치가 **프리페치**(prefetch)다. DDR4는 배열에서 핀당 8비트(8n)를 한꺼번에 읽어 와 핀으로 8번 연달아 내보내므로, 배열은 3200 ÷ 8 = 400MHz로만 돌면 된다. DDR5는 16n이다.

명령 하나에 연달아 실리는 전송 묶음이 **버스트**(burst)이고, 그 횟수가 **버스트 길이**(BL)다. 숫자는 캐시 라인 64바이트에 맞춰져 있다.
```text
 DDR4 DIMM          DDR5 DIMM
┌──────────┐      ┌─────┬─────┐
│ 64-bit   │      │  A  │  B  │
│ x BL8    │      │32bit│32bit│
│ = 64B    │      │BL16 │BL16 │
└──────────┘      └─────┴─────┘
```
DDR4 DIMM은 64비트 채널 하나에 BL8로 버스트 하나가 64바이트다. DDR5는 DIMM을 독립적인 32비트 **서브채널** 두 개로 나누고 BL을 16으로 늘렸다. 폭은 반, 길이는 두 배라 버스트 하나는 여전히 64바이트이고, 두 서브채널이 서로 다른 요청을 동시에 처리한다. 뱅크도 x8 칩 기준 16개(뱅크 그룹 4개)에서 32개(8개)로 늘었다. 코어가 많아져 서로 다른 곳을 노리는 작은 요청이 많아진 환경에 맞춘 변화다.

## 대역폭 = 전송률 × 버스 폭
피크 대역폭은 초당 전송 횟수에 한 번 전송하는 폭을 곱한 값이다. 버스트 하나의 바이트를 버스트 하나의 시간으로 나눠도 같아야 한다. 두 방법으로 계산하고, CL(열 읽기 지연 클록 수)을 나노초로 바꿔 보자. DDR4-3200 22-22-22와 DDR5-4800B 40-39-39는 JEDEC 속도 등급이다.
```python
def peak(mts, bits, n=1):
    """대역폭 = 전송률 × 버스 폭 (GB/s)"""
    return mts * 1e6 * bits / 8 * n / 1e9

def by_burst(mts, bits, bl, n=1):
    """다른 계산: 버스트 하나의 바이트 ÷ 버스트 하나의 시간"""
    size = bits // 8 * bl
    return size / (bl / (mts * 1e6)) * n / 1e9, size

for name, mts, bits, bl, n, cl in [("DDR4-3200", 3200, 64, 8, 1, 22),
                                   ("DDR5-4800", 4800, 32, 16, 2, 40)]:
    a, (b, size) = peak(mts, bits, n), by_burst(mts, bits, bl, n)
    ns = cl / (mts / 2) * 1e3            # 클록 = 전송률의 절반
    print(f"{name}: {a:.1f}GB/s, 버스트 {size}B, CL{cl} = {ns:.2f}ns")
    print(f"  두 계산 일치: {abs(a - b) < 1e-9}")
print(f"DDR5-4800 12채널: {peak(4800, 64, 12):.1f}GB/s")
```
```text
DDR4-3200: 25.6GB/s, 버스트 64B, CL22 = 13.75ns
  두 계산 일치: True
DDR5-4800: 38.4GB/s, 버스트 64B, CL40 = 16.67ns
  두 계산 일치: True
DDR5-4800 12채널: 460.8GB/s
```
DDR5-4800 DIMM은 DDR4-3200보다 대역폭이 1.5배인데 CL은 22에서 40으로 거의 두 배다. 클록이 빨라졌으니 나노초로 바꾸면 13.75ns 대 16.67ns로, 첫 데이터까지의 시간은 세대가 바뀌어도 크게 줄지 않는다. 세대 교체는 주로 대역폭을 키운다. 서버 CPU는 소켓에 채널을 여러 개(최근 세대는 8~12개) 달아 대역폭을 곱하고, DDR5-4800 12채널이면 460.8GB/s다.

## 주소 사상: 요청을 어디로 보낼까
메모리 컨트롤러는 물리 주소의 비트를 잘라 채널·랭크·뱅크 그룹·뱅크·행·열을 정한다. 이것이 **주소 사상**(address mapping)이다. 두 요구가 부딪힌다. 연속 주소를 같은 행에 모으면 행 버퍼 적중이 늘고, 여러 채널·뱅크로 흩으면 병렬성이 는다. 흔한 절충은 몇 라인 단위로 채널을 번갈아 쓰고(인터리빙), 뱅크 비트에 위쪽 행 비트를 XOR해 섞는 것이다. 2의 거듭제곱 간격으로 떨어진 배열들이 한 뱅크에 몰리지 않게 하려는 장치다. 실제 칩의 사상 함수는 대개 공개되지 않아 역공학 연구로 알려진 경우가 많다.
```text
 requests from cores
         ↓
┌──────────────────────┐
│ queue + scheduler    │
│ addr map: ch/bank/row│
└──┬──────┬───────┬────┘
   ↓      ↓       ↓
 bank0  bank1 … bank31
   └──────┴───┬───┘
              ↓
       shared data bus
```

## 스케줄링: FCFS와 FR-FCFS
도착 순서대로 처리하는 **FCFS**(first-come first-served)는 단순하지만, 다른 행을 번갈아 건드리는 요청이 섞이면 매번 프리차지와 활성화를 치른다. 릭스너 외(Rixner 외, ISCA 2000)의 메모리 접근 스케줄링에서 나온 **FR-FCFS**(first-ready FCFS)는 큐에서 열린 행에 맞아 곧바로 읽을 수 있는 요청을 먼저, 없으면 가장 오래된 요청을 고른다. 오늘날 메모리 컨트롤러 스케줄링의 기본형이다.

DDR5-4800B 서브채널 하나를 클록 단위로 흉내 내 보자. 행은 4KiB, 뱅크는 32개다. 뱅크들은 동시에 일하지만 데이터 버스는 하나라 버스트(8클록)가 줄을 선다. tRAS·tFAW·쓰기·리프레시 같은 나머지 제약은 뺐다. 먼저 손으로 셀 수 있는 두 경우로 확인한다. 한 행만 읽으면 `tRCD + tCL + n·tBURST`, 한 뱅크의 두 행을 번갈아 읽으면 매번 프리차지와 활성화가 끼어 `tRCD + (n−1)·(tCCD + tRP + tRCD) + tCL + tBURST`다.
```python
T = dict(CL=40, RCD=39, RP=39, BURST=8, CCD=8)  # DDR5-4800B, 클록

def plain(a):                     # 주소 → (뱅크, 행), 행 4KiB, 뱅크 32개
    return (a >> 12) & 31, a >> 17

def xor(a):                       # 뱅크 비트에 행 비트를 XOR
    return ((a >> 12) ^ (a >> 17)) & 31, a >> 17

def simulate(addrs, mapping, policy, window=16, t=T):
    reqs = [mapping(a) for a in addrs]
    row, ready = {}, {}           # 뱅크별 열린 행, 다음 명령 가능 시각
    bus = hits = 0
    pending, order = list(range(len(reqs))), []
    while pending:
        win = pending[:window]    # 큐에서 가장 오래된 window개만 본다
        pick = win[0]             # FCFS: 가장 오래된 요청
        if policy == "FR-FCFS":   # 열린 행에 맞는 요청이 있으면 먼저
            pick = next((i for i in win
                         if row.get(reqs[i][0]) == reqs[i][1]), pick)
        pending.remove(pick)
        order.append(pick)
        b, r = reqs[pick]
        t0 = ready.get(b, 0)
        if row.get(b) == r:                  # 행 적중: 바로 읽기
            cas, hits = t0, hits + 1
        elif b not in row:                   # 닫힌 뱅크: 활성화 후 읽기
            cas = t0 + t["RCD"]
        else:                                # 충돌: 프리차지·활성화
            cas = t0 + t["RP"] + t["RCD"]
        data = max(cas + t["CL"], bus)       # 데이터 버스는 하나
        cas = data - t["CL"]
        bus = data + t["BURST"]
        ready[b], row[b] = cas + t["CCD"], r
    return bus, hits, order

n, t = 20, T
same = [64 * i for i in range(n)]                    # 한 행만
ping = [(i % 2) << 17 for i in range(n)]             # 한 뱅크의 두 행
f1 = t["RCD"] + t["CL"] + n * t["BURST"]
f2 = (t["RCD"] + (n - 1) * (t["CCD"] + t["RP"] + t["RCD"])
      + t["CL"] + t["BURST"])
print("한 행 연속:", simulate(same, plain, "FCFS")[0], "= 공식", f1)
print("두 행 번갈아:", simulate(ping, plain, "FCFS")[0], "= 공식", f2)
```
```text
한 행 연속: 239 = 공식 239
두 행 번갈아: 1721 = 공식 1721
```
같은 20개 요청이 행 하나에 모이면 239클록, 두 행을 오가면 1,721클록이다. 앞 코드에 이어서, 코어 4개가 1MiB씩 떨어진 영역을 각각 순차로 읽고 요청이 번갈아 도착하는 상황을 만든다. 주소 사상 두 가지와 스케줄러 두 가지를 조합하고, 큐 크기도 바꿔 본다.
```python
streams = [[(k << 20) + 64 * i for i in range(128)] for k in range(4)]
addrs = [s[i] for i in range(128) for s in streams]   # 번갈아 도착
peak_bw = 64 / (8 / 2.4)                  # 서브채널 피크 19.2GB/s
for mname, m in [("plain", plain), ("xor", xor)]:
    print(mname, "뱅크:", sorted({m(s[0])[0] for s in streams}))
    for pol in ("FCFS", "FR-FCFS"):
        cyc, hits, order = simulate(addrs, m, pol)
        assert sorted(order) == list(range(len(addrs)))  # 모두 한 번씩
        gbs = len(addrs) * 64 / (cyc / 2.4)              # 2.4GHz 클록
        print(f"  {pol:7}: {cyc:6}클록, 행 적중 {hits / len(addrs):4.0%},",
              f"{gbs:4.1f}GB/s ({gbs / peak_bw:.0%})")
for w in (4, 16, 64):
    cyc, hits, _ = simulate(addrs, plain, "FR-FCFS", window=w)
    print(f"plain FR-FCFS 큐 {w:2}칸: {cyc:6}클록, 행 적중 {hits / 512:.0%}")
```
```text
plain 뱅크: [0]
  FCFS   :  43955클록, 행 적중   0%,  1.8GB/s (9%)
  FR-FCFS:   8387클록, 행 적중  89%,  9.4GB/s (49%)
xor 뱅크: [0, 8, 16, 24]
  FCFS   :   4175클록, 행 적중  98%, 18.8GB/s (98%)
  FR-FCFS:   4175클록, 행 적중  98%, 18.8GB/s (98%)
plain FR-FCFS 큐  4칸:  21491클록, 행 적중 56%
plain FR-FCFS 큐 16칸:   8387클록, 행 적중 89%
plain FR-FCFS 큐 64칸:   5423클록, 행 적중 96%
```
plain 사상에서는 1MiB 간격이 뱅크 비트를 건드리지 않아 네 영역이 모두 0번 뱅크에 몰린다. FCFS는 요청마다 다른 행을 열어 행 적중 0%, 피크의 9%만 쓴다. FR-FCFS는 큐 16칸 안에서 같은 행 요청을 모아 행 적중 89%, 5.2배 빠르다. 큐가 길수록 모을 요청이 많아 64칸이면 96%다. xor 사상은 네 영역을 뱅크 0·8·16·24로 흩어 같은 뱅크 안에서 행이 바뀌는 일이 거의 없고, FCFS로도 피크의 98%를 쓴다. 이 예에서는 사상이 스케줄러보다 크게 작용했고, 스케줄러는 사상이 피하지 못한 충돌을 구제한다.

FR-FCFS에도 약점이 있다. 행 적중을 계속 앞세우면 다른 행을 기다리는 오래된 요청이 굶는다. 실제 컨트롤러는 나이가 많은 요청을 먼저 처리하는 상한을 두고, 멀티코어의 공정성을 따지는 스케줄러 연구가 이어졌다. 쓰기는 따로 모아 두었다가 한꺼번에 내보낸다. 읽기와 쓰기를 바꿀 때마다 버스 방향을 돌리는 비용이 들기 때문이다.

## 코드에 주는 의미
- 대역폭이 필요한 코드는 스트림을 여러 개 띄워 채널·뱅크를 모두 바쁘게 한다. 스레드 하나의 순차 읽기로는 소켓 대역폭을 다 쓰지 못하는 경우가 많다.
- 큰 배열 여러 개를 2의 큰 거듭제곱 간격으로 두고 동시에 훑으면 같은 뱅크(와 같은 캐시 집합)에 몰릴 수 있다. 배열 시작을 조금씩 어긋나게 두는 패딩이 통할 때가 있다.
- DIMM은 채널마다 고르게 꽂는다. 채널 하나에 두 개보다 채널 두 개에 하나씩이 대역폭이 두 배다.
- CL 숫자는 나노초로 바꿔 비교한다.

## 숫자로 보기
| 항목 | DDR4 | DDR5 |
|---|---|---|
| 전송률(MT/s) | 1600~3200 | 4800~8800 |
| DIMM 채널 | 64비트 × 1 | 32비트 × 2 |
| 버스트 길이 | 8 | 16 |
| 버스트 크기 | 64B | 64B(각각) |
| 뱅크(x8 칩) | 16(4그룹) | 32(8그룹) |
| 프리페치 | 8n | 16n |
| 리프레시 주기 | 64ms | 32ms |
| ECC DIMM 폭 | 72비트 | 40비트 × 2 |

- DDR4-3200 22-22-22는 13.75ns, DDR5-4800B 40-39-39는 16.67ns다(CL 기준). DDR5 전송률 상한은 2024년 4월 JEDEC 개정(JESD79-5C)에서 8800MT/s로 올라갔다.

## 정리
- DDR은 프리페치로 느린 셀 배열에서 여러 비트를 꺼내 클록 양쪽 에지에 버스트로 실어, 배열 속도의 8~16배로 핀을 돌린다.
- DDR5는 DIMM을 32비트 서브채널 두 개로 나누고 BL16으로 늘려, 버스트 64바이트는 그대로 두고 동시에 처리하는 요청 수를 늘렸다.
- 대역폭 = 전송률 × 버스 폭이고 DDR5-4800 DIMM 하나가 38.4GB/s다. 첫 데이터까지의 지연은 세대가 바뀌어도 십몇 ns에 머문다.
- 같은 요청 512개가 사상과 스케줄링에 따라 43,955클록에서 4,175클록까지 10배 넘게 갈렸다.
