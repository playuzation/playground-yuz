# [메모리 시스템 10/10] 메모리 오류와 신뢰성: ECC, 해밍 부호, 로우해머

> **한 줄 요약** — DRAM의 비트는 방사선, 누설, 이웃 행의 간섭으로 뒤집히고, 64비트마다 검사 비트 8개를 붙이는 해밍 SECDED 부호는 1비트 오류를 고치고 2비트 오류를 잡지만 그 이상은 조용히 틀릴 수 있으므로, 칩 고장을 흩어 놓는 칩킬과 로우해머를 막는 리프레시 대책이 그 위에 겹겹이 쌓인다.

## 이 글에서 다루는 것
- 비트가 뒤집히는 원인: 알파 입자·우주선, 누설, 이웃 행 간섭
- 해밍 부호(1950)와 SECDED를 구현해 모든 1비트·2비트 오류 전수 검사
- ECC DIMM, DDR5 온다이 ECC, 칩킬
- 로우해머(김 외 2014)의 원리와 TRR·PARA·PRAC 같은 대책(공격 방법은 다루지 않는다)

## 비트는 왜 뒤집히나
5편 「DRAM의 구조: 1T1C 셀, 뱅크, 행 버퍼, 리프레시」의 DRAM 셀은 아주 작은 축전기의 전하로 비트를 담는다. 이 전하를 흔드는 원인은 여럿이다.
- **소프트 오류**(soft error): 방사선이 실리콘을 지나며 전하를 만들어 셀 값을 바꾼다. 흔적 없이 한 번 뒤집히고, 다시 쓰면 멀쩡하다. 인텔의 메이와 우즈(May, Woods)는 1978년 학회 발표와 1979년 논문에서 패키지 재료에 극미량 든 우라늄·토륨이 내는 알파 입자가 DRAM 오류를 일으킴을 보였다. 우주선이 대기에서 만든 중성자도 같은 일을 한다.
- **하드 오류**: 셀이나 배선이 망가져 같은 비트가 계속 틀린다. 칩 하나가 통째로 죽기도 한다.
- **보존 오류**: 리프레시 사이에 전하가 너무 빨리 새는 약한 셀이 값을 잃는다.
- **간섭**: 이웃 행을 반복해 열면 피해 행의 전하가 샌다. 뒤에서 볼 로우해머다.

## 해밍 부호: 틀린 자리를 가리키는 검사 비트
패리티 비트 하나는 홀수 개 오류를 알아채지만 어디가 틀렸는지 모른다. 벨 연구소의 리처드 해밍(Richard Hamming)은 1950년 논문에서 틀린 자리까지 찾는 부호를 발표했다. 열쇠는 위치 번호의 2진수다. 비트에 1번부터 번호를 붙이고 2의 거듭제곱 자리(1, 2, 4, 8, …)에 검사 비트를 둔다. 검사 비트 i는 "위치 번호의 i번째 비트가 1인 자리들"의 패리티를 짝수로 맞춘다. 비트 하나가 뒤집히면 그 자리를 포함하는 검사 식만 깨지고, 깨진 식들을 2진수로 읽은 **신드롬**(syndrome)이 곧 틀린 자리 번호다.
```text
pos    1  2  3  4  5  6  7
role   p1 p2 d  p4 d  d  d
p1: 1,3,5,7  (bit 0 of pos)
p2: 2,3,6,7  (bit 1 of pos)
p4: 4,5,6,7  (bit 2 of pos)
flip 6 → p2,p4 fail → 110₂ = 6
```
데이터 64비트에는 검사 비트 7개면 자리 71개와 "오류 없음"을 구별할 수 있다(2⁷ = 128 ≥ 72). 여기에 전체 패리티 비트 하나를 더하면 1비트 오류는 고치고(SEC) 2비트 오류는 고치지 않고 알리는(DED) **SECDED**가 된다. 2비트가 틀리면 신드롬은 0이 아닌데 전체 패리티는 맞기 때문에 구별된다. 64 + 8 = 72비트, ECC DIMM의 폭이 72비트인 이유다. 구현하고 모든 1비트·2비트 오류를 넣어 보자.
```python
import random
from itertools import combinations

POS = [p for p in range(1, 72) if p & (p - 1)]   # 데이터 자리 64개
MASK = [sum(1 << p for p in range(1, 72) if p >> i & 1) for i in range(7)]

def syndrome(w):                  # 검사 식 7개의 결과 = 틀린 자리 번호
    return sum(((w & MASK[i]).bit_count() & 1) << i for i in range(7))

def encode(d):
    """64비트 데이터 → 72비트 부호어(해밍 71비트 + 전체 패리티)"""
    w = sum((d >> k & 1) << p for k, p in enumerate(POS))
    for i in range(7):            # 1, 2, 4, …, 64번 자리: 검사 비트
        w |= ((w & MASK[i]).bit_count() & 1) << (1 << i)
    return w | (w.bit_count() & 1)          # 0번 자리: 전체 패리티

def decode(w):
    s, odd = syndrome(w), w.bit_count() & 1
    if s and not odd or s > 71:   # 짝수 개 오류: 고치지 않고 알린다
        return None, "검출"
    if odd:                       # 홀수 개: 1비트라 보고 s번 자리를 고친다
        w ^= 1 << s
    d = sum((w >> p & 1) << k for k, p in enumerate(POS))
    return d, "정정" if odd else "정상"

rng = random.Random(10)
words = [rng.getrandbits(64) for _ in range(30)]
print("37번 비트를 뒤집으면 신드롬:", syndrome(encode(words[0]) ^ 1 << 37))
one = two = 0
for d in words:
    w = encode(d)
    one += all(decode(w ^ 1 << i) == (d, "정정") for i in range(72))
    two += all(decode(w ^ 1 << i ^ 1 << j) == (None, "검출")
               for i, j in combinations(range(72), 2))
print(f"1비트 오류 72가지: {one}/30워드 모두 정정")
print(f"2비트 오류 2556가지: {two}/30워드 모두 검출")
w, res = encode(words[0]), {"검출": 0, "조용히 틀림": 0, "정정": 0}
for c in combinations(range(72), 3):
    d, _ = decode(w ^ sum(1 << i for i in c))
    res["검출" if d is None else "정정" if d == words[0] else "조용히 틀림"] += 1
print("3비트 오류 59640가지:", res)
```
```text
37번 비트를 뒤집으면 신드롬: 37
1비트 오류 72가지: 30/30워드 모두 정정
2비트 오류 2556가지: 30/30워드 모두 검출
3비트 오류 59640가지: {'검출': 14336, '조용히 틀림': 45304, '정정': 0}
```
1비트 오류 72가지는 30개 워드 모두에서 정정되고 2비트 오류 2,556가지도 모두 검출된다. 그러나 3비트 오류는 76%가 엉뚱한 부호어로 "고쳐져" 틀린 데이터가 경고 없이 나간다. 오류가 홀수 개면 해독기가 1비트 오류로 보기 때문이다. SECDED는 오류가 드물고 서로 독립이라는 가정 위에서만 안전하다.

## ECC DIMM과 DDR5 온다이 ECC
- 서버용 **ECC DIMM**은 DDR4에서 64비트 데이터에 8비트를 더한 72비트 폭이고, 메모리 컨트롤러가 SECDED를 계산한다. DDR5 ECC DIMM은 32비트 서브채널마다 8비트를 더해 40비트씩이다(6편 「DDR 메모리와 메모리 컨트롤러: 채널, 버스트, 스케줄링」).
- DDR5 칩은 내부에 **온다이 ECC**를 둔다. 데이터 128비트마다 8비트를 더 저장해(2⁸ = 256 ≥ 128 + 8 + 1이라 1비트 정정에 충분하다) 칩 안에서 1비트 오류를 고친 뒤 내보낸다. 셀이 작아져 늘어난 약한 셀을 칩이 스스로 가리는 장치로, 호스트에는 보이지 않고 칩과 컨트롤러 사이 버스의 오류는 막지 못한다. 일반 DDR5가 ECC 메모리가 된 것은 아니다.

## 칩킬: 칩 하나가 죽어도
x4 칩(데이터 핀 4개)으로 만든 DIMM에서 칩 하나가 통째로 고장 나면 4비트가 한꺼번에 틀린다. 앞 코드에 이어서, x4 칩 72개에 부호어 4개를 담는 두 배치를 비교한다. A는 칩 하나가 한 부호어의 이웃 4비트를 맡고, B는 칩 하나가 부호어 4개에 1비트씩 맡는다. 칩 72개 × 고장 패턴 15가지를 모두 넣는다.
```python
def chip_fail(layout):
    """x4 칩 72개에 부호어 4개(288비트). 칩 하나의 4비트가 망가지는 경우"""
    data = [rng.getrandbits(64) for _ in range(4)]
    words = [encode(d) for d in data]
    res = {"정정": 0, "검출": 0, "조용히 틀림": 0}
    for chip in range(72):
        for pat in range(1, 16):              # 4비트가 바뀌는 15가지
            bad = words[:]
            if layout == "A":                 # 칩 = 한 부호어의 이웃 4비트
                bad[chip // 18] ^= pat << 4 * (chip % 18)
            else:                             # 칩 = 부호어 4개에 1비트씩
                for j in range(4):
                    bad[j] ^= (pat >> j & 1) << chip
            out = [decode(b)[0] for b in bad]
            key = ("검출" if None in out else
                   "정정" if out == data else "조용히 틀림")
            res[key] += 1
    return res

print("A 칩 하나 → 부호어 하나:", chip_fail("A"))
print("B 칩 하나 → 부호어 넷:", chip_fail("B"))
```
```text
A 칩 하나 → 부호어 하나: {'정정': 288, '검출': 432, '조용히 틀림': 360}
B 칩 하나 → 부호어 넷: {'정정': 1080, '검출': 0, '조용히 틀림': 0}
```
A에서는 1비트만 바뀐 288가지만 고쳐지고, 3비트가 바뀐 288가지는 잘못 고쳐진다. 더 고약한 것은 4비트가 모두 뒤집힌 72가지다. 이웃한 자리 번호 4c, 4c+1, 4c+2, 4c+3을 모두 XOR하면 0이라 신드롬도 0, 전체 패리티도 짝수여서 아무 경고 없이 틀린 데이터가 나간다. B에서는 칩 고장이 부호어마다 1비트 오류로 흩어져 1,080가지가 모두 정정된다. 칩 하나의 고장을 견디는 이런 설계를 **칩킬**(chipkill)이라 하고, 오늘날 서버는 4비트·8비트 심볼 단위로 정정하는 부호로 같은 목표를 이룬다.

## 로우해머: 이웃 행을 두드리면
셀이 작아지고 행 사이가 좁아지면서, 한 행을 짧은 시간에 수없이 활성화·프리차지하면 이웃 행 셀의 전하가 새어 리프레시 전에 비트가 뒤집히는 현상이 드러났다. 김 외(Kim 외, ISCA 2014)는 2008~2014년에 만든 DRAM 모듈 129개 중 110개에서 이 오류를 재현했고, 이것이 **로우해머**(RowHammer)다. 읽기만으로 남의 메모리, 예컨대 페이지 테이블 항목(7편)을 바꿀 수 있어 보안 문제가 되었다. 공격 방법은 다루지 않고, 왜 생기고 어떻게 막는지만 숫자로 본다.

앞 코드에 이어서, 리프레시 주기 64ms 동안 한 뱅크에서 행을 몇 번 열 수 있는지 계산해(tRC 46ns 가정) 측정된 최소 문턱과 비교한다. 그다음 김 외가 제안한 대책 **PARA**(probabilistic adjacent row activation)를 모형화한다. 행을 열 때마다 확률 p로 이웃 행을 함께 리프레시하면, 문턱 T번을 채우는 동안 한 번도 리프레시되지 않을 확률은 (1 − p)^T다. 모의 실험으로 공식을 확인한다.
```python
import math

acts = 64e-3 / 46e-9              # 리프레시 주기 64ms ÷ 행 주기 tRC(가정)
print(f"64ms 동안 한 뱅크의 활성화 상한: 약 {acts / 1e6:.2f}백만 번")
for name, th in [("DDR3, 2014", 139_000), ("LPDDR4, 2020", 4_800)]:
    print(f"  {name} 문턱 {th:,}번의 {acts / th:.0f}배")

def para_miss(T, p, trials, rng):
    """활성화마다 확률 p로 이웃을 리프레시: T번 내내 한 번도 안 될 비율"""
    return sum(all(rng.random() >= p for _ in range(T))
               for _ in range(trials)) / trials

rng = random.Random(5)
print(f"T=200, p=0.01: 모의 실험 {para_miss(200, 0.01, 20000, rng):.4f},",
      f"공식 (1 − p)^T = {0.99 ** 200:.4f}")
for th in (139_000, 4_800):       # 놓칠 확률을 10의 거듭제곱으로
    e = [th * math.log10(1 - p) for p in (0.001, 0.01)]
    print(f"문턱 {th:,}: p=0.001 → 10^{e[0]:.1f}, p=0.01 → 10^{e[1]:.1f}")
```
```text
64ms 동안 한 뱅크의 활성화 상한: 약 1.39백만 번
  DDR3, 2014 문턱 139,000번의 10배
  LPDDR4, 2020 문턱 4,800번의 290배
T=200, p=0.01: 모의 실험 0.1365, 공식 (1 − p)^T = 0.1340
문턱 139,000: p=0.001 → 10^-60.4, p=0.01 → 10^-606.7
문턱 4,800: p=0.001 → 10^-2.1, p=0.01 → 10^-21.0
```
모의 실험은 표본 오차 안에서 공식과 맞는다. 리프레시 한 주기 안에 2014년 DDR3 문턱의 10배, 2020년 후속 측정 연구(Revisiting RowHammer)의 LPDDR4 문턱의 290배까지 한 행을 열 수 있다. 문턱이 6년 사이 약 30배 낮아진 것이다. PARA는 p = 0.001이면 문턱 139,000번에서 놓칠 확률이 10⁻⁶⁰이지만 4,800번에서는 1% 가까이로 무력해진다. p를 0.01로 올리면 다시 10⁻²¹이 되지만 이웃 리프레시가 열 배 늘어 성능과 전력을 갉아먹는다. 문턱이 낮아질수록 대책이 비싸지는 구조다.

실제 대책은 여러 층이다.
- **TRR**(target row refresh): DDR4 칩 안에서 자주 열리는 행을 추적해 이웃을 미리 리프레시한다. 그러나 추적 표가 작아서, 2020년 TRRespass 연구는 공격 행을 많이(최대 19개) 섞으면 DDR4 모듈 42개 중 13개에서 TRR을 우회할 수 있음을 보였다.
- **PRAC**(per-row activation counting): 2024년 4월 DDR5 표준 개정(JESD79-5C)에 들어갔다. 행마다 활성화 횟수를 세다가 넘치면 컨트롤러에 알려 트래픽을 멈추고 대응할 시간을 받는다. HBM4 표준도 로우해머용 리프레시 관리를 넣었다.
- ECC는 보조일 뿐이다. 앞에서 본 대로 한 부호어에 3비트 이상 뒤집히면 SECDED는 조용히 틀릴 수 있다.

## 코드에 주는 의미
- 서버와 오래 도는 계산에는 ECC 메모리를 쓴다. 정정된 오류 기록(리눅스 EDAC, rasdaemon)이 늘어나면 DIMM을 바꿀 신호다.
- 무결성이 중요한 저장 형식과 프로토콜은 자체 체크섬을 둔다. 메모리·버스·디스크의 ECC는 각자의 구간만 지키므로 종단 간 검사가 따로 필요하다.
- 대규모 분산 시스템은 조용한 데이터 오류(silent data corruption)를 가정하고 검증을 설계한다.

- 로우해머 문턱은 측정 방식(한쪽·양쪽 두드리기)과 칩 세대마다 다르다. 표의 두 값은 서로 다른 방식으로 잰 것이라 추세를 보는 용도다.

## 어디에 쓰이나
- 수학·기하 알고리즘 8편 「가우스 소거법: 연립방정식과 XOR 기저」: 해밍 부호는 GF(2) 위의 선형 부호이고, 검사 식 7개는 XOR 연립방정식, 신드롬은 검사 행렬과 받은 워드의 곱이다.
- 7편 「가상 메모리 하드웨어: 페이지 테이블 워크와 TLB」: 알려진 첫 로우해머 권한 상승 공격(2015)이 노린 것이 페이지 테이블 항목의 비트였다.

## 정리
- 비트는 방사선(소프트 오류), 고장(하드 오류), 누설, 이웃 행 간섭으로 뒤집히고, 셀이 작아질수록 잦아진다.
- 해밍 부호는 위치 번호의 2진수로 신드롬을 만들어 틀린 자리를 가리키고, 전체 패리티를 더한 (72,64) SECDED는 1비트를 고치고 2비트를 잡지만 3비트 오류의 76%는 조용히 틀렸다.
- 칩 고장은 4비트를 한꺼번에 바꾸므로, 칩마다 비트를 여러 부호어에 흩는 칩킬 배치가 1,080가지 고장을 모두 고쳤다.
- 로우해머 문턱은 6년 사이 약 30배 낮아졌고, PARA·TRR·PRAC 같은 대책은 문턱이 낮을수록 비싸진다.
