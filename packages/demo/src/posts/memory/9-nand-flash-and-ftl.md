# [메모리 시스템 9/10] 플래시 저장 장치: NAND 셀, FTL, 쓰기 증폭

> **한 줄 요약** — NAND 플래시는 절연체에 가둔 전하로 비트를 담아 전원 없이도 기억하지만 페이지 단위로 쓰고 블록 단위로만 지울 수 있어 제자리 덮어쓰기가 안 되므로, SSD 안의 FTL이 빈 페이지에 새로 쓰고 주소표를 고친 뒤 가비지 컬렉션으로 블록을 비우며, 그 대가인 쓰기 증폭은 여유 공간이 적을수록 급격히 커진다.

## 이 글에서 다루는 것
- 플로팅 게이트와 차지 트랩 셀, SLC에서 QLC까지
- 페이지 쓰기와 블록 지우기: 제자리 덮어쓰기가 안 되는 이유
- FTL 시뮬레이터로 여유 공간별 쓰기 증폭 세기(해석 모델과 대조)
- 웨어 레벨링, 뜨거운 데이터, NVMe 큐

## 병목: 휘발성이거나 느리거나
DRAM은 전원이 꺼지면 내용이 사라지고(5편), 하드 디스크는 헤드가 움직여 자리를 찾는 데 밀리초가 걸린다. NAND 플래시는 움직이는 부품 없이 전원 없이도 기억하고 페이지 하나를 수십 µs에 읽는다. 대신 쓰기와 지우기에 까다로운 규칙이 있고, SSD 설계의 대부분은 그 규칙을 감추는 일이다. 플래시 메모리는 도시바의 마스오카 후지오(Fujio Masuoka) 팀이 1984년 IEDM에서 NOR형을, 1987년 IEDM에서 NAND형을 발표했다.

## 셀: 전하를 가두는 트랜지스터
**플로팅 게이트**(floating gate) 셀은 트랜지스터의 제어 게이트와 채널 사이에 절연체로 사방이 막힌 게이트를 하나 더 둔다. 높은 전압으로 전자를 얇은 산화막 너머로 터널링시켜 넣으면 전자가 갇혀 나가지 못하고, 트랜지스터가 켜지는 **문턱 전압**(Vth)이 올라간다. 읽을 때는 두 준위 사이의 전압을 게이트에 걸고 전류가 흐르는지 본다. 3D NAND에서는 도체 대신 질화규소 절연층에 전하를 붙잡는 **차지 트랩**(charge trap) 셀이 주류다. 삼성전자가 2013년 8월 양산한 첫 3D NAND(V-NAND)가 24층 차지 트랩 구조였고, 지금은 수백 층을 쌓는다.

셀 하나에 문턱 전압 준위를 여럿 두면 비트를 더 담는다. 준위 2개는 **SLC**(1비트), 4개는 **MLC**, 8개는 **TLC**, 16개는 **QLC**(4비트)다. 같은 전압 창을 잘게 나눌수록 무엇을 잃는지 세어 보자.
```python
for name, b in [("SLC", 1), ("MLC", 2), ("TLC", 3), ("QLC", 4)]:
    lv = 2 ** b                   # 구별해야 하는 문턱 전압 준위 수
    gain = f", 앞 단계보다 용량 +{100 / (b - 1):.0f}%" if b > 1 else ""
    print(f"{name}: 준위 {lv:2}개, 준위 간격 {1 / (lv - 1):.3f}{gain}")
```
```text
SLC: 준위  2개, 준위 간격 1.000
MLC: 준위  4개, 준위 간격 0.333, 앞 단계보다 용량 +100%
TLC: 준위  8개, 준위 간격 0.143, 앞 단계보다 용량 +50%
QLC: 준위 16개, 준위 간격 0.067, 앞 단계보다 용량 +33%
```
비트를 하나 더할 때마다 준위는 두 배가 되어 간격이 반 아래로 줄지만, 용량 이득은 +100%, +50%, +33%로 작아진다. 간격이 좁으면 전하를 더 정밀하게 넣어야 하니 쓰기가 느려지고, 누설과 산화막 마모에 약해 견디는 쓰기·지우기 횟수가 준다. 그래서 TLC·QLC 드라이브는 빈 공간 일부를 SLC처럼 써서 쓰기를 먼저 받아 두고, 나중에 TLC·QLC로 옮겨 담는다.

## 페이지에 쓰고 블록으로 지운다
NAND는 셀을 직렬로 이은 줄(string)로 배열을 만든다(직렬 연결이 NAND 게이트를 닮아 붙은 이름이다). 같은 워드선에 걸린 셀들이 **페이지**(수~수십 KiB)를 이루고, 페이지 수백 개가 **블록**을 이룬다.
```text
block
┌──────────────────────┐
│ page 0  valid        │
│ page 1  invalid      │
│ page 2  valid        │
│ ...                  │
│ page k  erased(free) │
└──────────────────────┘
read, program: per page
erase: whole block only
```
규칙은 셋이다. 읽기와 쓰기(프로그램)는 페이지 단위다. 쓰기는 전하를 넣는 방향으로만 가능하고, 블록 안에서는 정해진 순서로 쓴다. 전하를 빼는 **지우기**는 블록 전체에만 할 수 있고, 수 ms가 걸리며 산화막을 조금씩 닳게 한다. 그래서 페이지 하나를 고치려고 블록 전체를 읽고 지우고 다시 쓸 수는 없다. 수 MB를 옮겨야 하고 블록이 금방 닳는다.

## FTL: 덮어쓰기를 흉내 내기
SSD 컨트롤러의 펌웨어인 **FTL**(flash translation layer)은 운영체제에 평범한 블록 장치를 보여 준다. 논리 페이지를 덮어쓰라는 요청이 오면 새 데이터를 빈 페이지에 쓰고, 논리 → 물리 주소표를 고치고, 옛 페이지에는 무효 표시만 한다. 빈 블록이 모자라면 **가비지 컬렉션**(GC)이 희생 블록을 골라 아직 유효한 페이지를 다른 곳에 옮겨 쓰고 블록을 지운다. 이 복사 때문에 플래시에 실제로 쓴 양이 사용자가 쓴 양보다 많아진다. 그 비율이 **쓰기 증폭**(write amplification, WA)이다. GC가 숨 쉴 공간이 사용자에게 보이지 않는 **여유 공간**(over-provisioning)이다.

균일한 무작위 쓰기에서 가장 먼저 찬 블록부터 비우는 FIFO 정책은 고전적인 해석 모델이 있다. 블록이 다 찬 뒤 물리 페이지 N개가 더 쓰이면 차례가 돌아오고, 그동안 사용자 쓰기 N·(1 − a)번이 각각 논리 페이지 L개 중 하나를 고르게 덮어쓴다. 한 페이지가 끝까지 유효할 확률 a는 다음 고정점이다.
```text
a  = exp(−(1 − a)·N/L)
WA = 1/(1 − a)
```
블록 512개 × 페이지 32개 장치를 만들어 여유 7%, 15%, 28%에서 FIFO와 유효 페이지가 가장 적은 블록을 고르는 greedy 정책을 비교한다. 빈 블록 2개와 채우는 중인 블록(평균 절반)은 순환에서 빠지므로 N = (512 − 2.5) × 32로 둔다. 마지막에 모든 논리 페이지를 읽어 최신 값이 나오는지도 검사한다.
```python
import math, random

class FTL:
    """페이지 단위 사상: 빈 페이지에만 쓰고, GC로 블록을 비운다"""
    def __init__(self, blocks, pages, op, policy):
        self.P, self.policy = pages, policy
        self.logical = int(blocks * pages * (1 - op))  # 사용자 용량
        self.map = {}                       # 논리 → (블록, 페이지)
        self.page = [[None] * pages for _ in range(blocks)]  # (논리, 값)
        self.valid, self.erases = [0] * blocks, [0] * blocks
        self.free, self.full = list(range(1, blocks)), []
        self.cur = self.ptr = self.host = self.nand = 0

    def _program(self, lpn, val):
        if lpn in self.map:                 # 옛 위치는 무효 표시만
            b, p = self.map[lpn]
            self.page[b][p] = None
            self.valid[b] -= 1
        if self.ptr == self.P:              # 블록이 차면 빈 블록으로
            self.full.append(self.cur)
            self.cur, self.ptr = self.free.pop(0), 0
        self.page[self.cur][self.ptr] = (lpn, val)
        self.valid[self.cur] += 1
        self.map[lpn] = (self.cur, self.ptr)
        self.ptr += 1
        self.nand += 1

    def write(self, lpn, val):
        self.host += 1
        self._program(lpn, val)
        while len(self.free) < 2:           # 빈 블록이 모자라면 GC
            if self.policy == "greedy":     # 유효 페이지가 가장 적은 블록
                v = min(self.full, key=lambda b: self.valid[b])
            else:                           # FIFO: 가장 먼저 찬 블록
                v = self.full[0]
            self.full.remove(v)
            for e in self.page[v]:          # 살아 있는 페이지만 옮긴다
                if e:
                    self._program(*e)
            self.page[v] = [None] * self.P  # 블록 통째로 지우기
            self.erases[v] += 1
            self.free.append(v)

    def read(self, lpn):
        b, p = self.map[lpn]
        return self.page[b][p][1]

def run(op, policy, hot=False, B=512, P=32, seed=1):
    f, rng, ref = FTL(B, P, op, policy), random.Random(seed), {}
    L = f.logical
    for k in range(5 * L):        # 한 번 채우고, 정상 상태로 만든 뒤 측정
        if k == 3 * L:
            h0, n0, e0 = f.host, f.nand, f.erases[:]
        if k < L:
            l = k
        elif hot and rng.random() < 0.9:    # hot: 쓰기 90%가 앞 10%로
            l = rng.randrange(L // 10)
        else:
            l = rng.randrange(L // 10 if hot else 0, L)
        f.write(l, k)
        ref[l] = k
    ok = all(f.read(l) == ref[l] for l in range(L))
    de = [a - b for a, b in zip(f.erases, e0)]
    return (f.nand - n0) / (f.host - h0), ok, min(de), max(de)

def fifo_model(op, B=512, P=32):
    """a = exp(−(1 − a)·N/L), WA = 1/(1 − a)"""
    N = (B - 2.5) * P                       # 순환하는 물리 페이지
    L = int(B * P * (1 - op))
    a = 0.5
    for _ in range(500):
        a = math.exp(-(1 - a) * N / L)
    return 1 / (1 - a)

for op in (0.07, 0.15, 0.28):
    wf, ok1, *_ = run(op, "fifo")
    wg, ok2, *_ = run(op, "greedy")
    print(f"여유 {op:.0%}: FIFO {wf:.2f}(식 {fifo_model(op):.2f}),",
          f"greedy {wg:.2f}, 읽기 검사 {ok1 and ok2}")
```
```text
여유 7%: FIFO 7.74(식 7.81), greedy 6.32, 읽기 검사 True
여유 15%: FIFO 3.59(식 3.61), greedy 3.28, 읽기 검사 True
여유 28%: FIFO 2.02(식 2.01), greedy 1.92, 읽기 검사 True
```
FIFO 시뮬레이션은 해석 모델과 1% 안에서 맞는다. 고른 무작위 쓰기에서 여유가 7%면 사용자가 1을 쓸 때 플래시에는 6~8을 쓴다. 희생 블록에 유효 페이지가 많이 남아 옮겨 쓸 것이 많기 때문이다. 여유를 28%로 늘리면 2 근처로 떨어진다. 쓰기 증폭은 그대로 수명과 쓰기 속도의 나눗수가 된다. greedy는 무효 페이지가 가장 많은 블록을 고르니 FIFO보다 늘 낫다. 소비자 SSD는 원시 용량을 GiB(2³⁰)로 갖추고 GB(10⁹)로 팔아 약 7%를 여유로 남기는 경우가 많고, 쓰기가 많은 데이터센터 제품은 여유를 더 크게 잡는다.

## 웨어 레벨링과 뜨거운 데이터
블록마다 견디는 지우기 횟수가 정해져 있으니, 지우기가 몇 블록에 몰리면 그 블록이 먼저 죽는다. 앞 코드에 이어서, 여유 15%에서 쓰기 90%가 논리 공간 10%에 몰리는 경우를 고른 무작위와 비교한다.
```python
for hot in (False, True):
    wa, ok, lo, hi = run(0.15, "greedy", hot=hot)
    name = "쓰기 90%가 10%로" if hot else "고른 무작위"
    print(f"{name}: WA {wa:.2f}, 블록당 지우기 {lo}~{hi}번, 읽기 검사 {ok}")
```
```text
고른 무작위: WA 3.28, 블록당 지우기 3~8번, 읽기 검사 True
쓰기 90%가 10%로: WA 4.13, 블록당 지우기 0~13번, 읽기 검사 True
```
쏠린 쓰기에서는 한 번도 지워지지 않은 블록과 13번 지워진 블록이 함께 있다. 차가운 데이터가 앉은 블록은 유효 페이지가 가득해 greedy가 고르지 않기 때문이다. 쓰기 증폭도 오히려 커졌다. 뜨거운 페이지와 차가운 페이지가 한 블록에 섞여, 희생 블록마다 차가운 페이지를 계속 옮겨 쓰기 때문이다. 실제 FTL은 차가운 블록을 일부러 옮겨 닳은 블록과 바꾸는 **정적 웨어 레벨링**과, 뜨거운 데이터와 차가운 데이터를 다른 블록에 모아 쓰는 분리를 함께 쓴다. 운영체제의 **TRIM** 명령은 지운 파일의 페이지가 무효라고 FTL에 알려, GC가 쓸모없는 데이터를 옮기지 않게 한다.

## NVMe: 큐를 많이
플래시 칩은 여러 개가 채널로 묶여 동시에 일하므로, SSD는 요청이 많이 쌓여 있을수록 빠르다. 하드 디스크 시절의 AHCI(SATA)는 큐 하나에 명령 32개까지였다. PCIe에 바로 붙는 **NVMe**는 입출력 큐를 최대 65,535개, 큐마다 명령을 65,536개까지 둘 수 있고, 코어마다 제출·완료 큐 쌍을 따로 주어 잠금 없이 명령을 넣는다. 리눅스의 blk-mq와 io_uring이 이 구조에 맞춘 인터페이스다.

## 코드에 주는 의미
- 작은 무작위 덮어쓰기보다 크고 순차적인 쓰기가 FTL에 쉽다. 블록이 통째로 무효가 되면 옮길 페이지가 없어 쓰기 증폭이 1에 가깝다.
- 응용의 쓰기 증폭과 장치의 쓰기 증폭은 곱해진다. 데이터베이스가 3배로 쓰고 SSD가 3배로 불리면 플래시에는 9배가 쓰인다.
- 디스크를 꽉 채우지 않는다. 남은 빈 공간도 TRIM을 거치면 여유 공간처럼 작동한다.
- 처리량이 필요하면 요청을 여러 개 동시에 띄운다(비동기 I/O, 여러 스레드). 큐 깊이 1로는 칩 대부분이 논다.

## 어디에 쓰이나

- 1편 「메모리 계층 지도: 레지스터에서 SSD까지 지연과 대역폭」: 계층 맨 아래의 SSD가 왜 읽기는 수십 µs인데 쓰기 성능은 들쭉날쭉한지가 이 글이다.
- 파일 시스템: 리눅스의 F2FS는 플래시에 맞춰 덧붙여 쓰는 로그 구조 파일 시스템이다.

## 정리
- NAND 셀은 절연체에 가둔 전하로 문턱 전압을 바꿔 비트를 담고, 준위를 늘리면(SLC → QLC) 용량은 조금씩 늘지만 여유는 반씩 준다.
- 쓰기는 페이지, 지우기는 블록 단위라 제자리 덮어쓰기가 안 되고, FTL이 새 페이지에 쓰고 주소표를 고친 뒤 GC로 블록을 비운다.
- 시뮬레이션에서 쓰기 증폭은 여유 7%에서 FIFO 7.7·greedy 6.3, 28%에서 2 근처였고, FIFO는 해석 모델과 1% 안에서 맞았다.
- 쏠린 쓰기는 지우기 횟수를 0~13번으로 벌려 놓으므로 웨어 레벨링과 데이터 분리가 필요하고, NVMe의 깊은 큐가 여러 칩을 동시에 일하게 한다.
