# [알고리즘 기법 12/14] 중간에서 만나기: 지수를 절반으로 줄이는 기법

> **한 줄 요약** — 중간에서 만나기는 지수 시간 탐색을 반으로 나눠 각 절반의 결과를 모두 만든 뒤 해시나 정렬로 짝을 맞추는 기법으로, 메모리를 내주고 2ⁿ을 2·2^(n/2)으로 줄여 n = 40급 부분집합 문제를 푼다.

## 이 글에서 다루는 것
- n = 40에서 2⁴⁰ 완전 탐색이 안 되는 이유와 반으로 나누는 아이디어
- 합이 S인 부분집합 수: 해시로 짝 맞추기
- 합이 W 이하인 부분집합 수: 정렬 + 투 포인터
- 네 배열의 합이 0인 쌍(4-sum)
- 양방향 BFS와 이중 암호화 공격

## 예제 문제: 합이 S인 부분집합 수
정수 40개(음수 포함, 절댓값 10⁶ 이하)에서 합이 정확히 S인, 공집합이 아닌 부분집합의 수를 구하자. 11편처럼 모든 부분집합을 보면 2⁴⁰ ≈ 1.1 × 10¹²개라, 1편의 어림(1초에 단순 연산 1억 번 안팎)으로도 몇 시간이고 파이썬이면 훨씬 더 걸린다. 합의 범위가 8 × 10⁷이나 되어 동적 계획법 2편 「배낭 문제: 0-1 배낭, 무한 배낭, 메모리 줄이기」처럼 합을 상태로 두는 DP도 부담스럽다. 원소 수는 작은데 값이 클 때가 **중간에서 만나기**(meet in the middle)의 자리다.

## 아이디어: 반으로 나눠 짝 맞추기
어떤 부분집합이든 "앞 절반에서 고른 것"과 "뒤 절반에서 고른 것"으로 나뉘고, 합도 두 부분의 합 x + y로 나뉜다. 그러니 앞 절반의 모든 부분합 L과 뒤 절반의 모든 부분합 R을 따로 만든 다음, L의 각 x마다 R 안에 S − x가 몇 개 있는지 세면 된다.
```text
 앞 절반 a₀…a₁₉     뒤 절반 a₂₀…a₃₉
       ↓                  ↓
 부분합 L (2²⁰개)   부분합 R (2²⁰개)
       x  ←── 짝 ──→  S − x
```
R을 해시(`Counter`)에 담으면 조회가 O(1)이라 전체가 O(2^(n/2))이다. 1974년 호로위츠(Horowitz)와 사니(Sahni)가 부분집합 합과 배낭 문제에 쓴 방법이다. 해시는 "정확히 같은 값"만 찾으므로 "합이 W 이하"처럼 부등식이 붙으면 두 목록을 정렬하고 4편 「투 포인터: 두 끝을 움직여 O(n)에 구간 찾기」로 센다. L의 x가 커질수록 x + y ≤ W를 만족하는 R의 경계는 왼쪽으로만 움직이기 때문이다.
```python
import random
from collections import Counter

def half_sums(xs):                        # 부분집합의 합 2^len(xs)개(공집합 포함)
    sums = [0]
    for x in xs:
        sums += [s + x for s in sums]
    return sums

def count_equal(a, S):                    # 합이 S인 공집합 아닌 부분집합 수
    L, R = half_sums(a[:len(a) // 2]), Counter(half_sums(a[len(a) // 2:]))
    return sum(R[S - x] for x in L) - (S == 0)   # 공집합+공집합 제외

def count_at_most(a, W):                  # 합이 W 이하인 부분집합 수(공집합 포함)
    L = sorted(half_sums(a[:len(a) // 2]))
    R = sorted(half_sums(a[len(a) // 2:]))
    total, j = 0, len(R)
    for x in L:                           # x가 커질수록 짝 R의 경계는 왼쪽으로
        while j > 0 and x + R[j - 1] > W:
            j -= 1
        total += j
    return total

def brute(a, S, W):
    sums = [sum(a[i] for i in range(len(a)) if m >> i & 1)
            for m in range(1 << len(a))]
    return sums[1:].count(S), sum(s <= W for s in sums)

rng = random.Random(12)
for _ in range(300):
    a = [rng.randint(-10, 10) for _ in range(rng.randint(1, 14))]
    S, W = rng.randint(-15, 15), rng.randint(-15, 15)
    assert (count_equal(a, S), count_at_most(a, W)) == brute(a, S, W)
print("무작위 300개 비교: 모두 일치")
a = [rng.randint(-10**6, 10**6) for _ in range(40)]
print("n=40, 합이 0인 부분집합:", count_equal(a, 0))
print(f"만든 합 {2 * 2**20}개, 완전 탐색이면 {2**40}개")
```
```text
무작위 300개 비교: 모두 일치
n=40, 합이 0인 부분집합: 248650
만든 합 2097152개, 완전 탐색이면 1099511627776개
```
`half_sums`는 원소 하나를 볼 때마다 지금까지의 합 목록에 그 원소를 더한 사본을 이어 붙여, 목록이 2배씩 자란다. 대조 검사의 `brute`는 11편의 비트마스크 열거 그대로다. 값을 −10~10으로 좁혀 합이 겹치는 경우를 많이 만들었다. 합이 같은 부분합이 R에 여러 개 있어도 `Counter`가 개수를 세므로 짝을 빠뜨리지 않는다. S = 0이면 "앞도 공집합, 뒤도 공집합"인 짝 하나가 끼어드니 빼야 한다.

## 네 배열의 합이 0인 쌍
같은 생각은 부분집합이 아닌 곳에도 통한다. 길이 n인 배열 A, B, C, D에서 하나씩 골라 a + b + c + d = 0이 되는 조합의 수를 구하자. 넷을 모두 고르면 n⁴이라 n = 1,000에서 10¹²이다. a + b를 앞 절반, c + d를 뒤 절반으로 보면 n²개씩 만들어 짝을 맞추면 된다.
```python
import random
from collections import Counter
from itertools import product

def four_sum_zero(A, B, C, D):
    ab = Counter(a + b for a in A for b in B)     # 앞 두 배열의 합 n²개
    return sum(ab[-(c + d)] for c in C for d in D)

def brute(A, B, C, D):
    return sum(a + b + c + d == 0 for a, b, c, d in product(A, B, C, D))

rng = random.Random(12)
for _ in range(300):
    arrs = [[rng.randint(-5, 5) for _ in range(rng.randint(1, 6))]
            for _ in range(4)]
    assert four_sum_zero(*arrs) == brute(*arrs)
print("무작위 300개 비교: 모두 일치")
n = 1000
arrs = [[rng.randint(-1000, 1000) for _ in range(n)] for _ in range(4)]
print(f"n={n}: {four_sum_zero(*arrs)}쌍, 합 계산 {2 * n * n}번 (n⁴ = {n**4})")
```
```text
무작위 300개 비교: 모두 일치
n=1000: 338387180쌍, 합 계산 2000000번 (n⁴ = 1000000000000)
```
답이 3억 개를 넘어도 하나씩 나열하지 않고 개수만 곱해 세므로 n² 번의 계산으로 끝난다. 세 배열이면 a + b와 c로 나눠 n²이 된다.

## 양방향 BFS와 이중 암호화
- 양방향 BFS: 시작점과 목표점에서 동시에 BFS를 넓혀 두 탐색이 만나면 멈춘다. 상태마다 다음 상태가 b개이고 답의 거리가 d라면 한쪽에서만 찾을 때 약 bᵈ개를 보지만, 양쪽에서 d/2씩이면 약 2·b^(d/2)개다. 퍼즐처럼 상태 공간이 큰 문제에서 쓰이며 그래프 알고리즘 1편에서 다룬다.
- 이중 암호화 공격: 56비트 키 DES로 두 번 암호화하면 키가 112비트라 2¹¹²번을 시도해야 할 것 같다. 1977년 디피(Diffie)와 헬먼(Hellman)은 평문을 모든 첫 키로 암호화한 중간값 표를 만들고, 암호문을 모든 둘째 키로 복호화해 표에서 찾으면 약 2·2⁵⁶ = 2⁵⁷번 연산(과 2⁵⁶개 저장)이면 된다는 것을 보였다. 그래서 실제로는 3중 DES가 쓰였다.

## 자주 하는 실수와 변형
- 공집합 처리: "공집합 아닌" 조건이면 양쪽이 모두 공집합인 짝을 빼야 하고, 반대로 공집합을 포함하는 문제에서 빼면 틀린다.
- 메모리: 2^(n/2)개 목록 둘을 들고 있어야 한다. n = 40이면 각 10⁶개라 괜찮지만, n = 50이면 각 3,300만 개라 파이썬 리스트로는 메모리가 버겁다.
- 변형: "S에 가장 가까운 합"은 정렬한 R에서 이분 탐색(3편)으로 S − x 양옆을 본다. 원소마다 더하기·빼기·안 쓰기 세 가지면 3ⁿ이 3^(n/2)이 된다. 배낭 문제(무게 W 이하에서 가치 최대)는 R을 무게순으로 정렬하고 가치의 접두 최댓값을 붙여 둔다.

## 복잡도
| 문제 | 완전 탐색 | 중간에서 만나기 |
|---|---|---|
| 합이 S인 부분집합 | O(2ⁿ) | O(2^(n/2)) 해시 |
| 합이 W 이하 | O(2ⁿ) | O(2^(n/2)·n) 정렬 |
| 4-sum | O(n⁴) | O(n²) |
- 공간: 한쪽 결과를 모두 저장하므로 O(2^(n/2)) 또는 O(n²)이다. 시간을 메모리로 산 셈이다.
- 정렬 판의 n은 2^(n/2)개를 정렬하는 비용 `2^(n/2)·log 2^(n/2)`에서 나온다.

## 어디에 쓰이나
- 이산수학 6편 「경우의 수: 순열과 조합」: 그 글의 곱의 법칙으로 보면 부분집합 2ⁿ = 2^(n/2) × 2^(n/2)인데, 중간에서 만나기는 이 곱을 하나씩 세지 않고 두 인수를 따로 만든 뒤 짝이 맞는 것만 센다.
- 이산수학 12편 「수 체계와 모듈러 연산: 2진수에서 해시까지」: 짝 맞추기의 O(1) 조회가 그 글의 해시 테이블 덕분이고, 해시가 같은 값만 찾을 수 있다는 한계 때문에 부등식 조건에는 정렬을 쓴다.
- 그래프 알고리즘 1편 「BFS 응용: 0-1 BFS, 다중 시작점, 상태 공간 탐색」: 양방향 BFS가 같은 원리로 탐색 반경을 절반으로 줄인다.
- 암호 분석: 이중 DES가 112비트가 아니라 약 57비트 수준의 안전성만 준다는 위 공격이 3중 DES가 쓰인 이유다.

## 정리
- 원소가 적고 값이 커서 DP가 어려운 지수 탐색은 반으로 나눠 각 절반의 결과를 모두 만든다.
- 등식 조건은 해시로, 부등식이나 "가장 가까운" 조건은 정렬 + 투 포인터나 이분 탐색으로 짝을 맞춘다.
- 2ⁿ이 2·2^(n/2)이 되는 대가로 2^(n/2)만큼의 메모리를 쓴다.
- 4-sum, 양방향 BFS, 이중 암호화 공격이 모두 "양쪽에서 만들어 가운데서 맞춘다"는 같은 구조다.
