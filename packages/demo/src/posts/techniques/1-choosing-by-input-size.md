# [알고리즘 기법 1/14] 입력 크기로 알고리즘 고르기: 복잡도 어림과 문제 읽기

> **한 줄 요약** — 문제의 입력 제한 N을 보고 "1초에 단순 연산 1억 번 안팎"이라는 경험칙으로 허용되는 복잡도를 거꾸로 읽으면 쓸 알고리즘이 좁혀지고, 그렇게 고른 빠른 풀이는 느리지만 확실한 풀이와 무작위 입력으로 대조해 검증한다.

## 이 글에서 다루는 것
- 온라인 저지 문제의 구조: 입력 형식, 제한, 예제
- N 제한에서 허용 복잡도를 거꾸로 읽기
- 파이썬의 연산 예산과 메모리 제한
- 오답의 종류와, 이 시리즈 전체의 검증 방법인 무작위 대조 검사(stress test)

## 문제는 이렇게 생겼다
코딩 테스트나 온라인 저지(online judge)의 문제는 거의 같은 틀을 따른다. 지문, 입력 형식, 출력 형식, 제한, 예제다. 이 글에서 계속 쓸 작은 문제 하나를 그 틀로 적어 보자.
```text
문제  합이 0인 쌍의 개수
입력  첫 줄에 N (1 ≤ N ≤ 200,000)
      둘째 줄에 정수 a₁ … a_N
      (∣aᵢ∣ ≤ 10⁹)
출력  aᵢ + aⱼ = 0 (i < j)인 쌍의 수
제한  시간 1초, 메모리 256MB
예제  입력 5 / -1 1 0 0 1
      출력 3
```
지문보다 먼저 읽을 곳은 **제한**이다. N ≤ 200,000이라는 숫자 하나가 "모든 쌍을 비교하는 이중 반복문은 안 된다"는 힌트를 준다. 값의 범위도 정보다. 답은 최대 N(N − 1)/2 ≈ 2 × 10¹⁰이라 32비트 정수의 한계(약 21억)를 넘는다. 파이썬 정수는 저절로 커지지만 C++·자바라면 64비트 정수를 써야 한다. 예제는 손으로 검산하는 곳이다. (−1, 1) 쌍이 2개, (0, 0) 쌍이 1개라 3이다.

## 제한에서 복잡도 거꾸로 읽기
점근 표기(이산수학 11편 「점근 표기법: 알고리즘의 비용 세기」)는 증가 속도만 말해 주지만, 실전에서는 상수를 대충 붙여 "몇 번쯤인가"를 어림한다. 흔히 쓰는 경험칙은 **C++ 같은 컴파일 언어로 1초에 단순 연산 1억(10⁸) 번 안팎**이다. 정확한 값이 아니라 자릿수만 맞추는 어림이다. 이 기준으로 N 제한을 거꾸로 읽으면 다음 표가 된다.

| N 제한 | 허용 복잡도 | 대표 기법 |
|---|---|---|
| 10~11 | N! | 순열 완전 탐색 |
| 20~25 | 2ᴺ | 부분집합, 비트마스크 |
| 40 | 2^(N/2) | 중간에서 만나기 |
| 500 | N³ | 구간 DP, 플로이드 |
| 10,000 | N² | 이중 반복, 2차원 DP |
| 10⁵~10⁶ | N log N | 정렬, 이분 탐색, 트리 |
| 10⁷~10⁸ | N | 투 포인터, 누적 합 |
| 10¹⁸ | log N | 이분 탐색, 거듭제곱 |

표의 각 줄이 정말 1억 번 근처인지 세어 보자.
```python
import math

cases = [  # (N 제한, 복잡도 이름, 연산 수)
    (11, "N!", lambda n: math.factorial(n)),
    (25, "2ᴺ", lambda n: 2**n),
    (500, "N³", lambda n: n**3),
    (10_000, "N²", lambda n: n**2),
    (1_000_000, "N log N", lambda n: n * math.log2(n)),
    (10**8, "N", lambda n: n),
]
for n, name, f in cases:
    print(f"N={n:<11,} {name:<7} {f(n) / 1e8:6.2f}억 번")
print(f"N=200,000에 N²이면 {200_000**2 / 1e8:,.0f}억 번")
```
```text
N=11          N!        0.40억 번
N=25          2ᴺ        0.34억 번
N=500         N³        1.25억 번
N=10,000      N²        1.00억 번
N=1,000,000   N log N   0.20억 번
N=100,000,000 N         1.00억 번
N=200,000에 N²이면 400억 번
```
N = 200,000에 N² 풀이를 내면 400억 번, 경험칙으로 400초다. 제한 1초짜리 문제에서 "조금 느린" 것이 아니라 수백 배 느리다. 반대로 N ≤ 20인 문제에서 N log N 풀이를 찾느라 애쓸 필요도 없다. 제한은 출제자가 의도한 복잡도를 거의 그대로 알려 준다.

## 파이썬의 연산 예산
경험칙의 "단순 연산"은 기계어 몇 개짜리 일이다. 파이썬(CPython)에서는 `s += x` 한 줄도 바이트코드 여러 개가 되고, 가상 머신이 그것을 하나씩 꺼내 해석한다(언어 기초 3편 「인터프리터 언어: 실행하면서 번역하기」). 실행된 바이트코드 수를 직접 세어 보자(파이썬 3.11 기준).
```python
import sys

def count_bytecodes(func, *args):
    count = 0
    def tracer(frame, event, arg):
        nonlocal count
        frame.f_trace_opcodes = True      # 바이트코드마다 이벤트를 받는다
        if event == "opcode":
            count += 1
        return tracer
    sys.settrace(tracer)
    func(*args)
    sys.settrace(None)
    return count

def loop_sum(a):
    s = 0
    for x in a:
        s += x
    return s

def builtin_sum(a):
    return sum(a)                         # 반복은 C로 짠 sum 안에서 돈다

for n in [10, 100, 1000]:
    a = list(range(n))
    print(f"n={n:<5} for문 {count_bytecodes(loop_sum, a):>5}개",
          f"sum() {count_bytecodes(builtin_sum, a)}개")
```
```text
n=10    for문    77개 sum() 5개
n=100   for문   707개 sum() 5개
n=1000  for문  7007개 sum() 5개
```
for문은 원소 하나에 바이트코드 7개(`FOR_ITER`, `STORE_FAST`, `LOAD_FAST` 두 번, `BINARY_OP`, `STORE_FAST`, `JUMP_BACKWARD`)를 실행하고, 그 하나하나가 명령 꺼내기·타입 확인·참조 횟수 갱신을 동반한다. 내장 함수 `sum`은 반복을 C 코드 안에서 돌리므로 파이썬 바이트코드는 n과 상관없이 5개다. 그래서 파이썬으로 풀 때는 예산을 한 자릿수 이상 낮춰 1초에 1,000만 번 안팎으로 잡고, 반복은 `sum`, `sorted`, 리스트 컴프리헨션 같은 내장 기능에 맡기는 편이 안전하다. 입력이 수십만 줄이면 `input()` 대신 `sys.stdin.readline`이나 `sys.stdin.buffer.read`로 읽는 것만으로 시간 초과를 피하는 경우도 많다.

## 메모리 제한
메모리 256MB는 C의 4바이트 정수로 약 6,400만 개지만, 파이썬 리스트는 원소마다 8바이트 포인터와 별도의 정수 객체를 가진다.
```python
import sys
from array import array

n = 10**6
lst = list(range(10**9, 10**9 + n))       # 큰 정수 100만 개
arr = array("i", lst)                     # C의 4바이트 int 배열
obj = sys.getsizeof(lst[0])
print("int 객체 하나:", obj, "바이트")
print("list:", (sys.getsizeof(lst) + obj * n) // 10**6, "MB")
print("array:", sys.getsizeof(arr) // 10**6, "MB")
```
```text
int 객체 하나: 28 바이트
list: 36 MB
array: 4 MB
```
정수 100만 개에 36MB이니 1,000만 개면 360MB로 제한을 넘는다. 큰 배열은 `array` 모듈이나 `bytearray`로 줄이고, 2차원 표는 필요한 줄만 남기는 방법(동적 계획법에서 자주 쓴다)을 쓴다. −5부터 256까지의 작은 정수는 CPython이 미리 만들어 둔 객체를 공유하므로 이 계산보다 덜 든다.

## 오답의 종류
| 결과 | 흔한 원인 | 첫 대처 |
|---|---|---|
| 시간 초과 | 복잡도 과다, 느린 입력 | 제한 다시 읽기 |
| 틀렸습니다 | 경계값, 오버플로, 논리 | 대조 검사 |
| 런타임 오류 | 인덱스, 0 나누기, 재귀 깊이 | 작은 입력 실행 |
| 메모리 초과 | 큰 표, 객체 과다 | 표 줄이기 |

가장 고치기 어려운 것은 "틀렸습니다"다. 채점 서버는 어떤 입력에서 틀렸는지 알려 주지 않는다. 파이썬의 재귀 깊이 한도(기본 1,000)로 생기는 런타임 오류는 2편에서 다룬다.

## 무작위 대조 검사
틀리는 입력을 스스로 찾는 방법이 **무작위 대조 검사**(stress test)다. 재료는 세 가지다.
1. 느리지만 정의 그대로라 믿을 수 있는 풀이(대개 완전 탐색)
2. 검사할 빠른 풀이
3. 작은 무작위 입력 생성기. 값의 범위를 좁게 잡아 중복·0·음수 같은 경계 상황이 자주 나오게 한다

두 풀이의 답이 다른 입력이 나오면 그것이 반례다. 앞의 문제에 그럴듯한 빠른 풀이 두 개를 대 보자.
```python
import random
from collections import Counter

def slow(a):                              # 정의 그대로: 모든 쌍 O(N²)
    n = len(a)
    return sum(1 for i in range(n) for j in range(i + 1, n)
               if a[i] + a[j] == 0)

def fast_buggy(a):                        # 짝 개수를 곱하고 2로 나눈다
    cnt = Counter(a)
    return sum(cnt[x] * cnt[-x] for x in cnt) // 2

def fast(a):                              # 앞에서 본 수 중 짝을 센다 O(N)
    cnt, ans = Counter(), 0
    for x in a:
        ans += cnt[-x]
        cnt[x] += 1
    return ans

def stress(solve, trials=500, seed=1):
    rng = random.Random(seed)
    for t in range(trials):
        n = rng.randint(1, 2 + t // 50)   # 작은 입력부터 점점 크게
        a = [rng.randint(-3, 3) for _ in range(n)]
        if solve(a) != slow(a):
            return f"반례 {a}: 빠른 답 {solve(a)}, 정답 {slow(a)}"
    return f"무작위 {trials}개 비교: 모두 일치"

print(stress(fast_buggy))
print(stress(fast))
print("예제:", fast([-1, 1, 0, 0, 1]))
```
```text
반례 [-1, 0, 0]: 빠른 답 2, 정답 1
무작위 500개 비교: 모두 일치
예제: 3
```
`fast_buggy`는 "x의 개수 × −x의 개수를 모두 더하고 2로 나누면 두 번 센 것이 상쇄된다"는 생각인데, x = 0이면 자기 자신과 짝지은 경우까지 센다. 입력 크기를 작은 것부터 키웠기 때문에 찾은 반례도 손으로 따라갈 만큼 짧다. 고친 `fast`는 왼쪽부터 보며 "앞에서 본 수 중 짝이 몇 개인가"를 더하므로 i < j 조건이 저절로 지켜진다. 난수는 `random.Random(1)`처럼 시드를 고정해 반례를 언제든 다시 만들 수 있게 한다.

대조 검사는 정확성만 본다. 시간은 최대 크기 입력을 만들어 연산 수를 세거나 직접 돌려 확인한다. 이 시리즈의 모든 글은 핵심 구현마다 이 틀로 검사한 결과를 함께 싣는다.

## 복잡도
| 풀이 | 시간 | 공간 |
|---|---|---|
| 모든 쌍 비교 | O(N²) | O(1) |
| 정렬 + 투 포인터 | O(N log N) | O(N) |
| 해시로 짝 세기 | 기대 O(N) | O(N) |

- N = 200,000이면 쌍이 약 200억 개라 모든 쌍 비교는 불가능하고, 해시 풀이는 원소마다 사전 연산 두 번이다.
- 정렬 + 투 포인터는 4편에서, 해시가 일부러 만든 충돌 입력에 약할 수 있다는 점은 14편에서 다룬다.

- 트랜지스터에서 자연어까지 13편 「AI 에이전트와 자연어 프로그래밍: 명세와 검증의 시대」: 느린 정답 풀이를 실행 가능한 명세로 삼아 빠른 풀이를 무작위로 검증하는 것은 그 글의 생성-검증 루프를 사람이 손으로 돌리는 형태다.

## 정리
- 지문보다 제한을 먼저 읽는다. N 제한과 "1초에 1억 번" 경험칙으로 허용 복잡도와 기법이 좁혀진다.
- 파이썬은 한 줄이 바이트코드 여러 개라 예산을 한 자릿수 이상 낮게 잡고, 반복은 내장 기능에 맡긴다.
- 메모리는 객체 크기까지 센다. 파이썬 정수 리스트는 원소당 36바이트 안팎이다.
- 빠른 풀이는 느린 정답 풀이와 작은 무작위 입력으로 대조해 반례를 스스로 찾는다.

5. 슬라이딩 윈도우와 단조 덱: 구간 최솟값을 한 번에
6. 누적 합과 차분 배열: 구간 합과 구간 갱신을 O(1)로
7. 그리디 알고리즘: 지금 최선이 전체 최선이 되는 조건
8. 분할 정복: 나누고 풀고 합치기
9. 단조 스택: 가장 가까운 큰 수와 히스토그램
10. 좌표 압축과 스위핑: 정렬해 놓고 한 방향으로 쓸기
11. 비트마스킹: 정수 하나로 집합 다루기
12. 중간에서 만나기: 지수를 절반으로 줄이는 기법
13. 제곱근 분할과 Mo's 알고리즘: 질의 순서를 바꿔 빠르게
14. 무작위 알고리즘: 퀵셀렉트, 저수지 표집, 해시 충돌 막기

### 알고리즘 시리즈 지도
- 알고리즘 기법(14편): 완전 탐색, 이분 탐색, 투 포인터, 그리디, 분할 정복처럼 여러 문제에 두루 쓰는 풀이 기법
- 동적 계획법(12편): 배낭·LIS·LCS부터 비트마스크·트리·자릿수 DP와 DP 가속 기법까지
- 고급 자료 구조(12편): 힙, 유니온 파인드, 세그먼트·펜윅 트리, 트립, LCA와 트리 분해
- 그래프 알고리즘(14편): 최단 경로, 최소 신장 트리, SCC, 네트워크 플로우와 이분 매칭
- 문자열 알고리즘(6편): 해싱, KMP, Z, 아호-코라식, 접미사 배열, Manacher
- 수학·기하 알고리즘(12편): 정수론, FFT, 가우스 소거법, 계산 기하, 게임 이론
- 게임 자원 관리(14편): 프레임 예산, 오브젝트 풀링, 할당자, 캐시, 공간 분할, 대역폭 절약
