# [알고리즘 기법 9/14] 단조 스택: 가장 가까운 큰 수와 히스토그램

> **한 줄 요약** — 단조 스택은 아직 답을 못 찾은 원소를 값이 한 방향으로 정렬된 스택에 쌓아 두고, 새 원소가 오면 그 원소가 답이 되는 것들을 위에서부터 한꺼번에 꺼내는 기법으로, 원소마다 한 번 들어가고 한 번 나오므로 이중 반복문처럼 보여도 O(n)이다.

## 이 글에서 다루는 것
- 오른쪽에서 처음 나오는 큰 수(다음 큰 원소)
- 왜 O(n)인가: 분할 상환 분석
- 히스토그램에서 가장 큰 직사각형
- 각 원소가 최솟값인 구간 개수와 같은 값 처리(기여도 세기)

## 예제 문제: 며칠 기다리면 더 따뜻해지나
일별 기온 배열에서 날마다 "처음으로 더 따뜻해지는 날까지 며칠"을 구하자. 기온이 [23, 21, 24, 22, 20, 25, 19]라면 첫날은 이틀 뒤 24도에서 답이 난다. 단순한 방법은 날마다 오른쪽으로 훑는 것인데, 기온이 계속 내려가는 입력에서는 n(n − 1)/2번 비교한다. n = 10⁵이면 약 5 × 10⁹번이다.

## 아이디어: 답을 기다리는 원소들의 스택
왼쪽부터 훑으며 아직 답을 못 찾은 날들을 모아 보자. 이들의 기온은 앞에서 뒤로 갈수록 작거나 같다. 앞날보다 더 따뜻한 날이 뒤에 있었다면 앞날은 이미 답을 찾았을 것이기 때문이다. 그래서 이 모음을 스택으로 두면 맨 위가 가장 작다. 새 날의 기온 x가 오면 위에서부터 x보다 작은 날을 꺼내며 답을 "오늘"로 확정하고, x 이상인 날을 만나면 그 아래는 더 크므로 멈춘다. 마지막으로 오늘을 쌓는다. 스택이 늘 위로 갈수록 작아지는(단조) 상태를 유지하므로 **단조 스택**(monotonic stack)이라 부른다.
```python
import random

def next_greater(a):
    ans, stack, pops = [-1] * len(a), [], 0
    for i, x in enumerate(a):
        while stack and a[stack[-1]] < x:  # x가 그 원소들의 첫 큰 수
            ans[stack.pop()] = i
            pops += 1
        stack.append(i)                   # 스택의 값은 위로 갈수록 작거나 같다
    return ans, pops

def brute(a):
    n = len(a)
    return [next((j for j in range(i + 1, n) if a[j] > a[i]), -1)
            for i in range(n)]

temps = [23, 21, 24, 22, 20, 25, 19]
ans, _ = next_greater(temps)
print("기다릴 날:", [j - i if j >= 0 else 0 for i, j in enumerate(ans)])
rng = random.Random(9)
for _ in range(500):
    a = [rng.randint(0, 5) for _ in range(rng.randint(0, 25))]
    assert next_greater(a)[0] == brute(a)
print("무작위 500개 비교: 모두 일치")
a = [rng.randint(0, 10**9) for _ in range(100000)]
print("n=100000, pop 횟수:", next_greater(a)[1])
```
```text
기다릴 날: [2, 1, 3, 2, 1, 0, 0]
무작위 500개 비교: 모두 일치
n=100000, pop 횟수: 99988
```
스택에는 값이 아니라 **인덱스**를 넣는다. 그래야 거리(j − i)나 폭을 계산할 수 있다. 끝까지 스택에 남은 원소는 답이 없는 날이다.

## 왜 O(n)인가: 분할 상환
`for` 안에 `while`이 있으니 O(n²)처럼 보인다. 하지만 각 인덱스는 정확히 한 번 쌓이고 많아야 한 번 꺼내진다. 한 번의 `while`이 길게 돌 수는 있어도 전체 pop 횟수의 합은 n을 넘지 못하므로 스택 연산은 모두 2n번 이하다. 위 출력에서 n = 100,000일 때 pop이 99,988번인 것이 그 증거다. 이렇게 한 번의 비용 대신 전체 비용의 합으로 묶어 세는 것을 **분할 상환 분석**(amortized analysis)이라 한다. 파이썬 리스트의 `append`가 가끔 배열을 통째로 옮겨도 평균 O(1)인 것과 같은 논리다.

방향과 크기 조건만 바꾸면 네 가지 질문에 모두 답한다. 왼쪽 방향의 답은 새 원소를 쌓기 직전 스택 맨 위에 있는 원소다.

| 구하는 것 | 꺼내는 조건 | 답이 정해지는 때 |
|---|---|---|
| 오른쪽 첫 큰 수 | 위 < x | 꺼낼 때 |
| 오른쪽 첫 작은 수 | 위 > x | 꺼낼 때 |
| 왼쪽 첫 큰 수 | 위 ≤ x | 쌓기 직전 |
| 왼쪽 첫 작은 수 | 위 ≥ x | 쌓기 직전 |

## 히스토그램에서 가장 큰 직사각형
너비 1인 막대들의 높이가 주어질 때 막대 안에 들어가는 가장 큰 직사각형의 넓이를 구하자. 왼쪽 끝을 고정하고 오른쪽으로 늘리며 최소 높이를 갱신하면 O(n²)이다. 핵심 관찰은 정답 직사각형의 높이가 반드시 어떤 막대 k의 높이라는 것이다. 그러면 폭은 막대 k의 좌우로 h[k] 이상인 막대가 이어지는 범위, 즉 왼쪽 첫 작은 막대와 오른쪽 첫 작은 막대 사이다. 높이가 증가하는 스택을 두면 막대 k가 꺼내지는 순간 지금 위치 i가 오른쪽 경계, 꺼낸 뒤의 스택 맨 위가 왼쪽 경계다.
```python
import random

def largest_rectangle(h):
    best, stack = 0, []                   # 높이가 증가하는 인덱스
    for i, x in enumerate(h + [0]):       # 끝의 0이 남은 막대를 모두 꺼낸다
        while stack and h[stack[-1]] >= x:
            k = stack.pop()
            left = stack[-1] + 1 if stack else 0
            best = max(best, h[k] * (i - left))   # h[k]가 높이인 가장 넓은 폭
        stack.append(i)
    return best

def brute(h):
    best = 0
    for l in range(len(h)):
        low = float("inf")
        for r in range(l, len(h)):
            low = min(low, h[r])
            best = max(best, low * (r - l + 1))
    return best

print(largest_rectangle([2, 1, 5, 6, 2, 3]))
rng = random.Random(9)
for _ in range(500):
    h = [rng.randint(0, 6) for _ in range(rng.randint(0, 25))]
    assert largest_rectangle(h) == brute(h)
print("무작위 500개 비교: 모두 일치")
```
```text
10
무작위 500개 비교: 모두 일치
```
[2, 1, 5, 6, 2, 3]에서는 높이 5인 막대 두 개가 만드는 5 × 2 = 10이 답이다. 끝에 높이 0인 **보초**(sentinel)를 붙여 마지막에 스택을 비우는 코드를 따로 쓰지 않았다. 같은 높이에서 `>=`로 꺼내면 앞쪽 막대의 폭은 짧게 계산되지만, 같은 높이의 뒤쪽 막대가 전체 폭을 대신 계산하므로 최댓값은 맞다.

## 각 원소가 최솟값인 구간 개수
이번에는 모든 연속 구간의 최솟값을 더하자. 구간이 n(n + 1)/2개라 하나씩 보면 느리다. 발상을 바꿔 **원소마다 기여도**를 센다. a[i]가 최솟값인 구간의 수를 c[i]라 하면 답은 `Σ a[i]·c[i]`이다. 구간의 왼쪽 끝은 왼쪽 첫 작은 원소 바로 뒤부터 i까지 L[i]가지, 오른쪽 끝은 i부터 오른쪽 경계 앞까지 R[i]가지이므로 `c[i] = L[i]·R[i]`이다. 함정은 같은 값이다. [3, 1, 2, 1]의 구간 [1, 2, 1]에는 최솟값 1이 두 개라, 양쪽 경계를 모두 "더 작은 원소"로 잡으면 두 1이 같은 구간을 한 번씩 가져간다. 한쪽은 "작은", 다른 쪽은 "작거나 같은"으로 잡아 가장 오른쪽 최솟값에게만 주어야 한다.
```python
import random

def min_counts(a, fix=True):
    n = len(a)
    left, right, st = [0] * n, [0] * n, []
    for i in range(n):                    # 왼쪽: a[i]보다 작은 원소에서 멈춤
        while st and a[st[-1]] >= a[i]:
            st.pop()
        left[i] = i - (st[-1] if st else -1)
        st.append(i)
    st = []
    def over(j, i):                       # 오른쪽: fix면 a[i] 이하에서 멈춤
        return a[j] > a[i] if fix else a[j] >= a[i]
    for i in range(n - 1, -1, -1):
        while st and over(st[-1], i):
            st.pop()
        right[i] = (st[-1] if st else n) - i
        st.append(i)
    return [l * r for l, r in zip(left, right)]  # a[i]가 최솟값인 구간 수

def brute_sum(a):
    n = len(a)
    return sum(min(a[l:r + 1]) for l in range(n) for r in range(l, n))

a = [3, 1, 2, 1]
c = min_counts(a)
print("구간 수:", c, "최솟값 합:", sum(x * k for x, k in zip(a, c)))
bad = min_counts(a, fix=False)
print("같은 값 처리 없이:", bad, "총", sum(bad), "≠", 4 * 5 // 2)
rng = random.Random(9)
for _ in range(500):
    a = [rng.randint(0, 4) for _ in range(rng.randint(0, 20))]
    got = sum(x * k for x, k in zip(a, min_counts(a)))
    assert got == brute_sum(a)
print("무작위 500개 비교: 모두 일치")
```
```text
구간 수: [1, 4, 1, 4] 최솟값 합: 13
같은 값 처리 없이: [1, 6, 1, 4] 총 12 ≠ 10
무작위 500개 비교: 모두 일치
```
구간 수의 합이 전체 구간 수 10과 같은지 보는 것만으로도 같은 값 처리 실수를 잡을 수 있다. 무작위 입력의 값을 0~4로 좁힌 것도 같은 값이 자주 나오게 하려는 것이다.

## 자주 하는 실수와 변형
- 꺼내는 조건의 `<`와 `<=`: "첫 큰 수"인지 "첫 크거나 같은 수"인지 문제마다 다르다. 값 범위가 넓은 무작위 입력으로는 이 실수가 드러나지 않는다.
- 끝까지 남은 원소를 잊는다. 답 없음(−1)으로 두거나 보초로 비운다.
- 변형: 모든 구간의 최댓값 합(부등호를 뒤집는다), "구간 최솟값 × 구간 합"의 최댓값(기여도 + 6편 「누적 합과 차분 배열: 구간 합과 구간 갱신을 O(1)로」), 바닥 쪽에서도 원소가 빠지는 고정 길이 윈도우(5편의 단조 덱).

## 복잡도
| 문제 | 단순한 방법 | 단조 스택 |
|---|---|---|
| 다음 큰 수 | O(n²) | O(n) |
| 히스토그램 | O(n²) | O(n) |
| 구간 최솟값 합 | O(n²) 이상 | O(n) |
- 시간: 원소마다 push 1번, pop 많아야 1번이라 합 2n번 이하(분할 상환).
- 공간: 스택과 답 배열 O(n).

## 어디에 쓰이나
- 이산수학 9편 「트리: 계층 구조와 구문 트리」: 단조 스택으로 각 원소의 좌우 첫 작은 원소를 구하면 "최솟값이 루트"인 이진 트리(카르테시안 트리)를 O(n)에 만들 수 있고, 원소가 최솟값인 구간이 곧 그 원소의 서브트리다.
- 수학·기하 알고리즘 10편 「볼록 껍질: 모노톤 체인과 그레이엄 스캔」: 정렬한 점을 스택에 쌓되 바깥으로 꺾이지 않는 점을 꺼내는 과정이 단조 스택과 같은 분할 상환 O(n)이다.
- 5편 「슬라이딩 윈도우와 단조 덱: 구간 최솟값을 한 번에」: 단조 스택에 "윈도우를 벗어난 원소를 바닥에서 뺀다"는 동작을 더한 것이 단조 덱이다.

## 정리
- 단조 스택은 답을 기다리는 원소를 값이 정렬된 상태로 쌓고, 새 원소가 답이 되는 원소를 위에서부터 꺼낸다.
- 원소마다 한 번 들어가고 한 번 나오므로 전체 O(n)이다(분할 상환).
- 히스토그램은 "높이가 막대 k의 높이인 가장 넓은 폭", 구간 최솟값 합은 "원소별 기여도"로 바꿔 푼다.
- 같은 값이 있을 때 경계를 한쪽만 "작거나 같은"으로 잡아야 중복을 피하고, 값 범위가 좁은 대조 검사가 이를 잡는다.
