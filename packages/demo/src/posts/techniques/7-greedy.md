# [알고리즘 기법 7/14] 그리디 알고리즘: 지금 최선이 전체 최선이 되는 조건

> **한 줄 요약** — 그리디 알고리즘은 매 단계에서 지금 가장 좋아 보이는 선택을 하고 되돌아보지 않는 방법으로, "어떤 최적해든 그리디의 선택을 포함하도록 바꿀 수 있다"는 교환 논증이 성립할 때만 맞으며, 그럴듯한 규칙 대부분은 완전 탐색과 대조하면 작은 반례가 금방 나온다.

## 이 글에서 다루는 것
- 회의실 배정: 끝나는 시간 순 그리디와 교환 논증

- 동전 거스름돈: 그리디가 실패하는 동전 체계 찾기
- 마감 시간 있는 작업: 우선순위 큐로 선택을 고치는 그리디

## 그리디와 교환 논증
**그리디 알고리즘**(greedy algorithm)은 매 단계에서 지금 가장 좋아 보이는 선택을 하고 되돌아보지 않는다. 2편의 백트래킹이 모든 갈래를 보는 것과 달리 한 갈래만 따라가므로 빠르지만, 그 선택이 전체 최적으로 이어진다는 보장이 있을 때만 맞다. 그 보장을 보이는 대표 도구가 **교환 논증**(exchange argument)이다. 임의의 최적해를 하나 잡고 그 안의 원소를 그리디가 고른 원소로 바꿔 넣어도 손해가 없음을 보이면, "그리디의 첫 선택을 포함하는 최적해가 있다"가 된다. 남은 부분 문제에 같은 논리를 반복하면(이산수학 4편의 귀납법) 그리디 전체가 최적이다.

## 회의실 배정
회의 n개의 시간 [시작, 끝)이 주어질 때 겹치지 않게 고를 수 있는 최대 회의 수를 구하자. 앞 회의가 끝나는 순간 다음 회의가 시작해도 된다. 규칙은 "끝나는 시간이 가장 이른 회의부터 보며, 겹치지 않으면 고른다"이다.

교환 논증은 이렇다. 끝이 가장 이른 회의를 g, 어떤 최적해의 첫 회의를 o라 하자. g는 o보다 늦게 끝나지 않는다. 최적해의 나머지 회의는 모두 o가 끝난 뒤에 시작하므로 g가 끝난 뒤에도 시작한다. 그러니 o를 g로 바꿔도 겹침이 없고 개수도 같다. 아래 코드는 이 규칙과 그럴듯한 다른 규칙들을 모든 부분집합을 보는 완전 탐색과 대조하고, 반례가 나오면 회의를 하나씩 빼 보며 반례가 유지되는 가장 작은 형태로 줄인다.
```python
import random

def fast(ms, key):                        # 정렬 후 마지막 끝 시간과만 비교
    count, end = 0, float("-inf")
    for s, e in sorted(ms, key=key):
        if s >= end:
            count, end = count + 1, e
    return count

def general(ms, key):                     # 고른 회의 모두와 겹침 검사
    chosen = []
    for s, e in sorted(ms, key=key):
        if all(e <= s2 or e2 <= s for s2, e2 in chosen):
            chosen.append((s, e))
    return len(chosen)

def brute(ms):                            # 서로 안 겹치는 부분집합의 최대 크기
    n, best = len(ms), 0
    for mask in range(1 << n):
        p = [ms[i] for i in range(n) if mask >> i & 1]
        if all(e1 <= s2 or e2 <= s1 for i, (s1, e1) in enumerate(p)
               for s2, e2 in p[i + 1:]):
            best = max(best, len(p))
    return best

def shrink(ms, bad):                      # 반례가 유지되는 한 회의를 뺀다
    i = 0
    while i < len(ms):
        if bad(ms[:i] + ms[i + 1:]):
            ms = ms[:i] + ms[i + 1:]
        else:
            i += 1
    return ms

solvers = {"끝": lambda ms: fast(ms, lambda m: m[1]),
           "끝·시작": lambda ms: fast(ms, lambda m: (m[1], m[0])),
           "시작": lambda ms: general(ms, lambda m: m[0]),
           "짧은 것": lambda ms: general(ms, lambda m: m[1] - m[0])}
for name, solve in solvers.items():
    rng, result = random.Random(17), "무작위 500개 비교: 모두 일치"
    bad = lambda ms: solve(ms) != brute(ms)
    for t in range(500):
        ms = []
        for _ in range(rng.randint(1, 2 + t // 60)):
            s = rng.randint(0, 6)
            ms.append((s, s + rng.randint(0, 4)))    # 길이 0인 회의도 있다
        if bad(ms):
            result = f"반례 {shrink(ms, bad)}"
            break
    print(f"{name}: {result}")
```
```text
끝: 반례 [(2, 2), (0, 2)]
끝·시작: 무작위 500개 비교: 모두 일치
시작: 반례 [(6, 8), (5, 8), (6, 6)]
짧은 것: 반례 [(2, 4), (3, 5), (0, 3)]
```
- `끝`: 끝나는 시간만으로 정렬하면 `[(2, 2), (0, 2)]`에서 틀린다. 길이 0인 회의 (2, 2)가 먼저 뽑혀 마지막 끝 시간이 2가 되고, 같은 시각에 끝나는 (0, 2)는 시작이 0이라 버려진다. 끝이 같으면 시작이 이른 것을 먼저 보도록 `(끝, 시작)` 쌍으로 정렬해야 하고, 그렇게 한 `끝·시작` 버전은 모두 일치한다. 증명은 맞았는데 구현의 동점 처리가 틀린 경우다.
- `시작`: 일찍 시작하지만 오래 걸리는 (5, 8)이 나머지 둘을 막는다.
- `짧은 것`: 가장 짧은 (2, 4)가 양옆의 (0, 3), (3, 5)와 모두 겹쳐 둘을 고를 기회를 없앤다.

## 동전 거스름돈: 그리디가 실패하는 체계
x원을 가장 적은 수의 동전으로 주는 문제에서 "큰 동전부터 최대한"은 우리가 쓰는 동전에서는 맞지만 모든 동전 체계에서 맞지는 않다. 모든 금액의 최소 동전 수를 DP로 구한 정답과 그리디를 비교해, 그리디가 처음 틀리는 금액을 찾아보자.
```python
def greedy_coins(coins, x):               # 큰 동전부터 최대한
    cnt = 0
    for c in sorted(coins, reverse=True):
        cnt += x // c
        x %= c
    return cnt

def first_failure(coins, limit):          # 그리디가 최적이 아닌 가장 작은 금액
    best = [0] + [limit] * limit          # best[x]: x를 만드는 최소 동전 수
    for x in range(1, limit + 1):
        best[x] = min(best[x - c] + 1 for c in coins if c <= x)
        if greedy_coins(coins, x) != best[x]:
            return x
    return None

print("10·50·100·500원:", first_failure([1, 5, 10, 50], 5000))  # 10원 단위
pairs = [(a, b) for a in range(2, 20) for b in range(a + 1, 21)]
fails = [(a, b, x) for a, b in pairs
         if (x := first_failure([1, a, b], 400))]
print(f"{{1, a, b}} {len(pairs)}가지 중 {len(fails)}가지 실패")
print("예:", *[f"{{1,{a},{b}}}→{x}" for a, b, x in fails[:3]])
print("가장 작은 반례 < a + b:", all(x < a + b for a, b, x in fails))
```
```text
10·50·100·500원: None
{1, a, b} 171가지 중 100가지 실패
예: {1,3,4}→6 {1,4,5}→8 {1,4,6}→8
가장 작은 반례 < a + b: True
```
10·50·100·500원 체계(10원 단위로 1·5·10·50)는 5만 원까지 실패가 없다(`None`). 반면 {1, 3, 4}에서 6원은 그리디가 4 + 1 + 1로 3개를 쓰지만 3 + 3이면 2개다. 1과 20 이하의 두 동전으로 만든 체계 171가지 중 100가지에서 그리디가 틀렸다. 그리디가 모든 금액에서 맞는 체계를 **정준 동전 체계**(canonical coin system)라 한다. 1994년 코젠(Kozen)과 자크스(Zaks)는 반례가 있다면 가장 작은 반례가 가장 큰 두 동전의 합보다 작다는 것을 보였고, 실험의 마지막 줄이 이를 확인한다. 그래서 그 금액까지만 검사하면 체계 전체를 판정할 수 있다. 정준이 아닌 체계는 동적 계획법 2편 「배낭 문제: 0-1 배낭, 무한 배낭, 메모리 줄이기」의 무한 배낭으로 푼다.

## 마감 시간 있는 작업
작업마다 마감일 d와 보상 w가 있고, 하루에 작업 하나를 할 수 있으며 d일째까지 끝낸 작업만 보상을 받는다. 보상 합의 최댓값은? 고른 작업 집합이 가능한지는 마감이 이른 순으로 하루씩 처리해 보면 안다. 마감 순으로 k번째 작업의 마감이 k 이상이면 된다. 그래서 마감 순으로 작업을 보며 일단 고르고, "d일까지 d개 초과"가 되면 지금까지 고른 것 중 보상이 가장 작은 작업 하나를 포기한다. 가장 작은 것을 꺼내는 데 최소 힙(고급 자료 구조 1편 「힙과 우선순위 큐: 가장 급한 것부터 꺼내기」)을 쓴다.
```python
import heapq
import random

def max_reward(jobs):                     # jobs: (마감일 d, 보상 w), 하루에 하나
    heap = []                             # 지금까지 고른 작업의 보상(최소 힙)
    for d, w in sorted(jobs):             # 마감이 이른 것부터
        heapq.heappush(heap, w)
        if len(heap) > d:                 # d일 안에 d개를 넘게 고를 수 없다
            heapq.heappop(heap)           # 가장 싼 작업을 포기한다
    return sum(heap)

def feasible(sub):                        # 마감 순으로 하루씩 하면 다 되는가
    return all(d >= k for k, (d, _) in enumerate(sorted(sub), 1))

def reward_brute(jobs):
    n = len(jobs)
    subs = ([jobs[i] for i in range(n) if m >> i & 1] for m in range(1 << n))
    return max(sum(w for _, w in s) for s in subs if feasible(s))

rng = random.Random(18)
for _ in range(500):
    jobs = [(rng.randint(1, 4), rng.randint(1, 9))
            for _ in range(rng.randint(0, 9))]
    assert max_reward(jobs) == reward_brute(jobs)
print("무작위 500개 비교: 모두 일치")
print(max_reward([(1, 6), (1, 7), (3, 2), (3, 1), (2, 4), (2, 5), (6, 1)]))
```
```text
무작위 500개 비교: 모두 일치
15
```
넘친 순간에는 어떤 작업 하나가 반드시 빠져야 하는데, 무엇을 빼든 남은 작업은 모두 마감 안에 해낼 수 있으므로 보상이 가장 작은 것을 빼는 것이 손해가 가장 적다. 예에서는 보상 7, 5, 2, 1을 골라 15다. 작업마다 처리 시간이 다르고 늦은 작업의 수를 최소로 하는 문제도 같은 구조다. 1968년 J. M. 무어(Moore)의 논문에 실린 무어-호지슨 알고리즘은 마감 순으로 넣다가 넘치면 처리 시간이 가장 긴 작업을 뺀다.

## 그리디를 믿기 전에
- 규칙이 떠오르면 증명보다 먼저 완전 탐색과 대조한다. 위의 `시작`, `짧은 것`처럼 그럴듯한 규칙 대부분이 원소 서너 개짜리 반례로 무너진다.
- 증명이 맞아도 동점 처리나 "같은 시각에 끝나고 시작" 같은 경계에서 구현이 틀릴 수 있다.
- 다른 시리즈의 그리디: 다익스트라(그래프 알고리즘 2편 「다익스트라 알고리즘: 음수 없는 최단 경로」), 크루스칼과 프림(그래프 알고리즘 5편 「최소 신장 트리: 크루스칼과 프림」), 허프만 부호(아래).

## 복잡도
| 문제 | 완전 탐색·DP | 그리디 |
|---|---|---|
| 회의실 배정 | O(2ⁿ · n²) | O(n log n) |
| 거스름돈(정준) | O(x · k) | O(k) |
| 마감 있는 작업 | O(2ⁿ · n log n) | O(n log n) |

- 회의실 배정과 마감 작업은 정렬이 지배하고, 마감 작업의 힙 연산은 작업당 O(log n)이다.
- 거스름돈의 k는 동전 종류 수, x는 금액이다. DP는 금액마다 동전 k개를 시도한다.

## 어디에 쓰이나
- 정보 이론 1편 「정보량과 엔트로피」: 확률이 가장 작은 두 묶음을 반복해서 합치는 허프만 부호가 그리디이고, 그 최적성도 "가장 드문 두 기호가 가장 깊은 곳에 형제로 놓인 최적 부호가 있다"는 교환 논증으로 보인다.
- 그래프 알고리즘 5편 「최소 신장 트리: 크루스칼과 프림」: 컷을 건너는 가장 가벼운 간선을 포함하는 최소 신장 트리가 있다는 컷 성질이 교환 논증이고, 크루스칼은 간선을 가벼운 순으로 보는 그리디다.
- 트랜지스터에서 자연어까지 10편 「운영체제: 기계를 나눠 쓰게 하는 층」: 그 글의 라운드 로빈과 달리, 동시에 도착한 작업을 실행 시간이 짧은 순으로 돌리면(SJF) 평균 대기 시간이 최소가 된다는 것도 이웃한 두 작업을 맞바꾸는 교환 논증으로 증명된다.

## 정리
- 그리디는 지금 최선의 선택을 되돌리지 않는 방법이고, 교환 논증으로 "그리디의 선택을 포함하는 최적해가 있다"를 보여야 맞다.
- 회의실 배정은 끝나는 시간 순(동점이면 시작 순), 마감 작업은 마감 순 + 최소 힙으로 가장 싼 작업 포기다.
- 동전 그리디는 정준 체계에서만 맞고, 가장 작은 반례는 가장 큰 두 동전의 합보다 작다.
- 그럴듯한 규칙은 증명하기 전에 완전 탐색과 무작위로 대조하고, 찾은 반례는 줄여서 읽는다.
