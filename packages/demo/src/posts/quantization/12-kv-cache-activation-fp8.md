## 활성값은 왜 어려운가
가중치는 학습이 끝나면 고정이라 오프라인에서 분포를 다 보고 9~11편의 방법을 마음껏 쓸 수 있다. 활성값은 입력마다 새로 생기고, 10편에서 본 채널 이상치와 3편의 거대 활성값이 섞인다. 스케일을 정하는 방법은 둘이다.
- **정적 스케일**(static): 보정 데이터로 범위를 미리 정해 고정한다. 추론 때 추가 계산이 없고 앞뒤 연산에 접어 넣기 쉽지만, 보정 때 못 본 큰 값은 잘린다.
- **동적 스케일**(dynamic): 추론 중에 토큰마다 absmax를 구한다. 입력에 맞춰 따라가지만 최댓값을 구하는 축소 연산이 매번 든다.

1편의 W8A8처럼 활성값까지 8비트로 만들면 행렬 곱 자체를 INT8·FP8 텐서 코어로 돌려, 연산 바운드인 프리필과 큰 배치가 빨라진다. 가중치 전용 W4A16이 디코드의 메모리 대역폭을 겨냥한다면, W8A8은 연산량을 겨냥한다.

## KV 캐시 양자화: 키는 채널별, 값은 토큰별
어텐션 4편에서 계산한 KV 캐시는 문맥 길이와 배치에 비례해 커져, 긴 문맥에서는 가중치보다 커지기도 한다. KIVI(Liu 등, 2024)는 키와 값을 다른 방향으로 2비트 비대칭 양자화한다. 키는 몇몇 채널에 늘 큰 값이 있어 **채널별**로, 값은 그런 패턴이 없고 어텐션 출력이 토큰들의 가중합이라 오차를 토큰 안에 가두는 **토큰별**로 묶는다. 값은 새 토큰이 올 때마다 바로 양자화해 붙이면 되지만, 키는 토큰 여러 개가 모여야 채널별 묶음을 만들 수 있어 최근 토큰을 잠시 원래 정밀도로 두었다가 묶음 단위로 양자화한다. 논문은 묶음 크기 32, 원래 정밀도로 두는 잔여 토큰 128개 정도가 잘 동작한다고 했고, 모델 가중치를 포함한 최대 메모리를 2.6배 줄이고 배치를 최대 4배 키워 처리량이 2.35~3.47배가 되었다고 보고했다.

키에는 늘 큰 채널 4개를, 값에는 토큰마다 다른 크기를 준 가상의 데이터로 네 조합을 비교한다. 쿼리는 일부 키와 닮게 만들어 어텐션이 몇 토큰에 집중하게 했다.
```python
import numpy as np

rng = np.random.default_rng(0)
T, d = 512, 128                             # 토큰, 헤드 차원
K = rng.normal(size=(T, d))
K[:, :4] = K[:, :4] * 2 + rng.uniform(8, 15, 4)   # 키: 늘 큰 채널 4개
V = rng.normal(size=(T, d)) * rng.lognormal(0, 0.7, (T, 1))  # 토큰별 크기
Q = (K[rng.choice(T, 64)] - K.mean(0)) * 0.5 + rng.normal(size=(64, d))

def quant(x, axis, bits=2, g=32):           # 비대칭, axis 방향 g개마다 스케일
    xs = np.moveaxis(x, axis, -1)
    xg = xs.reshape(*xs.shape[:-1], -1, g)
    lo, hi = xg.min(-1, keepdims=True), xg.max(-1, keepdims=True)
    s = (hi - lo) / (2 ** bits - 1)
    y = (np.round((xg - lo) / s) * s + lo).reshape(xs.shape)
    return np.moveaxis(y, -1, axis)

def attn(K, V):
    S = Q @ K.T / np.sqrt(d)
    P = np.exp(S - S.max(1, keepdims=True))
    return (P / P.sum(1, keepdims=True)) @ V

rel = lambda a, b: np.linalg.norm(a - b) / np.linalg.norm(b)
ref = attn(K, V)
ways = {"채널별": 0, "토큰별": 1}           # 0: 토큰 방향 묶음 = 채널별 스케일
for name, ax in ways.items():
    print(f"2비트 {name}: 키 오차 {rel(quant(K, ax), K):.3f},"
          f" 값 오차 {rel(quant(V, ax), V):.3f}")
for kn, ka in ways.items():
    for vn, va in ways.items():
        e = [rel(attn(quant(K, ka, b), quant(V, va, b)), ref) for b in (4, 2)]
        print(f"키 {kn} + 값 {vn}: 출력 오차 4비트 {e[0]:.3f}, 2비트 {e[1]:.3f}")
```
```text
2비트 채널별: 키 오차 0.177, 값 오차 0.498
2비트 토큰별: 키 오차 0.410, 값 오차 0.391
키 채널별 + 값 채널별: 출력 오차 4비트 0.098, 2비트 0.501
키 채널별 + 값 토큰별: 출력 오차 4비트 0.092, 2비트 0.459
키 토큰별 + 값 채널별: 출력 오차 4비트 0.121, 2비트 0.740
키 토큰별 + 값 토큰별: 출력 오차 4비트 0.116, 2비트 0.682
```

키는 채널별일 때 오차가 0.177로 토큰별(0.410)보다 훨씬 작다. 토큰별로 묶으면 모든 토큰의 묶음에 큰 채널이 끼어 격자가 거칠어지기 때문이고, 10편의 채널 이상치와 같은 이야기다. 값은 반대로 토큰마다 크기가 달라 토큰별(0.391)이 낫다. 어텐션 출력에서도 "키 채널별 + 값 토큰별"이 4비트·2비트 모두 가장 작다. 2비트에서 46%라는 오차는 가상의 데이터가 극단적이고 최근 토큰을 원래 정밀도로 두는 장치도 뺐기 때문이며, KIVI는 실제 모델에서 품질이 거의 유지됨을 보였다.

## FP8 추론: 스케일 세분도와 형식
2편에서 본 FP8 E4M3(최댓값 448)는 지수 비트가 있어 한 스케일 아래에서도 크기가 여러 자릿수에 걸친 값을 비슷한 상대 오차로 담는다. INT8과 같은 8비트지만 이상치에 대한 반응이 다르다. 거대 활성값 4개를 심은 가상의 활성값에서, 스케일을 텐서 하나로 둘 때와 1×128 타일마다 둘 때를 INT8·FP8·MXFP4(값 32개마다 2의 거듭제곱 스케일)로 비교한다. 거대 활성값 자체를 뺀 보통 값들의 상대 오차를 잰다.
```python
def fp_grid(e, m, bias, nan_top=False):     # 부동소수점 양수 값 나열
    v = [k / 2**m * 2.0 ** (1 - bias) for k in range(2**m)]  # 0, 비정규 수
    v += [(1 + k / 2**m) * 2.0 ** (x - bias)
          for x in range(1, 2**e) for k in range(2**m)]
    v = np.array(v[:-1] if nan_top else v)  # E4M3는 S.1111.111이 NaN
    return np.concatenate([-v[:0:-1], v])

E4M3, E2M1 = fp_grid(4, 3, 7, nan_top=True), fp_grid(2, 1, 1)
snap = lambda x, g: g[np.searchsorted((g[1:] + g[:-1]) / 2, x)]
print("E4M3 최댓값", E4M3.max(), "/ E2M1 양수", E2M1[E2M1 >= 0])

def int8(x):                                # absmax → 127
    s = np.abs(x).max() / 127
    return np.round(x / s) * s

def fp8(x):                                 # absmax → 448
    s = np.abs(x).max() / 448
    return snap(x / s, E4M3) * s

def mxfp4(x):                               # 2의 거듭제곱 스케일(E8M0)
    s = 2.0 ** (np.floor(np.log2(np.abs(x).max())) - 2)
    return snap(x / s, E2M1) * s            # 범위 밖은 ±6으로 포화

def blocks(f, b):                           # 연속한 b개마다 따로 스케일
    return lambda x: np.stack([f(r) for r in x.reshape(-1, b)]).reshape(x.shape)

rng = np.random.default_rng(0)
X0 = rng.normal(size=(256, 1024))           # 가상의 활성값 (토큰 × 채널)
idx = rng.integers(0, 256, 4), rng.integers(0, 1024, 4)
ways = {"INT8 텐서별": int8, "INT8 1×128": blocks(int8, 128),
        "FP8 텐서별": fp8, "FP8 1×128": blocks(fp8, 128),
        "MXFP4 32개": blocks(mxfp4, 32)}
for name, f in ways.items():
    r = []
    for big in [1e3, 1e5]:                  # 몇 개만 거대한 활성값
        X = X0.copy()
        X[idx] = big
        m = np.abs(X) < big                 # 보통 값들만 평가
        r.append(np.linalg.norm((f(X) - X)[m]) / np.linalg.norm(X[m]))
    print(f"{name}: 이상치 1e3 {r[0]:.3f}, 1e5 {r[1]:.3f}")
```
```text
E4M3 최댓값 448.0 / E2M1 양수 [0.  0.5 1.  1.5 2.  3.  4.  6. ]
INT8 텐서별: 이상치 1e3 1.000, 1e5 1.000
INT8 1×128: 이상치 1e3 0.044, 1e5 0.044
FP8 텐서별: 이상치 1e3 0.027, 1e5 0.126
FP8 1×128: 이상치 1e3 0.026, 1e5 0.026
MXFP4 32개: 이상치 1e3 0.117, 1e5 0.117
```

INT8에 텐서별 스케일 하나를 쓰면 간격이 1000/127 ≈ 7.9가 되어 보통 값이 거의 전부 0이 된다(오차 100%). 1×128 타일로 나누면 이상치가 든 타일 4개만 망가진다. 4.4% 중 대부분이 그 4개 타일에서 나오고, 나머지 타일만 따로 재면 0.65%다. FP8은 텐서별 스케일로도 이상치 1000까지는 2.7%로 버틴다. 지수 비트가 작은 값에도 상대 정밀도를 주기 때문이다. 하지만 이상치가 10만이면 보통 값이 448/10⁵ ≈ 0.0045로 축소되어 E4M3의 최소 노멀 수 2⁻⁶ ≈ 0.0156 아래 비정규 영역에 떨어지고 오차가 12.6%로 뛴다. 1×128 타일이면 이상치 크기와 무관하게 2.6%다. MXFP4는 4비트라 기본 오차가 11.7%로 크지만, 32개 블록 덕분에 이상치가 커져도 그대로다. 세분화된 스케일은 형식이 무엇이든 이상치의 피해를 블록 안에 가둔다.

## FP8 학습: 딥시크-V3
딥시크-V3(2024)는 대부분의 행렬 곱을 FP8로 계산하는 혼합 정밀도로 학습했다. 기술 보고서의 핵심은 두 가지다.
- **세분화 스케일**: 활성값은 1×128 타일(토큰 하나의 채널 128개)마다, 가중치는 128×128 블록마다 스케일을 둔다. 위 실험처럼 이상치의 영향이 타일 하나에 갇힌다. 앞선 연구들이 순전파에 E4M3, 역전파에 범위가 넓은 E5M2를 섞어 쓴 것과 달리, 세분화 스케일 덕분에 모든 텐서에 E4M3를 쓴다.
- **누적 정밀도**: 보고서에 따르면 H800 GPU의 텐서 코어는 FP8 행렬 곱을 누적할 때 곱의 가수 중 상위 14비트 정도만 덧셈에 쓴다. 길이 수천의 내적에서는 이 오차가 쌓이므로, 128개(N_C = 128) 곱을 누적할 때마다 부분합을 CUDA 코어로 옮겨 스케일을 곱하고 FP32 레지스터에 더한다.

FP8로 저장하는 것도 행렬 곱 입력만이 아니다. 역전파를 위해 보관하는 활성값도 FP8로 캐시하고, 옵티마이저 상태는 BF16으로 줄였다. 양자화가 추론 전용 압축을 넘어 학습의 핵심 설정으로 들어온 사례다.

## 블록 스케일 FP4와 gpt-oss
4비트 부동소수점 E2M1은 값이 ±{0, 0.5, 1, 1.5, 2, 3, 4, 6}뿐이라 블록 스케일 없이는 쓸 수 없다(2편).
- **MXFP4**: 값 32개가 E8M0(2의 거듭제곱) 스케일을 공유한다. 값당 4.25비트다.
- **NVFP4**: 값 16개가 E4M3 스케일을 공유하고 텐서 전체에 FP32 스케일이 하나 더 있다. 값당 4.5비트다.

OpenAI의 gpt-oss는 MoE 가중치를 MXFP4로 양자화한 상태로 후속 학습(post-training)했고, 모델 카드에 따르면 그 덕분에 gpt-oss-120b가 80GB GPU 한 장에, gpt-oss-20b가 16GB 메모리 안에 들어간다. 오픈 웨이트 모델 3편에서 전문가 가중치를 값당 4.25비트로 계산해 약 65GB가 나온 것이 이 형식이다. 이처럼 양자화를 학습 과정에 넣으면 9~11편의 PTQ보다 손실을 줄일 수 있다는 점은 13편에서 실험으로 확인한다.

## 정리
- 활성값은 입력마다 분포가 달라 정적 스케일(빠르지만 잘림)과 동적 스케일(정확하지만 추가 계산) 중 하나를 고른다.
- KV 캐시는 키를 채널별, 값을 토큰별로 묶는 것이 맞다. 실험에서 이 조합의 어텐션 출력 오차가 가장 작았다.
- FP8은 지수 비트 덕분에 텐서별 스케일로도 이상치를 견디지만 한계가 있고, 1×128 타일 스케일은 이상치의 영향을 타일 하나에 가둔다.
- 딥시크-V3는 세분화 스케일과 128개마다 FP32로 옮기는 누적으로 FP8 학습을 했고, gpt-oss는 MXFP4 전문가 가중치로 큰 모델을 GPU 한 장에 올렸다.
