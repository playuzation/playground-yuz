# [양자화 5/13] 임베딩 공간의 기하: 양자화가 이웃 관계를 흔드는 방식

> **한 줄 요약** — 임베딩의 의미는 좌표 하나하나가 아니라 "누가 더 가까운가"라는 순위에 담겨 있고, 양자화 잡음 σ가 이웃 사이의 간격 g를 넘으면 순위가 뒤집히므로(확률 ≈ Φ(−g/σ)), 이웃이 촘촘한 곳과 공통 평균 방향이 큰 비등방 공간부터 먼저 흔들린다.

## 이 글에서 다루는 것

## 임베딩: 토큰을 벡터로
**임베딩**(embedding)은 단어나 토큰 같은 이산 기호를 d차원 실수 벡터로 바꾼 것이다. 2013년 미콜로프(Mikolov) 등의 word2vec은 주변 단어를 예측하도록 학습하면 비슷한 문맥에 나오는 단어끼리 가까운 벡터를 갖게 된다는 것을 보였다. LLM에는 이런 행렬이 두 개 있다. 입력 임베딩 E(V × d)는 토큰 번호로 행 하나를 꺼내는 조회표이고, 출력 헤드(lm_head) W(V × d)는 마지막 은닉 상태 h와 모든 행의 내적으로 로짓 `z = W h`를 만든다. 다음 토큰은 h와 내적이 가장 큰 행, 즉 h의 "최근접 이웃"이다. 라마 3 8B는 어휘가 128,256개라 두 행렬이 전체 파라미터의 약 13%를 차지한다(오픈 웨이트 모델 1편).

## 거리, 코사인, 내적과 순위 잡음
세 척도는 하나로 묶여 있다.
```text
a·b = ‖a‖·‖b‖·cos θ
‖a − b‖² = ‖a‖² + ‖b‖² − 2·a·b   (단위 벡터면 2 − 2·cos θ)
```

단위 벡터끼리는 거리 순위와 코사인 순위가 같고, 내적은 여기에 노름이 곱해진다. 양자화는 각 좌표에 잡음을 더한다(`x̂ = x + ε`). 격자 간격이 Δ면 ε의 좌표별 분산은 Δ²/12다(1편). 질의 q에 대한 두 후보 x₁, x₂의 코사인 간격 g에는 q·(ε₁ − ε₂)/(‖q‖·‖x‖)가 더해지므로 어림하면 다음과 같다.
```text
σ ≈ √2 · (Δ/√12) / ‖x‖ = Δ / (√6 · ‖x‖)
P(1등과 2등이 뒤바뀜) ≈ Φ(−g / σ)    Φ: 표준 정규 누적분포
```

행마다 absmax 스케일을 쓰면 `Δ = max∣x∣ / (2^(b−1) − 1)`이라 비트를 하나 줄일 때마다 σ가 약 2배가 된다. 여러 행이 스케일 하나를 공유하면 Δ가 같으므로 노름 ‖x‖이 작은 행일수록 σ가 커진다. word2vec류 임베딩에서는 드문 단어의 노름이 작다는 관찰이 있고(Schakel·Wilson, 2015), Oyama 등(2023)은 이를 학습이 덜 끝난 결과로 해석했다.

## 실험: 비트 수와 차원
가상의 데이터로 현상을 재현해 보자. 의미 군집 100개에 토큰을 20개씩 흩뿌린 임베딩 2,000개를 행마다 양자화하고, 코사인 오차(RMS), 1등 이웃이 그대로인 비율, 10등 안의 이웃이 남는 비율을 잰다.
```python
import numpy as np

rng = np.random.default_rng(0)

def quant(x, bits):                      # 행(토큰)마다 대칭 absmax
    s = np.abs(x).max(axis=1, keepdims=True) / (2 ** (bits - 1) - 1)
    return np.round(x / s) * s

def cosmat(E):                           # 모든 쌍의 코사인, 자기 자신 제외
    U = E / np.linalg.norm(E, axis=1, keepdims=True)
    C = U @ U.T
    np.fill_diagonal(C, -np.inf)
    return C

def embed(d):                            # 의미 군집 100개 × 토큰 20개
    centers = rng.normal(size=(100, d))
    return np.repeat(centers, 20, axis=0) + 0.8 * rng.normal(size=(2000, d))

for d in (64, 256, 1024):
    E = embed(d)
    C = cosmat(E)
    nn = np.argsort(-C, axis=1)[:, :10]  # 이웃 10개
    off = np.isfinite(C)
    errs, top1, rec = [], [], []
    for bits in (8, 6, 4, 3):
        Cq = cosmat(quant(E, bits))
        nq = np.argsort(-Cq, axis=1)[:, :10]
        errs.append(np.sqrt(np.mean((Cq[off] - C[off]) ** 2)))
        top1.append(np.mean(nq[:, 0] == nn[:, 0]))
        rec.append(np.mean([len(set(a) & set(b)) for a, b in zip(nn, nq)]) / 10)
    print(f"d={d:<4} 오차", " ".join(f"{e:.4f}" for e in errs))
    print("       1등 ", "   ".join(f"{t:.2f}" for t in top1),
          " 10등 안", " ".join(f"{r:.2f}" for r in rec))
```
```text
d=64   오차 0.0010 0.0042 0.0186 0.0425
       1등  0.99   0.95   0.75   0.51  10등 안 1.00 0.98 0.92 0.84
d=256  오차 0.0006 0.0025 0.0111 0.0253
       1등  0.98   0.93   0.73   0.47  10등 안 0.99 0.98 0.91 0.82
d=1024 오차 0.0003 0.0014 0.0063 0.0151
       1등  0.99   0.93   0.70   0.41  10등 안 0.99 0.97 0.90 0.78
```

비트를 하나 줄일 때마다 코사인 오차는 약 2배가 되고(d = 256에서 0.0111 → 0.0253), 4비트에서 이미 1등 이웃의 4분의 1 이상이 바뀐다. 눈여겨볼 것은 차원이다. d가 64에서 1024로 커지면 코사인 오차는 1/√d를 따라 0.0186에서 0.0063으로 줄지만 4비트 1등 유지율은 0.75에서 0.70으로 오히려 나빠진다. 이웃 사이의 코사인 간격도 1/√d로 함께 줄고, 차원이 클수록 max∣x∣가 √(2 ln d)를 따라 조금씩 커져 Δ가 넓어지기 때문이다. 차원이 크다고 저절로 안전해지지 않는다.

## 실험: 이웃이 촘촘한 곳부터 뒤집힌다
같은 4비트에서 질의마다 1등과 2등의 코사인 간격 g를 구하고, 간격 구간별로 1등이 바뀐 비율을 Φ(−g/σ)와 비교한다.
```python
from scipy.stats import norm

E = embed(256)
C = cosmat(E)
i = np.arange(len(E))
j1, j2 = np.argsort(-C, axis=1)[:, :2].T
gap = C[i, j1] - C[i, j2]                # 1등과 2등의 코사인 간격
Cq = cosmat(quant(E, 4))
flip = Cq.argmax(axis=1) != j1           # 1등 이웃이 바뀌었나
sig = ((Cq[i, j1] - Cq[i, j2]) - gap).std()          # 간격에 더해진 잡음
delta = np.abs(E).max(axis=1) / 7                     # 4비트 격자 간격 Δ
theory = np.mean(delta / (np.sqrt(6) * np.linalg.norm(E, axis=1)))
print(f"간격 중앙값 {np.median(gap):.4f}, 잡음 σ {sig:.4f} (식 {theory:.4f})")
for lo, hi in [(0, .002), (.002, .005), (.005, .01), (.01, .02), (.02, 1)]:
    m = (gap >= lo) & (gap < hi)
    print(f"간격 {lo:.3f}~{hi:.3f} {m.sum():3d}개: 뒤집힘 {flip[m].mean():.2f},",
          f"Φ(−g/σ) {norm.cdf(-gap[m] / sig).mean():.2f}")
```
```text
간격 중앙값 0.0095, 잡음 σ 0.0108 (식 0.0110)
간격 0.000~0.002 268개: 뒤집힘 0.61, Φ(−g/σ) 0.46
간격 0.002~0.005 310개: 뒤집힘 0.44, Φ(−g/σ) 0.38
간격 0.005~0.010 464개: 뒤집힘 0.34, Φ(−g/σ) 0.25
간격 0.010~0.020 545개: 뒤집힘 0.14, Φ(−g/σ) 0.10
간격 0.020~1.000 413개: 뒤집힘 0.01, Φ(−g/σ) 0.01
```

간격에 더해진 잡음의 표준편차는 측정값 0.0108, 위 식 0.0110으로 맞는다. 간격이 0.002보다 좁은 질의는 61%가 뒤집히고 0.02 이상인 질의는 1%만 뒤집힌다. 측정값이 Φ보다 조금 큰 것은 2등만이 아니라 3등, 4등도 1등을 넘볼 수 있어서다. 같은 잡음이 촘촘한 영역에서는 순위를 바꾸고 성긴 영역에서는 아무 일도 하지 않는다. 이 "간격 대 잡음" 구도는 8편에서 드문 지식이 먼저 사라지는 이유로 다시 나온다.

## 비등방성과 중심화
실제 임베딩은 모든 방향으로 고르게 퍼져 있지 않다. Ethayarajh(2019)는 ELMo·BERT·GPT-2의 문맥 임베딩이 좁은 원뿔 안에 몰려 있고(**비등방성**, anisotropy), GPT-2 마지막 층에서는 무작위 두 단어의 평균 코사인 유사도가 거의 1이라고 보고했다. 공통 평균 방향 μ가 크면 행마다 max∣x∣가 μ 때문에 커지고, 정작 토큰을 구별하는 나머지 성분은 거친 격자에 올라간다. 해결책은 어텐션 8편의 K smoothing과 같다. 출력 헤드의 모든 행에서 평균 μ̄를 빼면 `z_i = h·(w_i − μ̄) + h·μ̄`에서 h·μ̄가 모든 토큰에 같은 상수라 softmax는 그대로다. μ̄는 벡터 하나라 높은 정밀도로 따로 두면 된다.
```python
def softmax(z):
    e = np.exp(z - z.max(axis=1, keepdims=True))
    return e / e.sum(axis=1, keepdims=True)

V, d = 4000, 256
mu = 3.0 * rng.normal(size=d)            # 모든 토큰에 공통인 방향
centers = rng.normal(size=(200, d))
W = mu + np.repeat(centers, 20, axis=0) + 0.8 * rng.normal(size=(V, d))
H = centers[rng.integers(0, 200, 2000)] + 0.5 * rng.normal(size=(2000, d))
C = cosmat(W)
print(f"토큰 쌍의 평균 코사인 {C[np.isfinite(C)].mean():.3f}")

mbar = W.mean(axis=0)                    # 행 방향 평균(토큰 평균)
Z = H @ W.T / np.sqrt(d)                 # 출력 헤드의 로짓
Zc = H @ (W - mbar).T / np.sqrt(d)       # 모든 로짓에서 h·μ̄가 빠질 뿐
print("중심화 전후 softmax 차이", np.abs(softmax(Z) - softmax(Zc)).max())
for bits in (8, 4, 3):
    for name, Wq in [("그대로", quant(W, bits)),
                     ("중심화", quant(W - mbar, bits) + mbar)]:  # μ̄는 FP
        Zq = H @ Wq.T / np.sqrt(d)
        err = np.sqrt(np.mean((Zq - Z) ** 2))
        keep = np.mean(Zq.argmax(axis=1) == Z.argmax(axis=1))
        print(f"{bits}비트 {name}: 로짓 오차 {err:.3f}, 1등 유지 {keep:.3f}")
```
```text
토큰 쌍의 평균 코사인 0.853
중심화 전후 softmax 차이 7.716050021144838e-15
8비트 그대로: 로짓 오차 0.025, 1등 유지 0.975
8비트 중심화: 로짓 오차 0.010, 1등 유지 0.991
4비트 그대로: 로짓 오차 0.455, 1등 유지 0.552
4비트 중심화: 로짓 오차 0.179, 1등 유지 0.806
3비트 그대로: 로짓 오차 1.062, 1등 유지 0.299
3비트 중심화: 로짓 오차 0.420, 1등 유지 0.568
```

평균 코사인이 0.853인 비등방 공간에서 중심화는 softmax를 10⁻¹⁴ 수준까지 그대로 두면서 로짓 오차를 약 2.5배 줄이고, 4비트에서 1등 유지율을 55%에서 81%로 올린다. 2.5배는 μ가 있을 때와 없을 때 좌표 표준편차의 비 `√(3² + 1.28²) / 1.28 ≈ 2.55`와 맞는다. 격자 간격이 μ의 크기에 맞춰져 있었던 것이다.

## 입력 임베딩과 출력 헤드를 남겨 두는 이유
많은 도구가 블록 안의 선형 층만 저비트로 내리고 출력 헤드는 높은 정밀도로 둔다. 트랜스포머스의 bitsandbytes 설정은 인과 언어 모델의 마지막 lm_head를 원래 dtype으로 남기고, vLLM의 AWQ 로더도 설정에 따로 적지 않으면 lm_head를 양자화되지 않은 층으로 다루며, llama.cpp의 양자화 도구는 출력 텐서의 형식을 따로 지정하는 옵션을 둔다. 이유는 위 실험에 있다.
- 출력 헤드의 결정은 어휘 전체(라마 3이면 12만 개 넘게) 가운데 1등 고르기다. 후보가 많을수록 1등 근처가 촘촘해 작은 g가 많고, 뒤에서 잡음을 평균해 줄 층도 없다.
- 입력 임베딩은 토큰마다 행 하나만 읽으므로, 양자화하면 메모리는 줄어도 디코드 때 읽는 양은 거의 줄지 않는다. 반면 거기서 생긴 오차는 모든 층을 지나간다(4편).
- 스케일을 여러 행이 공유하는 형식이면 노름이 작은 행이 상대 오차를 더 크게 받는다.

## 어디에 쓰이나
- 선형대수 2편 「내적과 코사인 유사도」: 이 글의 순위 뒤집힘은 그 글의 코사인 유사도가 좌표 잡음을 받았을 때 얼마나 움직이는가의 문제다.
- 확률과 분포 8편 「정규 분포: 종 모양 곡선의 정체」: 뒤집힘 확률 Φ(−g/σ)는 좌표 잡음 수백 개의 합이 정규 분포에 가깝다는 데서 나온다.
- 어텐션 8편 「세이지 어텐션: 양자화로 더 빠르게」: K의 토큰 평균 빼기와 출력 헤드 중심화는 "모든 점수에 같은 상수를 더해도 softmax는 그대로"라는 같은 성질을 쓴다.
- 8편 「왜 드문 지식이 먼저 사라지나: 데이터 분포와 롱테일」: 간격 대 잡음의 비가 뒤집힘을 정한다는 결론이 지식의 로짓 마진으로 옮겨 간다.

## 정리
- 임베딩의 의미는 벡터 사이의 순위에 있고, 양자화는 순위 간격 g에 표준편차 σ ≈ Δ/(√6·‖x‖)의 잡음을 더한다.
- 뒤집힘 확률은 Φ(−g/σ)다. 비트 하나를 줄이면 σ가 2배가 되고, 차원이 커져도 간격이 함께 줄어 안전해지지 않는다.
- 비등방 공간에서는 평균을 빼고 양자화하면 softmax는 그대로이면서 오차가 크게 준다.
- 출력 헤드는 촘촘한 1등 다툼이라 양자화에 민감해서, 높은 정밀도로 남기는 관행이 있다.
