# [게임 자원 관리 12/14] 텍스처 아틀라스와 사각형 빈 패킹

> **한 줄 요약** — 스프라이트마다 텍스처를 따로 두면 텍스처가 바뀔 때마다 그리기 호출이 끊기므로 작은 이미지들을 큰 텍스처 한 장(아틀라스)에 모으는데, 최적 배치는 NP-어려움이라 선반·스카이라인 같은 휴리스틱을 쓰고, 높이순 정렬 하나로 사용률이 52%에서 89%로 오른다.

## 이 글에서 다루는 것
- 그리기 호출과 텍스처 전환: 아틀라스가 호출 수를 줄이는 이유
- 사각형 빈 패킹 문제와 NP-어려움
- 선반 패킹과 스카이라인 패킹 구현, 겹침 검사
- 높이순 정렬의 효과와 사용률 비교 실험

## 왜 아틀라스인가: 텍스처가 바뀌면 호출이 끊긴다
2D 게임은 스프라이트를 뒤에서 앞으로 정해진 순서대로 그려야 겹침이 맞는다. CPU가 GPU에 "이 텍스처로 이 사각형들을 그려라"라고 보내는 명령 한 번이 **그리기 호출**(draw call)인데, 다음 스프라이트의 텍스처가 다르면 상태를 바꾸고 새 호출을 보내야 한다. 호출마다 드라이버의 검증과 상태 변경 비용이 붙으므로 호출 수가 CPU 시간을 잡아먹는다. 텍스처 150장에서 무작위로 고른 스프라이트 1,000개를 그린다고 하자.
```python
import random
rng = random.Random(1)
order = [rng.randrange(150) for _ in range(1000)]  # 그리는 순서(바꿀 수 없음)
calls = 1 + sum(a != b for a, b in zip(order, order[1:]))
print("텍스처 150장 따로: 그리기 호출", calls)
print("아틀라스 1장: 그리기 호출", 1)
```
```text
텍스처 150장 따로: 그리기 호출 993
아틀라스 1장: 그리기 호출 1
```
그리는 순서를 텍스처별로 정렬하면 호출이 150번으로 줄겠지만 겹침 순서가 깨진다. 이미지 150개를 큰 텍스처 한 장에 모아 두고 각 스프라이트는 그 안의 좌표(UV)만 다르게 쓰면, 순서를 지키면서도 한 번에 그릴 수 있다. 이것이 **텍스처 아틀라스**(texture atlas)다. 유니티의 스프라이트 아틀라스도 여러 텍스처를 하나로 합쳐 그리기 호출을 줄이는 기능으로 문서화되어 있다.

## 문제: 직사각형을 겹치지 않게 빽빽이
아틀라스를 만들려면 크기가 제각각인 사각형 n개를 폭 W인 판에 겹치지 않게 놓되, 쓴 높이를 가능한 한 줄여야 한다(높이가 정해진 여러 장에 나누면 빈 패킹, 높이를 줄이면 띠 패킹). 1차원 빈 패킹부터 NP-어려움이고 2차원은 이를 포함하므로, 큰 n에서 최적해를 구하는 다항 시간 알고리즘은 기대하기 어렵다. 그래서 빠른 휴리스틱을 쓰고 **사용률**(사각형 면적 합 ÷ 쓴 판 면적)로 평가한다. 대표적인 두 방법은 다음과 같다.
```text
선반              스카이라인
┌────────────┐    ┌────────────┐
│###  ##     │    │     ###    │
│###  ## ####│    │#### ###  ##│
├────────────┤    │######### ##│
│##### ### ##│    │############│
└────────────┘    └────────────┘
```
**선반 패킹**은 왼쪽부터 한 줄로 채우다 폭이 넘치면 그 줄에서 가장 높은 사각형 위에 새 선반을 연다. **스카이라인 패킹**은 지금까지 쌓은 윗면 윤곽(스카이라인)을 구간 목록으로 들고 있다가, 새 사각형이 가장 낮게 놓이는 자리(같으면 왼쪽)를 고른다. 선반은 줄 안의 키 차이만큼 빈 공간이 생기지만, 스카이라인은 낮은 곳을 찾아 채운다.
```python
import random

def shelf_pack(rects, W):
    x = y = shelf_h = 0
    pos = []
    for w, h in rects:
        if x + w > W:                             # 넘치면 새 선반
            x, y, shelf_h = 0, y + shelf_h, 0
        pos.append((x, y))
        x, shelf_h = x + w, max(shelf_h, h)
    return pos

def skyline_pack(rects, W):
    sky, pos = [(0, 0, W)], []                    # 윤곽: (x, y, 폭) 구간들
    for w, h in rects:
        best = None
        for i, (x, _, _) in enumerate(sky):
            if x + w > W:
                break
            y, j, need = 0, i, w
            while need > 0:                       # 폭 w가 걸치는 구간의 최고 높이
                y, need, j = max(y, sky[j][1]), need - sky[j][2], j + 1
            if best is None or (y, x) < best:
                best = (y, x)
        y, x = best
        pos.append((x, y))
        new = [(x, y + h, w)]
        for sx, sy, sw in sky:                    # 덮인 부분을 잘라 낸다
            if sx < x:
                new.append((sx, sy, min(sw, x - sx)))
            if sx + sw > x + w:
                left = max(sx, x + w)
                new.append((left, sy, sx + sw - left))
        new.sort()
        sky = []
        for seg in new:                           # 높이가 같은 이웃은 합친다
            if sky and sky[-1][1] == seg[1] and sum(sky[-1][::2]) == seg[0]:
                sky[-1] = (sky[-1][0], seg[1], sky[-1][2] + seg[2])
            else:
                sky.append(seg)
    return pos

def check(rects, pos, W):                         # 판 안 + 서로 안 겹침
    bs = [(x, y, x + w, y + h) for (x, y), (w, h) in zip(pos, rects)]
    if any(b[0] < 0 or b[2] > W or b[1] < 0 for b in bs):
        return False
    return not any(a[0] < b[2] and b[0] < a[2] and a[1] < b[3] and b[1] < a[3]
                   for i, a in enumerate(bs) for b in bs[i + 1:])

rng, ok = random.Random(12), 0
for _ in range(300):
    W = rng.randint(8, 64)
    rects = [(rng.randint(1, W), rng.randint(1, 40))
             for _ in range(rng.randint(1, 25))]
    for f in (shelf_pack, skyline_pack):
        ok += check(rects, f(rects, W), W)
print(f"겹침 검사 300개 × 2방법: {ok}개 통과")
```
```text
겹침 검사 300개 × 2방법: 600개 통과
```
스카이라인의 불변식은 "윤곽 구간들이 [0, W)를 빈틈없이 덮고, 각 구간 높이 위는 비어 있다"이다. 새 사각형은 걸치는 구간들의 최고 높이에 놓이므로 아래의 어떤 사각형과도 겹치지 않고, 놓은 뒤 그 폭을 새 높이로 덮어 불변식을 유지한다. 그 대신 윤곽 아래에 갇힌 빈칸은 다시 쓰지 못한다.

## 사용률 비교 실험
앞 코드에 이어서, 8~128픽셀 크기의 스프라이트 150개 묶음 20개를 폭 1024에 넣고 정렬 여부를 바꿔 본다.
```python
def height(rects, pos):
    return max(y + h for (x, y), (w, h) in zip(pos, rects))

W, rng = 1024, random.Random(3)
sets = [[(rng.randint(8, 128), rng.randint(8, 128)) for _ in range(150)]
        for _ in range(20)]
tallest = 0
for name, f, key in (("선반", shelf_pack, None),
                     ("선반+정렬", shelf_pack, lambda r: -r[1]),
                     ("스카이라인", skyline_pack, None),
                     ("스카이라인+정렬", skyline_pack, lambda r: -r[1])):
    us = []
    for rects in sets:
        rs = sorted(rects, key=key) if key else rects
        hgt = height(rs, f(rs, W))
        us.append(sum(w * h for w, h in rs) / (W * hgt))
        tallest = max(tallest, hgt) if key and f is skyline_pack else tallest
    print(f"{name}: 평균 {sum(us) / 20:.1%}, 최저 {min(us):.1%}")
print("정렬 스카이라인 최대 높이", tallest)
```
```text
선반: 평균 52.5%, 최저 47.5%
선반+정렬: 평균 88.7%, 최저 87.0%
스카이라인: 평균 82.2%, 최저 77.9%
스카이라인+정렬: 평균 91.1%, 최저 89.2%
정렬 스카이라인 최대 높이 825
```
정렬하지 않은 선반은 절반 가까이를 버린다. 키 큰 사각형 하나가 선반 높이를 정하면 그 줄의 작은 사각형 위가 모두 빈 공간이 되기 때문이다. 높이 내림차순으로 정렬하면 한 선반에 비슷한 키끼리 모여 사용률이 89%로 뛴다. 이 "높이순으로 정렬한 뒤 지금 선반에 채우기"는 띠 패킹의 고전 휴리스틱 NFDH(next fit decreasing height) 그대로다. 스카이라인은 정렬 없이도 82%를 내고, 정렬하면 91%로 가장 좋다. 정렬한 스카이라인으로는 가장 높은 묶음도 825픽셀이라 모두 1024×1024 한 장에 들어가므로, 처음 예의 그리기 호출 993번이 한 번으로 줄어든다.

## 자주 하는 실수와 변형
- 여백 없이 붙이면 텍스처를 선형 보간하거나 밉맵을 만들 때 옆 스프라이트의 색이 번진다. 1~2픽셀 여백을 두고 가장자리 픽셀을 밖으로 복제해 둔다.
- 90도 회전을 허용하면 더 빽빽해지지만, 그리는 쪽이 회전된 UV를 알아야 한다.
- 실행 중에 글리프(글자 모양)를 추가하는 글꼴 아틀라스처럼 동적으로 채우는 경우, 자리가 없으면 5편의 캐시 교체로 오래 안 쓴 것을 비우거나 판을 새로 만든다.
- 윌랭키의 조사 글 「A Thousand Ways to Pack the Bin」은 선반·기요틴·MaxRects·스카이라인 계열의 변형들을 비교하고 구현을 공개했다.

## 복잡도
| 방법 | 시간 | 근거 |
|---|---|---|
| 선반 | O(n) | 사각형마다 한 번 |
| 스카이라인 | O(n·s) | 구간 s개를 훑음 |
| 높이순 정렬 | O(n log n) | 정렬 한 번 |
| 겹침 검사 | O(n²) | 모든 쌍 |

- 윤곽 구간 수 s는 최대 n + 1이라 스카이라인은 최악 O(n²)지만, 합치기 덕분에 실제로는 훨씬 짧다. 아틀라스는 보통 빌드 때 한 번 만들므로 이 정도 비용은 문제가 아니다. 공간은 위치 목록 O(n)과 윤곽 O(s)다.

## 어디에 쓰이나
- 트랜지스터에서 자연어까지 7편 「빠르게 만드는 기술: 파이프라인, 캐시, 병렬성」: GPU는 같은 프로그램을 많은 데이터에 동시에 돌리는 장치라, 스프라이트 수백 개를 호출 하나로 묶어 넘겨야 그 병렬성을 다 쓴다.
- 3편 「메모리 할당자: 선형·스택·풀 할당자와 단편화」: 아틀라스는 2차원 메모리 할당이고, 선반은 줄마다 선형 할당자, 윤곽 아래 갇힌 빈칸은 외부 단편화다.
- 동적 계획법 2편 「배낭 문제: 0-1 배낭, 무한 배낭, 메모리 줄이기」: 용량 안에 물건을 담는 같은 계열의 문제로, 1차원은 의사 다항 DP가 있지만 2차원 배치는 휴리스틱에 기댄다.

## 정리
- 텍스처가 바뀔 때마다 그리기 호출이 끊기므로, 작은 이미지를 아틀라스 한 장에 모으면 그리는 순서를 지키면서 호출 수를 줄일 수 있다.
- 사각형 배치는 NP-어려움이라 선반·스카이라인 같은 휴리스틱을 쓰고, 겹침 검사로 정확성을, 사용률로 품질을 잰다.
- 높이순 정렬만으로 선반 패킹의 사용률이 52%에서 89%로 올랐고, 정렬한 스카이라인이 91%로 가장 좋았다.
- 여백, 회전, 동적 아틀라스는 실제 도구에서 함께 다뤄야 하는 변형이다.
