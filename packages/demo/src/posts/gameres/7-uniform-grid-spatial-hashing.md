# [게임 자원 관리 7/14] 공간 분할 1: 균일 격자와 공간 해싱

> **한 줄 요약** — 물체 n개의 충돌을 모든 쌍으로 검사하면 O(n²)이지만, 세계를 물체 지름 크기의 칸으로 나눠 이웃 칸끼리만 비교하면 고르게 퍼진 경우 O(n + 겹친 쌍 수)가 되고, 칸을 해시 테이블에 담으면 끝없는 세계도 고정된 메모리로 다룰 수 있다.

## 이 글에서 다루는 것
- 넓은 단계와 좁은 단계: 후보를 줄이고 정확히 검사하기
- 균일 격자: 몇 칸 떨어진 것까지 봐야 하나
- 셀 크기 선택: 검사 횟수와 칸 조회의 교환
- 딕셔너리 공간 해시와 고정 크기 해시 테이블(충돌은 비용일 뿐)
- 모든 쌍 검사와의 무작위 대조

## 문제: 원 2,000개, 겹친 쌍 찾기
250×250 공간에 반지름 1인 원(총알, 유닛, 파티클) 2,000개가 있다. 매 프레임 겹친 쌍을 모두 찾아야 한다. 모든 쌍을 보면 `2000 × 1999 / 2 = 1,999,000`번이다. 60fps라면 1초에 1억 2천만 번이고, 원 대신 다각형이라면 한 번의 검사도 훨씬 비싸다.

충돌 검사는 보통 두 단계로 나눈다. **넓은 단계**(broad phase)는 "겹칠 수도 있는" 후보 쌍을 싸게 추려 내고, **좁은 단계**(narrow phase)는 그 후보만 정확한 기하 계산으로 확인한다. 넓은 단계는 겹친 쌍을 하나도 빠뜨리면 안 되지만, 겹치지 않는 쌍을 후보에 넣는 것은 괜찮다. 비용만 늘 뿐이다. 이 글과 8편은 넓은 단계의 자료 구조를 다룬다.

## 균일 격자
공간을 한 변이 s인 정사각형 칸으로 나누고, 원을 중심이 속한 칸에 넣는다. 칸 번호는 `(⌊x/s⌋, ⌊y/s⌋)`다. 두 원이 겹치면 중심 거리가 2r(지름) 미만이므로, 칸 번호가 각 축으로 `⌈2r/s⌉`칸 넘게 차이 날 수 없다. 그래서 각 원은 자기 칸 주변 `(2·⌈2r/s⌉ + 1)²`칸만 보면 된다. s를 지름으로 잡으면 3×3칸이다.
```text
┌───┬───┬───┐
│ . │ . │ . │   s = 지름이면
├───┼───┼───┤   가운데 칸의 원은
│ . │ o │ . │   주변 9칸만 본다
├───┼───┼───┤
│ . │ . │ . │
└───┴───┴───┘
```
같은 쌍을 두 번 세지 않도록 "번호가 작은 쪽에서만" 검사한다. 칸 저장소는 두 가지로 만든다. 하나는 칸 번호를 키로 하는 딕셔너리로, 원이 있는 칸만 메모리를 쓴다. 다른 하나는 크기 T인 고정 배열에 칸 번호를 해시해 넣는 방식이다. 테셔(Teschner) 등의 2003년 논문 "Optimized Spatial Hashing for Collision Detection of Deformable Objects"가 이렇게 해시 함수로 끝없는 격자를 유한한 테이블에 압축했다. 서로 다른 칸이 같은 버킷에 떨어지면 남의 칸 물체가 후보에 섞이지만, 좁은 단계가 걸러 주므로 답은 그대로다.
```python
import math, random
from collections import defaultdict

def hit(p, q, r):                          # 좁은 단계: 두 원이 겹치나
    return (p[0] - q[0]) ** 2 + (p[1] - q[1]) ** 2 < (2 * r) ** 2

def brute(pts, r):                         # 모든 쌍 O(n²)
    n = len(pts)
    return {(i, j) for i in range(n) for j in range(i + 1, n)
            if hit(pts[i], pts[j], r)}

def grid(pts, r, cell, T=None):            # 넓은 단계 + 좁은 단계
    cellof = [(math.floor(x / cell), math.floor(y / cell)) for x, y in pts]
    if T is None:                          # 딕셔너리 공간 해시
        cells = defaultdict(list)
        slot, get = (lambda c: c), (lambda k: cells.get(k, ()))
    else:                                  # 크기 T인 고정 테이블
        cells = [[] for _ in range(T)]
        slot = lambda c: (c[0] * 73856093 ^ c[1] * 19349663) % T
        get = lambda k: cells[k]
    for i, c in enumerate(cellof):
        cells[slot(c)].append(i)
    reach = math.ceil(2 * r / cell)        # 몇 칸 떨어진 것까지 볼까
    pairs, tests, looks = set(), 0, 0
    for i, (cx, cy) in enumerate(cellof):
        keys = {slot((cx + dx, cy + dy)) for dx in range(-reach, reach + 1)
                for dy in range(-reach, reach + 1)}
        looks += len(keys)
        for k in keys:
            for j in get(k):
                if j > i:                  # 각 쌍은 번호 작은 쪽에서 한 번
                    tests += 1
                    if hit(pts[i], pts[j], r):
                        pairs.add((i, j))
    return pairs, tests, looks

rng = random.Random(1)
R, WORLD, N = 1.0, 250.0, 2000
pts = [(rng.uniform(0, WORLD), rng.uniform(0, WORLD)) for _ in range(N)]
ref = brute(pts, R)
print(f"전수: 검사 {N * (N - 1) // 2}번, 겹친 쌍 {len(ref)}개")
for cell in (0.5, 1, 2, 4, 8, 16):
    got, tests, looks = grid(pts, R, cell)
    print(f"칸 {cell:>4}: 검사 {tests:6} 조회 {looks:6} 합 {tests + looks:6}"
          f" {'일치' if got == ref else '불일치'}")
for T in (16, 256, 4096):
    got, tests, looks = grid(pts, R, 2, T)
    print(f"고정 테이블 T={T:<4}: 검사 {tests:7}"
          f" {'일치' if got == ref else '불일치'}")
```

```text
칸  0.5: 검사    693 조회 162000 합 162693 일치
칸    1: 검사    868 조회  50000 합  50868 일치

```

## 셀 크기는 지름 근처
`검사`는 좁은 단계 호출 수, `조회`는 들여다본 칸 수다. 칸이 크면 한 칸에 원이 많이 들어가 검사가 늘고(칸 16: 65,706번), 칸이 작으면 봐야 할 이웃 칸이 `(2⌈2r/s⌉ + 1)²`로 늘어 조회가 폭발한다(칸 0.5: 원 하나당 81칸). 합이 가장 작은 곳은 칸 = 지름(2)이고, 이때 전수 비교 199만 번이 검사 1,228번 + 조회 18,000번으로 줄었다. 100배 넘게 적다. 겹친 쌍 430개는 모든 셀 크기에서 전수 비교와 똑같다.

크기가 제각각이면 가장 큰 물체의 지름에 맞추는 것이 기본이다. 작은 물체가 대부분인데 거대한 보스가 하나 있으면 칸이 쓸데없이 커지므로, 큰 물체는 겹치는 모든 칸에 넣거나 따로 다룬다. 물체가 한쪽에 몰리면 그 칸들만 붐벼 다시 O(n²)에 가까워진다. 이 약점을 다루는 쿼드트리와 BVH는 8편에서 본다.

## 고정 테이블: 충돌은 비용일 뿐
딕셔너리는 칸이 생길 때마다 항목을 만들고 키 튜플을 할당한다. 고정 크기 테이블은 프레임마다 같은 배열을 비우고 다시 채우면 되니 2편·3편의 정신대로 할당이 없다. 대가는 해시 충돌이다. T=16이면 버킷 하나에 원이 평균 125개 섞여 검사가 100만 번으로 전수와 다를 바 없고, T=4096이면 5,289번이다. 셋 다 답은 맞다. 충돌이 정확성이 아니라 비용만 바꾼다는 것이 이 구조의 장점이다. 보통 T를 물체 수의 몇 배로 잡는다.

## 무작위 대조 검사
앞 코드에 이어서, 원 개수·반지름·셀 크기·테이블 크기(1 포함)를 무작위로 바꾸고 음수 좌표까지 섞어 모든 쌍 검사와 비교한다.
```python
rng, ok = random.Random(2), True
for _ in range(500):
    n, r = rng.randint(0, 60), rng.uniform(0.1, 3)
    span = rng.uniform(1, 40)
    pts = [(rng.uniform(-span, span), rng.uniform(-span, span))
           for _ in range(n)]
    cell = rng.uniform(0.3, 10)
    T = rng.choice([None, 1, 7, 64])
    ok &= grid(pts, r, cell, T)[0] == brute(pts, r)
print("무작위 500개 비교:", "모두 일치" if ok else "불일치")
```
```text
무작위 500개 비교: 모두 일치
```
`reach`를 늘 1로 고정하면(셀이 지름보다 작을 때 이웃이 모자람) 바로 "불일치"가 나온다.

### 자주 하는 실수
- 칸 번호에 `int(x / s)`를 쓴다: 0 쪽으로 잘라서 -s < x < s가 모두 0번 칸이 된다. 답은 맞지만(칸 번호 차이가 줄기만 한다) 원점 근처 칸이 두 배로 붐빈다. `math.floor`를 쓴다.
- 반지름이 아니라 지름으로 이웃 범위를 정해야 한다: 중심 거리가 2r까지 겹친다.
- 움직이는 물체: 매 프레임 다시 채우는 것이 O(n)으로 단순하고 빠르다. 칸이 바뀐 물체만 옮기는 방식은 물체가 느릴 때 유리하다.

## 복잡도
| 방법 | 프레임당 시간 | 메모리 |
|---|---|---|
| 모든 쌍 | O(n²) | O(1) |
| 격자(고른 분포) | O(n + k) | O(n + 칸 수) |
| 격자(한곳에 몰림) | O(n²) | 같음 |
| 고정 해시 테이블 | O(n + k + 충돌) | O(n + T) |

k는 겹친 쌍 수다. 칸당 물체 수의 기댓값이 상수(밀도 × s²)이면 원 하나가 보는 후보도 상수 개라서 전체가 선형이 된다.

## 정리
- 넓은 단계는 후보를 빠짐없이 싸게 추리고, 좁은 단계가 정확히 확인한다.
- 칸 크기 s에서 각 물체는 각 축으로 `⌈2r/s⌉`칸 안만 보면 되고, s = 지름일 때 검사와 조회의 합이 가장 작았다(전수의 100분의 1 이하).
- 딕셔너리 공간 해시는 끝없는 세계를, 고정 테이블은 할당 없는 프레임을 준다. 해시 충돌은 비용만 늘린다.
- 분포가 고르지 않으면 격자가 약해지므로 8편의 계층 구조가 필요하다.
