# [컴퓨터와 AI의 첫걸음 5/7] 현대 컴퓨터는 어떻게 복잡한 일을 하나: 층층이 쌓은 추상화와 속도

> **한 줄 요약** — 컴퓨터가 한 번에 하는 일은 더하기·비교·옮기기처럼 아주 단순하지만, 아래 층의 세부를 숨기고 위 층에 더 큰 부품을 내주는 추상화의 층과 그 단순한 일을 1초에 수십억 번 해내는 속도가 겹쳐 지도·사진·게임·AI 같은 복잡한 일이 된다.

## 이 글에서 다루는 것
- 사진 한 장을 밝게 할 때 컴퓨터가 실제로 하는 일
- 추상화의 층: 트랜지스터에서 응용 프로그램까지, 각 층이 숨기는 것
- 덧셈과 비교만으로 곱셈 → 정렬 → 낱말 세기를 쌓아 보기
- 속도와 규모: 트랜지스터 1개에서 2,000억 개까지
- 기억의 계층, 운영체제와 네트워크

## 사진을 밝게 하는 버튼 뒤에서
휴대폰 사진 앱에서 "밝게"를 누르면 무슨 일이 일어날까? 2편에서 본 것처럼 비트를 묶으면 색도 숫자로 적을 수 있다. 흔한 방식은 점(화소)마다 빨강·초록·파랑의 밝기를 0~255 숫자 세 개로 적는 것이라, 1,200만 화소 사진이면 숫자가 3,600만 개다. 가장 단순한 "밝게"는 숫자마다 일정한 값을 더하고, 255를 넘었는지 비교해서 넘었으면 255로 맞추는 일이다. 하나하나는 초등학생도 할 수 있는 더하기와 비교다. 다만 3,600만 번이다. 사람이 1초에 하나씩 하면 쉬지 않고 1년 넘게 걸릴 일을 휴대폰은 눈 깜짝할 사이에 끝낸다.

컴퓨터가 복잡한 일을 해내는 비결은 둘이다. 단순한 일을 엄청나게 빨리, 엄청나게 많이 하는 속도, 그리고 그 단순한 일을 묶어 점점 큰 일로 만드는 **추상화**(abstraction)다.

## 추상화: 아래를 몰라도 쓰게 하는 약속
운전하는 사람은 엔진 안에서 연료가 어떻게 타는지 몰라도 된다. 가속 페달을 밟으면 빨라진다는 약속만 알면 된다. 추상화는 이런 약속이다. 아래 층은 복잡한 세부를 안에 숨기고 위 층에는 "무엇을 해 주는지"만 드러낸다. 위 층은 그 약속만 믿고 더 큰 것을 만든다. 비유가 깨지는 곳도 있다. 컴퓨터의 층은 숨긴 세부가 가끔 속도나 오류로 새어 나온다(아래 흔한 오해).

컴퓨터는 이 약속을 여러 번 겹쳐 쌓은 기계다.

| 층 | 위 층에 내주는 것 | 숨기는 것 |
|---|---|---|
| 응용 프로그램 | 지도, 사진, 대화 | 프로그램 코드 |
| 프로그래밍 언어 | 변수, 반복, 함수 | 명령어, 레지스터 |
| 운영체제 | 파일, 창, 여러 앱 함께 실행 | 장치 차이, 메모리 위치 |
| CPU 명령어 | 더하기, 비교, 옮기기, 건너뛰기 | 회로 배선 |
| 회로 | 덧셈기, 기억 칸 | 게이트 연결 |
| 논리 게이트 | AND, OR, NOT | 트랜지스터 배치 |
| 트랜지스터 | 켜짐과 꺼짐 | 전압, 잡음 |

"밝게" 한 번은 이 층을 위에서 아래로 내려가며 점점 작은 일로 쪼개진다.
```text
[앱] "밝게" 버튼을 누름
  ↓
[언어] 숫자마다 +30, 최대 255
  ↓
[운영체제] 사진 파일을 메모리로
  ↓
[명령어] 읽기, 더하기, 비교, 쓰기
  ↓
[회로] 덧셈기와 비교기
  ↓
[트랜지스터] 스위치 켜짐과 꺼짐
```

앱을 만드는 사람은 덧셈기 회로를 몰라도 되고, 회로를 설계하는 사람은 사진 앱을 몰라도 된다. 각 층이 자기 약속만 지키면 전체가 맞물린다. 수많은 사람이 나눠 만든 것을 한 사람이 손바닥 위에서 쓸 수 있는 이유다.

## 직접 확인: 덧셈과 비교만으로 쌓아 올리기
층을 쌓는 느낌을 파이썬으로 흉내 내 보자. 0층에서 기계가 할 줄 아는 일은 더하기(`add`)와 비교(`less`) 둘뿐이라고 정한다. 그 위 층은 아래 층이 내준 기능만 쓴다. 곱셈은 더하기를 되풀이하고, 정렬은 비교해서 자리를 바꾸고, 낱말 세기는 정렬한 뒤 같은 낱말끼리 센다. 코드를 읽지 못해도 괜찮다. 층마다 만든 결과와 0층 일을 몇 번 했는지만 출력에서 보자.
```python
n = {"더하기": 0, "비교": 0}          # 0층 일을 몇 번 했나

def add(a, b):                        # 0층: 더하기
    n["더하기"] += 1
    return a + b

def less(a, b):                       # 0층: 비교(a가 b보다 앞인가)
    n["비교"] += 1
    return a < b

def multiply(a, k):                   # 1층: 곱셈 = 더하기를 k번
    total = 0
    for _ in range(k):
        total = add(total, a)
    return total

def sort(xs):                         # 2층: 정렬 = 비교하고 자리 바꾸기
    xs = list(xs)
    for i in range(1, len(xs)):
        j = i
        while j > 0 and less(xs[j], xs[j - 1]):
            xs[j - 1], xs[j] = xs[j], xs[j - 1]
            j -= 1
    return xs

def word_counts(words):               # 3층: 정렬한 뒤 같은 낱말 세기
    counts = []
    for w in sort(words):
        if counts and not less(counts[-1][0], w):   # 앞 낱말과 같다
            counts[-1][1] = add(counts[-1][1], 1)
        else:
            counts.append([w, 1])
    return counts

def show(result):
    print(result, f"| 더하기 {n['더하기']:,}번, 비교 {n['비교']:,}번")
    n["더하기"] = n["비교"] = 0

fruits = "사과 배 사과 감 배 사과".split()
show(f"1층 7 × 6 = {multiply(7, 6)}")
show(f"2층 {sort([5, 3, 8, 1])}")
show("3층 " + ", ".join(f"{w} {c}" for w, c in word_counts(fruits)))
for k in (10, 100):
    word_counts(fruits * k)
    show(f"3층 낱말 {6 * k}개")
```
```text
1층 7 × 6 = 42 | 더하기 6번, 비교 0번
2층 [1, 3, 5, 8] | 더하기 0번, 비교 5번
3층 감 1, 배 2, 사과 3 | 더하기 3번, 비교 14번
3층 낱말 60개 | 더하기 57번, 비교 671번
3층 낱말 600개 | 더하기 597번, 비교 56,246번
```

7 × 6은 더하기 6번이 되었고, 숫자 4개 정렬은 비교 5번이 되었다. 낱말 세기를 만든 사람은 `sort`가 안에서 무엇을 하는지 몰라도 되고, `sort`를 만든 사람은 그것이 과일 이름에 쓰일지 몰라도 된다. 위 표의 층과 같은 모양이다. 장난감이라 단순하게 셌다는 점은 밝혀 둔다. 낱말 두 개의 비교는 실제로는 글자를 하나씩 견주는 여러 번의 비교이고, 반복문이 몇 번째인지 세는 일도 더하기와 비교지만 세지 않았다. 실제 CPU에는 곱셈 회로가 따로 있는데, 그 회로도 덧셈기를 엮어 만든다.

마지막 두 줄이 흥미롭다. 낱말이 60개에서 600개로 10배 늘자 비교는 671번에서 56,246번으로 80배 넘게 늘었다. 이 정렬 방법은 새 낱말을 앞의 낱말들과 하나씩 견주기 때문에, 일의 양이 낱말 수의 제곱에 가깝게 는다. 같은 일도 방법(알고리즘)에 따라 셈의 수가 크게 달라진다는 뜻이고, 그래서 실제 프로그램은 훨씬 영리한 정렬 방법을 쓴다.

## 같은 기계가 지도도 되고 게임도 되는 이유
1편에서 본 저장 프로그램 방식 덕분이다. 프로그램도 숫자로 메모리에 들어 있으므로, 지도 앱을 열면 지도 프로그램의 명령어가, 게임을 열면 게임의 명령어가 메모리에 올라오고 CPU는 그것을 차례로 실행할 뿐이다. 기계(하드웨어)는 그대로이고 바뀌는 것은 메모리 속 명령어, 곧 **소프트웨어**(software)다. 새 기능이 필요할 때 칩을 새로 만들지 않고 앱을 내려받기만 하면 되는 이유다.

## 속도와 규모: 스위치 1개에서 2,000억 개까지
층이 쓸모 있으려면 맨 아래가 엄청나게 빠르고 많아야 한다. 1947년 12월 미국 벨 연구소의 존 바딘(John Bardeen)과 월터 브래튼(Walter Brattain)이 첫 트랜지스터를 만들었다. 전기로 켜고 끄는 작은 고체 스위치다. 1971년 인텔 4004는 CPU 하나를 칩 하나에 담은 첫 상용 마이크로프로세서로, 트랜지스터가 약 2,300개였다. 1초에 74만 번 박자(클록 740kHz)를 맞추며 짧은 명령을 1초에 약 9만 개 실행했다.

오늘날 칩에는 트랜지스터가 수백억 개에서 2,000억 개 넘게 들어간다(아래 숫자로 보기). PC나 휴대폰 CPU의 **코어**(core, 명령을 실행하는 단위) 하나는 1초에 수십억 번 박자를 맞추고(수 GHz), 한 박자에 명령을 여러 개 끝내기도 하며, 칩 하나에 그런 코어가 여러 개 있다. 이 차이를 숫자로 느껴 보자.
```python
year = 60 * 60 * 24 * 365                  # 1년은 몇 초인가
print(f"2,080억 ÷ 2,300 = {208e9 / 2300:,.0f}")
print(f"10억 번을 1초에 하나씩: {1e9 / year:.1f}년")
```
```text
2,080억 ÷ 2,300 = 90,434,783
10억 번을 1초에 하나씩: 31.7년
```

반세기 남짓 만에 칩 하나의 트랜지스터가 약 9,000만 배로 늘었다. 2년마다 두 배쯤 늘어 온 셈이고, 이 흐름을 무어의 법칙이라 부른다. 1초에 10억 번 계산하는 기계가 1초 동안 한 일을 사람이 1초에 하나씩 따라 하면 쉬지 않고 31.7년이 걸린다.

## 기억의 계층: 손, 책상, 책꽂이, 창고
CPU가 아무리 빨라도 계산할 숫자가 제때 오지 않으면 기다려야 한다. 그래서 기억 장치를 여러 단으로 둔다. 위로 갈수록 빠르고 작고 비싸며, 아래로 갈수록 느리고 크고 싸다.
- 레지스터: CPU 안의 아주 적은 칸. 손에 쥔 메모지.
- 캐시: CPU 곁의 작은 기억. 책상 위에 펼친 책.
- 메모리(RAM): 방 안의 책꽂이. 전원이 꺼지면 내용을 잃는다.
- 저장 장치(SSD 등): 창고. 느리지만 전원이 꺼져도 남는다.

비유와 다른 점은, 사람은 책을 직접 옮기지만 컴퓨터에서는 곧 쓸 것 같은 데이터를 하드웨어와 운영체제가 알아서 위 단으로 복사해 둔다는 것이다. 단마다 실제로 얼마나 빠르고 큰지는 메모리 시스템 1편 「메모리 계층 지도: 레지스터에서 SSD까지 지연과 대역폭」에서 숫자로 본다.

## 여러 프로그램, 여러 컴퓨터가 함께
휴대폰의 코어는 몇 개뿐인데 실행 중인 프로그램은 그보다 훨씬 많다. 그래도 음악을 들으며 메신저를 쓸 수 있는 것은 **운영체제**(operating system)가 아주 짧은 간격으로 프로그램을 번갈아 실행하고, 프로그램마다 따로 메모리 구역을 내주어 서로 침범하지 못하게 하기 때문이다(트랜지스터에서 자연어까지 10편 「운영체제: 기계를 나눠 쓰게 하는 층」).

컴퓨터끼리도 함께 일한다. 지도 앱에서 길을 찾으면 휴대폰은 네트워크로 데이터 센터에 질문을 보내고, 그곳의 컴퓨터들이 나눠 계산한 답을 받는다. 서로 다른 회사가 만든 기계끼리 말이 통하는 것은 4편에서 본 TCP처럼 모두가 같은 약속(프로토콜)을 따르기 때문이다. 같은 계산을 수많은 데이터에 한꺼번에 하는 GPU 같은 칩도 있다. 6편의 언어 모델은 이런 칩을 아주 많이 묶어 곱하고 더하기를 어마어마하게 되풀이하며 배운다.

## 흔한 오해
- "컴퓨터는 똑똑해서 복잡한 일을 한다." 한 번에 하는 일은 더하기, 비교, 옮기기, 다른 명령으로 건너뛰기 정도다. 복잡함은 층의 설계와 엄청난 양에서 나온다. 거꾸로 "단순하니 별것 아니다"도 틀렸다. 단순한 일도 수십억 번 겹치고 층을 이루면 사람이 다 따라갈 수 없는 결과를 낸다.
- "클록(GHz)이 높으면 무조건 빠르다." 박자마다 끝내는 명령 수, 코어 수, 메모리를 기다리는 시간이 함께 속도를 정한다. 그리고 앞의 실험처럼 방법을 잘못 고르면 빠른 기계도 소용없다.
- "추상화는 세부를 없앤다." 숨길 뿐 없애지 않는다. 같은 계산도 데이터를 읽는 순서에 따라 몇 배씩 느려질 수 있는데, 원인은 위 층에서 보이지 않는 캐시에 있다(트랜지스터에서 자연어까지 7편 「빠르게 만드는 기술: 파이프라인, 캐시, 병렬성」). 세부가 이렇게 새어 나오면 아래 층을 아는 사람이 문제를 푼다.

- 트랜지스터에서 자연어까지 5편 「CPU의 구조: 명령어를 실행하는 기계」: 더하기·비교·옮기기·건너뛰기가 명령어로 실행되는 모습을 장난감 CPU로 한 박자씩 따라간다.
- 이산수학 11편 「점근 표기법: 알고리즘의 비용 세기」: 낱말이 10배 늘 때 비교가 80배 넘게 는 현상을 "n²에 비례한다"는 말로 정확히 다룬다.
- AI 기초 4편 「컴퓨터 사이언스로 보는 AI 모델: 텐서, 연산, 메모리」: AI 모델도 이 글의 층 위에서 도는 거대한 곱셈·덧셈의 묶음이라는 것을 연산량과 메모리로 센다.

## 정리
- 컴퓨터가 한 번에 하는 일은 더하기·비교·옮기기·건너뛰기처럼 단순하고, 복잡함은 층의 설계와 양에서 나온다.
- 추상화의 각 층은 아래 층의 세부를 숨기고 위 층에 더 큰 부품을 내주며, 덧셈과 비교만으로도 곱셈·정렬·낱말 세기를 쌓을 수 있다.
- 칩 하나의 트랜지스터는 1971년 약 2,300개에서 2024년 약 2,080억 개로 늘었고, 코어 하나가 1초에 수십억 번 박자를 맞춘다.
- 기억의 계층이 빠른 CPU에 데이터를 대 주고, 운영체제와 네트워크가 여러 프로그램과 여러 컴퓨터를 함께 일하게 한다.
