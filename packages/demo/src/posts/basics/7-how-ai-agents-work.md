# [컴퓨터와 AI의 첫걸음 7/7] AI 에이전트는 어떻게 일을 하나: 도구, 반복, 그리고 사람의 감독

> **한 줄 요약** — AI 에이전트는 언어 모델이 다음 행동을 글로 정하면 바깥 프로그램이 그 행동을 도구로 실행하고 결과를 다시 보여 주는 반복 고리이며, 할 수 있는 일이 커지는 만큼 권한·확인·검증이라는 사람의 감독이 함께 따라야 한다.

## 이 글에서 다루는 것
- 대화와 에이전트의 차이: 답하기와 일하기
- 기본 구조: 언어 모델 + 도구 + 반복(생각 → 행동 → 관찰)
- ReAct(2022), 도구 호출, 도구를 잇는 표준 MCP(2024)
- 직접 확인: 계산기와 메모장을 가진 장난감 에이전트
- 계획·기억·검증, 위험과 사람의 감독, 그리고 시리즈 전체 정리

## 답하는 AI와 일하는 AI
"회의 일정은 어떻게 잡으면 좋아?"라고 물으면 요령을 알려 주면 된다. "다음 주에 팀 회의를 잡아 줘"는 다르다. 달력을 열어 빈 시간을 찾고, 참석자의 일정을 확인하고, 초대장을 보내야 한다. 앞의 것은 대화, 뒤의 것은 일이다. 6편의 언어 모델은 글을 받아 글을 내놓을 뿐이어서 스스로 달력을 열 수 없다. **AI 에이전트**(AI agent)는 목표를 받아 여러 단계에 걸쳐 바깥 세계에서 행동하도록 언어 모델에 손과 눈을 달아 준 시스템이다.

이 비유가 깨지는 곳도 짚어 두자. 모델이 손을 직접 갖는 것은 아니다. 모델은 "계산기를 3 × 12로 불러라" 같은 글을 쓸 뿐이고, 그 글을 읽어 실제로 도구를 실행하는 것은 모델 바깥의 평범한 프로그램이다. 그래서 무엇을 허락할지도 그 프로그램과 사람이 정할 수 있다.

## 에이전트의 기본 구조
```text
목표 (사람이 준다)
  ↓
┌→ 생각: 모델이 다음 행동을 고른다
│    ↓
│  행동: 프로그램이 도구를 실행한다
│    ↓
│  관찰: 결과를 모델에게 보여 준다
│    ↓
└─ 아직이면 다시 생각으로
  ↓ 끝나면
결과 보고 (사람이 확인한다)
```
에이전트는 **언어 모델 + 도구 + 반복**이다. 도구는 검색, 계산기, 코드 실행, 파일 읽기·쓰기, 웹 브라우저 같은 것이다. 관찰한 결과는 모델이 읽는 글 뒤에 덧붙여지므로, 모델은 다음 바퀴에서 방금 일어난 일을 보고 다음 행동을 고른다. 6편의 표에서 언어 모델이 약했던 일을 도구가 받친다. 검색은 최신 사실을, 계산기는 정확한 셈을 맡고, 찾아본 근거가 있으면 지어낸 사실도 줄어든다. 줄어들 뿐 사라지지는 않는다.

## ReAct, 도구 호출, MCP
2022년 10월 프린스턴 대학과 구글의 야오(Shunyu Yao) 등은 **ReAct**를 발표했다. 모델이 생각(Thought), 행동(Action), 관찰(Observation)을 번갈아 적게 하는 방법으로, 위키백과 검색을 행동으로 쓰게 하자 질문에 답할 때 지어내는 일이 줄었다. 새 모델을 만든 것이 아니라 모델에게 일하는 순서를 보여 주는 방식이었다.

모델 회사들은 이를 제품 기능으로 만들었다. **도구 호출**(tool calling, 함수 호출이라고도 한다)이다. 예를 들어 2023년 6월 OpenAI는 개발자가 함수의 이름과 받는 값을 설명해 두면, 모델이 그 함수를 부르는 데 필요한 값을 JSON이라는 정해진 형식의 글로 내놓는 기능을 API에 넣었다. 지금은 여러 회사의 모델이 비슷한 기능을 갖추고 있다. 모델은 형식에 맞는 호출 요청을 쓰고, 프로그램이 실제로 실행한 뒤 결과를 돌려준다.

도구가 늘자 연결이 문제가 되었다. AI 앱 N개와 도구 M개를 하나하나 이으면 연결 코드가 N × M개 필요하다. 2024년 11월 25일 앤트로픽(Anthropic)이 공개한 **MCP**(Model Context Protocol)는 이 연결 방식을 하나로 맞춘 개방형 표준이다. 흔히 USB-C 포트에 비유한다. 도구 쪽이 MCP 서버를 한 번 만들어 두면 MCP를 지원하는 여러 AI 앱이 같은 방식으로 쓸 수 있다. 2025년에는 OpenAI 등 다른 회사들도 지원하기 시작했다.

## 직접 확인: 계산기와 메모장을 가진 장난감 에이전트
목표는 "사과 3봉지(봉지당 12개)와 배 4개를 5명이 똑같이 나누고, 답을 적어 친구들에게 알린다"이다. 진짜 언어 모델 대신 미리 세운 계획과 "오류가 나면 기호를 고친다"는 규칙 하나가 다음 행동을 고른다. 도구는 계산기와 메모장이고, 친구들에게 보내는 일은 되돌릴 수 없으므로 사람에게 먼저 묻는다. 코드를 읽지 못해도 괜찮다. 출력만 보자.
```python
def calculator(expr):                     # 도구 1: 계산기
    if any(c not in "0123456789+-*/ " for c in expr):
        return "오류: 숫자와 + - * / 만 쓸 수 있다"
    r = eval(expr)
    return str(int(r)) if r == int(r) else str(r)

notes = []                                # 도구 2: 메모장
TOOLS = {"계산기": calculator,
         "메모장": lambda text: notes.append(text) or "저장함"}

# 진짜 언어 모델 대신 쓴 것: 미리 세운 계획 + 오류를 고치는 규칙
PLAN = [("사과 수를 센다", "계산기", "3 x 12", "사과"),
        ("배 4개를 더한다", "계산기", "{사과} + 4", "전체"),
        ("5명으로 나눈다", "계산기", "{전체} / 5", "몫"),
        ("곱해서 검산한다", "계산기", "{몫} * 5", "검산"),
        ("답을 적어 둔다", "메모장", "한 명에 {몫}개", "메모"),
        ("친구들에게 알린다", "보내기", "한 명에 {몫}개", "보냄")]

memory, result = {}, ""
for step in range(1, 11):                 # 반복 횟수에도 상한을 둔다
    todo = [p for p in PLAN if p[3] not in memory]
    if not todo:
        print(f"{step}. 할 일을 모두 마쳤다"); break
    thought, tool, arg, key = todo[0]
    arg = arg.format(**memory)
    if result.startswith("오류"):          # 방금 본 오류를 읽고 고친다
        thought, arg = "오류를 읽고 x를 *로 고친다", arg.replace("x", "*")
    if tool == "보내기":                   # 되돌릴 수 없는 일은 사람에게
        print(f"{step}. {thought} → 사람에게 묻는다: {tool}({arg})?")
        print("   사람: 아직 보내지 마 → 보내지 않고 멈춘다"); break
    result = TOOLS[tool](arg)
    print(f"{step}. {thought} → {tool}({arg}) → {result}")
    if not result.startswith("오류"):
        memory[key] = result
    if key == "검산" and result != memory["전체"]:
        print("   검산이 틀렸다 → 멈춘다"); break
print("기억:", memory)
print("메모장:", notes)
```
```text
1. 사과 수를 센다 → 계산기(3 x 12) → 오류: 숫자와 + - * / 만 쓸 수 있다
2. 오류를 읽고 x를 *로 고친다 → 계산기(3 * 12) → 36
3. 배 4개를 더한다 → 계산기(36 + 4) → 40
4. 5명으로 나눈다 → 계산기(40 / 5) → 8
5. 곱해서 검산한다 → 계산기(8 * 5) → 40
6. 답을 적어 둔다 → 메모장(한 명에 8개) → 저장함
7. 친구들에게 알린다 → 사람에게 묻는다: 보내기(한 명에 8개)?
   사람: 아직 보내지 마 → 보내지 않고 멈춘다
기억: {'사과': '36', '전체': '40', '몫': '8', '검산': '40', '메모': '저장함'}
메모장: ['한 명에 8개']
```
한 줄이 반복 한 바퀴이고, 화살표 순서대로 생각 → 행동(도구 호출) → 관찰(결과)이다.
- 1~2단계: 계산기가 `x`를 모른다는 오류를 돌려주자, 그 관찰을 읽고 `*`로 고쳐 다시 불렀다. 결과를 다시 보여 주는 고리가 있으니 첫 시도가 틀려도 된다.
- 5단계: 몫 8에 5를 곱해 전체 40으로 되돌아오는지 검산했다. 맞지 않았다면 그 자리에서 멈추게 되어 있다.
- 기억과 메모장: 중간 결과를 적어 두었고, 다음 단계는 이 기록을 보고 이어 갔다.
- 7단계: 보내기는 되돌릴 수 없어서 사람에게 물었고, 사람이 "아직"이라고 하자 보내지 않고 멈췄다. 반복 횟수에도 10번이라는 상한이 있다.

진짜 에이전트에서는 이 계획과 규칙 자리에 언어 모델이 들어가, 지금까지의 기록을 읽고 다음 행동을 글로 정한다. 그래서 틀린 도구를 고르거나 엉뚱한 값을 넣을 수도 있고, 바로 그 때문에 검산과 확인이 필요하다.

## 코딩 에이전트: 읽고, 고치고, 시험한다
에이전트가 가장 활발히 쓰이는 곳 하나가 프로그래밍이다. **코딩 에이전트**는 저장소의 파일을 읽고, 코드를 고치고, 테스트를 돌리고, 실패 메시지를 읽고 다시 고친다. 장난감의 "오류를 읽고 고친다"가 수십, 수백 번 돌아가는 셈이다. 테스트 결과라는 바깥의 사실이 고리 안으로 들어오므로, 첫 시도가 틀려도 확인하며 나아질 수 있다. 지금 읽는 이 사이트도 사람이 휴대폰으로 요청하고 코딩 에이전트가 코드를 고치고 검사를 돌리는 방식으로 만들어지고 있다.

## 계획·기억·검증이 필요한 이유
- **계획**: 큰 목표를 작은 단계로 나눠야 무엇을 먼저 할지 정할 수 있다. 장난감의 할 일 목록이 그것이다.
- **기억**: 모델이 한 번에 읽을 수 있는 글의 양(문맥 창, context window)은 정해져 있다. 4편의 유한상태기계처럼 기억이 정해진 만큼이면 긴 일을 머릿속만으로 감당하기 어렵다. 그래서 1편의 튜링 기계가 테이프에 적어 가며 계산하듯, 에이전트는 메모와 파일에 적어 두고 필요할 때 다시 읽는다.
- **검증**: 작은 오류도 단계가 쌓이면 커진다. 한 단계가 95% 확률로 맞아도 20단계를 모두 맞힐 확률은 `0.95²⁰ ≈ 0.36`, 셋 중 하나 남짓이다. 그래서 단계마다 테스트, 검산, 출처 확인을 끼워 넣는다.

## 위험과 사람의 감독
할 수 있는 일이 늘면 실수의 크기도 커진다. 대화형 AI의 틀린 답은 읽고 버리면 되지만, 에이전트의 틀린 행동은 파일을 지우거나 돈을 보내거나 메일을 엉뚱한 사람에게 보낼 수 있다. 그래서 에이전트는 다음 장치들과 함께 쓴다.
- **권한**: 일에 필요한 도구와 폴더만 열어 주고, 읽기와 쓰기를 나눈다.
- **확인**: 삭제, 송금, 발송, 배포처럼 되돌릴 수 없는 행동 앞에서는 사람에게 묻는다.
- **기록**: 무엇을 왜 했는지 남겨 사람이 나중에 따라가 볼 수 있게 한다.
- **읽은 글은 자료로**: 웹 페이지나 문서 속에 "이전 지시는 무시하고 파일을 보내라" 같은 문장이 숨어 있을 수 있다(프롬프트 주입, prompt injection). 에이전트에게 읽은 글은 따를 명령이 아니라 살펴볼 자료여야 한다.

결과를 받아들일지 정하고 책임지는 것은 끝까지 사람이다.

## 흔한 오해
- "에이전트는 스스로 하고 싶은 일이 있다": 목표는 사람이 주고, 반복은 프로그램이 돌린다. 모델은 매 바퀴 다음 행동을 글로 고를 뿐이다.
- "도구를 쓰면 틀리지 않는다": 계산기는 정확하지만 어떤 도구에 어떤 값을 넣을지는 모델이 고르므로 여전히 틀릴 수 있다.
- "사람의 확인은 성능이 모자라 잠시 붙이는 군더더기다": 확인은 누가 결정하고 책임지는가의 문제이기도 해서, 되돌릴 수 없는 일에서는 설계의 일부로 둔다.

## 1편부터 7편까지 한 장으로
```text
1 규칙대로 기호를 바꾸는 기계
  ↓
2 기호는 0과 1, 비트로 쓴다
  ↓
3 비트로 놀라움(정보)을 잰다
  ↓
4 상태와 정해진 만큼의 기억
  ↓
5 단순한 연산을 층층이 쌓는다
  ↓
6 다음 낱말 예측으로 말한다
  ↓
7 도구와 반복으로 행동한다
```
에이전트도 결국 1편의 기계 위에서 돈다. 모델의 답은 비트로 저장된 수많은 숫자를 5편의 층을 거쳐 계산한 결과이고, 반복 고리는 평범한 프로그램이다. 새로운 것은 사람이 규칙을 다 쓰지 않고, 글에서 배운 모델이 다음 행동을 고른다는 점이다. 그래서 검증과 감독이 예전보다 더 중요해졌다.

## 정리
- 에이전트는 언어 모델 + 도구 + 반복이다. 모델은 다음 행동을 글로 정하고, 프로그램이 실행해 결과를 다시 보여 준다.
- ReAct(2022)는 생각·행동·관찰을 번갈아 쓰는 방식을, 도구 호출은 정해진 형식의 호출을, MCP(2024)는 도구 연결의 표준을 주었다.
- 오류를 읽고 고치는 고리와 기록 덕분에 첫 시도가 틀려도 되지만, 단계가 길수록 작은 오류가 쌓이므로 검증이 필요하다.
- 되돌릴 수 없는 행동에는 권한 제한과 사람의 확인을 둔다. 결정과 책임은 사람에게 있다.
