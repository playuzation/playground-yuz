# [컴퓨터와 AI의 첫걸음 4/7] 유한상태기계란 무엇인가: 기억이 정해진 만큼인 기계

> **한 줄 요약** — 유한상태기계는 정해진 몇 개의 상태 가운데 하나에 머물다가 입력이 들어오면 규칙표대로 다음 상태로 옮겨 가는 기계로, 자판기·신호등·문자열 검사처럼 지난 일을 짧게 요약해 두면 되는 일에 잘 맞지만, 기억이 정해진 만큼뿐이라 끝없이 깊어지는 괄호 짝 맞추기는 해내지 못한다.

## 이 글에서 다루는 것
- 상태와 전이: 개찰구와 자판기로 보는 유한상태기계
- 출력이 어디에 붙나: 무어 기계와 밀리 기계
- 정규 표현식: 글자를 읽는 상태 기계(매컬러·피츠에서 클리니까지)
- 기억이 유한해서 생기는 한계: 깊이 4에서 틀리는 괄호 검사기
- 튜링 기계와의 차이, 그리고 오늘날의 쓰임

## 자판기는 무엇을 기억할까
음료가 300원인 자판기에 100원짜리를 하나씩 넣으면 세 번째 동전에서 음료가 나온다. 이때 자판기는 동전이 언제, 어떤 순서로 들어왔는지 기억할 필요가 없다. "지금까지 얼마가 들어왔나" 하나만 알면 된다. 0원, 100원, 200원 셋 가운데 어디에 있는지가 자판기가 기억하는 전부다.

이렇게 지나온 일을 다음 행동에 필요한 만큼만 요약한 것을 **상태**(state)라고 한다. 상태의 개수가 미리 정해져 있고, 입력이 올 때마다 규칙에 따라 상태를 옮기는 기계가 **유한상태기계**(finite-state machine, 줄여서 FSM)다. "유한"은 상태가 몇 개인지 정해져 있어 일하는 도중에 늘어나지 않는다는 뜻이다. 1편의 튜링 기계와 달리 테이프 같은 기억이 따로 없고, 기억은 상태 하나뿐이다.

## 상태와 전이: 개찰구 그림
회전 막대 개찰구는 상태가 둘이다. 잠김(LOCKED)과 열림(OPEN). 입력도 둘이다. 표를 대는 것(coin)과 막대를 미는 것(push).
```text
  push                     coin
  ┌──┐                     ┌──┐
  │  ↓        coin         ↓  │
┌─┴──────┐ ──────────→ ┌──────┴─┐
│ LOCKED │             │  OPEN  │
└────────┘ ←────────── └────────┘
              push
```

화살표 하나하나가 **전이**(transition)다. 잠긴 상태에서 표를 대면 열리고, 열린 상태에서 밀고 지나가면 다시 잠긴다. 잠긴 채로 밀거나 열린 채로 표를 또 대면 제자리로 도는 화살표를 따라 상태가 그대로다. 그림을 표로 옮기면 이렇다.

| 지금 상태 | 입력 | 다음 상태 |
|---|---|---|
| 잠김 | 표 대기 | 열림 |
| 잠김 | 밀기 | 잠김 |
| 열림 | 표 대기 | 열림 |
| 열림 | 밀기 | 잠김 |

유한상태기계는 네 가지로 정해진다. 상태의 목록, 입력의 목록, 시작 상태, 그리고 (지금 상태, 입력) 짝마다 다음 상태를 적은 규칙표다. 신호등(초록 → 노랑 → 빨강, 입력은 "시간이 다 됨")이나 세탁기(급수 → 세탁 → 헹굼 → 탈수)도 이렇게 적을 수 있다.

## 출력은 어디에 붙나: 무어 기계와 밀리 기계
기계가 무언가를 내보내는(출력하는) 방법은 두 가지다.
- **무어 기계**(Moore machine): 출력이 상태에 붙는다. 신호등은 빨강 상태에 있는 동안 내내 빨간불을 켠다. 상태만 보면 출력을 안다.
- **밀리 기계**(Mealy machine): 출력이 전이에 붙는다. 자판기는 "200원 상태에서 100원이 들어오는 순간" 음료를 내보낸다. 같은 상태라도 입력에 따라 출력이 다르다.

이름은 두 사람의 논문에서 왔다. 조지 밀리(George Mealy)는 1955년 「Bell System Technical Journal」에 순차 회로 설계법을 발표했고, 에드워드 무어(Edward F. Moore)의 「Gedanken-experiments on Sequential Machines」는 1956년 『Automata Studies』에 실렸다. 두 방식은 할 수 있는 일이 같아 서로 바꿀 수 있다. 다만 밀리 기계를 무어 기계로 바꾸면 출력마다 상태를 나눠야 해서 상태 수가 늘 수 있다.

## 직접 확인 1: 자판기를 규칙표로 돌리기
아래 파이썬 코드는 300원짜리 음료 자판기를 밀리 기계로 만든 것이다. 코드를 읽지 못해도 괜찮다. 규칙표(`RULES`)가 개찰구 표와 같은 모양이라는 것만 보고 출력을 따라가 보자.
```python
# 음료 한 개 300원, 100원 동전만 받는 자판기
# 규칙표: (지금 상태, 입력) → (다음 상태, 내보내는 것)
RULES = {
    ("0원", "100원"): ("100원", ""),
    ("100원", "100원"): ("200원", ""),
    ("200원", "100원"): ("0원", "음료"),
    ("0원", "반환"): ("0원", ""),
    ("100원", "반환"): ("0원", "동전 100원"),
    ("200원", "반환"): ("0원", "동전 200원"),
}

state = "0원"                                 # 시작 상태
for x in ["100원", "100원", "반환", "100원", "100원", "100원"]:
    nxt, out = RULES[(state, x)]
    print(f"{state} -({x})→ {nxt}", f"  내보냄: {out}" if out else "")
    state = nxt
```
```text
0원 -(100원)→ 100원
100원 -(100원)→ 200원
200원 -(반환)→ 0원   내보냄: 동전 200원
0원 -(100원)→ 100원
100원 -(100원)→ 200원
200원 -(100원)→ 0원   내보냄: 음료
```

입력을 여섯 번 받는 동안 자판기가 붙잡고 있던 것은 언제나 상태 하나였다. 동전을 1,000개 넣어도 상태는 0원·100원·200원 가운데 하나다. "기억이 정해진 만큼인 기계"라는 말이 이것이다. 실제 자판기는 동전 종류, 거스름돈, 재고까지 다루어 상태와 규칙이 훨씬 많지만, 규칙표대로 움직인다는 뼈대는 같다.

## 정규 표현식: 글자를 읽는 상태 기계
글자를 하나씩 입력으로 주면 "이 글이 정해진 모양인가"를 검사하는 기계가 된다. "숫자가 하나 이상 나오고 '원'으로 끝나는 글"(300원, 1500원)을 검사하는 기계는 시작, 숫자 중, 끝, 실패의 네 상태면 된다.

| 지금 상태 | 숫자가 오면 | '원'이 오면 |
|---|---|---|
| 시작 | 숫자 중 | 실패 |
| 숫자 중 | 숫자 중 | 끝 |
| 끝 | 실패 | 실패 |

다른 글자가 오면 어느 상태에서든 실패로 가고, 실패에서는 빠져나오지 못한다. 다 읽었을 때 '끝'에 있으면 통과다. 이런 모양을 짧게 적는 약속이 **정규 표현식**(regular expression)이다. 위 기계는 `[0-9]+원`이라고 적는다. `[0-9]`는 숫자 한 글자, `+`는 "앞의 것이 한 번 이상"이라는 뜻이다. 편집기의 찾기, 가입 화면의 입력 검사, 기록 파일 검색에 널리 쓰인다.
```python
import re
for s in ["300원", "1500원", "원", "300", "3백원"]:
    ok = re.fullmatch(r"[0-9]+원", s)
    print(s, "→ 통과" if ok else "→ 실패")
```
```text
300원 → 통과
1500원 → 통과
원 → 실패
300 → 실패
3백원 → 실패
```

정규 표현식과 유한상태기계는 정확히 같은 힘을 가진다. 정규 표현식으로 적을 수 있는 모양은 모두 유한상태기계로 검사할 수 있고, 그 반대도 성립한다. 증명한 사람의 이름을 따 클리니 정리(Kleene's theorem)라고 부른다.

## 역사 한 토막: 뇌세포 모형에서 검색 명령까지
이 이야기는 뇌에서 시작했다. 1943년 워런 매컬러(Warren McCulloch)와 월터 피츠(Walter Pitts)는 「A Logical Calculus of the Ideas Immanent in Nervous Activity」에서 신경세포를 "발화하거나 안 하거나" 둘 중 하나인 논리 소자로 보고 그 연결망을 논리식으로 다뤘다. 실제 신경세포는 훨씬 복잡하지만, 이 모형은 인공 신경망의 출발점이 되었다(6편).

수학자 스티븐 클리니(Stephen Kleene)는 "그런 신경망이 알아볼 수 있는 입력의 모양은 무엇인가"를 물었다. 1951년 RAND 연구소 보고서로 쓰고 1956년 섀넌과 매카시가 엮은 『Automata Studies』에 실은 「Representation of Events in Nerve Nets and Finite Automata」에서, 그는 그 모양을 적는 표기법(오늘날의 정규 표현식)을 만들고 신경망과 유한 자동자가 알아보는 것이 정확히 그 모양들임을 보였다.

이론은 곧 도구가 되었다. 켄 톰프슨(Ken Thompson)은 클리니의 표기법을 문서 편집기 QED에 넣었고, 1968년 「Communications of the ACM」에 정규 표현식을 기계어 프로그램으로 바꿔 검색하는 방법을 발표했다. 지금도 쓰는 검색 명령 `grep`의 이름은 유닉스 편집기 ed의 명령 `g/re/p`(정규 표현식으로 찾아 출력)에서 왔다.

## 직접 확인 2: 기억이 모자라면 틀리는 괄호 검사
이제 유한상태기계가 못 하는 일을 보자. `(())`처럼 여는 괄호와 닫는 괄호의 짝이 맞는지 검사하는 일이다. 사람은 왼쪽부터 읽으며 열린 괄호 수를 센다. 여는 괄호에서 하나 더하고 닫는 괄호에서 하나 빼서, 도중에 0 아래로 내려가거나 끝에서 0이 아니면 틀린 것이다.

문제는 이 수에 끝이 없다는 것이다. 괄호는 100겹으로도 100만 겹으로도 쌓을 수 있다. 아래 `machine`은 열린 괄호 수를 상태 0~3으로만 세는 유한상태기계다. 넷째 여는 괄호가 와도 셀 칸이 없어 3에 머문다. 정답 `truth`는 같은 기계에 칸을 무한히 준 것이다.
```python
def machine(text, top=3):          # 상태 0~top: 열린 괄호 수
    state = 0
    for ch in text:
        if ch == "(":
            state = min(state + 1, top)   # 칸이 모자라면 top에 머문다
        elif state == 0:
            return "틀림"                 # 닫을 괄호가 없다
        else:
            state -= 1
    return "맞음" if state == 0 else "틀림"

def truth(text):                   # 정답: 칸을 무한히 준 같은 기계
    return machine(text, top=float("inf"))

for t in ["(())", "(()", "((()))", "(((())))", "(((()))"]:
    print(f"{t:9} 기계: {machine(t)}  정답: {truth(t)}")

for top in (3, 10, 100):           # 상태를 늘리면 해결될까?
    d = 1
    while machine("(" * d + ")" * d, top) == "맞음":
        d += 1
    print(f"0~{top}까지 세는 기계: 깊이 {d}에서 처음 틀림")
```
```text
(())      기계: 맞음  정답: 맞음
(()       기계: 틀림  정답: 틀림
((()))    기계: 맞음  정답: 맞음
(((())))  기계: 틀림  정답: 맞음
(((()))   기계: 맞음  정답: 틀림
0~3까지 세는 기계: 깊이 4에서 처음 틀림
0~10까지 세는 기계: 깊이 11에서 처음 틀림
0~100까지 세는 기계: 깊이 101에서 처음 틀림
```

깊이 3까지는 정답과 같다. 그런데 깊이 4인 `(((())))`는 맞는 글인데 틀렸다고 하고, 닫는 괄호가 하나 모자란 `(((()))`는 틀린 글인데 맞다고 한다. 기계 안에서 "열린 괄호 3개"와 "4개"가 같은 상태라 둘을 구별하지 못하기 때문이다. 상태를 11개, 101개로 늘려도 틀리는 깊이가 뒤로 밀릴 뿐 사라지지 않는다.

기계를 서툴게 만들어서가 아니다. 상태가 k개인 기계는 어떻게 만들든, 여는 괄호를 0개부터 k개까지 읽은 k + 1가지 경우 가운데 적어도 두 경우가 같은 상태에 떨어진다. 이산수학 7편 「비둘기집 원리와 포함·배제의 원리」의 비둘기집 원리다. 여는 괄호 5개와 8개를 읽은 뒤의 상태가 같다면, 둘 다 뒤에 닫는 괄호 5개를 붙였을 때 기계는 같은 답을 낼 수밖에 없다. 한쪽은 맞고 한쪽은 틀린데도. 그래서 괄호 짝 맞추기는 어떤 유한상태기계로도, 따라서 어떤 정규 표현식으로도 완벽하게 할 수 없다.

## 튜링 기계와 무엇이 다른가
괄호를 끝까지 세려면 필요한 만큼 늘어나는 기억이 있어야 한다. 1편의 튜링 기계가 그렇다. 유한한 상태와 규칙표에 더해, 칸을 얼마든지 쓰고 지울 수 있는 테이프가 있다. 거꾸로 보면 유한상태기계는 테이프에 쓰지 못하고 입력을 한 방향으로 한 번 읽기만 하는 튜링 기계다. 중간 단계도 있다. 접시를 쌓듯 맨 위에만 넣고 빼는 기억(스택, stack)을 붙이면 괄호 짝을 맞출 수 있고, 프로그래밍 언어를 읽어 들이는 프로그램이 중첩된 괄호와 문장을 다룰 때 이런 기억을 쓴다.

## 상태 기계는 어디에나 있다
- CPU의 제어 장치: 명령을 가져오고, 뜻을 풀고, 실행하는 단계를 차례로 오간다.
- 통신 프로토콜: 인터넷의 TCP 표준(RFC 793)은 연결을 LISTEN, ESTABLISHED, TIME-WAIT 같은 상태 11개와 그 사이의 전이로 정해 둔다. 두 컴퓨터가 같은 규칙표를 따르기 때문에 말이 통한다.
- 게임 캐릭터: 팩맨의 유령은 추격(chase), 흩어짐(scatter), 겁먹음(frightened) 세 모드를 오가고, 팩맨이 구석의 큰 알약(energizer)을 먹으면 겁먹음으로 바뀐다.
- 화면(UI): 버튼은 보통 → 불러오는 중 → 완료 또는 오류를 오간다. 상태를 나눠 두면 "불러오는 중에 또 눌리는" 버그를 막기 쉽다.

## 흔한 오해
- "컴퓨터도 메모리가 유한하니 결국 유한상태기계 아닌가?" 엄밀히는 맞다. 하지만 16GB 메모리는 1,280억 비트라서 가능한 상태가 2를 1,280억 번 곱한 만큼이다. 상태 그림으로는 이해할 수 없는 크기라, 컴퓨터 전체는 "필요하면 기억을 더 붙일 수 있는" 튜링 기계로 보고, 유한상태기계는 기억이 작고 정해진 부품을 설명할 때 쓴다.
- "정규 표현식이면 어떤 모양이든 검사할 수 있다." 끝없이 중첩되는 괄호는 이론상의 정규 표현식으로 검사할 수 없다. 일부 정규식 도구에는 이 한계를 넘는 확장 기능이 있지만, 그것은 이미 더 강한 장치다.

## 어디에 쓰이나
- 트랜지스터에서 자연어까지 4편 「순차 회로: 클록, 플립플롭, 메모리」: 상태를 레지스터에, 규칙표를 조합 회로에 담고 클록마다 한 걸음씩 옮기면 이 글의 상태 기계가 그대로 전기 회로가 된다.
- 문자열 알고리즘 2편 「KMP: 실패 함수로 되돌아가지 않는 검색」: "패턴의 몇 글자까지 맞았나"를 상태로 삼아 긴 글에서 낱말을 찾는 상태 기계를 만든다.
- 확률과 분포 12편 「마르코프 연쇄: 현재만 기억하는 확률 과정」: 다음 상태가 지금 상태에만 달려 있다는 점은 같고, 다음 상태가 규칙표 대신 확률로 정해진다. 6편의 다음 글자 예측 모형도 이 생각을 쓴다.

## 정리
- 유한상태기계는 정해진 개수의 상태와 "(지금 상태, 입력) → 다음 상태" 규칙표로 움직이며, 상태는 지난 일을 필요한 만큼만 남긴 요약이다.
- 출력이 상태에 붙으면 무어 기계(1956), 전이에 붙으면 밀리 기계(1955)이고, 두 방식은 할 수 있는 일이 같다.
- 정규 표현식과 유한상태기계는 같은 힘을 가지며(클리니, 1956), 이 생각은 1943년 매컬러·피츠의 신경 모형에서 이어졌다.
- 기억이 유한하므로 끝없이 깊어지는 괄호 짝은 검사할 수 없고, 이를 넘으려면 스택이나 튜링 기계의 테이프처럼 늘어나는 기억이 필요하다.
