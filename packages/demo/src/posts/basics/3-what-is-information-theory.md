# [컴퓨터와 AI의 첫걸음 3/7] 정보 이론이란 무엇인가: 놀라움을 비트로 재기

> **한 줄 요약** — 정보 이론은 섀넌이 1948년에 세운 학문으로, 메시지의 뜻이 아니라 얼마나 예측하기 어려운지(놀라움)를 비트로 재며, 그 평균인 엔트로피는 얼마나 짧게 줄일 수 있는지를, 통신로의 용량은 잡음 속에서 얼마나 확실하게 보낼 수 있는지를 알려 준다.

## 이 글에서 다루는 것
- 섀넌이 던진 두 질문: 얼마나 짧게, 얼마나 확실하게
- 정보량은 놀라움이다: 뻔한 소식과 드문 소식
- 엔트로피: 스무고개로 비트 세기, 그리고 압축의 한계
- 잡음을 이기는 오류 정정 부호: 반복 부호와 해밍 부호
- 정보 이론이 재지 않는 것: 뜻

## 섀넌의 두 질문
사진을 보낼 때 "압축한다"는 말을 자주 듣는다. 얼마나 줄일 수 있을까? 무선 신호에는 늘 잡음이 섞이는데, 내려받은 파일은 왜 한 글자도 틀리지 않을까? 1948년 벨 연구소의 클로드 섀넌(Claude Shannon)은 논문 「A Mathematical Theory of Communication」(벨 시스템 기술 저널 7월호와 10월호에 나눠 실림)에서 이 두 질문을 수학으로 다뤘다.
- 메시지를 얼마나 짧게 줄일 수 있나? (압축)
- 잡음이 섞이는 길로 얼마나 확실하게 보낼 수 있나? (오류 정정)

섀넌이 본 통신의 모습은 이렇다. 보내는 쪽은 메시지를 비트로 바꾸며 군더더기는 빼고 잡음에 대비한 여분은 일부러 붙인다. 받는 쪽은 그 여분으로 틀린 곳을 고쳐 원래 메시지로 되돌린다.
```text
보내는 사람
  ↓ 부호화: 줄이고, 여분을 붙인다
통신로 ← 잡음
  ↓ 복호화: 고치고, 되돌린다
받는 사람
```

두 질문에 답하려면 먼저 정보의 양을 재는 자가 필요하다.

## 정보량은 놀라움이다
"내일 아침에도 해가 뜬다"는 소식은 새로 알려 주는 것이 없다. 누구나 이미 알기 때문이다. "한여름에 눈이 왔다"는 소식은 다르다. 드문 일일수록 우리를 놀라게 하고, 놀라운 소식일수록 많은 것을 알려 준다. 섀넌은 이 직관을 숫자로 만들었다. 확률이 p인 일이 일어났을 때의 **정보량**(information content)은 `log₂(1/p)` 비트다. 말로 풀면 "확률이 절반으로 줄 때마다 1비트씩 늘어난다"는 뜻이다.

| 일어난 일 | 확률 | 정보량 |
|---|---|---|
| 해가 뜬다 | 1 | 0비트 |
| 동전 앞면 | 1/2 | 1비트 |
| 동전 세 번 모두 앞면 | 1/8 | 3비트 |
| 주사위 6 | 1/6 | 약 2.6비트 |

정보량은 소수가 될 수도 있다. 여기서 비트는 2편의 "0이나 1이 들어가는 칸"이 아니라 정보의 양을 재는 단위다. 반반의 확률로 0이나 1이 들어가는 칸 하나에 담기는 정보가 정확히 1비트다.

## 엔트로피: 스무고개로 비트 세기
친구가 1부터 8까지의 수 중 하나를 마음에 두었다. "4보다 큰가?"처럼 남은 후보를 반씩 자르는 질문을 하면 세 번 만에 맞힐 수 있다. 후보가 16개면 네 번, 100만 개라도 스무 번이면 된다(2²⁰ = 1,048,576). 이 질문 수가 그 답에 담긴 정보, 곧 3비트, 4비트, 20비트다.

결과마다 확률이 다르면 평균을 생각한다. 각 결과의 정보량을 그 결과가 나올 확률만큼 쳐서 평균한 값이 **엔트로피**(entropy)다. 식으로는 `H = Σ p × log₂(1/p)`이고, 말로는 "결과 하나를 알려 줄 때 평균적으로 필요한 비트 수", 곧 평균 놀라움이다.
- 공정한 동전: 1비트. 매번 예/아니오 질문 하나가 꼭 필요하다.
- 앞면이 90% 나오는 동전: 약 0.47비트. 대부분 앞면이라 덜 놀랍다. 여러 번 던진 결과를 묶어서 물으면 한 번당 질문을 평균 0.47번 가까이로 줄일 수 있다.
- 늘 앞면만 나오는 동전: 0비트. 물어볼 필요가 없다.

엔트로피는 글 한 편이 아니라 그 글을 만들어 내는 출처(어떤 결과가 얼마의 확률로 나오는가)의 성질이다. 실제로는 출처의 확률을 모르므로, 아래 예처럼 나온 결과의 빈도를 세어 어림한다.

## 압축의 한계와 모스 부호
섀넌은 엔트로피가 압축의 한계임을 보였다. 원래대로 되돌릴 수 있게 줄이는 한, 기호 하나에 드는 평균 비트 수는 엔트로피보다 작을 수 없고, 잘 만든 부호는 엔트로피에 얼마든지 가까워질 수 있다. 비결은 자주 나오는 기호에 짧은 부호를, 드문 기호에 긴 부호를 주는 것이다.

이 생각은 섀넌보다 100여 년 앞선 모스 부호에 이미 들어 있었다. 지금 쓰는 국제 모스 부호에서 영어의 가장 흔한 글자 E는 점 하나(·), T는 선 하나(−)이고, 드문 Q는 −−·−, Z는 −−··로 길다. 새뮤얼 모스와 함께 일한 앨프리드 베일(Alfred Vail)이 뉴저지의 한 신문사 활자 상자에서 글자별 활자 개수를 세어 영어 글자의 빈도를 어림했다고 전해진다.

## 직접 확인: 엔트로피를 재고 압축해 보기
아래 코드는 먼저 짧은 한글·영문 문장의 글자 빈도로 엔트로피를 재고, 컴퓨터가 그 문장을 저장할 때 쓰는 비트와 견준다. 다음으로 여러 종류의 글을 2,000글자씩 만들어 실제 압축 프로그램 zlib(ZIP 파일이 흔히 쓰는 것과 같은 방식)으로 줄인 뒤 엔트로피와 견준다. 코드를 읽지 못해도 괜찮다. 출력의 숫자만 보자.
```python
import math, random, zlib
from collections import Counter

def entropy(text):          # 글자 빈도로 잰 글자당 평균 놀라움(비트)
    n, counts = len(text), Counter(text).values()
    return sum(c / n * math.log2(n / c) for c in counts)

def zlib_bits(text):        # zlib으로 압축한 뒤 글자당 몇 비트가 남나
    packed = zlib.compress(text.encode("utf-8"), 9)
    return len(packed) * 8 / len(text)

ko = "하늘이 맑으면 소풍을 가고, 비가 오면 집에서 책을 읽는다."
en = "If the sky is clear we go on a picnic; if it rains we stay in."
for name, t in (("한글", ko), ("영문", en)):
    saved = len(t.encode("utf-8")) * 8 / len(t)
    print(f"{name} 문장: 저장 {saved:.1f} / 엔트로피 {entropy(t):.2f}")

rng = random.Random(1)
N, abc = 2000, "abcdefghijklmnopqrstuvwxyz"   # H는 앞면, T는 뒷면
tests = {
    "늘 앞면": "H" * N,
    "치우친 동전": "".join(rng.choices("HT", [9, 1], k=N)),  # 앞면 90%
    "공정한 동전": "".join(rng.choices("HT", k=N)),
    "무작위 글자": "".join(rng.choices(abc, k=N)),
    "영문×30": en * 30,                       # 같은 문장 30번
}
for name, t in tests.items():
    print(f"{name}: 엔트로피 {entropy(t):.2f}, zlib {zlib_bits(t):.2f}")
```
```text
한글 문장: 저장 19.2 / 엔트로피 4.14
영문 문장: 저장 8.0 / 엔트로피 3.86
늘 앞면: 엔트로피 0.00, zlib 0.09
치우친 동전: 엔트로피 0.47, zlib 0.84
공정한 동전: 엔트로피 1.00, zlib 1.54
무작위 글자: 엔트로피 4.70, zlib 4.98
영문×30: 엔트로피 3.86, zlib 0.34
```

숫자는 모두 글자당 비트다. 출력을 차례로 읽어 보자.
- 한글 문장은 저장할 때 글자당 평균 19.2비트(한글 한 글자에 3바이트, 띄어쓰기와 문장 부호는 1바이트)를 쓰지만, 글자 빈도로 잰 엔트로피는 4.14비트다. 이렇게 짧은 글에서 센 빈도는 거친 어림이지만, 저장 방식에 군더더기가 많다는 것은 분명하다.
- 늘 앞면인 글은 엔트로피가 0이고 zlib도 거의 0으로 줄인다. 남은 0.09비트는 "H를 2,000번 되풀이하라"는 짧은 지시와 압축 파일의 머리말에 드는 몫이다.
- 앞면이 90% 나오는 치우친 동전, 공정한 동전, 알파벳 26자를 무작위로 고른 글에서 zlib은 엔트로피 아래로 내려가지 못한다. 엔트로피가 넘을 수 없는 바닥이고, 압축 프로그램은 그 위에서 바닥에 다가갈 뿐이다.
- 마지막 줄은 반대처럼 보인다. 같은 영문 문장을 30번 이어 붙이면 글자 빈도는 그대로(3.86비트)인데 zlib은 0.34비트까지 줄인다. zlib은 글자를 하나씩 따로 보지 않고 "아까 나온 덩어리가 또 나왔다"는 것까지 쓰기 때문이다. 글자 빈도로 잰 값은 글자를 하나씩 따로 볼 때의 한계이고, 앞뒤 관계까지 보면 다음 글자를 맞히기 쉬워져 진짜 엔트로피는 더 낮아진다. 앞 글자로 다음 글자를 예측하는 이 생각은 6편에서 언어 모델로 이어진다.

## 잡음을 이기는 법: 여분을 붙인다
이제 두 번째 질문이다. 통신로가 비트를 5%의 확률로 뒤집는다고 하자. 가장 단순한 대책은 같은 비트를 세 번씩 보내고, 받는 쪽에서 셋 중 다수를 따르는 **반복 부호**(repetition code)다.
```python
import random

rng = random.Random(5)
FLIP = 0.05                       # 통신로가 비트 하나를 뒤집을 확률 5%

def channel(bits):                # 잡음이 있는 통신로
    return [1 - b if rng.random() < FLIP else b for b in bits]

def encode3(bits):                # 같은 비트를 세 번씩 보낸다
    return [b for b in bits for _ in range(3)]

def groups(bits):                 # 셋씩 묶기
    return [bits[i:i + 3] for i in range(0, len(bits), 3)]

def decode3(bits):                # 묶음마다 다수결
    return [1 if sum(g) >= 2 else 0 for g in groups(bits)]

def show(bits):                   # 묶음 사이를 띄어 보여 주기
    return " ".join("".join(map(str, g)) for g in groups(bits))

sent = encode3([1, 0, 1, 1])
got = sent[:]
for i in (1, 4):                  # 일부러 두 비트를 뒤집어 본다
    got[i] = 1 - got[i]
print("보낸 것:", show(sent))
print("받은 것:", show(got))
print("다수결:", "".join(map(str, decode3(got))))

msg = [rng.randint(0, 1) for _ in range(100_000)]
wrong = lambda out: sum(a != b for a, b in zip(msg, out))
plain = channel(msg)                          # 그냥 보내기
three = decode3(channel(encode3(msg)))        # 세 번씩 보내고 다수결
print(f"그냥 보내기: 10만 비트 중 {wrong(plain):,}개 틀림")
print(f"세 번씩 보내기: {wrong(three):,}개 틀림")
```
```text
보낸 것: 111 000 111 111
받은 것: 101 010 111 111
다수결: 1011
그냥 보내기: 10만 비트 중 4,962개 틀림
세 번씩 보내기: 690개 틀림
```

1011을 111 000 111 111로 보냈는데 두 비트가 뒤집혀 101 010 111 111이 도착했다. 묶음마다 다수결을 하니 원래 1011이 되살아났다. 10만 비트로 해 보면 그냥 보낼 때는 약 5%인 4,962비트가 틀렸고, 세 번씩 보내면 690비트로 약 7분의 1이 되었다. 한 묶음 안에서 두 비트가 함께 뒤집히는 드문 경우에는 다수결도 틀린다. 대가는 세 배의 전송량이다.

더 영리한 방법도 있다. 벨 연구소의 리처드 해밍(Richard Hamming)은 주말에만 쓸 수 있던 계전기 컴퓨터가 오류를 발견할 때마다 하던 일을 버리고 다음 작업으로 넘어가 버리는 데 지쳐, 1950년 논문 「Error Detecting and Error Correcting Codes」에서 틀린 자리를 스스로 찾아 고치는 부호를 발표했다. 가장 작은 **해밍 부호**(Hamming code)는 데이터 4비트에 검사 비트 3개를 붙여 7비트로 보내고, 7비트 중 하나가 틀리면 어디가 틀렸는지 찾아 고친다. 반복 부호가 세 배를 보낼 때 1.75배만 보낸다.

섀넌은 1948년 논문에서 더 놀라운 사실도 보였다. 통신로마다 **용량**(channel capacity)이라는 한계 속도가 있어서, 그보다 느리게만 보내면 부호를 잘 만들어 오류를 원하는 만큼 줄일 수 있다. 비트를 5%의 확률로 뒤집는 통신로의 용량은 보낸 비트 하나에 약 0.71비트다. 보낸 비트 100개에 정보를 71비트 가까이 실어도 이론상 오류를 얼마든지 줄일 수 있다는 뜻이다. 33비트만 싣고도 0.7%가 틀리는 반복 부호는 그 한계에서 한참 멀다. 오늘날 휴대전화, 와이파이, QR 코드, 저장 장치는 모두 오류 정정 부호를 쓰고, 최신 통신용 부호는 이 한계에 꽤 가까이 다가갔다.

## 정보 이론이 재지 않는 것
섀넌은 논문 첫머리에서 메시지의 의미는 공학 문제와 관계가 없다고 못 박았다. 정보 이론이 재는 것은 "얼마나 예측하기 어려운가"이지 "얼마나 뜻깊은가"가 아니다. 무작위로 친 알파벳 100글자는 같은 길이의 영어 편지보다 예측하기 어려워 정보량이 크지만 아무 뜻도 없다. 이 선택 덕분에 같은 이론이 글, 사진, 음악, 유전자 서열에 똑같이 쓰일 수 있었다.

## 흔한 오해
- "정보가 많다 = 중요하다": 정보량은 놀라움의 크기다. 뜻이나 가치와는 다른 축이다.
- "압축 프로그램은 무엇이든 줄일 수 있다": 무작위 데이터는 줄지 않는다. 이미 압축된 사진이나 ZIP 파일을 또 압축해도 거의 줄지 않는 이유다. 모든 파일을 줄이는 압축이 불가능하다는 것은 이산수학 7편 「비둘기집 원리와 포함·배제의 원리」에서 증명한다.
- "정보의 비트와 저장 칸의 비트는 같다": 저장 칸은 0이나 1을 담는 자리이고, 정보의 비트는 양을 재는 단위다. 칸 8개에 담긴 정보가 8비트보다 훨씬 적을 수 있고, 그 차이가 압축할 수 있는 여지다.

## 어디에 쓰이나
- 정보 이론 1편 「정보량과 엔트로피」: 이 글의 놀라움과 엔트로피를 식으로 정의하고, 허프만 부호로 압축의 한계에 다가가는 과정을 계산한다.
- 정보 이론 2편 「교차 엔트로피」: AI 모델을 학습시킬 때 줄이는 대표적인 손실 값이 "모델이 예측한 확률로 잰 놀라움의 평균"이다.
- 메모리 시스템 10편 「메모리 오류와 신뢰성: ECC, 해밍 부호, 로우해머」: 해밍 부호를 실제로 구현해 메모리의 1비트 오류를 고치는 과정을 본다.
- 6편 「AI는 어떻게 사람과 대화하게 되었나: 규칙에서 다음 단어 예측까지」: 앞 글자로 다음 글자를 예측하는 확률 모형이 언어 모델의 출발점이다.

## 정리
- 정보 이론은 섀넌의 1948년 논문에서 시작했고, 압축과 잡음 속 전송의 한계에 비트로 답한다.
- 정보량은 놀라움(`log₂(1/p)`)이고 엔트로피는 그 평균이며, 무손실 압축은 평균적으로 엔트로피 아래로 내려갈 수 없다.
- 잡음에는 여분으로 맞선다. 반복 부호는 단순하지만 비싸고, 해밍 부호(1950)는 더 적은 여분으로 틀린 자리를 고치며, 섀넌의 용량이 그 한계를 정한다.
- 정보 이론은 뜻을 재지 않는다. 그래서 어떤 종류의 데이터에도 쓰인다.
