# [문자열 알고리즘 6/6] Manacher 알고리즘: 회문을 선형 시간에 찾기

> **한 줄 요약** — Manacher 알고리즘은 글자 사이에 구분자를 끼워 홀수·짝수 회문을 하나로 다루고, 지금까지 찾은 가장 오른쪽 회문 안에서는 중심 반대편의 거울 위치 반지름을 빌려 와서, 모든 중심의 최대 회문 반지름을 O(n)에 구한다.

## 이 글에서 다루는 것
- 중심 확장법 O(n²)과 그 낭비
- 구분자 삽입으로 홀수·짝수 회문 통합
- 반지름 배열과 거울 위치 재사용, 왜 O(n)인가
- 가장 긴 회문, 회문 부분 문자열 개수, 구간 회문 판정 O(1)

## 예제 문제와 중심 확장법
문자열에서 가장 긴 **회문**(palindrome, 앞뒤로 읽어도 같은 문자열) 부분 문자열과 회문 부분 문자열의 개수를 구하자. 모든 부분 문자열을 뒤집어 보면 O(n³)이다. 조금 나은 방법은 **중심 확장법**이다. 회문은 중심에서 양쪽으로 같은 글자가 이어지는 모양이므로, 중심 2n − 1개(글자 n개와 글자 사이 n − 1개)마다 양쪽으로 넓히며 어긋날 때까지 센다.
```python
def expand_all(s):
    n, best, count, comps = len(s), "", 0, 0
    for c in range(2 * n - 1):            # 짝수 c는 글자, 홀수 c는 글자 사이
        l, r = c // 2, (c + 1) // 2
        while l >= 0 and r < n:
            comps += 1
            if s[l] != s[r]:
                break
            count += 1                    # s[l:r+1]은 회문
            if r - l + 1 > len(best):
                best = s[l:r + 1]
            l, r = l - 1, r + 1
    return best, count, comps

print(expand_all("abacabad")[:2])
print("최악 입력 비교 횟수", expand_all("a" * 2000)[2])
```
```text
('abacaba', 13)
최악 입력 비교 횟수 2001000
```
"aaaa…a"에서는 모든 중심이 끝까지 넓어져 약 n²번 비교한다. 그런데 큰 회문 안쪽의 오른쪽 절반은 왼쪽 절반의 거울상이다. 왼쪽에서 이미 잰 반지름을 오른쪽에서 다시 잴 필요가 없다. 이 관찰로 O(n)을 얻은 것이 Glenn Manacher가 1975년 JACM에 발표한 방법이다. 원 논문은 "가장 짧은 접두사 회문"을 온라인으로 찾는 문제를 다뤘지만, 같은 방법이 모든 중심의 회문 반지름을 구하는 데 그대로 쓰인다.

## 구분자로 홀수·짝수 통합하기
짝수 길이 회문은 중심이 글자 사이라서 따로 다뤄야 한다. 글자 사이와 양 끝에 구분자를 끼워 `t = "#a#b#a#a#b#"`처럼 만들면 모든 회문의 길이가 홀수가 되고 중심이 t의 한 칸이 된다. `p[i]`를 t의 위치 i를 중심으로 한 최대 반지름이라 하면, **p[i]가 곧 원래 문자열에서 그 회문의 길이**다. 구분자 위치의 반지름은 짝수 회문, 글자 위치의 반지름은 홀수 회문이다.

비교하는 두 칸 `i − k`와 `i + k`는 홀짝이 같으므로 구분자는 언제나 구분자끼리만 비교된다. 그래서 원래 문자열에 '#'이 들어 있어도 상관없다(아래 대조 검사에서 일부러 섞는다).

## 거울 위치 재사용
지금까지 찾은 회문 중 오른쪽 끝이 가장 먼 것을 중심 c, 오른쪽 끝 `r = c + p[c]`로 기억한다. 새 위치 i가 r 안쪽이면, c를 기준으로 한 거울 위치 `j = 2c − i`가 있다.
```text
t  ├──────P──────┤
   l      c      r
      ↑       ↑
     2c−i     i
```
[l, r]은 회문이므로 j 둘레와 i 둘레는 서로 뒤집힌 모양이다. 그래서 `p[i] ≥ min(p[j], r − i)`이다.
- `p[j] < r − i`: j의 회문이 [l, r] 안에서 끝나므로 i도 정확히 `p[j]`다.
- `p[j] > r − i`: 정확히 `r − i`다. 더 크다면 [l, r]이 더 넓은 회문이 되어 모순이다.
- 같으면 r − i까지는 확실하고, r 너머만 새로 비교해 넓힌다.

새로 성공한 비교는 r을 오른쪽으로 밀고, r은 줄지 않으므로 성공한 비교는 전체 2n + 1번 이하다. 실패한 비교는 위치마다 한 번이다. 3편의 Z 알고리즘이 [l, r) 상자를 재사용한 것과 같은 구조다(앞 코드에 이어서).
```python
import random

def manacher(s):
    t = "#" + "#".join(s) + "#"           # 길이 2n + 1
    n = len(t)
    p, c, r, comps = [0] * n, 0, 0, 0
    for i in range(n):
        if i < r:
            p[i] = min(r - i, p[2 * c - i])   # 거울 위치 값을 빌린다
        while i - p[i] - 1 >= 0 and i + p[i] + 1 < n:
            comps += 1
            if t[i - p[i] - 1] != t[i + p[i] + 1]:
                break
            p[i] += 1
        if i + p[i] > r:
            c, r = i, i + p[i]            # 가장 오른쪽 회문 갱신
    return p, comps

p, _ = manacher("abaab")
print(" ".join("#" + "#".join("abaab") + "#"))
print(" ".join(map(str, p)))
print("최악 입력 비교 횟수", manacher("a" * 2000)[1])
```
```text
# a # b # a # a # b #
0 1 0 3 0 1 4 1 0 1 0
최악 입력 비교 횟수 3999
```
t의 'b' 자리 반지름 3은 "aba", 'a' 사이 '#' 자리 반지름 4는 "baab"다. 같은 최악 입력에서 비교가 약 200만 번에서 약 4,000번으로 줄었다.

## 답 꺼내기와 무작위 대조
- **가장 긴 회문**: `p[i]`가 최대인 i에서 원래 시작 위치는 `(i − p[i]) // 2`, 길이는 `p[i]`다.
- **회문 부분 문자열 개수**: 중심 i의 최대 반지름이 `p[i]`면 그 안에 같은 중심의 더 짧은 회문이 `(p[i] + 1) // 2`개 있다. 모두 더한다.
- **구간 회문 판정**: s[l:r]의 중심은 t의 위치 l + r이므로 `p[l + r] ≥ r − l`이면 회문이다. O(n) 전처리 후 질의마다 O(1)이다.

중심 확장법, 그리고 부분 문자열을 모두 뒤집어 보는 O(n³) 완전 탐색과 대조한다(앞 코드에 이어서).
```python
def palindromes(s):
    p, _ = manacher(s)
    i = max(range(len(p)), key=p.__getitem__)
    start = (i - p[i]) // 2
    return s[start:start + p[i]], sum((x + 1) // 2 for x in p), p

def is_pal(p, l, r):                      # s[l:r]이 회문인가, O(1)
    return p[l + r] >= r - l

rng = random.Random(6)
for _ in range(500):
    abc = rng.choice(["a", "ab", "abc", "a#"])
    s = "".join(rng.choice(abc) for _ in range(rng.randint(0, 30)))
    best, count, p = palindromes(s)
    e_best, e_count, _ = expand_all(s)
    subs = [(l, r) for l in range(len(s)) for r in range(l + 1, len(s) + 1)]
    assert len(best) == len(e_best) and best == best[::-1]
    assert count == e_count == sum(s[l:r] == s[l:r][::-1] for l, r in subs)
    assert all(is_pal(p, l, r) == (s[l:r] == s[l:r][::-1]) for l, r in subs)
print(palindromes("abacabad")[:2])
print("무작위 500개 비교: 모두 일치")
```
```text
('abacaba', 13)
무작위 500개 비교: 모두 일치
```

## 자주 하는 실수와 변형
- t의 위치를 원래 위치로 바꿀 때 `(i − p[i]) // 2`를 틀린다. 작은 예로 직접 확인해 두는 것이 가장 빠르다.
- `min(r − i, …)`을 빼먹어 큰 회문 밖까지 같다고 가정하거나, r을 "끝 다음 칸"과 "끝 칸" 중 어느 쪽으로 정했는지 섞는다.
- 홀수·짝수 반지름 배열 두 개(d₁, d₂)로 구분자 없이 쓰는 방법도 있다. 메모리는 줄지만 인덱스 실수가 늘어난다.
- 변형: 각 위치에서 끝나는 가장 긴 회문, "회문을 붙여 만든 가장 짧은 회문" 유형, 회문으로 나누는 최소 횟수(구간 회문 판정 + DP). 1편의 정방향·역방향 해시 + 이분 탐색으로도 O(n log n)에 풀리지만 확률적이다. 서로 다른 회문을 모두 다루려면 회문 트리(eertree)를 쓴다.

## 복잡도
| 방법 | 시간 | 공간 |
|---|---|---|
| 완전 탐색 | O(n³) | O(1) |
| 중심 확장 | O(n²) | O(1) |
| 해시 + 이분 탐색 | O(n log n) | O(n) |
| Manacher | O(n) | O(n) |

Manacher의 비교 횟수는 t의 길이 2n + 1에 비례하고, 구간 회문 판정 질의는 전처리 뒤 O(1)이다.

## 어디에 쓰이나
- 이산수학 11편 「점근 표기법: 알고리즘의 비용 세기」: for 안의 while이 n²처럼 보여도 "r은 줄지 않는다"는 사실 하나로 전체 비교가 선형임을 보이는 분할 상환 분석이다.
- 동적 계획법 5편 「구간 DP: 행렬 곱셈 순서와 파일 합치기」: 회문 분할 DP는 "s[l:r]이 회문인가"를 O(n²) 표로 미리 채우는데, Manacher의 반지름 배열 하나로 O(n) 전처리와 O(1) 질의로 바꿀 수 있다.
- DNA 서열: 제한 효소 EcoRI가 자르는 자리 GAATTC는 뒤집어 상보 염기로 바꾸면 자기 자신이 되는 서열이다. 비교를 "같은 글자" 대신 "상보 염기"로 바꾸고 글자 사이 중심만 보면 같은 틀로 이런 자리를 찾을 수 있다.

## 정리
- 구분자를 끼우면 모든 회문이 홀수 길이가 되고, t에서의 반지름 `p[i]`가 곧 원래 회문의 길이다.
- 가장 오른쪽 회문 [c − p[c], r] 안에서는 거울 위치 반지름 `min(p[2c − i], r − i)`을 빌리고 r 너머만 새로 비교하므로 O(n)이다.
- 반지름 배열 하나로 가장 긴 회문, 회문 부분 문자열 개수, 구간 회문 판정 O(1)이 모두 나온다.
- 이 시리즈의 KMP·Z·Manacher는 "이미 확인한 정보를 버리지 않는다"는 같은 원리로 단순한 O(n²)을 O(n)으로 만든다.
