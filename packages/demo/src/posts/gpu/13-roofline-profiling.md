# [GPU와 CUDA 13/14] 루프라인 모델과 프로파일링: 계산이 한계인가 메모리가 한계인가

> **한 줄 요약** — 커널이 낼 수 있는 성능의 상한은 `min(최대 FLOPS, 메모리 대역폭 × 산술 강도)`이므로, 산술 강도(FLOP/바이트)를 계산해 능선의 왼쪽(메모리 한계)인지 오른쪽(계산 한계)인지 먼저 알고, 측정값이 지붕에서 얼마나 떨어져 있는지를 프로파일러 지표로 진단한다.

## 이 글에서 다루는 것
- 루프라인 모델과 능선(ridge point)
- 커널별 산술 강도: 벡터 덧셈, 리덕션, 행렬-벡터, 행렬 곱, 어텐션
- 파이썬으로 H100 SXM5 기준 루프라인 위치 계산과 시간 모델 대조
- Nsight Compute가 보여 주는 주요 지표의 뜻

## 두 개의 지붕
커널 하나는 두 가지 일을 한다. 연산 장치로 FLOP을 계산하고, 메모리에서 바이트를 옮긴다. 둘이 완전히 겹친다고 하면 실행 시간은 둘 중 긴 쪽이다.
```text
계산 시간 = FLOP ÷ 최대 FLOPS
이동 시간 = 바이트 ÷ 대역폭
실행 시간 ≥ max(계산 시간, 이동 시간)
강도 = FLOP ÷ 바이트
성능 ≤ min(최대 FLOPS, 대역폭 × 강도)
```

**산술 강도**(arithmetic intensity)는 옮긴 바이트 하나당 FLOP 수다. 2009년 윌리엄스(Samuel Williams)·워터먼(Andrew Waterman)·패터슨(David Patterson)이 Communications of the ACM에 발표한 **루프라인 모델**(roofline model)은 이 식을 로그-로그 그림으로 그린다. 가로축이 강도, 세로축이 성능이고, 왼쪽은 기울기가 대역폭인 비탈, 오른쪽은 최대 FLOPS의 평평한 지붕이다. 둘이 만나는 **능선**(ridge point) = 최대 FLOPS ÷ 대역폭보다 강도가 낮은 커널은 메모리가, 높은 커널은 계산이 한계다.
```text
perf (log)
  ^       ridge
  |    ____.___________ peak
  |   /
  |  /  slope = bandwidth
  | /
  +----------------------> AI (log)
```

## H100 위에 커널 놓기
H100 SXM5 기준 FP32(텐서 코어 아님) 67TFLOPS, FP16 텐서 코어(밀집) 989TFLOPS, HBM3 3.35TB/s로 커널 여섯 개의 위치를 계산한다. 바이트는 입력을 HBM에서 한 번 읽고 출력을 한 번 쓴다고 센다. 어텐션은 헤드 하나(길이 n = 8,192, 헤드 차원 d = 128)이고, 표준 구현은 어텐션 7편 「플래시 어텐션: 메모리 계층을 아는 정확한 어텐션」처럼 n×n 행렬 S와 P를 HBM에 쓰고 읽는다.
```python
import random

PEAK = {"FP32": 67e12, "FP16": 989e12}   # H100 SXM5, FP16은 텐서 코어 밀집
BW = 3.35e12                             # HBM3 바이트/초

def roof(ai, peak):                      # 루프라인: 달성 가능한 FLOP/s
    return min(peak, BW * ai)

print("능선:", ", ".join(f"{p} {v / BW:.0f} FLOP/B" for p, v in PEAK.items()))
n, d, N = 8192, 128, 4096
kernels = {                              # 이름: (FLOP, 바이트, 정밀도)
    "벡터 덧셈": (n, 12 * n, "FP32"),            # z = x + y
    "리덕션": (n, 4 * n, "FP32"),
    "행렬-벡터": (2 * N * N, 2 * N * N + 4 * N, "FP16"),
    "행렬 곱": (2 * N**3, 3 * 2 * N * N, "FP16"),
    "어텐션 표준": (4 * n * n * d, 8 * n * d + 8 * n * n, "FP16"),
    "어텐션 플래시": (4 * n * n * d, 8 * n * d, "FP16"),
}
for name, (f, b, p) in kernels.items():
    ai = f / b
    kind = "계산" if BW * ai >= PEAK[p] else "메모리"
    s = f"{ai:.3g}" if ai < 100 else f"{ai:,.0f}"
    print(f"{name}({p}): 강도 {s}, {kind} 한계,",
          f"최대 {roof(ai, PEAK[p]) / 1e12:.3g}TFLOPS")
```
```text
능선: FP32 20 FLOP/B, FP16 295 FLOP/B
벡터 덧셈(FP32): 강도 0.0833, 메모리 한계, 최대 0.279TFLOPS
리덕션(FP32): 강도 0.25, 메모리 한계, 최대 0.838TFLOPS
행렬-벡터(FP16): 강도 1, 메모리 한계, 최대 3.35TFLOPS
행렬 곱(FP16): 강도 1,365, 계산 한계, 최대 989TFLOPS
어텐션 표준(FP16): 강도 63, 메모리 한계, 최대 211TFLOPS
어텐션 플래시(FP16): 강도 4,096, 계산 한계, 최대 989TFLOPS
```

능선은 FP32가 20, FP16 텐서 코어가 295 FLOP/바이트다. 텐서 코어가 지붕을 15배쯤 높이면서 능선도 오른쪽으로 멀어졌다. 벡터 덧셈(원소당 1 FLOP에 12바이트)과 리덕션은 0.3, 0.8TFLOPS가 상한이라, 이런 커널의 목표는 FLOPS가 아니라 대역폭이다. 배치 1 추론의 행렬-벡터 곱은 가중치 하나(2바이트)를 읽어 곱셈-덧셈 한 번(2 FLOP)에만 쓰므로 강도가 1이고, 텐서 코어가 있어도 3.35TFLOPS를 넘지 못한다. 4096³ 행렬 곱은 강도 1,365로 지붕 아래 넉넉히 들어간다.

표준 어텐션은 FLOP만 보면 행렬 곱 덩어리지만, S·P 왕복 때문에 강도가 63에 그쳐 FP16 능선 295의 왼쪽, 메모리 한계다. 플래시 어텐션처럼 Q·K·V·O만 옮기면 강도가 n/2 = 4,096으로 뛰어 계산 한계로 넘어간다. 실제 플래시 어텐션은 쿼리 블록마다 K·V를 다시 읽으므로 강도가 이보다 낮지만, 같은 FLOP을 하면서 위치가 능선 오른쪽으로 옮겨 가는 것이 핵심이다.

앞 코드에 이어서, `min` 공식이 "계산 시간과 이동 시간 중 긴 쪽"이라는 시간 모델과 같은 답을 내는지 무작위 커널로 확인하고, 측정값이 지붕의 몇 %인지 구하는 함수를 만든다. 아래 두 측정값은 설명을 위한 가상의 값이다.
```python
rng, ok = random.Random(13), True
for _ in range(300):                     # 시간으로 계산해도 같은가
    f, b = 10 ** rng.uniform(6, 13), 10 ** rng.uniform(6, 11)
    peak = rng.choice(list(PEAK.values()))
    t = max(f / peak, b / BW)            # 계산 시간과 이동 시간 중 긴 쪽
    ok &= abs(f / t - roof(f / b, peak)) <= 1e-9 * roof(f / b, peak)
print("무작위 300개, min 공식 = 시간 모델:", ok)

def report(name, f, b, sec, p):          # 측정값을 루프라인에 놓기
    got = f / sec
    print(f"{name}: {got / 1e12:.3g}TFLOPS, {b / sec / 1e12:.2f}TB/s,",
          f"지붕의 {got / roof(f / b, PEAK[p]):.0%}")

report("벡터 덧셈 2²⁸개", 2**28, 12 * 2**28, 1.2e-3, "FP32")   # 가상의 측정
report("행렬 곱 4096³", 2 * N**3, 6 * N * N, 0.25e-3, "FP16")
```
```text
무작위 300개, min 공식 = 시간 모델: True
벡터 덧셈 2²⁸개: 0.224TFLOPS, 2.68TB/s, 지붕의 80%
행렬 곱 4096³: 550TFLOPS, 0.40TB/s, 지붕의 56%
```

벡터 덧셈이 1.2ms 걸렸다면 FLOPS로는 0.2TFLOPS뿐이지만 HBM을 2.68TB/s로 써서 지붕의 80%다. 더 손볼 곳이 많지 않다. 행렬 곱이 0.25ms였다면 550TFLOPS로 지붕의 56%이고, 메모리는 0.4TB/s만 쓰므로 계산 쪽(텐서 코어 이용률, 파이프라인)을 봐야 한다. 같은 "느리다"도 강도에 따라 고칠 곳이 정반대다.

## 지붕 아래가 비어 있을 때: Nsight Compute
루프라인은 상한만 알려 준다. 측정점이 지붕보다 한참 아래면 이유를 프로파일러로 찾는다. Nsight Compute(`ncu --set full -o report ./app`)는 커널 하나를 여러 번 다시 실행하며 하드웨어 카운터를 모은다. 주요 섹션은 다음과 같다.
- **GPU Speed Of Light Throughput**: SM(계산)과 메모리 각각이 이론 최대의 몇 %로 일했는지 보여 준다. 루프라인 그림도 이 섹션에 있다. 둘 다 낮으면 지연이 한계라는 뜻이다.
- **Memory Workload Analysis**: L1·L2·DRAM 단계별로 옮긴 바이트와 적중률. 요청당 섹터 수가 많으면 병합이 안 된 것이고(6편 「메모리 병합: 전역 메모리를 32바이트 섹터로 읽기」), 공유 메모리 뱅크 충돌도 여기서 센다.
- **Occupancy**: 이론 점유율과 달성 점유율(8편 「점유율과 지연 숨기기: 레지스터와 공유 메모리가 동시 워프 수를 정한다」).
- **Warp State Statistics**: 워프가 발행하지 못하고 멈춘 이유의 분포. Long Scoreboard는 전역·로컬 메모리(L1TEX) 결과 대기, Barrier는 `__syncthreads()` 대기, MIO Throttle은 공유 메모리 등 메모리 명령 줄이 넘친 것, Math Pipe Throttle은 연산 장치가 바쁜 것이다.

| 증상 | 뜻 | 손볼 곳 |
|---|---|---|
| 메모리 %가 높음 | 메모리 한계 | 재사용·융합 |
| SM %가 높음 | 계산 한계 | 텐서 코어·정밀도 |
| 둘 다 낮음 | 지연 한계 | 점유율·ILP |
| Long Scoreboard | 메모리 대기 | 병합·타일링 |

여러 커널과 복사가 섞인 전체 흐름은 Nsight Systems로 먼저 보고(12편 「스트림과 비동기 실행: 복사와 계산을 겹치기」), 시간을 가장 많이 쓰는 커널을 Nsight Compute로 판다.

## 흔한 오해
- 산술 강도는 알고리즘만의 성질이 아니다. 같은 행렬 곱도 10편 「행렬 곱셈 커널 최적화: 타일링에서 레지스터 블로킹까지」의 단순 커널은 0.25, 블록 128×128은 32였다. 캐시 적중도 실제 HBM 바이트를 바꾼다.
- 메모리 한계 커널을 빠르게 하는 가장 큰 수단은 바이트를 줄이는 것이다. 원소별 연산 여러 개를 커널 하나로 **융합**(fusion)하면 중간 결과의 HBM 왕복이 사라진다. 행렬 곱 뒤의 편향 덧셈·활성화를 행렬 곱 커널의 마지막 단계에 붙이는 것, `torch.compile`이 원소별 연산을 묶는 것이 그 예다.
- 지붕은 HBM 하나만이 아니다. L2와 공유 메모리에도 각자의 대역폭 비탈이 있어, 계층별로 그린 루프라인에서 어느 층이 막혔는지 본다.

- 강도(위 계산): 벡터 덧셈 0.083, 리덕션 0.25, 행렬-벡터 1, 표준 어텐션 63, 4096³ 행렬 곱 1,365.

## 어디에 쓰이나
- 어텐션 7편 「플래시 어텐션: 메모리 계층을 아는 정확한 어텐션」: 플래시 어텐션은 FLOP을 줄이지 않고 바이트를 줄여 커널을 능선 왼쪽에서 오른쪽으로 옮긴 사례다.
- 어텐션 4편 「KV 캐시와 MQA·GQA·MLA」: 디코딩은 KV 캐시를 읽는 행렬-벡터 계산이라 메모리 한계이고, GQA는 쿼리 헤드 여러 개가 같은 K·V를 써서 강도를 높인다.
- AI 기초 4편 「컴퓨터 사이언스로 보는 AI 모델: 텐서, 연산, 메모리」: 그 글의 연산 병목과 메모리 대역폭 병목 구분을 그림 한 장으로 그린 것이 루프라인이다.
- 메모리 시스템 8편 「HBM과 GDDR: 넓게 쌓은 메모리와 빠르게 달리는 메모리」: 루프라인 비탈의 기울기가 바로 그 글의 HBM 대역폭이다.

## 정리
- 성능 상한은 `min(최대 FLOPS, 대역폭 × 산술 강도)`이고, 능선 = 최대 FLOPS ÷ 대역폭이 메모리 한계와 계산 한계를 가른다.
- H100 SXM5의 능선은 FP32 20, FP16 텐서 295 FLOP/바이트다. 벡터 덧셈·리덕션·행렬-벡터·표준 어텐션은 왼쪽, 큰 행렬 곱과 플래시 어텐션은 오른쪽이다.
- 측정값을 지붕 대비 %로 바꾸면 고칠 곳이 보인다. 메모리 한계면 바이트를, 계산 한계면 연산 경로를, 둘 다 낮으면 지연 숨기기를 본다.
- Nsight Compute의 Speed Of Light, 메모리 분석, 점유율, 워프 멈춤 이유가 이 진단의 근거가 된다.
