# [GPU와 CUDA 3/14] SIMT와 워프: 32개 스레드가 함께 걷는 법

> **한 줄 요약** — GPU는 스레드 32개를 워프로 묶어 명령 하나를 함께 실행하고, 스레드마다 다른 길로 가는 분기는 활성 마스크로 꺼 가며 두 경로를 차례로 실행하므로, 워프 안에서 갈리는 만큼 레인이 놀게 된다.

## 이 글에서 다루는 것
- 워프와 SIMT: 스칼라 코드를 쓰고 하드웨어가 묶어 실행한다
- 활성 마스크, 분기 갈림(divergence), 다시 합치기(reconvergence)
- 파이썬 SIMT 시뮬레이터로 분기 패턴별 레인 활용률 세기와 공식 대조
- 볼타 이후의 독립 스레드 스케줄링과 `__syncwarp()`
- 갈림을 줄이는 코드 배치

## 명령 하나를 32개 레인이 함께
2편의 워프 스케줄러는 스레드 하나가 아니라 **워프**(warp) 하나에 명령을 낸다. 워프는 연속된 스레드 32개의 묶음이고(블록의 스레드 0~31이 워프 0, 32~63이 워프 1), 명령 인출·해독·발행을 32개 스레드가 나눠 쓴다. 명령 하나를 해독해 32개 레인에서 실행하니 제어 회로가 32분의 1로 준다. 1편에서 본 "계산 레인에 면적을 몰아준다"는 설계의 핵심 장치다.

CPU의 SIMD(CPU 마이크로아키텍처 8편 「SIMD와 벡터 명령어: SSE에서 AVX-512, NEON, SVE까지」)도 명령 하나로 여러 값을 처리하지만 프로그래머나 컴파일러가 벡터 폭과 마스크를 직접 다룬다. 엔비디아는 자기 방식을 **SIMT**(single instruction, multiple threads)라 부른다. 프로그래머는 스레드 하나의 스칼라 코드를 쓰고, 스레드마다 레지스터와 주소가 따로 있어서 서로 다른 주소를 읽거나 다른 분기로 갈 수 있다. 묶어서 실행하는 일은 하드웨어가 한다. 다만 "갈 수 있다"와 "공짜로 갈 수 있다"는 다르다.

## 활성 마스크와 분기 갈림
워프의 모든 스레드는 같은 명령을 실행하므로, 조건이 스레드마다 다르면 하드웨어는 두 경로를 차례로 실행한다. 각 레인이 이번 명령을 실제로 수행할지는 32비트 **활성 마스크**(active mask)가 정한다. 참인 레인만 켜고 then 쪽을 실행한 뒤, 거짓인 레인만 켜고 else 쪽을 실행하고, 분기가 끝나는 지점에서 원래 마스크로 다시 합친다. 이것이 **분기 갈림**(branch divergence)이다.

아래 커널에서 `kind[i]`가 워프 안에서 섞여 있으면 경로 A와 B가 모두 실행되고, 각 경로 동안 레인의 일부는 논다(직접 실행하지 않은 읽기용 코드다).
```cuda
__global__ void shade(float* out, const float* in, const int* kind, int n)
{
    int i = blockIdx.x * blockDim.x + threadIdx.x;
    if (i >= n) return;               // 경계 검사: 마지막 워프만 갈린다
    if (kind[i] == 0) {
        out[i] = expf(in[i]);         // 경로 A
    } else {
        out[i] = sqrtf(in[i]) * 2.0f; // 경로 B
    }
}
```
갈림은 정확성에는 영향이 없고 시간만 잡아먹는다. 다른 워프와는 상관없다는 점도 중요하다. 워프 0의 스레드가 모두 A로 가고 워프 1이 모두 B로 가면 갈림이 없다.

## SIMT 시뮬레이터
구조화된 프로그램(일반 명령, if/else, 반복문)을 워프 하나로 실행하면서, 낸 명령 수와 그 명령마다 켜져 있던 레인 수를 센다. **레인 활용률**은 `활성 레인 합 ÷ (32 × 낸 명령 수)`다. 갈리면 두 경로를 차례로, 끝나면 원래 마스크로 합치는 볼타 이전 방식의 모델이다.
```python
FULL = (1 << 32) - 1                       # 32개 레인 모두 활성

def run(prog, mask, ctx, st):
    """구조화된 프로그램을 워프 하나로 실행한다(볼타 이전 방식의 모델).
    st = [낸 명령 수, 활성 레인 합]. 갈리면 두 경로를 차례로 실행한다."""
    for ins in prog:
        if ins[0] == "op":                 # 일반 명령 n개
            st[0] += ins[1]
            st[1] += ins[1] * bin(mask).count("1")
        elif ins[0] == "if":               # ("if", 조건, then, else)
            st[0] += 1                     # 분기 명령 자체
            st[1] += bin(mask).count("1")
            t = mask & sum(1 << l for l in range(32) if ins[1](l, ctx))
            if t:
                run(ins[2], t, ctx, st)    # 참인 레인만 켜고 실행
            if mask & ~t:
                run(ins[3], mask & ~t, ctx, st)
        elif ins[0] == "loop":             # ("loop", 반복 횟수, 본문)
            trips = [ins[1](l, ctx) for l in range(32)]
            i = 0
            while True:
                m = mask & sum(1 << l for l in range(32) if trips[l] > i)
                st[0] += 1                 # 반복 조건 검사
                st[1] += bin(mask).count("1")
                if not m:
                    break
                run(ins[2], m, ctx, st)
                i += 1
    return st                              # 끝나면 원래 마스크로 다시 합친다

def util(prog, ctx=None):
    issued, active = run(prog, FULL, ctx, [0, 0])
    return issued, active / (32 * issued)

A, B = [("op", 10)], [("op", 10)]          # 두 경로의 본문
cases = {
    "분기 없음": [("op", 21)],
    "lane % 2 == 0": [("if", lambda l, c: l % 2 == 0, A, B)],
    "lane < 16": [("if", lambda l, c: l < 16, A, B)],
    "워프 전체가 같은 쪽": [("if", lambda l, c: c % 2 == 0, A, B)],
    "반복 횟수 = lane": [("loop", lambda l, c: l, [("op", 5)])],
}
for name, prog in cases.items():
    n, u = util(prog, ctx=7)
    print(f"{name}: 명령 {n}개, 레인 활용률 {u:.0%}")
```
```text
분기 없음: 명령 21개, 레인 활용률 100%
lane % 2 == 0: 명령 21개, 레인 활용률 52%
lane < 16: 명령 21개, 레인 활용률 52%
워프 전체가 같은 쪽: 명령 11개, 레인 활용률 100%
반복 횟수 = lane: 명령 187개, 레인 활용률 59%
```

짝수·홀수로 갈리든 앞뒤 절반으로 갈리든 결과는 같다. 워프 안에 두 종류가 섞이기만 하면 두 경로를 다 실행한다. 조건이 워프 단위로 같으면(`ctx`는 워프 번호 7) 한 경로만 실행해 명령이 11개로 준다. 반복 횟수가 레인마다 다르면 워프는 가장 긴 레인(31번)이 끝날 때까지 돌고, 일찍 끝난 레인은 꺼진 채 따라간다.

손으로 세는 공식은 이렇다. if/else는 `1 + a·[n_A > 0] + b·[n_B > 0]`개 명령을 내고(a, b는 경로 길이, n_A, n_B는 각 경로의 레인 수), 반복문은 본문을 `max(trips)`번, 조건 검사를 그보다 한 번 더 실행한다. 무작위 마스크와 반복 횟수로 대조해 보자(앞 코드에 이어서).
```python
import random
rng = random.Random(3)
ok = 0
for _ in range(300):
    bits = [rng.random() < rng.random() for _ in range(32)]
    trips = [rng.randint(0, 9) for _ in range(32)]
    a, b, body = rng.randint(1, 20), rng.randint(1, 20), rng.randint(1, 6)
    prog = [("if", lambda l, c: c[0][l], [("op", a)], [("op", b)]),
            ("loop", lambda l, c: c[1][l], [("op", body)])]
    n, u = util(prog, ctx=(bits, trips))
    nA, nB, k = sum(bits), 32 - sum(bits), max(trips)
    # 공식: 분기 1개 + 쓰인 경로, 반복은 본문 k번 + 조건 검사 k+1번
    n_f = 1 + a * (nA > 0) + b * (nB > 0) + (k + 1) + body * k
    act = 32 + a * nA + b * nB + 32 * (k + 1) + body * sum(trips)
    ok += n == n_f and abs(u - act / (32 * n_f)) < 1e-12
print(f"무작위 300개 비교: 공식과 일치 {ok}/300")
```
```text
무작위 300개 비교: 공식과 일치 300/300
```

## 갈림을 워프 밖으로 밀어내기
갈림의 비용은 조건이 "워프 안에서" 섞인 정도로 정해진다. 그렇다면 데이터를 조건별로 모아 같은 워프에 넣으면 된다. 원소 1,024개(워프 32개)에 무작위 조건을 주고, 섞인 그대로와 조건별로 정렬한 뒤를 비교한다(앞 코드에 이어서).
```python
rng = random.Random(4)
flags = [rng.random() < 0.5 for _ in range(1024)]    # 원소 1,024개 = 워프 32개
prog = [("if", lambda l, c: c[l], A, B)]
for name, data in [("섞인 그대로", flags), ("조건별로 정렬", sorted(flags))]:
    tot_n = tot_act = 0
    for w in range(32):
        n, u = util(prog, ctx=data[32 * w: 32 * w + 32])
        tot_n, tot_act = tot_n + n, tot_act + u * 32 * n
    print(f"{name}: 명령 {tot_n}개, 활용률 {tot_act / (32 * tot_n):.0%}")
```
```text
섞인 그대로: 명령 672개, 활용률 52%
조건별로 정렬: 명령 362개, 활용률 97%
```

정렬하면 경계에 걸친 워프 하나만 갈리고 나머지 31개는 한 경로만 실행한다. 명령 수가 거의 절반이 된다. 레이 트레이싱에서 같은 재질에 맞은 광선을 모으거나, 희소 행렬의 행을 길이별로 묶는 것이 같은 발상이다. 정렬 비용이 갈림 비용보다 작을 때만 이득이라는 점은 따져야 한다.

## 볼타 이후: 독립 스레드 스케줄링
볼타(계산 능력 7.0, 2017) 이전에는 워프 전체가 프로그램 카운터 하나를 공유했고, 갈린 경로는 스택에 쌓아 하나씩 끝까지 실행했다. 볼타부터는 스레드마다 프로그램 카운터와 호출 스택을 따로 두는 **독립 스레드 스케줄링**(independent thread scheduling)을 쓴다. 스케줄러는 같은 명령에 있는 스레드를 모아 실행하므로 한 번에 한 경로만 도는 것은 같지만, 갈린 경로를 번갈아 진행할 수 있다.
```text
pre-Volta: one PC per warp
 0-15  A A A . . . C
16-31  . . . B B B C
Volta+: one PC per thread
 0-15  A . A . A . C
16-31  . B . B . B C
```
덕분에 워프 안의 스레드끼리 잠금을 주고받아도 교착되지 않는다. 예전에는 잠금을 쥔 스레드의 경로가 영영 실행되지 않아 같은 워프의 다른 스레드가 무한히 기다릴 수 있었다. 대신 "워프는 늘 함께 실행된다"는 가정이 깨졌다. 갈렸던 스레드가 C에서 다시 합쳐진다는 보장이 없으므로, 워프 안 스레드끼리 데이터를 주고받는 코드는 `__syncwarp()`로 명시적으로 모으고, 셔플 같은 워프 함수는 참여할 레인 마스크를 받는 `_sync` 판(`__shfl_down_sync(0xffffffff, v, off)`)을 써야 한다(9편).

## 코드에 주는 의미
- 분기 조건을 워프 경계에 맞춘다. `threadIdx.x % 2` 대신 `(threadIdx.x / 32) % 2`처럼 워프 단위로 일을 나누면 갈림이 사라진다. 워프 크기는 내장 변수 `warpSize`로 읽는다.
- 데이터를 조건별로 정렬·분할해 같은 일을 하는 스레드를 같은 워프에 모은다.
- 짧은 분기는 걱정하지 않아도 된다. 컴파일러가 술어 명령(predication)이나 선택 명령으로 바꿔, 분기 없이 두 값을 계산하고 고른다.
- 반복 횟수가 제각각인 루프는 워프마다 일의 양을 고르게 나눈다. 행 하나를 워프 하나에 맡기는 희소 행렬 곱이 그 예다.
- 경계 검사(`if (i >= n) return;`)는 마지막 워프 하나만 갈리게 하므로 비용이 거의 없다.

## 숫자로 보기
| 항목 | 값 | 근거 |
|---|---|---|
| 워프 크기 | 32 스레드 | CUDA 가이드 |
| SM당 워프 스케줄러 | 4(A100, H100) | 백서 |
| 블록당 최대 스레드 | 1,024(워프 32개) | CUDA 가이드 |
| SM당 상주 워프 | 최대 64(CC 8.0, 9.0) | CUDA 가이드 |
| 독립 스레드 스케줄링 | CC 7.0(볼타)부터 | CUDA 가이드 |

워프 크기 32는 지금까지 모든 엔비디아 세대에서 같았지만 언어가 약속한 상수는 아니다. AMD GPU는 64스레드(웨이브프런트)를 오래 썼고 RDNA 세대부터 32도 지원한다.

## 어디에 쓰이나
- CPU 마이크로아키텍처 3편 「분기 예측: 2비트 카운터에서 gshare와 TAGE까지」: CPU는 분기를 예측해 파이프라인을 채우고, GPU는 예측 대신 두 경로를 다 실행한다. 대신 바꾸지 않는 비용이 갈림이다.
- 이산수학 2편 「명제 논리와 불 대수: 참과 거짓의 계산」: 활성 마스크의 갱신은 `t = mask AND cond`, `else = mask AND NOT cond`라는 비트 단위 불 연산이다.
- 알고리즘 기법 11편 「비트마스킹: 정수 하나로 집합 다루기」: 32개 레인의 활성 여부를 32비트 정수 하나로 다루는 것이 그 글의 비트마스크 집합 표현이다.
- 레이 트레이싱 렌더러와 희소 행렬 라이브러리는 작업을 종류별로 다시 묶어 갈림을 줄인다.

## 정리
- 워프는 스레드 32개가 명령 하나를 함께 실행하는 단위이고, SIMT는 스칼라 코드를 하드웨어가 워프로 묶어 실행하는 방식이다.
- 워프 안에서 조건이 섞이면 활성 마스크로 두 경로를 차례로 실행하므로 레인 활용률이 떨어진다(반반이면 약 52%).
- 갈림은 워프 안에서만 비용이므로, 조건을 워프 경계에 맞추거나 데이터를 정렬하면 사라진다(52% → 97%).
- 볼타부터는 스레드마다 프로그램 카운터가 있어 워프 안 잠금이 안전해졌지만, 워프가 늘 함께 걷는다는 가정 대신 `__syncwarp()`와 `_sync` 함수로 명시해야 한다.
