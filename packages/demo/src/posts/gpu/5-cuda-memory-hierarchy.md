# [GPU와 CUDA 5/14] CUDA 메모리 계층: 레지스터, 공유, 전역, 상수, 로컬

> **한 줄 요약** — CUDA는 보이는 범위와 수명이 다른 다섯 메모리 공간(스레드의 레지스터·로컬, 블록의 공유, 그리드의 전역·상수)을 드러내고, CPU 캐시와 달리 무엇을 칩 안에 둘지 프로그래머가 고르게 하므로, 같은 계산도 어느 공간에서 읽느냐에 따라 DRAM 트래픽이 몇 배 달라진다.

## 이 글에서 다루는 것
- 다섯 메모리 공간의 범위·수명·물리 위치
- `cudaMalloc`·`cudaMemcpy`·`cudaFree`, `__shared__`, `__constant__`
- 레지스터가 넘칠 때의 로컬 메모리(스필)와 통합 메모리
- 파이썬으로 스텐실 커널의 공간별 접근 수와 DRAM 트래픽 어림, 식과 대조

## 왜 프로그래머가 고르나
CPU는 캐시를 하드웨어가 알아서 관리하고 프로그램은 주소 하나만 본다(메모리 시스템 3편 「캐시 미스의 종류와 정책: 3C, 교체, 쓰기」). GPU에도 L1·L2 캐시가 있지만, SM 하나에 스레드 2,048개가 올라가면 스레드당 L1 몫은 100바이트 안팎이라 캐시 운에 맡기기 어렵다. 그래서 CUDA는 칩 안의 SRAM 일부를 **공유 메모리**로 떼어 주고, 무엇을 올려 재사용할지 프로그래머가 정하게 했다. 레지스터와 상수 메모리도 각자 쓰임이 정해져 있다.
```text
thread : registers, local
block  : shared memory
grid   : global, constant
host  <-> global (cudaMemcpy)
```

| 공간 | 범위 | 위치 | 특징 |
|---|---|---|---|
| 레지스터 | 스레드 | SM 레지스터 파일 | 가장 빠름 |
| 로컬 | 스레드 | DRAM(캐시 거침) | 스필·배열 |
| 공유 | 블록 | SM의 SRAM | 직접 관리 |
| 전역 | 그리드·호스트 | DRAM(HBM) | 가장 큼 |
| 상수 | 그리드(읽기) | DRAM + 상수 캐시 | 64KB, 방송 |

- **레지스터**: 지역 변수는 대부분 레지스터에 산다. 스레드가 끝나면 사라진다. 마이크로벤치마크로 잰 지연이 L1 약 33사이클, L2 수백 사이클, DRAM 수백~700사이클(A100·H100)인 것과 달리 레지스터는 명령의 피연산자로 바로 읽힌다.
- **공유 메모리**: `__shared__`로 선언하고 블록이 살아 있는 동안만 존재한다. L1과 같은 SRAM을 나눠 쓰며 지연도 L1 수준이다. 뱅크 구조는 7편에서 본다.
- **전역 메모리**: `cudaMalloc`으로 잡는 HBM 영역이다. 모든 스레드와 호스트(복사로)가 보고, `cudaFree`할 때까지 남는다. 어떻게 읽어야 빠른지는 6편의 주제다.
- **상수 메모리**: `__constant__`로 선언하는 64KB 읽기 전용 영역이다. DRAM에 있지만 SM마다 상수 캐시가 있고, 워프의 모든 스레드가 같은 주소를 읽으면 한 번에 방송된다.
- **로컬 메모리**: 이름과 달리 칩 밖 DRAM에 있다. 스레드 전용이라 "로컬"일 뿐이며 L1·L2를 거친다.

## 스텐실 커널로 보는 다섯 공간
1차원 5점 스텐실 `out[i] = Σ coef[k]·in[i+k]`(k = −2~2)를 예로 든다. 계수는 모든 스레드가 같은 값을 읽으니 상수 메모리에, 이웃 원소는 블록이 함께 쓰니 공유 메모리 타일에, 누적값은 레지스터에 둔다(직접 실행하지 않은 읽기용 코드다).
```cuda
#define R 2                               // 반지름: 양쪽 이웃 2칸
#define BLOCK 256
__constant__ float coef[2 * R + 1];       // 모든 스레드가 같은 계수

__global__ void stencil(const float* in, float* out, int n)
{
    __shared__ float tile[BLOCK + 2 * R]; // 블록이 함께 쓰는 타일
    int g = blockIdx.x * blockDim.x + threadIdx.x;
    int s = threadIdx.x + R;              // 타일 안 위치
    tile[s] = (g < n) ? in[g] : 0.0f;
    if (threadIdx.x < R) {                // 왼쪽·오른쪽 헤일로
        int l = g - R, r = g + BLOCK;
        tile[s - R] = (l >= 0) ? in[l] : 0.0f;
        tile[s + BLOCK] = (r < n) ? in[r] : 0.0f;
    }
    __syncthreads();                      // 타일이 다 찰 때까지 기다림
    if (g < n) {
        float acc = 0.0f;                 // 레지스터
        for (int k = -R; k <= R; k++)
            acc += coef[k + R] * tile[s + k];
        out[g] = acc;
    }
}
```
호스트에서는 `cudaMalloc(&d_in, bytes)`로 전역 메모리를 잡고, `cudaMemcpy(d_in, h_in, bytes, cudaMemcpyHostToDevice)`로 복사하고, 계수는 `cudaMemcpyToSymbol(coef, h_coef, sizeof(h_coef))`로 상수 메모리에 올린다. 실행은 `stencil<<<(n + BLOCK - 1) / BLOCK, BLOCK>>>(d_in, d_out, n)`이고, 끝나면 `cudaFree(d_in)`으로 돌려준다.

먼저 상수 메모리의 규칙부터 보자. 상수 캐시는 워프 명령 하나를 서로 다른 주소 수만큼 나눠 처리한다.
```python
def const_cost(addrs):
    """상수 캐시: 워프 명령 하나가 서로 다른 주소 수만큼 나뉘어 처리된다."""
    return len(set(addrs))

print("coef[k], 모두 같은 주소:", const_cost([2] * 32))
print("coef[lane % 5]:", const_cost([l % 5 for l in range(32)]))
print("table[lane]:", const_cost(range(32)))
```
```text
coef[k], 모두 같은 주소: 1
coef[lane % 5]: 5
table[lane]: 32
```

스텐실의 `coef[k + R]`은 워프 전체가 같은 주소라 한 번이면 된다. 스레드마다 다른 원소를 읽는 표를 상수 메모리에 두면 32번으로 쪼개지므로, 그런 표는 전역 메모리에 두는 편이 낫다.

이제 커널 전체를 스레드 단위로 흉내 내어 공간별 접근 수를 센다. 공유 메모리 없이 이웃 다섯 개를 전역에서 직접 읽는 단순 버전과 비교한다(앞 코드에 이어서).
```python
def count(n, R, block, tiled):
    """1차원 스텐실의 모든 스레드를 흉내 내며 메모리 공간별 접근을 센다.
    전역·공유는 원소(4바이트) 단위, 상수는 워프 명령당 비용."""
    c = {"gld": 0, "gst": 0, "shared": 0, "const": 0}
    for b in range((n + block - 1) // block):
        for w in range(0, block, 32):
            live = [g for g in range(b * block + w, b * block + w + 32)
                    if g < n]
            if live:                            # 워프 전체가 coef[k]를 읽음
                c["const"] += sum(const_cost([k] * len(live))
                                  for k in range(2 * R + 1))
        for t in range(block):                  # threadIdx.x
            g = b * block + t
            if tiled:
                c["gld"] += g < n               # 자기 원소를 타일로
                c["shared"] += 1
                if t < R:                       # 왼쪽·오른쪽 헤일로
                    c["gld"] += (g - R >= 0) + (g + block < n)
                    c["shared"] += 2
                if g < n:
                    c["shared"] += 2 * R + 1    # 타일에서 이웃 읽기
            elif g < n:                         # 이웃을 전역에서 직접
                c["gld"] += sum(0 <= g + k < n for k in range(-R, R + 1))
            c["gst"] += g < n
    return c

n, R, block = 1 << 18, 2, 256
for tiled in (False, True):
    c = count(n, R, block, tiled)
    mib = (c["gld"] + c["gst"]) * 4 / 2**20      # 캐시가 없다고 칠 때
    print("타일" if tiled else "단순",
          f"전역 읽기 {c['gld'] / n:.2f}n, 공유 {c['shared'] / n:.2f}n,",
          f"DRAM {mib:.2f}MiB ≈ {mib * 2**20 / 3.35e12 * 1e6:.2f}µs")
```
```text
단순 전역 읽기 5.00n, 공유 0.00n, DRAM 6.00MiB ≈ 1.88µs
타일 전역 읽기 1.02n, 공유 6.02n, DRAM 2.02MiB ≈ 0.63µs
```

타일 버전은 원소마다 전역 읽기가 5번에서 약 1번(헤일로 몫 0.02)으로 줄고, 나머지는 공유 메모리 읽기로 옮겨 간다. 캐시가 없다고 치면 DRAM 트래픽이 3분의 1이 되어 H100 SXM5 대역폭(3.35TB/s)으로 1.88µs가 0.63µs가 된다. 실제로는 L1·L2가 단순 버전의 이웃 읽기를 상당 부분 잡아 주므로 차이는 이보다 작다. 공유 메모리는 재사용을 캐시 운에 맡기지 않고 보장하는 수단이다.

이 수치가 맞는지 손으로 유도한 식과 대조한다. 단순 버전의 읽기는 양 끝에서 빠지는 이웃을 뺀 `(2R+1)·n − R(R+1)`, 타일 버전은 `n + 헤일로 수`, 상수 접근은 워프마다 `2R+1`번이다(앞 코드에 이어서).
```python
import random
rng = random.Random(7)
ok = 0
for _ in range(300):
    R, block = rng.randint(1, 4), rng.choice([32, 64, 128, 256])
    n = rng.randint(R + 1, 3000)
    grid = (n + block - 1) // block
    a, b = count(n, R, block, False), count(n, R, block, True)
    right = sum(max(0, (n - 1 - t) // block) for t in range(R))
    want = {  # 손으로 유도한 식
        "단순 읽기": (2 * R + 1) * n - R * (R + 1),
        "타일 읽기": n + R * (grid - 1) + right,
        "타일 공유": grid * block + 2 * R * grid + (2 * R + 1) * n,
        "상수": (2 * R + 1) * ((n + 31) // 32),
    }
    got = [a["gld"], b["gld"], b["shared"], b["const"]]
    ok += got == list(want.values())
print(f"무작위 300개 비교: 공식과 일치 {ok}/300")
```
```text
무작위 300개 비교: 공식과 일치 300/300
```

## 레지스터가 넘치면: 로컬 메모리
레지스터는 스레드당 최대 255개이고, SM의 65,536개를 상주 스레드가 나눠 쓴다. 커널이 레지스터를 너무 많이 원하면 컴파일러는 일부를 로컬 메모리로 내보낸다. 이것이 **스필**(spill)이다. 실행 시점에 바뀌는 인덱스로 접근하는 지역 배열(`float a[16]; a[idx]`)도 레지스터에 둘 수 없어 로컬 메모리로 간다. 로컬 메모리는 DRAM에 있으므로 L1에서 놓치면 수백 사이클이 든다. `nvcc -Xptxas -v`로 컴파일하면 커널마다 레지스터 수와 스필 바이트가 출력되니, 성능이 이상하면 먼저 확인할 곳이다. 레지스터 수를 묶는 `__launch_bounds__`와 점유율의 맞바꿈은 8편에서 다룬다.

## 통합 메모리: 포인터 하나로
`cudaMallocManaged(&p, bytes)`로 잡은 **통합 메모리**(unified memory)는 CPU와 GPU가 같은 포인터로 접근한다. 파스칼(2016) 이후 GPU는 페이지 폴트를 낼 수 있어서, 커널이 GPU에 없는 페이지를 건드리면 해당 스레드를 멈추고 페이지 이동 엔진이 페이지를 GPU로 옮긴다. 운영체제의 요구 페이징과 같은 원리이고(메모리 시스템 7편 「가상 메모리 하드웨어: 페이지 테이블 워크와 TLB」), GPU 메모리보다 큰 할당도 가능해진다. 대신 첫 접근마다 폴트 비용이 들기 때문에, 데이터를 쓸 곳이 분명하면 `cudaMemPrefetchAsync`로 미리 옮겨 두는 것이 좋다. 편하지만 공짜는 아니다.

## 코드에 주는 의미
- 여러 스레드가 다시 읽는 데이터는 공유 메모리 타일에 올린다. 올린 뒤에는 `__syncthreads()`로 다 찰 때까지 기다린다(7편).
- 워프 전체가 같은 값을 읽는 작은 읽기 전용 데이터(필터 계수, 상수 매개변수)는 `__constant__`에 둔다. 스레드마다 다른 원소를 읽는 표는 두지 않는다.
- `-Xptxas -v`로 스필을 확인하고, 동적 인덱스 지역 배열을 피한다.
- 통합 메모리는 프로토타입에 편하지만, 성능이 중요하면 프리페치하거나 명시적 복사로 바꾼다.

## 숫자로 보기
| 항목 | 값 | 근거 |
|---|---|---|
| SM당 레지스터 | 32비트 65,536개 | CUDA 가이드 |
| 스레드당 레지스터 | 최대 255개 | CUDA 가이드 |
| SM당 공유 메모리 | 164KB(A100), 228KB(H100) | CUDA 가이드 |
| 상수 메모리 | 64KB | CUDA 가이드 |
| 할당 정렬 | 256바이트 이상 | CUDA 가이드 |
| L1 지연 | 약 33사이클 | 측정 논문 |
| L2 지연 | 약 200~400사이클(A100) | 측정 논문 |

공유 메모리는 블록 하나가 정적으로 48KB까지 쓸 수 있고, 그 이상은 동적 공유 메모리와 `cudaFuncSetAttribute`로 한도를 올려야 한다. 지연은 측정 방법과 클록에 따라 달라지는 대략값이다.

## 정리
- 레지스터·로컬은 스레드, 공유는 블록, 전역·상수는 그리드 전체가 보는 공간이고, 레지스터와 공유 메모리만 칩 안에 있다.
- 공유 메모리 타일로 이웃을 재사용하면 5점 스텐실의 전역 읽기가 원소당 5번에서 약 1번으로 준다(식과 300개 대조 일치).
- 상수 메모리는 워프가 같은 주소를 읽을 때만 빠르며, 서로 다른 주소 수만큼 나뉘어 처리된다.
- 레지스터가 넘치면 DRAM의 로컬 메모리로 스필되고, 통합 메모리는 페이지 폴트로 데이터를 옮기므로 편한 만큼 비용이 있다.
