# [통계학 1/11] 기술 통계: 데이터를 숫자 몇 개로 요약하기

> **한 줄 요약** — 기술 통계는 데이터 전체를 "중심이 어디인가"와 "얼마나 퍼져 있는가"를 나타내는 숫자 몇 개로 줄이는 방법이며, 어떤 숫자를 고르느냐에 따라 같은 데이터가 전혀 다르게 보일 수 있다.

## 이 글에서 다루는 것
- 중심을 나타내는 값: 평균, 중앙값, 최빈값
- 퍼짐을 나타내는 값: 분산과 표준편차
- 분위수와 사분위 범위
- 이상치 하나가 평균과 중앙값을 얼마나 흔드는지
- 응답 시간을 평균 대신 p50·p99로 보는 이유

## 왜 요약하나
서버가 하루에 처리한 요청 10만 건의 응답 시간을 하나씩 읽을 수는 없다. 그래서 "보통 몇 ms 걸렸나", "얼마나 들쭉날쭉했나"를 숫자 몇 개로 줄여 본다. 이렇게 가진 데이터 자체를 요약하는 것이 **기술 통계**(descriptive statistics)다. 가진 데이터를 넘어 그 뒤의 더 큰 집단에 대해 말하는 **추론 통계**는 2편부터 다룬다.

## 중심: 평균, 중앙값, 최빈값
```text
평균    x̄ = (x₁ + x₂ + … + xₙ) / n
중앙값  크기순으로 정렬했을 때 한가운데 값 (n이 짝수면 가운데 두 값의 평균)
최빈값  가장 자주 나오는 값
```

| 값 | 이상치에 | 잘 맞는 경우 |
|---|---|---|
| 평균 | 민감하다 | 대칭이고 극단값이 없을 때 |
| 중앙값 | 둔감하다 | 한쪽으로 치우친 분포(응답 시간, 소득) |
| 최빈값 | 둔감하다 | 범주형 데이터(가장 많이 쓰는 언어) |

## 퍼짐: 분산과 표준편차
평균이 같아도 값이 평균 근처에 몰려 있는지, 넓게 흩어져 있는지는 다를 수 있다. 각 값이 평균에서 떨어진 거리(편차) `xᵢ − x̄`를 그냥 더하면 항상 0이 되므로, 제곱해서 평균을 낸다.
```text
분산      s² = (1/n) Σ (xᵢ − x̄)²
표준편차  s  = √s²
```

분산은 단위가 제곱(ms²)이라 읽기 어렵다. 제곱근을 씌운 **표준편차**는 데이터와 단위가 같아서 "값들이 평균에서 보통 이 정도 떨어져 있다"로 읽을 수 있다. 여기서는 n으로 나눴지만, 데이터를 더 큰 집단에서 뽑은 표본으로 보고 그 집단의 분산을 추정할 때는 n−1로 나눈다. 그 이유는 3편 「추정량의 성질: 편향과 분산」에서 시뮬레이션으로 확인한다.

## 분위수와 사분위 범위
**분위수**는 데이터를 크기순으로 늘어놓고 일정 비율 지점에서 자른 값이다. 25% 지점을 1사분위수(Q1), 50% 지점을 2사분위수(Q2, 곧 중앙값), 75% 지점을 3사분위수(Q3)라 한다. 백분율로 부를 때는 50번째 백분위수를 p50, 99번째를 p99라고 쓴다.

**사분위 범위**(IQR)는 `Q3 − Q1`, 즉 가운데 50% 데이터가 차지하는 폭이다. 양 끝의 극단값을 아예 보지 않으므로 이상치에 강하다. 흔히 `Q1 − 1.5·IQR`보다 작거나 `Q3 + 1.5·IQR`보다 큰 값을 이상치 후보로 본다. 분위수를 계산하는 보간 방식은 여러 가지라서 도구마다 값이 조금씩 다를 수 있다. 실제로 아래 데이터의 Q1은 파이썬 `statistics.quantiles` 기본값으로 12.0, NumPy `np.percentile` 기본값으로 12.25가 나온다.

## 파이썬으로 확인하기
표준 라이브러리 `statistics` 모듈로 응답 시간 10개를 요약해 보자.
```python
import statistics as st

ms = [12, 15, 11, 14, 13, 15, 12, 16, 14, 15]   # 응답 시간(밀리초) 10개
print(st.mean(ms), st.median(ms), st.mode(ms))   # 평균, 중앙값, 최빈값
print(st.pvariance(ms), round(st.pstdev(ms), 2)) # 분산, 표준편차 (n으로 나눔)
print(st.quantiles(ms, n=4))                     # 사분위수 Q1, Q2, Q3

ms[-1] = 980                                     # 한 번은 타임아웃 직전까지 걸렸다
print(st.mean(ms), st.median(ms))                # 평균은 크게 흔들리고 중앙값은 그대로
```
```text
13.7 14.0 15
2.41 1.55
[12.0, 14.0, 15.0]
110.2 14.0
```

`pvariance`·`pstdev`는 n으로, `variance`·`stdev`는 n−1로 나눈다.

## 이상치 하나가 바꾸는 것
값 하나를 15에서 980으로 바꿨을 뿐인데 평균은 13.7에서 110.2로 여덟 배가 됐다. 반면 중앙값은 14.0 그대로다. 평균은 모든 값을 더하므로 극단값 하나가 전체를 끌고 가지만, 중앙값은 순서만 보므로 가장 큰 값이 얼마나 큰지는 상관하지 않는다. 퍼짐 쪽도 마찬가지로, 표준편차는 1.55에서 약 290으로 치솟지만 IQR은 3에서 3.25로 거의 변하지 않는다.

그렇다고 이상치를 지우는 것이 답은 아니다. 980ms짜리 요청은 실제로 누군가 겪은 느린 경험이다. 중요한 것은 요약값이 무엇을 숨기는지 알고 고르는 것이다.

## 응답 시간은 p50과 p99로 본다
응답 시간은 대부분 빠르고 가끔 아주 느린, 오른쪽으로 꼬리가 긴 분포를 따른다. 이런 데이터에서 평균은 "보통"도 "최악"도 아닌 애매한 값이 된다.
```python
import random
import statistics as st

random.seed(0)
# 대부분은 빠르고 가끔 아주 느린 요청이 섞인 응답 시간 10,000개 (로그 정규 분포)
ms = [random.lognormvariate(3, 0.6) for _ in range(10_000)]

cuts = st.quantiles(ms, n=100)        # 1%, 2%, …, 99% 지점 99개
print(f"평균 {st.mean(ms):.1f}  p50 {cuts[49]:.1f}  p99 {cuts[98]:.1f}  최대 {max(ms):.1f}")
```
```text
평균 24.1  p50 20.2  p99 81.0  최대 218.1
```

p50(20.2ms)은 "절반의 요청은 이보다 빠르다", p99(81.0ms)는 "100번 중 1번은 이보다 느리다"는 뜻이다. 평균 24.1ms만 보면 꼬리에 81ms를 넘는 요청이 100건이나 있다는 사실이 보이지 않는다. 화면 하나를 그리려고 요청을 10번 보낸다면 그중 하나라도 p99를 넘을 확률은 `1 − 0.99¹⁰ ≈ 9.6%`라서, 꼬리 지연은 생각보다 자주 사용자 눈에 띈다. 그래서 성능 지표는 보통 p50·p95·p99를 함께 본다.

## 정리
- 기술 통계는 데이터의 중심(평균, 중앙값, 최빈값)과 퍼짐(분산, 표준편차, IQR)을 숫자 몇 개로 요약한다.
- 평균과 표준편차는 극단값 하나에 크게 흔들리고, 중앙값과 IQR은 순서만 보므로 둔감하다.
- 꼬리가 긴 데이터(응답 시간 등)는 평균보다 p50·p99 같은 분위수로 보는 편이 실제 경험을 더 잘 드러낸다.
