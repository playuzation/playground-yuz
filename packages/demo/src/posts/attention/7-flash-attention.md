## GPU의 메모리 계층
GPU에는 크고 느린 메모리와 작고 빠른 메모리가 있다. FlashAttention 논문이 예로 든 A100의 수치는 다음과 같다.

| 메모리 | 크기 | 대역폭 |
|---|---|---|
| HBM(GPU 메모리) | 40~80GB | 1.5~2.0TB/s |
| SRAM(칩 안) | SM당 192KB × 108개 | 약 19TB/s |

SRAM은 HBM보다 10배쯤 빠르지만 다 합쳐도 20MB 남짓이다. 연산 장치는 SRAM과 레지스터에 올라온 데이터만 계산할 수 있으므로, 커널은 HBM에서 데이터를 가져와 계산하고 결과를 다시 HBM에 쓴다. 이 왕복이 느리면 연산 장치가 논다(AI 기초 4편의 메모리 대역폭 병목).

## 표준 구현은 메모리 바운드다
표준 어텐션은 단계마다 결과를 HBM에 쓴다. S = QKᵀ를 쓰고, S를 읽어 softmax로 만든 P를 쓰고, 다시 P를 읽어 PV를 계산한다. softmax는 원소마다 지수와 덧셈 몇 번뿐이라 연산은 적은데 n × n 행렬을 네 번 옮긴다.
```python
n, d, b = 8192, 128, 2                    # FP16/BF16은 2바이트
qkvo = 4 * n * d * b                      # Q, K, V 읽기 + O 쓰기
sp = 4 * n * n * b                        # S 쓰기·읽기, P 쓰기·읽기
print(f"Q·K·V·O {qkvo / 2**20:.0f} MiB, S·P 왕복 {sp / 2**20:.0f} MiB")
```
```text
Q·K·V·O 8 MiB, S·P 왕복 512 MiB
```

길이 8,192, 헤드 차원 128에서 꼭 필요한 입출력(Q, K, V, O)은 8MiB인데 S와 P의 왕복이 512MiB로 64배다. 여기에 헤드 수와 배치 크기가 곱해지고, 시간 대부분이 계산이 아니라 이동에 쓰인다. 역전파를 위해 P를 저장해 두면 메모리도 O(n²)이 든다.

## 타일링과 온라인 소프트맥스
**플래시 어텐션**(FlashAttention, Dao 등, 2022)은 Q, K, V를 SRAM에 들어가는 블록(타일)으로 잘라, 블록을 SRAM에 올린 채 점수 계산부터 softmax, V와의 곱까지 끝내고 최종 출력만 HBM에 쓴다. 어려운 점은 softmax다. 한 행의 softmax를 구하려면 그 행 전체의 최댓값과 지수 합을 알아야 하는데, 블록 단위로는 행의 일부만 보인다.

해결책은 **온라인 소프트맥스**(online softmax)다. 행마다 지금까지의 최댓값 m, 지수 합 ℓ, 정규화 전 출력 o를 들고 다니다가, 새 블록에서 더 큰 최댓값이 나오면 이전 값들에 `exp(m − m_new)`를 곱해 기준을 맞춘다.
```text
m_new = max(m, 새 블록의 행 최댓값)
ℓ ← exp(m − m_new)·ℓ + Σ exp(s − m_new)
o ← exp(m − m_new)·o + exp(s − m_new)·V_블록
끝나면 출력 = o / ℓ
```

`exp(s − m)·exp(m − m_new) = exp(s − m_new)`이므로 기준을 바꿔도 값이 정확히 보존된다. 근사가 아니라 덧셈 순서만 바꾼 같은 계산이다.
```python
import numpy as np

rng = np.random.default_rng(0)
n, d, B = 1000, 64, 128                   # 길이, 헤드 차원, 블록 크기
Q, K, V = (rng.normal(size=(n, d)) for _ in range(3))
scale = 1 / np.sqrt(d)

# 표준 구현: n×n 행렬 S와 P를 통째로 만든다
S = Q @ K.T * scale
P = np.exp(S - S.max(axis=1, keepdims=True))
ref = (P / P.sum(axis=1, keepdims=True)) @ V

# 타일링 + 온라인 소프트맥스: 블록 크기 B×B 행렬만 만든다
out = np.empty_like(Q)
for i in range(0, n, B):                  # 쿼리 블록 (SRAM에 올린다)
    q = Q[i:i + B]
    m = np.full(len(q), -np.inf)          # 지금까지의 행별 최댓값
    l = np.zeros(len(q))                  # 지금까지의 행별 지수 합
    o = np.zeros((len(q), d))             # 정규화 전 출력
    for j in range(0, n, B):              # 키·값 블록을 차례로
        s = q @ K[j:j + B].T * scale      # (B, B) 블록 점수
        m_new = np.maximum(m, s.max(axis=1))
        alpha = np.exp(m - m_new)         # 옛 기준을 새 기준으로
        p = np.exp(s - m_new[:, None])
        l = alpha * l + p.sum(axis=1)
        o = alpha[:, None] * o + p @ V[j:j + B]
        m = m_new
    out[i:i + B] = o / l[:, None]         # 마지막에 한 번 나눈다
print(np.abs(out - ref).max())
```
```text
3.0531133177191805e-16
```

블록 크기 128로 나눠 계산한 결과가 표준 구현과 3 × 10⁻¹⁶, 즉 FP64 반올림 오차 수준으로 같다. 길이 1000이 128로 나누어떨어지지 않아도 상관없다. 이 과정에서 만들어지는 가장 큰 중간 행렬은 128 × 128 블록이고, n × n 행렬은 어디에도 존재하지 않는다. 논문은 HBM 접근량이 표준 구현의 Θ(n·d + n²)에서 Θ(n²·d²/M)(M은 SRAM 크기)으로 줄어든다고 분석했다.

## 역전파: 저장 대신 재계산
역전파에는 P가 필요하다. 표준 구현은 n × n의 P를 저장해 두지만, 플래시 어텐션은 행마다 숫자 하나인 로그-합-지수(logsumexp) L = m + log ℓ만 저장하고, 역전파 때 블록별로 S를 다시 계산해 `P = exp(S − L)`로 복원한다.
```python
S = Q @ K.T * scale                       # 역전파 때 블록별로 다시 계산
mx = S.max(axis=1)
lse = mx + np.log(np.exp(S - mx[:, None]).sum(axis=1))  # 행마다 숫자 하나
P_re = np.exp(S - lse[:, None])           # 저장해 둔 lse만으로 복원
P_ref = np.exp(S - mx[:, None])
P_ref /= P_ref.sum(axis=1, keepdims=True)
print(np.abs(P_re - P_ref).max(), lse.shape)
```
```text
2.7755575615628914e-17 (1000,)
```

길이 1000짜리 벡터 하나로 1000 × 1000의 P를 정확히 복원했다. 행렬 곱을 한 번 더 하므로 FLOPs는 늘지만, HBM에서 n × n 행렬을 읽는 것보다 SRAM에서 다시 계산하는 편이 빨라서 전체로는 더 빠르다. 연산을 더 해서 메모리 이동을 줄이는, 메모리 계층을 아는 설계의 전형이다. 원 논문은 GPT-2(길이 1K) 학습이 기존 구현보다 약 3배 빨라졌다고 보고했다.

## FlashAttention-2와 3
- **FlashAttention-2**(Dao, 2023): 알고리즘은 같고 GPU 작업 분할을 고쳤다. 행렬 곱이 아닌 연산을 줄이고(위 코드처럼 ℓ로 나누기를 마지막에 한 번만), 배치·헤드뿐 아니라 시퀀스 길이 방향으로도 병렬화하고, 워프 사이의 일 분배를 바꿔 공유 메모리 통신을 줄였다. 논문은 FlashAttention보다 약 2배 빠르고 A100 이론 최대 FLOPs/s의 50~73%에 이른다고 보고했다.
- **FlashAttention-3**(Shah 등, 2024): H100(Hopper)의 비동기 기능을 활용한다. 데이터를 옮기는 워프와 계산하는 워프를 나누고(워프 특화), TMA로 복사와 텐서 코어 계산을 겹치며, 한 블록의 softmax를 다른 블록의 행렬 곱과 엇갈려 실행한다. FP8도 지원하는데, 블록별 양자화와 아다마르 변환으로 이상치를 퍼뜨려(incoherent processing) 오차를 줄인다. 논문은 H100에서 FP16 최대 약 740TFLOPS(이론치의 75%), FP8 약 1.2PFLOPS를 보고했다.

## 정리
- 플래시 어텐션은 근사가 아니라 정확한 어텐션이며, 결과가 표준 구현과 반올림 오차 수준으로 같다.
- 표준 구현은 n × n 행렬을 HBM에 여러 번 왕복해 메모리 바운드이고, 플래시 어텐션은 블록을 SRAM에 올린 채 끝까지 계산한다.
- 온라인 소프트맥스는 행별 최댓값 m과 합 ℓ을 갱신하며 exp(m − m_new)로 기준을 맞춰 블록 결과를 정확히 합친다.
- 역전파는 행별 로그-합-지수만 저장하고 P를 재계산해, 추가 메모리를 길이에 선형으로 줄이면서 더 빠르다.
