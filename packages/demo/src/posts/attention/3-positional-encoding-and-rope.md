## 어텐션은 순서를 모른다
1편의 식 `softmax(QKᵀ/√d)V`에는 위치를 뜻하는 항이 없다. 입력 토큰의 순서를 섞으면 출력도 똑같이 섞일 뿐 값은 그대로다. 이런 성질을 **순열 등변성**(permutation equivariance)이라 한다.
```python
import numpy as np

def softmax(x):
    e = np.exp(x - x.max(axis=-1, keepdims=True))
    return e / e.sum(axis=-1, keepdims=True)

def self_attn(X, Wq, Wk, Wv):
    Q, K, V = X @ Wq, X @ Wk, X @ Wv
    return softmax(Q @ K.T / np.sqrt(Q.shape[-1])) @ V

rng = np.random.default_rng(0)
n, d = 5, 8
Wq, Wk, Wv = (rng.normal(size=(d, d)) for _ in range(3))
X = rng.normal(size=(n, d))
perm = np.array([3, 0, 4, 1, 2])        # 토큰 순서를 섞는다
a = self_attn(X[perm], Wq, Wk, Wv)      # 섞은 뒤 어텐션
b = self_attn(X, Wq, Wk, Wv)[perm]      # 어텐션 뒤 섞기
print(np.allclose(a, b))
```
```text
True
```

"개가 사람을 물었다"와 "사람이 개를 물었다"는 같은 토큰들의 다른 배열이므로, 위치 정보가 없는 어텐션은 각 토큰에 대해 같은 결과를 낸다. 인과 마스크를 쓰는 디코더는 마스크 모양에서 위치를 어느 정도 스스로 알아낼 수 있지만(NoPE, 위치 인코딩 없음), 대부분의 모델은 위치 정보를 명시적으로 넣는다.

## 사인 위치 인코딩
원 트랜스포머는 위치 pos마다 정해진 벡터를 토큰 임베딩에 **더했다**.
```text
PE(pos, 2i)   = sin(pos / 10000^(2i/d))
PE(pos, 2i+1) = cos(pos / 10000^(2i/d))
```

차원 쌍 (2i, 2i+1)마다 속도가 다른 시계 바늘이 하나씩 있다고 보면 된다. 앞쪽 쌍은 빨리 돌고 뒤쪽 쌍은 천천히 돈다. 각 쌍이 (sin, cos)라서 위치가 k만큼 바뀌는 것은 그 쌍을 정해진 각도만큼 회전하는 것과 같고, 그래서 두 위치 벡터의 내적은 거리 p − q에만 의존한다.
```python
def sinusoidal(n_pos, d):
    pos = np.arange(n_pos)[:, None]
    w = 10000.0 ** (-np.arange(0, d, 2) / d)   # 주파수 d/2개
    pe = np.zeros((n_pos, d))
    pe[:, 0::2] = np.sin(pos * w)
    pe[:, 1::2] = np.cos(pos * w)
    return pe

pe = sinusoidal(600, 64)
for p, q in [(5, 3), (50, 48), (500, 498), (500, 400)]:
    print(p, q, round(pe[p] @ pe[q], 6))
```
```text
5 3 28.303862
50 48 28.303862
500 498 28.303862
500 400 17.874669
```

거리가 2인 쌍은 어디에 있든 내적이 같다. 하지만 이 벡터는 임베딩에 더해진 뒤 W_Q, W_K를 거치므로, 실제 q·k에는 내용과 위치가 뒤섞인 항이 생겨 상대 위치만 남는 성질이 그대로 유지되지 않는다.

## 학습 위치 임베딩
BERT와 GPT-2는 위치마다 학습되는 벡터 표(최대 길이 × d)를 두었다. 간단하고 잘 동작하지만 표의 크기가 곧 최대 길이(BERT 512, GPT-2 1024)라서, 학습 때 없던 위치로는 늘릴 수 없다.

## RoPE: 위치만큼 회전하기
**RoPE**(rotary position embedding, 회전 위치 임베딩, 2021)는 위치를 더하는 대신 쿼리와 키를 회전시킨다. 벡터를 2차원씩 쌍으로 묶고, i번째 쌍을 위치 m에 비례하는 각도 m·θᵢ만큼 돌린다.
```text
θᵢ = base^(−2i/d),  i = 0, 1, …, d/2 − 1
위치 m에서 i번째 쌍 (a, b)를 m·θᵢ만큼 회전:
  a′ = a·cos(mθᵢ) − b·sin(mθᵢ)
  b′ = a·sin(mθᵢ) + b·cos(mθᵢ)
```

회전 행렬 R은 전치가 곧 역행렬이고 두 회전을 합성하면 각도가 더해지므로, 위치 m의 쿼리와 위치 n의 키의 내적은 `(Rₘq)·(Rₙk) = q·R₍ₙ₋ₘ₎k`가 되어 두 위치의 차에만 의존한다. 회전은 W_Q, W_K를 거친 뒤에 적용하므로 사인 인코딩과 달리 이 성질이 실제 점수에 그대로 남는다. 값 V는 회전하지 않는다.
```python
def rope(x, pos, base=10000.0):
    d = x.shape[-1]
    theta = base ** (-np.arange(0, d, 2) / d)   # 쌍마다 회전 속도
    c, s = np.cos(pos * theta), np.sin(pos * theta)
    x1, x2 = x[0::2], x[1::2]                   # (짝수, 홀수) 차원 쌍
    out = np.empty_like(x)
    out[0::2] = x1 * c - x2 * s                 # 2차원 회전
    out[1::2] = x1 * s + x2 * c
    return out

q, k = rng.normal(size=64), rng.normal(size=64)
for m, n_ in [(3, 1), (10, 8), (1000, 998), (1000, 900)]:
    score = rope(q, m) @ rope(k, n_)
    print(f"m={m:4d} n={n_:3d} m−n={m - n_:3d}  q·k={score:.6f}")
print(round(np.linalg.norm(q), 6), round(np.linalg.norm(rope(q, 1000)), 6))
```
```text
m=   3 n=  1 m−n=  2  q·k=0.057740
m=  10 n=  8 m−n=  2  q·k=0.057740
m=1000 n=998 m−n=  2  q·k=0.057740
m=1000 n=900 m−n=100  q·k=-22.749792
9.282122 9.282122
```

거리가 2인 쌍은 위치가 (3, 1)이든 (1000, 998)이든 점수가 소수점 여섯째 자리까지 같고, 회전이라 벡터의 길이도 변하지 않는다. RoPE에는 학습할 파라미터가 없으며, 모델은 "얼마나 떨어져 있는가"를 점수에서 직접 읽는다. 위 코드는 (짝수, 홀수) 차원을 쌍으로 묶었지만, Hugging Face의 라마 구현처럼 앞 절반과 뒤 절반을 짝지어도 원리는 같다. 라마 3는 base(설정 이름 `rope_theta`)로 500,000을 쓴다.

## ALiBi 한 줄
ALiBi(Press 등, 2021)는 위치 벡터 없이 점수에 거리에 비례하는 벌점 −mₕ·(i − j)를 직접 더한다. 헤드마다 기울기 mₕ가 달라서 어떤 헤드는 가까운 토큰만, 어떤 헤드는 먼 토큰까지 본다.

## 문맥 길이 확장: 위치 보간, NTK, YaRN
RoPE의 쌍마다 한 바퀴 도는 데 걸리는 토큰 수(파장 2π/θᵢ)가 다르다. 파장이 학습 길이 L보다 긴 쌍은 학습 중에 한 바퀴도 돌지 못했으므로, L보다 먼 거리에서는 처음 보는 각도를 만나 성능이 무너진다.
```python
d, L = 128, 8192                         # 헤드 차원, 학습 길이
for base in [10000.0, 500000.0]:
    theta = base ** (-np.arange(0, d, 2) / d)
    wave = 2 * np.pi / theta             # 한 바퀴 도는 데 드는 토큰 수
    print(f"base={base:>8.0f}  파장 {wave.min():.1f} ~ {wave.max():,.0f}"
          f"  L보다 긴 쌍 {np.sum(wave > L)}/{d // 2}")
```
```text
base=   10000  파장 6.3 ~ 54,410  L보다 긴 쌍 14/64
base=  500000  파장 6.3 ~ 2,559,196  L보다 긴 쌍 29/64
```

헤드 차원 128 기준으로 base가 10,000이면 64쌍 중 14쌍이, 500,000이면 29쌍이 학습 길이 8192 안에서 한 바퀴를 다 돌지 못한다. 문맥을 늘리는 기법들은 결국 이런 저주파 쌍을 어떻게 다룰지의 문제다.
- **위치 보간**(position interpolation, Chen 등, 2023): 위치 m을 m·L/L′로 줄여, 늘린 길이 L′을 학습 때 본 각도 범위 안에 밀어 넣는다. 간단하지만 빨리 도는 고주파 쌍까지 촘촘해져 가까운 토큰끼리의 구분이 흐려진다.
- **NTK 방식**(NTK-aware scaling): 위치 대신 base를 키워서 고주파 쌍은 거의 그대로 두고 저주파 쌍만 크게 늘린다.
- **YaRN**(Peng 등, 2023): 파장이 L보다 훨씬 짧은 쌍은 그대로, L 이상인 쌍은 보간하고 그 사이는 섞는 식으로 주파수 대역마다 다르게 처리하며, 어텐션 점수에 온도 보정을 더한다. 적은 양의 추가 학습으로 문맥을 늘린다.

라마 3.1의 config.json을 보면 `rope_scaling`에 `factor` 8.0, `original_max_position_embeddings` 8192가 들어 있다. 주파수 대역별로 다르게 늘리는 비슷한 방식으로 8K 문맥을 128K로 확장한 것이다.

## 어디에 쓰이나
- 선형대수 4편 「선형 변환으로서의 행렬」: RoPE의 2×2 회전 행렬은 길이를 보존하는 선형 변환이고, 회전 두 번의 합성이 각도의 합이 되는 성질이 상대 위치 의존성을 만든다.
- 선형대수 9편 「직교성과 사영」: 회전 행렬은 직교 행렬이라 Rᵀ = R⁻¹이며, 덕분에 `(Rₘq)·(Rₙk)`가 `q·R₍ₙ₋ₘ₎k` 하나로 정리된다.
- 4편 「KV 캐시와 MQA·GQA·MLA」: 키는 RoPE로 회전된 상태로 캐시에 저장되며, MLA가 RoPE용 키를 따로 두는 이유도 이 회전에 있다.
- 오픈 웨이트 모델 5편 「config.json으로 모델 구조 읽기」: `rope_theta`와 `rope_scaling` 필드가 이 글의 base와 문맥 확장 설정이다.

## 정리
- 어텐션은 순열 등변이라 위치 정보를 따로 넣어야 한다.
- 사인 위치 인코딩과 학습 위치 임베딩은 위치 벡터를 임베딩에 더하며, 학습 임베딩은 표 크기를 넘어 늘릴 수 없다.
- RoPE는 쿼리와 키의 2차원 쌍을 위치 × θᵢ만큼 회전시켜, 내적이 상대 거리 m − n에만 의존하게 만든다.
- 학습 길이보다 파장이 긴 저주파 쌍이 문맥 확장의 핵심 문제이고, 위치 보간·NTK·YaRN은 이를 다루는 방식이 다르다.
