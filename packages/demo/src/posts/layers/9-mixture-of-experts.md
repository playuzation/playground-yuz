# [신경망 레이어 9/11] 전문가 혼합(MoE) 층

> **한 줄 요약** — 전문가 혼합(MoE) 층은 FFN을 여러 개(전문가) 두고 라우터가 토큰마다 상위 k개만 골라 계산하게 해서, 전체 파라미터는 전문가 수만큼 늘리면서 토큰당 계산은 k개 분량으로 묶어 두는 층이며, 라우팅이 한쪽으로 쏠리지 않게 하는 보조 손실과 용량 제한이 핵심 운영 장치다.

## 이 글에서 다루는 것
- 전문가와 라우터, top-k 선택과 게이트 가중치
- 전체 파라미터와 활성 파라미터
- 부하 불균형, 보조 손실, 용량
- 공유 전문가와 세분화 전문가
- NumPy 라우팅 시뮬레이션

## FFN을 여러 개 두고 일부만 쓴다
8편에서 본 대로 트랜스포머 파라미터의 대부분은 FFN에 있다. 모델을 키우면 성능이 좋아지지만, 밀집(dense) 모델은 파라미터를 늘린 만큼 토큰당 계산도 늘어난다. **전문가 혼합**(mixture of experts, MoE) 층은 이 둘을 떼어 놓는다. FFN 하나 대신 같은 모양의 FFN **전문가**(expert) N개를 두고, 작은 선형 층인 **라우터**(router)가 토큰마다 어느 전문가에게 보낼지 정한다.
```text
p = softmax(x W_r)            라우터 확률 (전문가 N개)
S = top-k(x W_r)              점수 상위 k개 전문가
y = Σ_{i∈S} gᵢ · Eᵢ(x)        g: 고른 k개의 점수를 다시 정규화
```

선택되지 않은 전문가는 계산하지 않는다. 그래서 전문가가 8개든 256개든, 토큰 하나가 쓰는 계산은 전문가 k개 분량이다. 게이트 가중치 g를 만드는 방식은 모델마다 조금씩 다르다. 믹스트랄은 고른 k개의 로짓에만 softmax를 걸고, Switch Transformer(2021)는 k = 1로 하나만 고르면서 그 전문가의 확률을 그대로 곱한다. 아이디어 자체는 2017년 샤지어 등이 LSTM 층 사이에 수많은 전문가를 넣은 연구로 대규모 언어 모델에 처음 들어왔고, GShard(2020)가 트랜스포머 FFN에 top-2 MoE를 적용했다.

## 전체 파라미터와 활성 파라미터
MoE 모델에는 숫자가 두 개 붙는다. **전체 파라미터**는 모든 전문가를 합한 크기로 메모리 요구량을 정하고, **활성 파라미터**는 토큰 하나가 실제로 거치는 크기로 계산량(AI 기초 4편의 토큰당 약 2N FLOPs의 N)을 정한다. 라마 3 8B 크기의 SwiGLU 전문가(층당 약 1.76억 개)로 계산해 보자.
```python
from math import comb

d, h = 4096, 14336                                # 8편의 라마 3 8B FFN 크기
expert = 3 * d * h                                # SwiGLU 전문가 하나
print(f"밀집 FFN 하나: {expert / 1e9:.2f}B")
for n, k, m in [(16, 2, 1), (64, 8, 4)]:          # m: 전문가 하나를 m조각으로
    e = expert // m
    print(f"{n}개 중 {k}개: 전체 {n * e / 1e9:.2f}B, 활성 {k * e / 1e9:.2f}B,",
          f"조합 {comb(n, k):,}가지")
```
```text
밀집 FFN 하나: 0.18B
16개 중 2개: 전체 2.82B, 활성 0.35B, 조합 120가지
64개 중 8개: 전체 2.82B, 활성 0.35B, 조합 4,426,165,368가지
```

전문가 16개 중 2개를 쓰면 층의 전체 파라미터는 28.2억 개인데 토큰당 활성 파라미터는 3.5억 개로 8분의 1이다. 둘째 줄은 아래에서 다룰 세분화 전문가다. 활성 파라미터가 계산을 정하지만 전문가는 모두 메모리에 올려 두어야 하므로, MoE는 "계산은 작은 모델처럼, 메모리는 큰 모델처럼" 든다는 점을 기억해야 한다. 실제 모델의 수치 비교는 오픈 웨이트 모델 3편에서 다룬다.

## 부하 불균형과 보조 손실
라우터를 그냥 학습시키면 쏠림이 생긴다. 초기에 조금 더 자주 뽑힌 전문가가 더 많이 학습되어 더 좋아지고, 그래서 더 자주 뽑히는 부익부 현상이다. 극단적으로는 몇 개 전문가만 일하고 나머지는 놀게 되어, 파라미터를 늘린 의미가 사라지고 일하는 전문가가 있는 GPU에 부하가 몰린다.

이를 막는 대표적인 장치가 Switch Transformer의 **보조 손실**(auxiliary loss)이다. 전문가 i가 실제로 받은 토큰 비율을 fᵢ, 라우터가 전문가 i에 준 평균 확률을 Pᵢ라 할 때 다음 항을 손실에 더한다.
```text
L_aux = α · N · Σᵢ fᵢ · Pᵢ          (Switch Transformer는 α = 10⁻²)
```

fᵢ는 개수를 센 값이라 미분할 수 없지만 Pᵢ는 미분할 수 있어서, 많이 배정된 전문가의 확률을 낮추는 방향으로 기울기가 흐른다. 완전히 균등하면 fᵢ = Pᵢ = 1/N이라 α를 뺀 값이 정확히 1이고, 쏠릴수록 커진다.

또 하나의 장치는 **용량**(capacity)이다. GPU에서 효율적으로 계산하려면 전문가마다 처리할 토큰 수의 상한을 미리 정해야 한다. 상한은 `용량 계수 × (토큰 수 × k / N)`이고, 상한을 넘은 토큰은 그 전문가의 계산을 건너뛰고 잔차 연결로만 다음 층에 넘어간다(토큰 드롭). 균형 잡힌 라우터와 두 전문가를 편애하는 라우터를 비교해 보자.
```python
import numpy as np

def softmax(z):
    e = np.exp(z - z.max(-1, keepdims=True))
    return e / e.sum(-1, keepdims=True)

def route(x, W_r, k, bias=0.0):
    logits = x @ W_r + bias                       # (토큰, 전문가)
    top = np.argsort(-logits, axis=-1)[:, :k]     # 점수 상위 k개 전문가
    gate = softmax(np.take_along_axis(logits, top, -1))  # 고른 k개끼리 정규화
    return softmax(logits), top, gate

rng = np.random.default_rng(0)
T, d, N, k = 4096, 64, 8, 2
x = rng.normal(size=(T, d))
W_r = rng.normal(0, 1 / np.sqrt(d), (d, N))       # 로짓 표준편차 약 1
skew = np.array([1.5, 1.0, 0, 0, 0, 0, 0, 0])    # 전문가 0·1을 편애하는 라우터

for name, bias in [("균형", 0.0), ("편중", skew)]:
    probs, top, gate = route(x, W_r, k, bias)
    f = np.bincount(top.ravel(), minlength=N) / (T * k)  # 실제 배정 비율
    P = probs.mean(0)                             # 평균 라우터 확률
    aux = N * np.sum(f * P)                       # Switch식 보조 손실(α 제외)
    cap = int(np.ceil(1.25 * T * k / N))          # 용량 계수 1.25
    dropped = np.maximum(np.bincount(top.ravel(), minlength=N) - cap, 0).sum()
    print(f"{name}: 배정 비율 {np.round(f, 3)}")
    print(f"      보조 손실 {aux:.3f}, 용량 {cap}, 넘친 배정 {dropped}개")
print("게이트 합:", gate.sum(-1)[:3])
```
```text
균형: 배정 비율 [0.11  0.128 0.115 0.125 0.127 0.132 0.135 0.128]
      보조 손실 1.002, 용량 1280, 넘친 배정 0개
편중: 배정 비율 [0.358 0.239 0.06  0.067 0.069 0.073 0.065 0.068]
      보조 손실 1.497, 용량 1280, 넘친 배정 2334개
게이트 합: [1. 1. 1.]
```

균형 잡힌 라우터는 배정 비율이 모두 1/8 = 0.125 근처이고 보조 손실은 1.00, 용량 1,280을 넘는 전문가가 없다. 편중된 라우터는 전문가 0과 1이 배정의 60%를 가져가고 보조 손실이 1.50으로 커지며, 배정 8,192건 중 2,334건(약 28%)이 용량을 넘쳐 계산되지 못한다. 보조 손실은 이 상태를 벌점으로 바꿔 라우터를 균형 쪽으로 밀고, 용량은 쏠림이 남아 있어도 계산 시간과 메모리를 예측 가능하게 묶어 둔다. 보조 손실이 너무 크면 품질을 해치기 때문에, 딥시크-V3는 보조 손실에 기대는 대신 전문가별 편향을 조절해 균형을 맞추는 방법을 썼다(오픈 웨이트 모델 3편).

## 공유 전문가와 세분화 전문가
딥시크MoE(2024)는 전문가 구성 자체를 바꾸는 두 가지 아이디어를 제안했고, 이후 많은 모델이 따랐다.
- **세분화 전문가**(fine-grained experts): 전문가 하나를 은닉 크기가 1/m인 작은 전문가 m개로 쪼개고, m배 많이 고른다. 위 계산의 둘째 줄처럼 전체·활성 파라미터는 그대로인데, 고를 수 있는 조합은 16개 중 2개(120가지)에서 64개 중 8개(약 44억 가지)로 늘어 토큰마다 훨씬 정교한 조합을 만들 수 있다.
- **공유 전문가**(shared experts): 라우팅과 상관없이 모든 토큰이 항상 거치는 전문가를 한두 개 둔다. 모든 토큰에 필요한 공통 지식을 공유 전문가가 맡으면, 라우팅되는 전문가들이 같은 지식을 중복해 배우지 않고 각자 전문화한다.

이 방향은 극단까지 가고 있다. 예를 들어 Qwen3-Next는 전문가 512개 중 10개를 고르고 공유 전문가 1개를 더한다.

## 정리
- MoE 층은 FFN 전문가 N개와 라우터로 이루어지고, 토큰마다 상위 k개 전문가의 출력을 게이트 가중치로 섞는다.
- 전체 파라미터(메모리)는 N에, 활성 파라미터(계산)는 k에 비례한다.
- 라우팅 쏠림은 보조 손실 `α·N·Σ fᵢ·Pᵢ`(α를 빼면 균등할 때 1)와 전문가별 용량으로 다스린다.
- 세분화 전문가는 같은 계산으로 조합의 수를 늘리고, 공유 전문가는 공통 지식을 맡아 나머지의 전문화를 돕는다.
