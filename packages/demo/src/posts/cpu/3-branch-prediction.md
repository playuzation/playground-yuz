# [CPU 마이크로아키텍처 3/12] 분기 예측: 2비트 카운터에서 gshare와 TAGE까지

> **한 줄 요약** — 깊은 파이프라인은 분기 결과를 알기 전에 다음 명령어를 계속 인출해야 하므로, 분기마다 포화 카운터를 두는 방식(스미스 1981)에서 주소와 전역 이력을 섞는 gshare(맥팔링 1993), 여러 길이의 이력 중 가장 긴 일치를 쓰는 TAGE(세즈넥 2006)로 정확도를 높여 왔고, 끝내 예측이 안 되는 분기는 조건부 이동으로 없앤다.

## 이 글에서 다루는 것
- 예측 실패 한 번의 값: 벌점 × 실패율
- 정적 예측, 1비트·2비트 포화 카운터
- 전역 이력과 gshare, TAGE의 아이디어
- 반복문·주기·상관·무작위 트레이스로 예측기별 적중률을 시뮬레이션하고 공식과 대조
- 분기 없는 코드: gcc가 만든 `cmov`

## 분기 하나가 비싼 이유
2편 「파이프라인 해저드: 포워딩과 스톨을 사이클 단위로」의 5단 파이프라인에서 뜀 분기는 2사이클을 버렸다. 실제 코어는 단계가 훨씬 많아서, 인텔은 Golden Cove의 예측 실패 벌점이 최소 17사이클이라고 밝혔다. 4폭 코어라면 실패 한 번에 μop 슬롯을 최대 68개(17 × 4) 버린다. 분기가 명령어 5개에 하나이고 그중 5%를 틀리면 CPI에 `0.2 × 0.05 × 17 = 0.17`이 더해지는데, 4폭 코어의 이상적인 CPI 0.25의 3분의 2다.

게다가 프런트엔드는 해독하기도 전에, 매 사이클 다음 인출 주소를 정해야 한다. 그래서 예측기는 세 가지를 맞힌다. 이 바이트 묶음에 분기가 있는가, 뛴다면 어디로 가는가(분기 목적지 버퍼 BTB, branch target buffer), 그리고 뛰는가 안 뛰는가다. 이 글은 마지막 방향 예측을 다룬다.

## 정적 예측과 포화 카운터
가장 단순한 것은 **정적 예측**이다. 늘 "뜀"으로 찍으면 반복문의 되돌아가는 분기를 대부분 맞힌다. "뒤로 가는 분기는 뜀, 앞으로 가는 분기는 안 뜀"(BTFN) 규칙도 같은 관찰에서 나왔다.

**동적 예측**은 분기 주소의 하위 비트로 표를 골라 과거 결과를 기억한다. 1비트 예측기는 지난번 결과를 그대로 다음 예측으로 쓴다. 반복문이라면 빠져나갈 때 한 번, 다음에 다시 들어와 첫 반복에서 또 한 번 틀린다. 짐 스미스가 1981년 ISCA 논문 「A Study of Branch Prediction Strategies」에서 분석한 **2비트 포화 카운터**는 0~3을 세고 2 이상이면 뜀으로 예측한다. 한 번 틀렸다고 바로 뒤집지 않으므로 반복문의 출구에서 한 번만 틀린다.
```text
   T→      T→      T→
 ┌───┐   ┌───┐   ┌───┐   ┌───┐
 │ 0 ├──→│ 1 ├──→│ 2 ├──→│ 3 │
 │ N │←──┤ N │←──┤ T │←──┤ T │
 └───┘   └───┘   └───┘   └───┘
      ←N      ←N      ←N
```
뜀(T)이면 오른쪽, 안 뜀(N)이면 왼쪽으로 한 칸 가고 양 끝에서 멈춘다. 아래 줄이 그 상태의 예측이다.

## 전역 이력과 gshare
분기끼리는 서로 얽혀 있다. `if (x > 0)`을 두 번 검사하면 두 번째 결과는 첫 번째와 같다. 분기 주소만 보는 카운터는 이것을 모른다. **전역 이력**(global history)은 최근 분기 h개의 결과를 비트로 이어 붙인 시프트 레지스터다. 이 이력으로 카운터를 고르면 "직전에 무슨 일이 있었나"에 따라 다른 카운터를 쓴다. 예와 패트가 1991년 이력으로 카운터 표를 고르는 2단계 적응 예측을 제안했고, 스콧 맥팔링은 1993년 DEC 기술 보고서 「Combining Branch Predictors」에서 분기 주소와 전역 이력을 XOR해 표 하나를 고르는 **gshare**를 제안했다. 같은 보고서는 성격이 다른 두 예측기 중 잘 맞는 쪽을 고르는 결합 예측기도 제안했다.

아래 시뮬레이터는 정적 예측, 1비트, 2비트, 그리고 12비트 이력의 gshare를 네 가지 트레이스에 돌린다. 트레이스는 (분기 주소, 뜀 여부)의 열이다. `loop`는 10번 도는 반복문을 1000번, `TTN`은 뜀·뜀·안 뜀이 되풀이되는 분기, `corr`는 무작위 분기 뒤에 같은 결과의 분기가 따라오는 경우, `rand`는 동전 던지기다.
```python
import random

class Static:                       # 정적 예측: 늘 "뜀"
    def predict(self, pc): return True
    def update(self, pc, t): pass

class Counter:  # n비트 포화 카운터 표. hist > 0이면 gshare(PC xor 전역 이력)
    def __init__(self, bits, hist=0, size=4096):
        self.top, self.size, self.hbits, self.h = 2**bits - 1, size, hist, 0
        self.t = [2**(bits - 1) - 1] * size     # 약하게 "안 뜀"에서 시작
    def i(self, pc): return (pc ^ self.h) % self.size
    def predict(self, pc): return self.t[self.i(pc)] > self.top // 2
    def update(self, pc, t):
        i = self.i(pc)
        self.t[i] = min(self.t[i] + 1, self.top) if t else max(self.t[i] - 1, 0)
        self.h = (self.h << 1 | t) & (2**self.hbits - 1)

def misses(pred, trace):            # 트레이스: (분기 주소, 뜀 여부)
    m = 0
    for pc, t in trace:
        m += pred.predict(pc) != t
        pred.update(pc, t)
    return m

rng = random.Random(3)
def loop(R, n=10):                  # n번 도는 반복문을 R번: T…TN
    return [(0x10, i < n - 1) for _ in range(R) for i in range(n)]
corr = []
for _ in range(5000):               # if (x > 0) …  if (x > 0) …
    t = rng.random() < 0.5
    corr += [(0x30, t), (0x34, t)]
traces = {"loop": loop(1000),
          "TTN": [(0x20, t) for _ in range(3000) for t in (1, 1, 0)],
          "corr": corr,
          "rand": [(0x40, rng.random() < 0.5) for _ in range(10000)]}
preds = {"static": lambda: Static(), "1bit": lambda: Counter(1),
         "2bit": lambda: Counter(2), "gshare": lambda: Counter(2, 12)}
print("trace  " + "".join(f"{p:>8}" for p in preds))
for name, tr in traces.items():
    acc = [1 - misses(mk(), tr) / len(tr) for mk in preds.values()]
    print(f"{name:7}" + "".join(f"{a:8.1%}" for a in acc))
```
```text
trace    static    1bit    2bit  gshare
loop      90.0%   80.0%   90.0%   99.8%
TTN       66.7%   33.3%   66.7%   99.9%
corr      51.0%   48.6%   49.9%   74.4%
rand      49.5%   49.3%   50.1%   50.0%
```

1비트는 반복문에서 출구와 재진입에 두 번씩 틀려 80%이고, 2비트는 출구에서만 틀려 90%다. `TTN`에서 1비트는 33.3%로 찍기만도 못하다. gshare는 이력에 "몇 번째 반복인가"와 "직전 분기가 어땠나"가 담겨 `loop`와 `TTN`을 거의 다 맞히고, `corr`에서는 두 번째 분기를 다 맞혀 75% 가까이 오른다. 첫 번째 분기와 `rand`는 정말 무작위라 어떤 예측기도 50%를 넘지 못한다.

## 공식과 대조하기
반복 횟수 n인 반복문을 R번 돌리면, 위 초기 상태에서 1비트는 정확히 2R번, 2비트는 R + 1번 틀려야 한다(2비트는 맨 처음 진입에서 한 번 더 틀린다). 또 이력이 0비트인 gshare는 2비트 카운터와 같은 예측기여야 한다. 앞 코드에 이어서 실행한다.
```python
ok = all(misses(Counter(1), loop(R, n)) == 2 * R and
         misses(Counter(2), loop(R, n)) == R + 1
         for R in (1, 7, 100) for n in (3, 10, 50))
print("반복문 공식(1비트 2R, 2비트 R + 1)과 일치:", ok)
print("gshare(이력 0비트) = 2비트:",
      all(misses(Counter(2, 0), tr) == misses(Counter(2), tr)
          for tr in traces.values()))
for h in (4, 8, 9):                 # 이력이 반복 횟수보다 짧으면?
    print(f"gshare 이력 {h:2}비트, loop 적중률",
          f"{1 - misses(Counter(2, h), traces['loop']) / 10000:.1%}")
```
```text
반복문 공식(1비트 2R, 2비트 R + 1)과 일치: True
gshare(이력 0비트) = 2비트: True
gshare 이력  4비트, loop 적중률 89.9%
gshare 이력  8비트, loop 적중률 79.8%
gshare 이력  9비트, loop 적중률 99.8%
```

마지막 세 줄이 이력 길이의 함정이다. 10번 도는 반복문의 9번째와 10번째 분기는 직전 8개 결과가 모두 "뜀"으로 같아서, 8비트 이력으로는 같은 카운터를 나눠 쓴다. 그 카운터는 뜀과 안 뜀을 번갈아 받으며 1과 2 사이를 오가고, 하필 두 번 다 틀려 2비트보다 못한 80%가 된다. 9비트가 되어야 직전 출구의 "안 뜀"이 이력에 들어와 둘이 갈린다.

## TAGE: 여러 길이의 이력을 함께
긴 이력은 먼 상관을 잡지만, 같은 분기가 이력마다 다른 칸을 쓰므로 표가 커야 하고 배우는 데 오래 걸린다. 짧은 이력은 빨리 배우지만 위처럼 패턴을 구별하지 못한다. 앙드레 세즈넥과 피에르 미쇼가 2006년 JILP에 발표한 **TAGE**(TAgged GEometric history length)는 둘을 함께 쓴다.
- 기본 예측기 하나(주소만 보는 카운터 표)와, 이력 길이가 등비수열로 늘어나는 표 여러 개를 둔다.
- 각 표는 주소와 그 길이만큼의 이력을 해시해 칸을 고르고, 칸마다 부분 태그를 저장해 "정말 이 분기, 이 이력의 기록인가"를 확인한다. 다른 상황이 같은 칸을 빌려 쓰는 별칭(aliasing)을 걸러 낸다.
- 태그가 맞는 표 가운데 가장 긴 이력의 표가 예측한다. 틀리면 더 긴 이력의 표에 새 칸을 배정한다.

현대 고성능 코어의 예측기는 TAGE 계열이나 퍼셉트론 계열을 바탕으로 한다고 알려져 있지만, 제조사는 세부 구조를 공개하지 않는다.

## 분기 없는 코드
예측기가 아무리 좋아도 데이터가 무작위면 50%다. 바이트 배열에서 128 이상인 값만 더하는 반복문의 분기를, 데이터가 무작위일 때와 정렬되었을 때 2비트 카운터로 돌려 보자. 앞 코드에 이어서 실행한다.
```python
data = [rng.randrange(256) for _ in range(20000)]
for name, d in (("무작위", data), ("정렬", sorted(data))):
    m = misses(Counter(2), [(0x50, x >= 128) for x in d])
    print(f"{name}: 실패 {m}번 ({m / len(d):.1%}),",   # 벌점 17사이클
          f"원소당 {m * 17 / len(d):.2f}사이클 손실")
```
```text
무작위: 실패 10081번 (50.4%), 원소당 8.57사이클 손실
정렬: 실패 2번 (0.0%), 원소당 0.00사이클 손실
```

벌점을 17사이클로 잡으면 무작위 데이터에서는 원소 하나에 평균 8.6사이클을 버린다. 원소당 일이 몇 사이클이면 끝나는 반복문에서 이것이 시간을 지배한다. 정렬하면 경계에서 두 번만 틀린다. 정렬할 수 없다면 분기를 없앤다. 이 C 함수를 gcc 13.3으로 컴파일했다(x86-64).
```c
long sum_big(const unsigned char *a, long n) {
    long s = 0;
    for (long i = 0; i < n; i++)
        if (a[i] >= 128)
            s += a[i];
    return s;
}
```
`-O2`가 만든 반복문 몸체(AT&T 문법, 탭은 공백으로 바꿨다)와, 같은 옵션에 `-fno-if-conversion -fno-if-conversion2`를 더해 조건부 이동 변환을 끈 결과다.
```asm
.L4:
    movzbl  (%rdi), %eax
    movq    %rax, %rcx
    addq    %rdx, %rax
    testb   %cl, %cl
    cmovs   %rax, %rdx
    addq    $1, %rdi
    cmpq    %rdi, %rsi
    jne     .L4
```
```asm
.L4:
    movzbl  (%rdi), %eax
    testb   %al, %al
    jns     .L3
    addq    %rax, %rdx
.L3:
    addq    $1, %rdi
    cmpq    %rdi, %rsi
    jne     .L4
```
기본 `-O2`는 `s + a[i]`를 늘 계산하고, `testb`로 최상위 비트(128 이상이면 1)를 본 뒤 `cmovs`로 부호 비트가 섰을 때만 s를 바꾼다. 데이터에 따라 뛰는 분기가 사라지고 반복문 끝의 `jne`만 남는데, 이것은 반복문 패턴이라 잘 맞는다. 변환을 끈 쪽은 `jns`가 데이터에 따라 뛰므로 무작위 입력에서 절반을 틀린다.

조건부 이동이 늘 이기는 것은 아니다. 제어 의존을 데이터 의존으로 바꾸므로 양쪽 값을 다 계산해야 하고, 결과가 조건을 기다린다. 잘 맞는 분기라면 분기 쪽이 빠를 수 있어서 컴파일러는 휴리스틱으로 고른다. 프로파일 기반 최적화(PGO)는 실제 분기 확률을 알려 이 선택을 돕는다. `__builtin_expect`나 C++20의 `[[likely]]`는 주로 코드 배치를 바꿀 뿐, 실행 중의 예측기를 바꾸지 않는다.

## 어디에 쓰이나
- 확률과 분포 12편 「마르코프 연쇄: 현재만 기억하는 확률 과정」: 분기 결과가 서로 독립이면 2비트 카운터는 상태 4개짜리 마르코프 연쇄이고, 전역 이력은 "현재 상태"에 과거 h개를 넣어 기억을 늘리는 방법이다.
- 알고리즘 기법 11편 「비트마스킹: 정수 하나로 집합 다루기」: 전역 이력 레지스터의 시프트·OR·마스크와 gshare의 XOR 색인이 그 글의 비트 연산 그대로다.
- 데이터베이스와 정렬 라이브러리: 분기 없는 비교·분할(branchless partition)과 술어를 마스크로 계산하는 벡터화 필터가 이 글의 조건부 이동 아이디어를 쓴다.

## 정리
- 예측 실패의 비용은 실패율 × 벌점이고, 벌점이 17사이클 수준인 깊은 파이프라인에서는 실패율 몇 %가 CPI를 크게 바꾼다.
- 2비트 포화 카운터는 반복문 출구에서만 틀리고(R + 1번, 공식과 일치), 전역 이력을 섞은 gshare는 패턴과 분기 간 상관을 잡아 `corr`에서 50%를 74%로 올렸다.
- 이력이 너무 짧으면 서로 다른 상황이 한 칸을 나눠 써 2비트보다 나빠질 수 있다. TAGE는 여러 길이의 태그 달린 표 중 가장 긴 일치를 써서 이를 피한다.
- 무작위 데이터의 분기는 정렬로 예측 가능하게 만들거나, `cmov` 같은 조건부 이동으로 없앤다.
