# [CPU 마이크로아키텍처 12/12] 전력과 클록: 동적 전력, DVFS, 터보, 이종 코어

> **한 줄 요약** — 동적 전력은 `α·C·V²·f`라서 전압과 주파수를 함께 낮추는 DVFS는 연산당 에너지를 크게 줄이지만 누설·나머지 전력 때문에 너무 느리면 오히려 손해이고, 터보는 평균 전력 한도가 허락하는 짧은 동안만 클록을 올리며, 데나드 스케일링이 끝난 뒤 칩은 모든 회로를 동시에 켜지 못해 큰 코어와 작은 코어를 섞는다.

## 이 글에서 다루는 것
- 동적 전력과 누설 전력, 연산당 에너지는 주파수와 무관하다는 사실
- DVFS: 전압·주파수 조합별 전력과 에너지, 에너지 최소점을 두 방법으로 찾기
- 터보: 긴 구간 전력 한도(PL1)와 짧은 구간 한도(PL2), 터보가 유지되는 시간을 닫힌 식과 대조
- 다크 실리콘과 이종 코어(big.LITTLE, P/E 코어), 코드가 할 일

## 전력이 한계가 된 이유
트랜지스터에서 자연어까지 7편 「빠르게 만드는 기술: 파이프라인, 캐시, 병렬성」에서 본 대로, 데나드 스케일링(1974) 시절에는 트랜지스터를 줄이면 전압도 함께 내려가 같은 면적의 전력이 그대로였다. 2000년대 중반 전압을 더 내리지 못하게 되자 클록을 올릴 때마다 전력 밀도가 커졌다. 그 뒤로 CPU 설계의 첫 제약은 트랜지스터 수가 아니라 **와트**다. 데스크톱은 냉각이, 노트북·휴대폰은 배터리와 표면 온도가, 데이터센터는 전기 요금이 한계를 정한다.

## 동적 전력과 누설 전력
```text
P_dyn  = α · C · V² · f
P_leak = V · I_leak
E/op   = α · C · V²
f_max  ∝ (V − Vt)^a / V
```
CMOS 게이트는 출력이 바뀔 때 부하 용량 C를 충전하고 방전한다. 한 번에 `C·V²`의 에너지가 들고, 사이클마다 바뀌는 비율이 α(활동률), 초당 사이클이 f다. 그래서 **연산 하나의 에너지는 `α·C·V²`로 주파수와 무관**하다. 같은 전압에서 클록만 낮추면 전력은 줄지만 일이 늦게 끝나 에너지는 그대로다. 에너지를 줄이려면 전압을 낮춰야 한다.

전압을 낮추면 트랜지스터가 느려진다. 문턱 전압 Vt에 가까울수록 전류가 줄어 최대 클록이 대략 `(V − Vt)^a / V`(알파 멱 법칙, a는 1~2 사이)로 떨어진다. 꺼져 있어도 흐르는 **누설 전류**도 있다. 누설 에너지는 켜져 있는 시간에 비례하므로 너무 천천히 돌면 쌓인다. 하드웨어는 쓰지 않는 블록의 클록을 끊어 α를 0으로 만들고(클록 게이팅), 오래 쉬는 코어는 전원을 끊어 누설까지 없앤다(파워 게이팅, C-state).

## DVFS: 전압과 주파수를 함께 낮추기
**DVFS**(dynamic voltage and frequency scaling)는 부하에 따라 전압·주파수 쌍(P-state)을 바꾼다. 4×10⁹ 사이클짜리 일을 여러 전압에서 처리할 때의 전력·시간·에너지를 계산해 본다. 상수는 1.2V·4GHz에서 동적 전력 40W가 되게 맞춘 설명용 값이다.
```python
VT, EXP_A = 0.35, 1.5             # 문턱 전압, 속도 공식의 지수 a
K = 4.0 * 1.2 / (1.2 - VT) ** EXP_A   # f(1.2V) = 4.0GHz가 되게
C = 40 / (1.2 ** 2 * 4.0)         # 동적 전력 40W @ 1.2V·4GHz
I_LEAK = 4.0                      # 누설 전류(A): P_leak = I·V
N = 4.0                           # 할 일: 4×10⁹ 사이클

def freq(v):                      # 최대 클록 ∝ (V − Vt)^a / V
    return K * (v - VT) ** EXP_A / v

def run(v, p_sys=0.0):            # p_sys: 깨어 있는 동안의 나머지 전력
    f = freq(v)
    p = C * v * v * f + I_LEAK * v + p_sys
    return f, p, N / f, p * N / f  # GHz, W, 초, 줄

print(" V    GHz    W     s     J")
for v in (1.2, 1.0, 0.8, 0.6, 0.5):
    print("{:.1f} {:5.2f} {:5.1f} {:5.2f} {:5.1f}".format(v, *run(v)))

def best_grid(p_sys):             # 0.001V 간격 전수 탐색
    return min((run(v / 1000, p_sys)[3], v / 1000)
               for v in range(400, 1201))[1]

def best_bisect(p_sys, h=1e-6):   # dE/dV = 0을 이분법으로
    lo, hi = 0.4, 1.2
    for _ in range(60):
        m = (lo + hi) / 2
        d = run(m + h, p_sys)[3] - run(m - h, p_sys)[3]
        lo, hi = (m, hi) if d < 0 else (lo, m)
    return lo

for p_sys in (0.0, 10.0):
    g, b = best_grid(p_sys), best_bisect(p_sys)
    print(f"나머지 {p_sys:4.1f}W: 최소 {g:.3f}V"
          f"(이분법 {b:.3f}V) {freq(g):.2f}GHz")
```
```text
 V    GHz    W     s     J
1.2  4.00  44.8  1.00  44.8
1.0  3.21  26.3  1.25  32.8
0.8  2.31  13.5  1.73  23.3
0.6  1.28   5.6  3.13  17.5
0.5  0.71   3.2  5.62  18.2
나머지  0.0W: 최소 0.558V(이분법 0.558V) 1.04GHz
나머지 10.0W: 최소 0.786V(이분법 0.786V) 2.24GHz
```

1.2V에서 0.6V로 내리면 클록은 3.1배 느려지는데 전력은 8배 준다. 일을 끝내는 데 드는 에너지는 44.8J에서 17.5J로 줄어든다. 그러나 0.5V까지 내리면 시간이 길어져 누설 에너지가 늘고 총에너지가 다시 오른다. 에너지가 가장 작은 전압이 따로 있다는 뜻이고, 0.001V 간격 전수 탐색과 도함수가 0인 점을 찾는 이분법이 같은 0.558V를 가리킨다.

메모리·I/O처럼 코어가 깨어 있는 동안 늘 드는 **나머지 전력**을 10W 넣으면 최적점이 0.786V, 2.24GHz로 올라간다. 오래 깨어 있을수록 이 전력이 쌓이기 때문이다. 시스템 전체 전력이 크면 빨리 끝내고 깊이 잠드는 편(race to idle)이 낫고, 코어 전력이 지배하면 천천히 도는 편이 낫다. 실제 칩에서는 운영체제가 정책을 주고 하드웨어가 P-state를 직접 고르는 방식(인텔 Speed Shift 등)이 늘었다.

## 터보: 한도 안에서 잠깐 더 빠르게
칩의 전력 한도는 대개 **평균**에 대한 것이다. 방열판과 칩에는 열용량이 있어 잠깐은 한도를 넘어도 온도가 바로 오르지 않는다. 인텔 **터보 부스트**는 2008년 Nehalem 기반 Core i7에서 시작해, 전력·전류·온도 한도 안에서 코어 클록을 기본보다 올린다. 요즘 인텔 칩은 긴 구간의 지수 가중 이동 평균 전력을 PL1 이하로, 짧은 구간의 전력을 PL2 이하로 제한한다(Core i9-12900K의 표기로 기본 전력 125W, 최대 터보 전력 241W). 이를 단순화해 모델로 만든다. 시간 상수 τ = 28초는 가정이다.
```python
import math

PL1, PL2 = 125.0, 241.0           # 긴 구간 한도, 짧은 구간 한도(W)
TAU, DT = 28.0, 0.01              # 평균의 시간 상수(가정), 시간 간격(초)

def turbo(seconds, start_avg=10.0):
    """평균 전력이 PL1에 닿을 때까지 PL2로, 그 뒤로는 PL1로 달린다.
    클록은 P^(1/3)에 비례한다고 본다(V ∝ f일 때 P ∝ f³)."""
    avg, work, t_switch = start_avg, 0.0, None
    a = 1 - math.exp(-DT / TAU)   # 지수 가중 이동 평균의 계수
    for k in range(int(seconds / DT)):
        p = PL2 if avg < PL1 else PL1
        if p == PL1 and t_switch is None:
            t_switch = k * DT
        avg += a * (p - avg)
        work += (p / PL1) ** (1 / 3) * DT  # PL1 클록에서 1초 = 일 1
    return t_switch, work

t_sim, _ = turbo(60)
t_formula = TAU * math.log((PL2 - 10.0) / (PL2 - PL1))  # 닫힌 식
print(f"PL2 유지: 시뮬레이션 {t_sim:.2f}초, 공식 {t_formula:.2f}초")
print(f"터보 클록 비: {(PL2 / PL1) ** (1 / 3):.3f}배")
for sec in (10, 120):
    print(f"{sec}초 동안 한 일: 터보 {turbo(sec)[1]:.1f}, PL1 고정 {sec}")
```
```text
PL2 유지: 시뮬레이션 19.29초, 공식 19.29초
터보 클록 비: 1.245배
10초 동안 한 일: 터보 12.4, PL1 고정 10
120초 동안 한 일: 터보 124.7, PL1 고정 120
```

평균이 `PL2 + (시작값 − PL2)·e^(−t/τ)`로 올라가므로 PL1에 닿는 시각은 `τ·ln((PL2 − 시작값)/(PL2 − PL1))`이고, 시뮬레이션이 이 닫힌 식과 맞는다. 전력이 1.93배여도 클록은 세제곱근인 1.245배만 오른다. 처음 10초 동안은 일을 24% 더 하지만, 2분 동안을 따지면 4% 더 할 뿐이다. 터보는 짧게 몰리는 대화형 작업을 위한 장치이고, 벤치마크를 짧게 돌리면 지속 성능보다 좋게 나오는 이유이기도 하다. 냉각이 나쁘면 온도 한도가 먼저 걸려 더 일찍 클록이 내려간다(열 스로틀링).

## 다크 실리콘과 이종 코어
전력 한도가 고정되면 트랜지스터가 늘어도 모두를 동시에 최고 클록으로 켤 수 없다. 에스마일자데(Esmaeilzadeh) 등은 2011년 ISCA 논문 「Dark Silicon and the End of Multicore Scaling」에서 같은 크기의 칩에서 꺼 두어야 하는 부분(**다크 실리콘**)이 세대마다 커져, 2024년까지 병렬 워크로드의 평균 속도 향상이 7.9배에 그친다고 예측했다. 남는 트랜지스터는 늘 켜 둘 코어 대신, 필요할 때만 켜는 특화 회로(미디어 엔진, 신경망 가속기)와 다른 성격의 코어에 쓰이게 되었다.

**이종 코어**는 같은 ISA를 실행하는 큰 코어와 작은 코어를 한 칩에 둔다. 큰 코어는 넓은 비순차 백엔드로 스레드 하나를 빠르게 하지만, 낮은 성능 구간에서는 단순한 작은 코어가 연산당 에너지가 적다. ARM의 big.LITTLE이 이 방식이고, 삼성 Exynos 5 Octa(2013)는 Cortex-A15 4개와 Cortex-A7 4개를 묶었다. 인텔은 Alder Lake(2021)에서 P 코어와 E 코어를 섞었고, 하드웨어가 스레드의 명령어 구성과 코어 상태를 운영체제에 알려 주는 Thread Director를 더했다.

코드에서 할 일도 여기서 나온다. 뒤에서 도는 작업에는 낮은 우선순위나 QoS를 주어 운영체제가 작은 코어와 낮은 P-state로 보내게 하고, 바쁜 대기(spin)보다 잠들기를 써서 코어가 C-state로 내려갈 틈을 준다. 성능을 잴 때는 터보와 온도의 영향을 생각해 충분히 길게, 여러 번 잰다.

## 어디에 쓰이나
- 트랜지스터에서 자연어까지 7편 「빠르게 만드는 기술: 파이프라인, 캐시, 병렬성」: 그 글의 데나드 스케일링 계산에서 전압을 못 내리면 전력 밀도가 세대마다 두 배가 되던 것이, 이 글의 DVFS·터보·다크 실리콘이 생긴 출발점이다.
- 게임 자원 관리 1편 「프레임 예산: 16.67ms 안에 모든 일을 끝내기」: 휴대폰 게임은 처음 몇 분의 터보 성능이 아니라 열 한도 아래의 지속 클록으로 프레임 예산을 잡아야 한다.
- 양자화 1편 「양자화의 기본: 실수를 정수 격자에 올리기」: 비트 수가 적은 연산은 바뀌는 트랜지스터가 적어 연산당 에너지 `α·C·V²`가 작으므로, 양자화는 메모리뿐 아니라 전력도 아낀다.

## 정리
- 동적 전력은 `α·C·V²·f`이고 연산당 에너지는 `α·C·V²`라서, 에너지를 줄이려면 클록이 아니라 전압을 낮춰야 한다.
- DVFS는 전압과 주파수를 함께 낮추지만, 누설과 나머지 전력 때문에 에너지가 최소인 지점이 있다(모델에서 0.558V, 나머지 전력 10W면 0.786V).
- 터보는 평균 전력 한도 안에서 잠깐 클록을 올린다. 짧은 일은 크게, 긴 일은 조금 빨라진다.
- 데나드 스케일링 이후 칩은 모든 회로를 동시에 켜지 못해, 특화 회로와 큰 코어·작은 코어를 섞고 운영체제가 일을 배치한다.
