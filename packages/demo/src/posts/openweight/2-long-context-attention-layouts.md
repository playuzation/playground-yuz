> **한 줄 요약** — 긴 문맥에서 KV 캐시와 어텐션 비용을 줄이려고 최근 모델들은 짧은 윈도만 보는 층과 전체 문맥을 보는 층을 정해진 비율로 섞으며, 미스트랄 7B(전부 윈도)부터 젬마 2(1 : 1), 젬마 3(5 : 1), gpt-oss(128토큰 윈도 + 싱크)까지 그 비율과 윈도 크기가 KV 캐시 크기를 결정한다.

## 출발점: 세 가지 마스크
1편의 라마 3 8B는 모든 층이 앞의 모든 토큰을 본다. 문맥이 n이면 층마다 KV 캐시가 n개씩 쌓이고, 새 토큰을 만들 때마다 n개 전부를 읽는다. 어텐션 5편 「슬라이딩 윈도와 희소 어텐션」의 슬라이딩 윈도는 각 토큰이 최근 w개만 보게 해서 층당 캐시를 w개로 묶는다. 이 글의 모델들은 이 아이디어를 "어느 층에, 얼마나" 쓰는지가 다르다. 먼저 마스크 세 가지를 그려 보자(■ = 볼 수 있음).
```python
import numpy as np

n, w = 8, 4
i, j = np.indices((n, n))
masks = {
    "전체(인과)": j <= i,
    "슬라이딩 w=4": (j <= i) & (i - j < w),
    "청크 c=4": (j <= i) & (i // w == j // w),
}
for name, m in masks.items():
    print(name, "→ 본 쌍", m.sum())
    for row in m:
        print("  " + "".join("■" if v else "·" for v in row))
```


전체 어텐션은 n(n + 1)/2쌍을 보지만, 윈도는 토큰마다 최대 w개만 본다. 청크는 같은 블록 안의 앞 토큰만 보므로 블록 경계 직후의 토큰(5행)이 자기 자신만 본다는 점이 윈도와 다르다.

## 미스트랄 7B: 모든 층이 윈도 4,096
미스트랄 7B(2023)는 라마형 블록(32층, d = 4,096, GQA 32 : 8)의 모든 층에 윈도 W = 4,096의 슬라이딩 윈도 어텐션을 썼다. 한 층에서는 4,096토큰 밖을 못 보지만 층을 거칠 때마다 정보가 윈도 하나만큼 더 멀리 전달되므로, 마지막 층의 이론적 시야는 4,096 × 32 ≈ 131K 토큰이다(어텐션 5편의 "w × 층"). 캐시는 **롤링 버퍼**(rolling buffer)로 관리한다. 위치 i의 키·값을 `i mod W`번 칸에 덮어써서, 문맥이 아무리 길어도 층당 W개만 남긴다.

## 젬마 2: 로컬과 글로벌을 한 층씩
젬마 2(2024)는 윈도 4,096의 로컬 층과 8,192토큰 전체를 보는 글로벌 층을 한 층씩 번갈아 쌓았다. 절반의 층이 여전히 모든 토큰을 보므로 먼 거리 정보를 직접 가져올 수 있다. 문맥 8K에서는 로컬 층의 캐시가 절반이므로 KV 캐시가 전부 글로벌일 때의 75%다.

젬마 2는 어텐션 점수와 최종 출력 로짓에 **소프트캡**(soft-capping) `cap · tanh(x / cap)`을 걸었다(어텐션 50, 최종 30). 작은 값은 거의 그대로 두고 큰 값은 ±cap 안으로 부드럽게 눌러 학습을 안정시킨다. 정규화는 서브층의 입력과 출력 양쪽에 RMSNorm을 둔다.

## 젬마 3: 로컬 5 : 글로벌 1, 윈도 1,024
젬마 3(2025)는 비율을 더 밀어붙였다. 로컬 층 5개마다 글로벌 층 1개를 두고(첫 층은 로컬), 로컬 윈도는 1,024로 줄였으며, 문맥은 128K(1B 모델은 32K)로 늘렸다. RoPE 기저는 글로벌 층만 100만으로 키우고 로컬 층은 1만으로 두어, 먼 거리를 담당하는 층에만 느린 회전을 준다. 젬마 2의 소프트캡은 **QK-Norm**으로 대체했다. 쿼리와 키를 정규화해 점수가 폭주하지 않게 하는 방식으로, 신경망 레이어 7편 「정규화 층: LayerNorm에서 RMSNorm까지」에서 다룬다.

## gpt-oss: 128토큰 윈도와 어텐션 싱크
OpenAI가 2025년 공개한 gpt-oss(120b, 20b)는 전체 어텐션 층과 윈도 128토큰의 띠(banded) 어텐션 층을 번갈아 쓴다. 윈도가 극단적으로 짧은 대신 절반의 층이 전체 문맥(128K)을 본다. GQA는 쿼리 64 : KV 8, 헤드 차원은 64다.

윈도가 이렇게 짧으면 어텐션 5편의 **어텐션 싱크**(attention sink) 문제가 두드러진다. 소프트맥스 가중치는 합이 1이어야 해서 볼 것이 없어도 어딘가에 가중치를 버려야 하는데, 그 자리 역할을 하던 첫 토큰들이 윈도 밖으로 밀려나기 때문이다. gpt-oss는 헤드마다 학습되는 싱크 로짓을 소프트맥스 분모에만 더해 "아무 데도 보지 않기"를 허용한다. 젬마 2의 소프트캡도 함께 계산해 보자.
```python
import numpy as np

s = np.array([2.0, 1.0, 0.5, -1.0])      # 한 쿼리의 어텐션 점수
def softmax(z):
    e = np.exp(z - z.max())
    return e / e.sum()

print(softmax(s).round(3), softmax(s).sum().round(3))
sink = 3.0                                # 헤드마다 학습되는 싱크 로짓
p = softmax(np.append(s, sink))[:-1]      # 분모에만 참여하고 버린다
print(p.round(3), p.sum().round(3))

cap = 50.0                                # 젬마 2의 어텐션 소프트캡
x = np.array([10.0, 50.0, 200.0])
print((cap * np.tanh(x / cap)).round(2))
```
```text
[0.609 0.224 0.136 0.03 ] 1.0
[0.229 0.084 0.051 0.011] 0.376
[ 9.87 38.08 49.97]
```

싱크가 확률의 일부를 가져가서 실제 토큰들의 가중치 합이 0.376이 되었다. 헤드가 가져올 정보가 없다고 판단하면 출력을 거의 0으로 만들 수 있다는 뜻이다. 소프트캡은 10을 9.87로 거의 그대로 두고 200은 49.97로 눌렀다.

## 라마 4: 청크 어텐션과 NoPE
라마 4(2025)는 다른 길을 택했다. vLLM 블로그와 공개 구현 설정에 따르면 4층 중 3층은 8,192토큰 단위로 끊은 **청크 어텐션**(위 그림의 청크 마스크, RoPE 사용)이고, 나머지 1층은 위치 인코딩 없이(NoPE) 전체 문맥을 본다. 청크는 블록 경계에서 시야가 리셋되는 대신, 블록마다 독립적으로 계산된다.

## KV 캐시 절감 계산
층 종류별로 저장할 토큰 수만 다르게 세면 된다. 로컬 층은 min(문맥, 윈도)개, 글로벌 층은 문맥 전체다. 모두 BF16(2바이트) 기준이다.
```python
def kv_gib(layers, kv, hd, ctx, window=None, nbytes=2):
    """layers: 층 종류 목록('full' 또는 'local')"""
    per_tok = 2 * kv * hd * nbytes                 # 한 층, 한 토큰의 K+V
    toks = [ctx if t == "full" else min(ctx, window) for t in layers]
    return per_tok * sum(toks) / 2**30

K32, K128 = 32 * 1024, 128 * 1024
# 미스트랄 7B: 32층 모두 윈도 4096, KV 헤드 8 × 128
print("미스트랄 전체", kv_gib(["full"] * 32, 8, 128, K32))
print("미스트랄 윈도", kv_gib(["local"] * 32, 8, 128, K32, 4096))
# 젬마 3 27B: 62층, 로컬 5 : 글로벌 1, 윈도 1024, KV 헤드 16 × 128
g3 = ["full" if (i + 1) % 6 == 0 else "local" for i in range(62)]
print("젬마3 글로벌 층 수", g3.count("full"))
print("젬마3 전부 글로벌", kv_gib(["full"] * 62, 16, 128, K128))
print("젬마3 5:1", round(kv_gib(g3, 16, 128, K128, 1024), 2))
# gpt-oss-120b: 36층, 윈도 128 층과 전체 층 교대, KV 헤드 8 × 64
go = ["local", "full"] * 18
print("gpt-oss 전부 전체", kv_gib(["full"] * 36, 8, 64, K128))
print("gpt-oss 교대", round(kv_gib(go, 8, 64, K128, 128), 3))
```
```text
미스트랄 전체 4.0
미스트랄 윈도 0.5
젬마3 글로벌 층 수 10
젬마3 전부 글로벌 62.0
젬마3 5:1 10.41
gpt-oss 전부 전체 9.0
gpt-oss 교대 4.504
```

| 모델 (문맥) | 배치 | 전부 전체 | 실제 |
|---|---|---|---|
| 미스트랄 7B (32K) | 전부 윈도 4K | 4.0 GiB | 0.5 GiB |
| 젬마 3 27B (128K) | 5 : 1, 윈도 1K | 62 GiB | 10.4 GiB |
| gpt-oss-120b (128K) | 1 : 1, 윈도 128 | 9.0 GiB | 4.5 GiB |

미스트랄은 32K 문맥에서 캐시가 8분의 1이 된다. 젬마 3 27B는 62층 중 글로벌 층이 10개뿐이라 약 6분의 1로 줄고, 로컬 층 52개의 몫은 416MiB에 불과하다. gpt-oss는 윈도 층의 캐시가 사실상 0이라 거의 정확히 절반이 된다. 여기에 GQA까지 겹치므로, 모든 층이 전체를 보는 MHA였을 때와 비교하면 젬마 3 27B는 약 12배, gpt-oss-120b는 약 16배 작다.

## 어디에 쓰이나
- AI 기초 4편 「컴퓨터 사이언스로 보는 AI 모델: 텐서, 연산, 메모리」: 어텐션의 `O(n²)` 비용과 KV 캐시 메모리 문제를, 윈도 층은 층당 연산 n·w와 캐시 w개로 묶어 해결한다.
- 어텐션 5편 「슬라이딩 윈도와 희소 어텐션」: 그 글의 로컬·글로벌 층 교대와 어텐션 싱크 개념이 이 글에서 미스트랄, 젬마, gpt-oss의 실제 배치로 나타난다.
- 어텐션 3편 「위치 정보: 사인 위치 인코딩에서 RoPE까지」: 젬마 3가 글로벌 층에만 큰 RoPE 기저(느린 회전)를 주는 것은 그 글의 회전 주파수 개념을 층 종류별로 나눠 쓴 것이고, 라마 4의 NoPE 층은 "어텐션은 순서를 모른다"는 성질을 일부러 남긴 층이다(순서 정보는 RoPE를 쓰는 다른 층과 인과 마스크에서 온다).

## 정리
- 윈도 층은 최근 w개만 저장해 캐시를 묶고, 글로벌 층은 먼 거리 검색을 맡는다. 모델마다 다른 것은 그 비율과 w다.
- 미스트랄 7B는 전부 윈도(4,096), 젬마 2는 1 : 1(4,096), 젬마 3는 5 : 1(1,024), gpt-oss는 1 : 1(128)이다.
- 소프트캡(젬마 2), QK-Norm(젬마 3), 학습되는 싱크 로짓(gpt-oss)은 어텐션 점수를 안정시키는 장치다.
- 128K 문맥에서 젬마 3 27B의 KV 캐시는 전부 글로벌일 때의 62GiB에서 10.4GiB로 준다.
