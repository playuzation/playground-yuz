# [오픈 웨이트 모델 3/5] MoE 모델: 믹스트랄, 딥시크-V3, Qwen3

> **한 줄 요약** — MoE 모델은 FFN을 여러 전문가로 나누고 토큰마다 몇 개만 골라 쓰므로 계산은 활성 파라미터만큼 들지만 메모리는 전체 파라미터만큼 필요하며, 믹스트랄(8개 중 2개)에서 딥시크-V3(256개 중 8개 + 공유 1개)와 Qwen3(128개 중 8개)로 오면서 전문가는 더 많고 잘게 나뉘었다.

## 이 글에서 다루는 것
- 믹스트랄 8x7B: 전체 46.7B, 활성 12.9B를 코드로 확인
- 딥시크-V3: 세분화·공유 전문가, MLA, 보조 손실 없는 부하 균형, MTP
- Qwen3 MoE와 gpt-oss·키미 K2까지 비교 표
- 활성 파라미터와 메모리 요구량의 차이

## 복습: MoE 층
전문가 혼합(MoE) 층은 FFN 여러 개(전문가)와 라우터로 이루어지고, 라우터가 토큰마다 점수가 높은 k개 전문가만 골라 그 출력을 가중합한다. 라우팅, 부하 불균형, 공유 전문가의 기본은 신경망 레이어 9편 「전문가 혼합(MoE) 층」에서 다뤘다. 이 글의 모델들은 1편의 라마형 블록에서 FFN만 MoE로 바꾼 것이라, 어텐션 쪽은 1~2편의 이야기가 그대로 적용된다.

## 믹스트랄 8x7B: 8개 중 2개
미스트랄 AI가 2023년 12월 공개한 믹스트랄 8x7B는 미스트랄 7B와 같은 크기의 블록(32층, d = 4,096, GQA 32 : 8)에서 FFN을 SwiGLU 전문가 8개로 바꾸고, 층마다 토큰당 2개를 고른다. 문맥은 32K다. 이름은 8 × 7B지만 전체가 56B보다 작은 이유는 어텐션과 임베딩은 복제하지 않기 때문이다.
```python
d, L, V, E, k = 4096, 32, 32000, 8, 2
attn = 2 * d * d + 2 * d * (8 * 128)      # Wq·Wo + Wk·Wv (KV 헤드 8 × 128)
expert = 3 * d * 14336                    # SwiGLU 전문가 하나
router = d * E
emb = 2 * V * d
total = L * (attn + E * expert + router) + emb
active = L * (attn + k * expert + router) + emb
print(f"전체 {total / 1e9:.2f}B, 활성 {active / 1e9:.2f}B")
print(f"전문가 몫 {L * E * expert / total:.1%}")
print(f"8 × 7.24B = {8 * 7.24:.1f}B (단순 곱)")
```
```text
전체 46.70B, 활성 12.88B
전문가 몫 96.6%
8 × 7.24B = 57.9B (단순 곱)
```

전문가 하나는 1편 라마 3의 FFN과 같은 d × 14,336 행렬 3개이고, 파라미터의 96.6%가 전문가에 있다. 토큰 하나는 그중 2개만 지나므로 계산량은 13B 모델 수준이다. 미스트랄 AI가 발표한 전체 46.7B, 활성 12.9B와 일치한다.

## 딥시크-V3: 671B 중 37B
딥시크(DeepSeek)가 2024년 12월 공개한 딥시크-V3는 전체 671B, 토큰당 활성 37B다. 61층 중 앞의 3층은 일반 FFN(은닉 18,432)이고 나머지 58층이 MoE다.
- 세분화·공유 전문가: 층마다 라우팅 전문가 256개 중 8개를 고르고, 모든 토큰이 지나는 공유 전문가 1개를 더한다. 전문가 하나의 은닉 크기는 2,048로 작다. 작은 전문가가 많을수록 조합이 다양해지고, 공통 지식은 공유 전문가가 맡는다.
- MLA: 키와 값을 저차원 잠재 벡터(층당 512차원 + RoPE용 64차원)로 압축해 캐시한다. 원리는 어텐션 4편 「KV 캐시와 MQA·GQA·MLA」에서 다룬다.
- 라우터: 전문가 친화도를 소프트맥스 대신 시그모이드로 구하고, 부하 균형을 보조 손실 대신 전문가별 편향으로 맞춘다(아래 실험). 한 시퀀스 안의 극단적 쏠림을 막는 아주 작은 보조 손실만 남겼다.
- MTP: 다음 토큰에 더해 그다음 토큰까지 예측하는 **다중 토큰 예측**(multi-token prediction) 모듈로 학습 신호를 늘린다. 추론 때는 떼어 내거나 추측 디코딩에 쓸 수 있다. 공개 체크포인트의 685B는 본체 671B에 MTP 모듈 14B를 더한 크기다.
- FP8 학습: 대부분의 행렬 곱을 FP8로 계산하는 혼합 정밀도로 학습했다.

**보조 손실 없는 부하 균형**은 이렇게 동작한다. 전문가마다 편향 bᵢ를 두고 top-k를 고를 때만 친화도에 더한다. 출력에 곱할 가중치는 원래 친화도로 계산한다. 스텝마다 과부하 전문가는 bᵢ를 γ만큼 내리고, 한가한 전문가는 올린다. 앞쪽 전문가가 인기가 많도록 일부러 기울인 라우터로 실험해 보자.
```python
import numpy as np

rng = np.random.default_rng(0)
E, K, T, d = 8, 2, 4096, 16
emb = rng.normal(size=(E, d))                # 전문가 중심 벡터
skew = np.linspace(1.0, -1.0, E)             # 앞쪽 전문가가 인기가 많다
b = np.zeros(E)                              # 라우팅 전용 편향
gamma = 0.01

def route(x, b):
    s = 1 / (1 + np.exp(-(x @ emb.T + skew)))    # 시그모이드 친화도
    top = np.argsort(-(s + b), axis=1)[:, :K]    # 선택에만 편향을 더함
    g = np.take_along_axis(s, top, 1)
    return top, g / g.sum(1, keepdims=True)      # 가중치는 원래 s로

for step in range(301):
    x = rng.normal(size=(T, d)) * 0.3
    top, g = route(x, b)
    load = np.bincount(top.ravel(), minlength=E) / (T * K / E)
    if step in (0, 300):
        print(step, load.round(2), "최대/평균", load.max().round(2))
    b -= gamma * np.sign(load - 1)               # 과부하면 내리고 한가하면 올림
print("편향", b.round(2))
```
```text
0 [2.16 1.7  1.44 1.04 0.96 0.32 0.33 0.06] 최대/평균 2.16
300 [0.93 0.99 1.04 1.05 0.98 1.07 1.02 0.91] 최대/평균 1.07
편향 [-0.2  -0.15 -0.15 -0.09 -0.06  0.05  0.09  0.2 ]
```

처음에는 가장 인기 있는 전문가가 평균의 2.16배를 받았지만, 편향이 인기 전문가를 깎고(−0.2) 한가한 전문가를 올려(+0.2) 300스텝 뒤에는 최대 부하가 평균의 1.07배가 되었다. 손실에 항을 더하지 않으므로 언어 모델링의 기울기를 건드리지 않는다는 것이 장점이다.

## Qwen3 MoE: 공유 전문가 없이 128개 중 8개
알리바바의 Qwen3(2025)는 밀집 모델과 함께 MoE 모델 Qwen3-235B-A22B와 Qwen3-30B-A3B를 냈다. 이름의 A22B가 활성 파라미터다. 235B 모델은 94층, GQA 64 : 4이고, 층마다 전문가 128개 중 8개를 고른다. 딥시크-V3와 달리 공유 전문가를 두지 않았고, 부하 균형 손실을 마이크로 배치가 아니라 전역 배치 단위로 계산해 전문가 특화를 덜 방해하도록 했다.

## 비교 표
| 모델 | 전체 / 활성 | 전문가 (선택) | 공유 |
|---|---|---|---|
| 믹스트랄 8x7B | 46.7B / 12.9B | 8 (2) | 없음 |
| 딥시크-V3 | 671B / 37B | 256 (8) | 1 |
| Qwen3-235B-A22B | 235B / 22B | 128 (8) | 없음 |
| gpt-oss-120b | 117B / 5.1B | 128 (4) | 없음 |
| 키미 K2 | 1T / 32B | 384 (8) | 1 |

공개된 설정 기준이다. 문샷 AI의 키미 K2(2025)는 딥시크-V3와 같은 61층·MLA 골격에서 전문가를 384개로 늘리고 어텐션 헤드를 128개에서 64개로 줄였다. 활성 비율은 믹스트랄이 27.6%인 데 비해 딥시크-V3 5.5%, Qwen3-235B 9.4%, gpt-oss-120b 4.4%, 키미 K2 3.2%로 훨씬 낮다. 전체 용량은 키우고 토큰당 계산은 묶어 두는 방향이다.

## 활성 파라미터 ≠ 메모리
계산량(FLOPs)은 활성 파라미터에 비례하지만, 어떤 토큰이 어떤 전문가를 고를지 미리 모르므로 가중치는 전부 메모리에 올려야 한다.
```python
GB = 1e9
models = {  # 이름: (전체, 활성, 저장 형식의 바이트 수)
    "Mixtral 8x7B (BF16)": (46.7e9, 12.9e9, 2),
    "DeepSeek-V3 (FP8)": (671e9, 37e9, 1),
    "Qwen3-235B-A22B (BF16)": (235e9, 22e9, 2),
}
for name, (tot, act, b) in models.items():
    print(f"{name:<23} 가중치 {tot * b / GB:>4.0f} GB,"
          f" 토큰당 읽기 {act * b / GB:>4.1f} GB")

# gpt-oss-120b: 전문가만 MXFP4(4비트 값 32개가 8비트 스케일 공유)
experts = 36 * 128 * 3 * 2880 * 2880           # 층 × 전문가 × 행렬 3개
attn = 2 * 2880 * (64 * 64) + 2 * 2880 * (8 * 64)  # Wq·Wo + Wk·Wv
rest = 36 * attn + 2 * 201088 * 2880           # 어텐션 + 임베딩(BF16)
size = experts * (4 + 8 / 32) / 8 + rest * 2
print(f"gpt-oss-120b 전문가 {experts / 1e9:.2f}B → 전체 {size / GB:.1f} GB")
```
```text
Mixtral 8x7B (BF16)     가중치   93 GB, 토큰당 읽기 25.8 GB
DeepSeek-V3 (FP8)       가중치  671 GB, 토큰당 읽기 37.0 GB
Qwen3-235B-A22B (BF16)  가중치  470 GB, 토큰당 읽기 44.0 GB
gpt-oss-120b 전문가 114.66B → 전체 65.1 GB
```

딥시크-V3는 한 바이트로 저장해도 671GB라 GPU 여러 대에 나눠 올려야 하지만, 요청 하나를 처리할 때 토큰마다 읽는 가중치는 37GB 정도다. AI 기초 4편의 "생성 속도 ≈ 대역폭 ÷ 읽는 양" 어림에서 분모가 전체가 아니라 활성 파라미터가 되는 셈이다. 다만 배치가 커지면 토큰마다 다른 전문가를 고르므로 결국 대부분의 전문가를 읽게 된다. gpt-oss-120b는 전체의 98%인 전문가 가중치만 MXFP4(값당 4.25비트)로 저장해 약 65GB가 되므로, 단일 80GB GPU에서 돌아간다는 OpenAI의 설명과 맞는다.

## 어디에 쓰이나
- AI 기초 4편 「컴퓨터 사이언스로 보는 AI 모델: 텐서, 연산, 메모리」: "가중치 메모리 = 파라미터 수 × 바이트 수"에는 전체 파라미터를, "토큰당 연산 ≈ 2 × 파라미터 수"에는 활성 파라미터를 넣어야 한다.
- 신경망 레이어 9편 「전문가 혼합(MoE) 층」: 그 글의 top-k 라우팅, 공유 전문가, 부하 불균형이 실제 모델에서 256개 중 8개, 공유 1개, 편향 조정 같은 구체적 선택으로 나타난다.
- 어텐션 4편 「KV 캐시와 MQA·GQA·MLA」: 딥시크-V3와 키미 K2는 MoE로 FFN 비용을, MLA로 KV 캐시를 함께 줄인다.

## 정리
- MoE 모델은 전체 파라미터만큼 메모리가, 활성 파라미터만큼 연산이 든다. 믹스트랄은 46.7B 중 12.9B, 딥시크-V3는 671B 중 37B를 쓴다.
- 딥시크-V3는 세분화 전문가 256개 + 공유 1개, MLA, 편향으로 맞추는 보조 손실 없는 부하 균형, MTP를 묶었다.
- Qwen3 MoE는 공유 전문가 없이 128개 중 8개를 고르고, 부하 균형 손실을 전역 배치로 계산한다.
- 전문가 수는 늘고 활성 비율은 낮아지는 추세이며, 저정밀 저장(FP8, MXFP4)이 큰 MoE를 적은 GPU에 올리는 열쇠다.
