# [언어 기초 3/6] 인터프리터 언어: 실행하면서 번역하기

> **한 줄 요약** — 인터프리터는 프로그램을 미리 기계어 실행 파일로 만들어 두지 않고 실행하는 순간에 해석해 동작시키며, 현대의 인터프리터는 대부분 바이트코드와 JIT 컴파일을 함께 쓴다.

## 인터프리터가 하는 일
컴파일러가 "책 한 권을 통째로 번역해 번역본을 건네주는 번역가"라면, 인터프리터는 "옆에서 한 문장씩 통역해 주는 통역사"에 가깝다. 번역본(실행 파일)이 따로 남지 않으므로, 프로그램을 실행할 때마다 인터프리터가 함께 있어야 한다.
```text
인터프리터 방식
  소스 코드 → [인터프리터: 해석하면서 바로 실행] → 결과

컴파일 방식
  소스 코드 → [컴파일러] → 실행 파일
  실행 파일 → (컴파일러 없이) 실행 → 결과
```

## 구현 방식 세 가지
### 1. 트리 순회 인터프리터
소스 코드를 파싱해 **추상 구문 트리**(AST)를 만들고, 트리의 노드를 하나씩 방문하면서 바로 계산한다. 구현이 가장 단순해서 교육용 언어나 설정 언어에서 많이 쓴다. 아래는 파이썬으로 만든 아주 작은 계산기 인터프리터다.
```python
# 식 (1 + 2) * 3 을 나타내는 AST
tree = ("*", ("+", 1, 2), 3)

def evaluate(node):
    if isinstance(node, int):       # 숫자는 그 자체가 값
        return node
    op, left, right = node          # 연산자 노드는 양쪽을 먼저 계산
    a, b = evaluate(left), evaluate(right)
    return a + b if op == "+" else a * b

print(evaluate(tree))  # 9
```

### 2. 바이트코드 가상 머신
소스를 먼저 **바이트코드**라는 중간 명령어로 컴파일한 뒤, **가상 머신**(VM)이 이 명령을 하나씩 꺼내 실행한다. 트리를 따라 내려가는 것보다 빠르고, 바이트코드를 캐시해 두면 다음 실행 때 파싱을 건너뛸 수 있다. CPython, 루비(YARV), 루아가 이 방식이다.

바이트코드 VM의 핵심은 "명령 꺼내기 → 해석 → 실행"을 반복하는 루프다. 위와 같은 식 `(1 + 2) * 3`을 스택 기반 바이트코드로 바꾸면 다음과 같다.
```python
code = [("PUSH", 1), ("PUSH", 2), ("ADD", None), ("PUSH", 3), ("MUL", None), ("PRINT", None)]
stack = []

for op, arg in code:
    if op == "PUSH":
        stack.append(arg)
    elif op == "ADD":
        b, a = stack.pop(), stack.pop()
        stack.append(a + b)
    elif op == "MUL":
        b, a = stack.pop(), stack.pop()
        stack.append(a * b)
    elif op == "PRINT":
        print(stack.pop())  # 9
```

### 3. JIT(Just-In-Time) 컴파일
실행 중에 **자주 실행되는 코드(핫스팟)를 찾아 그 자리에서 기계어로 컴파일**한다. 처음에는 인터프리터로 실행하다가, 충분히 많이 호출된 함수만 최적화된 기계어로 바꿔 속도를 끌어올린다. 자바스크립트의 V8, 자바의 HotSpot JVM, 파이썬의 PyPy가 대표적이다.

## 컴파일 방식과 비교
| 항목 | 인터프리터 방식 | 컴파일 방식 |
|---|---|---|
| 번역 시점 | 실행하는 동안 | 실행 전에 한 번 |
| 배포하는 것 | 소스 코드나 바이트코드 | 플랫폼별 실행 파일 |
| 수정 후 실행까지 | 바로 실행 | 빌드를 거쳐야 함 |
| 실행 속도 | 대체로 느림 (JIT로 격차를 줄임) | 대체로 빠름 |
| 오류 발견 | 해당 코드가 실행될 때 | 상당수를 컴파일할 때 |
| 이식성 | 인터프리터만 있으면 어디서나 | 플랫폼마다 다시 빌드 |

## 장점과 단점
**장점**
- 고치고 바로 실행할 수 있어 실험과 학습이 빠르다. 한 줄씩 입력해 결과를 보는 REPL이 대표적이다.
- 실행 중에 코드를 만들어 실행하거나(`eval`) 객체의 구조를 바꾸는 등 동적인 기능을 제공하기 쉽다.
- 같은 소스를 여러 운영체제에서 그대로 실행할 수 있다.

**단점**
- 해석하는 비용이 들어 같은 일을 하는 기계어보다 느리다.
- 실행 환경에 인터프리터가 설치되어 있어야 한다.
- 오타나 타입 오류가 그 줄이 실제로 실행될 때까지 드러나지 않을 수 있다.

## 흔한 오해
- **"인터프리터 언어는 컴파일을 안 한다"** — 대부분 바이트코드로 컴파일한다. 차이는 기계어 실행 파일을 미리 만들어 배포하느냐에 있다.
- **"인터프리터 언어는 무조건 느리다"** — JIT를 쓰는 V8은 계산이 반복되는 코드에서 컴파일 언어에 꽤 가까운 성능을 낸다. 다만 시작 직후나 매우 동적인 코드에서는 여전히 손해를 본다.
- **"언어마다 실행 방식이 정해져 있다"** — 같은 파이썬도 CPython(바이트코드 VM)과 PyPy(JIT)처럼 구현에 따라 실행 방식이 다르다.

## 정리
- 인터프리터는 실행 시점에 프로그램을 해석해 동작시킨다.
- 현대 인터프리터는 트리 순회보다 바이트코드 VM과 JIT를 주로 쓴다.
- 빠른 개발 주기와 이식성을 얻는 대신, 실행 속도와 실행 환경 의존성을 내준다.
