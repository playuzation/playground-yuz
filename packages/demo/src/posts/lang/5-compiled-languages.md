## 컴파일러의 단계
컴파일러는 보통 **프런트엔드 → 중간 표현(IR) → 백엔드** 구조로 되어 있다.
```text
소스 코드
   ↓  프런트엔드: 어휘 분석 → 구문 분석 → 의미 분석
중간 표현 (IR)
   ↓  최적화
   ↓  백엔드: 코드 생성
목적 파일 (.o)
   ↓  링커
실행 파일
```

1. **어휘 분석(lexing)**: `int x = 1 + 2;`를 `int`, `x`, `=`, `1`, `+`, `2`, `;` 같은 토큰으로 자른다.
2. **구문 분석(parsing)**: 토큰의 나열을 문법에 맞춰 구문 트리(AST)로 만든다. 괄호 짝이 맞지 않는 등의 문법 오류는 여기서 걸린다.
3. **의미 분석**: 선언되지 않은 변수나 타입이 맞지 않는 연산을 찾아낸다.
4. **최적화**: 동작은 그대로 두고 더 빠르거나 작은 코드로 바꾼다.
5. **코드 생성**: 대상 CPU(x86-64, ARM64 등)의 기계어를 만든다.

LLVM 같은 공용 백엔드 덕분에 언어를 만드는 사람은 프런트엔드만 작성해도 여러 CPU용 기계어를 얻을 수 있다. Clang(C/C++), rustc(Rust), Swift가 모두 LLVM을 백엔드로 쓴다. 마지막의 링크 단계는 6편에서 따로 다룬다.

## 정적 타입 검사: 실행 전에 잡히는 오류
Go로 작성한 다음 프로그램은 정수를 받는 함수에 문자열을 넘기고 있다.
```go
package main

import "fmt"

func square(n int) int { return n * n }

func main() {
	fmt.Println(square("5"))
}
```
```text
./main.go:8:21: cannot use "5" (untyped string constant) as int value in argument to square
```

이 프로그램은 **한 번도 실행되지 않고** 빌드 단계에서 거부된다. 파이썬이었다면 그 줄이 실행되는 순간에야 오류가 났을 것이다(2편 참고). 테스트로 모든 경로를 실행해 보지 않아도 이런 종류의 실수가 전부 걸러진다는 것이 정적 타입 컴파일 언어의 큰 장점이다.

## 최적화: 컴파일러가 대신 고쳐 주는 코드
컴파일러는 프로그램 전체를 미리 볼 수 있기 때문에 사람이 일일이 하기 어려운 최적화를 해 준다. 1편에서 본 "1부터 10까지 더하기"를 C 함수로 만들어 보자.
```c
int sum_to_10(void) {
    int total = 0;
    for (int i = 1; i <= 10; i++) {
        total += i;
    }
    return total;
}
```

`gcc -O2`로 컴파일하면 반복문이 통째로 사라지고 결과값만 남는다.
```asm
sum_to_10:
    mov  eax, 55
    ret
```

반복문을 실행할 때마다 돌리는 대신, 컴파일할 때 답을 미리 계산해 버린 것이다(**상수 접기**). 이 밖에도 함수 호출을 본문으로 바꿔 넣는 **인라이닝**, 쓰이지 않는 코드를 지우는 **죽은 코드 제거**, 여러 데이터를 한 번에 처리하는 **벡터화** 같은 최적화가 자동으로 일어난다.

## AOT와 JIT, 그리고 크로스 컴파일
- **AOT(Ahead-Of-Time)**: 실행 전에 미리 컴파일한다. C, C++, Rust, Go가 일반적으로 이 방식이다.
- **JIT(Just-In-Time)**: 실행 중에 컴파일한다. 자바와 C#은 먼저 바이트코드로 컴파일해 배포하고, 실행할 때 JVM이나 .NET 런타임이 자주 쓰이는 코드를 다시 기계어로 컴파일한다(3편 참고).
- **크로스 컴파일**: 지금 쓰는 컴퓨터와 다른 CPU·운영체제용 실행 파일을 만든다. 예를 들어 Go는 `GOOS=linux GOARCH=arm64 go build` 한 줄로 맥에서 리눅스 ARM64용 실행 파일을 만든다.

## 장점과 단점
| 장점 | 단점 |
|---|---|
| 기계어로 바로 실행되어 빠르다 | 고칠 때마다 빌드를 기다려야 한다 |
| 타입 오류 등 많은 실수를 실행 전에 잡는다 | 운영체제·CPU마다 따로 빌드해야 한다 |
| 실행 파일만 배포하면 되는 경우가 많다 | 실행 중에 코드를 바꾸는 동적 기능이 제한적이다 |

## 대표적인 컴파일 언어
- **C**: 1972년에 등장한 시스템 프로그래밍의 기준. 운영체제와 임베디드 분야의 공용어다.
- **C++**: C에 객체지향과 템플릿을 더한 언어. 게임 엔진, 브라우저, 고성능 서버에 쓰인다.
- **Go**: 단순한 문법, 빠른 컴파일, 가벼운 동시성(goroutine). 클라우드 인프라 도구에 많이 쓰인다.
- **Rust**: 메모리 안전성을 컴파일 시점에 보장한다(4편 참고).

## 정리
- 컴파일러는 어휘·구문·의미 분석, 최적화, 코드 생성을 거쳐 기계어를 만든다.
- 실행 전에 프로그램 전체를 보기 때문에 오류를 미리 잡고 강력한 최적화를 할 수 있다.
- 대신 빌드 시간과 플랫폼별 빌드라는 비용을 치른다.
