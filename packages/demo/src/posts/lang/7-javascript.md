## 표준, 엔진, 호스트 환경
"자바스크립트"라는 말은 사실 세 가지를 함께 가리킨다.
- **ECMAScript**: 문법과 기본 동작을 정한 표준 명세. TC39 위원회가 매년 개정한다.
- **엔진**: 명세를 구현해 실제로 코드를 실행하는 프로그램. V8, SpiderMonkey 등이 있다.
- **호스트 환경**: 엔진을 품고 추가 기능(API)을 제공하는 쪽. 브라우저는 `document`와 `fetch`를, Node.js는 파일 시스템과 네트워크 API를 제공한다.

`document.querySelector`나 `setTimeout`은 언어의 일부가 아니라 호스트 환경이 제공하는 API다. 그래서 같은 자바스크립트라도 브라우저와 Node.js에서 쓸 수 있는 기능이 다르다.

## 브라우저 안에서 일어나는 일
브라우저는 HTML을 읽어 **DOM**(문서 객체 모델)이라는 트리를 만들고, `<script>`를 만나면 엔진에게 코드를 넘긴다. 자바스크립트는 DOM을 읽고 고쳐서 화면을 바꾼다.
```html
<button id="like">♥ 0</button>
<script>
  let count = 0;
  const button = document.querySelector('#like');
  button.addEventListener('click', () => {
    count += 1;
    button.textContent = `♥ ${count}`;
  });
</script>
```

엔진 안에서는 3편 「인터프리터 언어」에서 본 방식이 그대로 쓰인다. V8은 소스를 파싱해 바이트코드를 만들고 인터프리터(Ignition)로 실행하다가, 자주 실행되는 함수를 최적화 컴파일러(TurboFan)로 기계어로 바꾼다. 그 사이를 잇는 중간 단계 컴파일러도 있어, 코드가 "뜨거워질수록" 점점 더 빠른 형태로 실행된다.

## 이벤트 루프: 스레드 하나로 기다리지 않기
자바스크립트 코드는 기본적으로 **스레드 하나**에서 실행된다. 그런데도 네트워크 응답을 기다리는 동안 화면이 멈추지 않는 것은 **이벤트 루프** 덕분이다. 오래 걸리는 일은 호스트 환경에 맡기고, 결과가 준비되면 콜백이 **작업 큐**에 들어간다. 이벤트 루프는 지금 실행 중인 코드가 끝날 때마다 큐에서 다음 작업을 꺼내 실행한다.
```js
console.log('1. 시작');
setTimeout(() => console.log('4. 타이머 콜백'), 0);
Promise.resolve().then(() => console.log('3. 프로미스 콜백'));
console.log('2. 끝');
```
```text
1. 시작
2. 끝
3. 프로미스 콜백
4. 타이머 콜백
```

지연 시간을 0으로 줘도 타이머 콜백은 지금 코드가 다 끝난 뒤에 실행된다. 또 프로미스 콜백(마이크로태스크)은 타이머 같은 일반 작업보다 먼저 처리된다. `async`/`await`는 이 프로미스를 동기 코드처럼 읽히게 쓰는 문법이다.
```js
async function loadTitles() {
  const res = await fetch('/api/posts');   // 기다리는 동안 다른 작업을 처리한다
  const { posts } = await res.json();
  return posts.map((p) => p.title);
}
```

## 브라우저 밖으로: Node.js
2009년 라이언 달(Ryan Dahl)은 V8 엔진에 파일·네트워크 API와 이벤트 루프를 붙여 **Node.js**를 만들었다. 덕분에 같은 언어로 서버와 명령줄 도구를 작성할 수 있게 되었다. 지금 보고 있는 이 플랫폼의 서버도 Node.js에서 동작한다.
```js
// server.mjs — 실행: node server.mjs
import { createServer } from 'node:http';

createServer((req, res) => {
  res.end('Hello from Node.js');
}).listen(3000);
```

## npm: 패키지 생태계
**npm**은 Node.js와 함께 설치되는 패키지 매니저이자, 세계에서 가장 큰 공개 패키지 저장소(레지스트리)다. 프로젝트가 의존하는 패키지는 `package.json`에 적는다.
```json
{
  "name": "my-app",
  "type": "module",
  "scripts": {
    "test": "node --test"
  },
  "dependencies": {
    "markdown-it": "^15.0.0"
  }
}
```
- `npm install`: `package.json`의 패키지를 `node_modules/`에 설치하고, 실제로 설치된 정확한 버전을 `package-lock.json`에 기록한다.
- `npm ci`: lock 파일과 똑같은 버전으로 설치한다. CI처럼 재현성이 중요한 곳에서 쓴다.
- `npm run test`: `scripts`에 정의한 명령을 실행한다.
- `^15.0.0`: **유의적 버전**(SemVer) 범위. 15.0.0 이상 16.0.0 미만의 최신 버전을 허용한다는 뜻이다.

의존성이 쉽게 불어난다는 점은 주의해야 한다. 패키지 하나가 수십 개의 하위 패키지를 끌고 오기도 하고, 2016년 `left-pad` 사건처럼 작은 패키지 하나가 사라져 수많은 빌드가 깨지거나, 악성 코드가 섞인 패키지가 배포되는 공급망 공격도 일어난다. lock 파일을 커밋하고 꼭 필요한 패키지만 쓰는 습관이 중요하다.

## 타입스크립트
**타입스크립트**는 자바스크립트에 정적 타입을 더한 언어다. 컴파일러(`tsc`)가 타입을 검사한 뒤 타입 정보를 지운 자바스크립트를 만들어 내므로, 실제로 실행되는 것은 결국 자바스크립트다.
```ts
function likeCount(post: { likes: number }): string {
  return `♥ ${post.likes}`;
}

likeCount({ likes: '3' });
```
```text
like.ts(5,13): error TS2322: Type 'string' is not assignable to type 'number'.
```

2편에서 본 파이썬의 타입 힌트와 비슷한 역할이지만, 타입스크립트는 검사를 통과하지 못하면 빌드 단계에서 멈춘다는 점이 다르다. 최근에는 Node.js도 타입 정보만 지우고 `.ts` 파일을 바로 실행할 수 있어서, 이 플랫폼의 서버 코드도 별도 빌드 없이 그렇게 실행된다.

## 장점과 단점
| 장점 | 단점 |
|---|---|
| 모든 브라우저에 들어 있어 설치 없이 실행된다 | 암묵적 형변환 같은 역사적 특이점이 많다 (`[] + {}`의 결과는 `"[object Object]"`) |
| 프런트엔드와 백엔드를 한 언어로 작성할 수 있다 | 의존성이 쉽게 불어나고 공급망 위험이 있다 |
| npm 생태계가 거대하다 | 스레드 하나라서 CPU를 오래 쓰는 작업에 불리하다 (Web Worker 등으로 보완) |
| JIT 엔진 덕분에 동적 언어치고 빠르다 | 번들러·트랜스파일러 같은 도구 설정이 복잡해지기 쉽다 |

## 정리
- 자바스크립트는 ECMAScript 표준을 엔진이 구현하고, 브라우저나 Node.js 같은 호스트 환경이 API를 더해 동작한다.
- 스레드 하나와 이벤트 루프로, 기다리는 작업이 있어도 막히지 않고 다음 일을 처리한다.
- npm은 거대한 생태계를 주지만 lock 파일과 의존성 관리가 필수다.
