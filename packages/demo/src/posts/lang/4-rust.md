## 러스트가 풀려는 문제
C와 C++은 빠르지만, 해제한 메모리를 다시 쓰거나(use-after-free), 같은 메모리를 두 번 해제하거나, 여러 스레드가 동시에 같은 데이터를 고치는(데이터 경쟁) 실수를 컴파일러가 막아 주지 못한다. 마이크로소프트와 구글 크롬 팀은 자사 제품에서 발견된 심각한 보안 취약점의 약 70%가 이런 메모리 안전성 문제라고 발표한 바 있다.

자바나 파이썬은 **가비지 컬렉터**(GC)로 이 문제를 피하지만, GC는 실행 중에 추가 비용과 예측하기 어려운 멈춤을 만든다. 러스트는 **GC 없이, 컴파일 시점의 규칙 검사만으로** 메모리 안전성을 보장하는 길을 택했다.

## 소유권: 값의 주인은 하나
러스트의 모든 값에는 **주인(owner)인 변수가 정확히 하나** 있다. 주인이 스코프를 벗어나면 값은 자동으로 해제된다. 값을 다른 변수에 대입하면 소유권이 **이동**(move)하고, 원래 변수는 더 이상 쓸 수 없다.
```rust
fn main() {
    let a = String::from("안녕");
    let b = a;             // 소유권이 a에서 b로 이동
    println!("{}", a);     // 컴파일 오류: a는 이미 이동됨
}
```
```text
error[E0382]: borrow of moved value: `a`
```

이 규칙 덕분에 "누가 메모리를 해제할 책임이 있는가"가 항상 분명하고, 같은 메모리를 두 번 해제하는 일이 원천적으로 일어나지 않는다.

## 빌림: 소유권 없이 잠깐 쓰기
값을 넘기지 않고 참조(`&`)로 **빌려줄** 수도 있다. 빌림에는 핵심 규칙이 하나 있다.

> 어느 시점이든 **불변 참조(`&T`) 여러 개** 또는 **가변 참조(`&mut T`) 하나** 중 한쪽만 가질 수 있다.

```rust
fn total_len(words: &[String]) -> usize {
    words.iter().map(|w| w.len()).sum()   // 빌려서 읽기만 한다
}

fn shout(words: &mut [String]) {
    for w in words.iter_mut() {
        w.push('!');                      // 가변으로 빌려서 수정한다
    }
}

fn main() {
    let mut words = vec![String::from("hello"), String::from("rust")];
    shout(&mut words);
    println!("{:?} {}", words, total_len(&words)); // ["hello!", "rust!"] 11
}
```

"읽는 쪽이 여럿이면 아무도 고치지 못하고, 고치는 쪽은 혼자여야 한다"는 뜻이다. 컴파일러의 **빌림 검사기**(borrow checker)가 이 규칙을 확인하기 때문에, 반복 중에 컬렉션을 수정하는 단일 스레드 버그부터 멀티스레드의 데이터 경쟁까지 같은 원리로 막힌다.

**수명**(lifetime)은 "참조가 가리키는 값보다 참조가 더 오래 살아남지 않는다"는 것을 컴파일러가 확인하기 위한 개념이다. 대부분은 컴파일러가 알아서 추론하므로 처음에는 이 정도만 알아 두면 충분하다.

## 예외 대신 Result
러스트는 복구 가능한 오류를 예외가 아니라 **값**으로 다룬다. 실패할 수 있는 함수는 `Result<T, E>`를 돌려주고, 호출하는 쪽은 성공과 실패를 모두 처리해야 컴파일된다. `?` 연산자는 오류를 만나면 그 자리에서 호출자에게 돌려준다. 복구할 수 없는 상황은 `panic!`으로 프로그램을 멈춘다.
```rust
use std::num::ParseIntError;

fn parse_and_double(input: &str) -> Result<i32, ParseIntError> {
    let n: i32 = input.trim().parse()?;   // 실패하면 여기서 Err를 반환
    Ok(n * 2)
}

fn main() {
    match parse_and_double("21") {
        Ok(v) => println!("결과: {v}"),   // 결과: 42
        Err(e) => println!("오류: {e}"),
    }
}
```

## 도구: cargo
러스트는 빌드 도구이자 패키지 매니저인 **cargo**를 기본으로 제공한다. 라이브러리(크레이트)는 crates.io에서 받아 쓰고, 코드 포매터 rustfmt와 린터 clippy도 공식 도구로 함께 쓴다.
```sh
cargo new hello          # 새 프로젝트 만들기
cd hello
cargo run                # 빌드하고 실행
cargo test               # 테스트 실행
cargo build --release    # 최적화 빌드
```

## 장점과 단점
| 장점 | 단점 |
|---|---|
| C·C++에 가까운 성능, GC로 인한 멈춤이 없다 | 소유권·빌림 개념 때문에 학습 곡선이 가파르다 |
| 메모리 오류와 데이터 경쟁을 컴파일 시점에 막는다 | 컴파일 시간이 긴 편이다 |
| cargo, rustfmt, clippy 등 공식 도구가 일관되고 강력하다 | C·C++에 비해 생태계와 기존 코드 자산이 아직 작다 |

꼭 필요한 경우에는 `unsafe` 블록 안에서 컴파일러 대신 개발자가 안전성을 책임지고 하드웨어나 C 라이브러리를 직접 다룰 수 있다. 위험한 코드가 `unsafe`로 표시되어 있으므로 검토할 범위가 좁아진다.

## 어울리는 분야
- **운영체제·드라이버**: 리눅스 커널이 6.1부터 러스트 지원을 받아들였다.
- **CLI 도구**: ripgrep, fd, bat처럼 빠른 명령줄 도구
- **웹 서버·네트워크**: tokio 기반의 비동기 서버
- **WebAssembly**: 브라우저에서 실행되는 고성능 모듈

## 정리
- 러스트는 소유권과 빌림 규칙을 컴파일 시점에 검사해 GC 없이 메모리 안전성을 보장한다.
- 오류는 예외 대신 `Result`로 다루어, 처리하지 않은 실패를 컴파일러가 잡아낸다.
- 배우기는 어렵지만, 컴파일을 통과한 코드에서는 많은 종류의 버그가 이미 사라져 있다.
