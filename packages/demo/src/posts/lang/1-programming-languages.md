# [언어 기초 1/8] 프로그래밍 언어란 무엇인가

> **한 줄 요약** — 프로그래밍 언어는 사람이 이해할 수 있는 형태로 컴퓨터에게 일을 시키기 위한 약속이며, 어떤 언어로 쓰든 결국 CPU가 실행하는 기계어로 바뀌어야 동작한다.

## 이 글에서 다루는 것
- 프로그래밍 언어가 필요한 이유
- 같은 일을 여러 추상화 수준에서 표현해 보기
- 언어를 분류하는 네 가지 기준
- 언어를 고를 때 따져 볼 것

## 왜 프로그래밍 언어가 필요한가
CPU가 직접 이해하는 것은 0과 1로 된 **기계어**(machine code)뿐이다. 기계어는 "레지스터에 5를 넣어라", "메모리의 값을 더하라"처럼 아주 작은 단위의 명령으로 이루어져 있어서, 사람이 큰 프로그램을 기계어로 직접 쓰는 것은 사실상 불가능하다.

프로그래밍 언어는 이 간극을 메우는 도구다. 사람은 `total = price * count`처럼 의미가 드러나는 코드를 쓰고, 컴파일러나 인터프리터 같은 **언어 처리기**가 이를 기계가 실행할 수 있는 형태로 바꾼다.

## 같은 일, 다른 수준의 표현
"1부터 10까지 더하기"를 세 가지 수준의 언어로 써 보면 차이가 분명해진다.

**파이썬** — 고수준. 의도만 적으면 된다.
```python
print(sum(range(1, 11)))  # 55
```

**C** — 중간 수준. 변수와 반복을 직접 다룬다.
```c
int total = 0;
for (int i = 1; i <= 10; i++) {
    total += i;
}
```

**x86-64 어셈블리** — 저수준. CPU 명령을 하나하나 지시한다.
```asm
    xor  eax, eax      ; total = 0
    mov  ecx, 1        ; i = 1
again:
    add  eax, ecx      ; total += i
    inc  ecx           ; i++
    cmp  ecx, 10
    jle  again         ; i <= 10 이면 반복
```

추상화 수준이 높을수록 읽고 쓰기 쉽고, 낮을수록 하드웨어를 세밀하게 제어할 수 있다. 어느 쪽이 "더 좋은" 것이 아니라 목적에 맞게 고르는 것이다.

## 언어를 나누는 네 가지 기준
| 기준 | 질문 | 예시 |
|---|---|---|
| 추상화 수준 | 하드웨어에 얼마나 가까운가? | 어셈블리(저) · C(중) · 파이썬(고) |
| 실행 방식 | 미리 번역하는가, 실행하면서 번역하는가? | 컴파일(C, Rust) · 인터프리트(Python, Ruby) |
| 패러다임 | 프로그램을 어떤 모양으로 짜는가? | 절차형 · 객체지향 · 함수형 |
| 타입 시스템 | 타입을 언제, 얼마나 엄격하게 검사하는가? | 정적(Rust, Java) · 동적(Python, JavaScript) |

표를 읽을 때 주의할 점이 있다.
- **실행 방식은 언어가 아니라 구현의 성질이다.** 파이썬도 바이트코드로 컴파일한 뒤 가상 머신에서 실행하고, 자바스크립트 엔진은 실행 중에 기계어로 컴파일(JIT)한다. "컴파일 언어", "인터프리터 언어"는 대표적인 구현 방식을 가리키는 편의상의 표현이다.
- **패러다임은 섞어 쓴다.** 파이썬과 러스트는 모두 절차형, 객체지향, 함수형 스타일을 함께 지원한다.
- **정적/동적과 강한/약한은 다른 축이다.** 파이썬은 동적 타입이지만 `"1" + 1`을 허용하지 않는 강한 타입 언어다.

## 언어는 어떻게 고르나
- **무엇을 만들 것인가**: 운영체제·드라이버는 C나 Rust, 데이터 분석·자동화는 파이썬, 웹 프런트엔드는 자바스크립트·타입스크립트가 사실상의 표준이다.
- **성능과 생산성 중 무엇이 급한가**: 실행 속도가 중요하면 컴파일 언어, 빠른 실험과 개발이 중요하면 인터프리터 언어가 유리한 경우가 많다.
- **생태계와 팀**: 라이브러리, 도구, 커뮤니티, 그리고 팀이 이미 익숙한 언어가 실제로는 가장 큰 결정 요인이 되기도 한다.

## 정리
- CPU는 기계어만 실행하며, 프로그래밍 언어는 사람과 기계 사이의 번역 가능한 약속이다.
- 언어는 추상화 수준, 실행 방식, 패러다임, 타입 시스템으로 나누어 볼 수 있다.
- "컴파일 언어/인터프리터 언어"는 언어 자체보다 구현 방식에 대한 분류다.
