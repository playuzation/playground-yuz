# [수학·기하 알고리즘 1/12] 유클리드 호제법과 확장 유클리드: 모듈러 역원 구하기

> **한 줄 요약** — `gcd(a, b) = gcd(b, a mod b)`를 반복하는 유클리드 호제법은 많아야 수의 자릿수에 비례하는 단계로 끝나고, 같은 과정을 거꾸로 따라가면 `ax + by = gcd(a, b)`의 정수해가 나와 나머지 세계의 나눗셈인 모듈러 역원까지 O(log m)에 구할 수 있다.

## 이 글에서 다루는 것
- 유클리드 호제법이 맞는 이유와 단계 수(최악은 연속한 피보나치 수)
- 확장 유클리드 알고리즘: 베주 계수 x, y 찾기
- 일차 부정방정식 `ax + by = c`의 해 판정과 모든 해
- 모듈러 역원과 파이썬 `pow(a, -1, m)`, 무작위 대조 검사

## 예제 문제: 나머지 세계에서 나누기
"답이 매우 크므로 1,000,000,007로 나눈 나머지를 출력하라"는 문제는 흔하다. 덧셈·뺄셈·곱셈은 중간에 언제 나머지를 취해도 된다는 것을 이산수학 12편 「수 체계와 모듈러 연산: 2진수에서 해시까지」에서 보았다. 그런데 나눗셈은 그렇지 않다. `(12 / 4) mod 7 = 3`이지만 `(12 mod 7) / (4 mod 7) = 5 / 4`는 정수조차 아니다. 그래서 "b로 나누기"를 "b를 곱하면 1이 되는 수를 곱하기"로 바꾼다. 이 수가 **모듈러 역원**(modular inverse)이다. 작은 예로 법 40에서 7의 역원 x, 즉 `7x ≡ 1 (mod 40)`인 x를 찾아보자.

가장 단순한 방법은 x = 0, 1, …, 39를 모두 넣어 보는 것이다. 답은 23이다(7 × 23 = 161 = 4 × 40 + 1). 하지만 법이 10⁹ + 7이면 10억 번을 시도해야 하고, 그런 나눗셈이 문제 하나에 수십만 번 나온다. 핵심은 `7x ≡ 1 (mod 40)`이 "어떤 정수 y에 대해 `7x + 40y = 1`"과 같은 말이라는 점이다. 이 방정식은 최대공약수를 구하는 2,300년 된 알고리즘을 조금 고치면 풀린다.

## 유클리드 호제법
**유클리드 호제법**(Euclidean algorithm)은 기원전 300년 무렵 유클리드의 『원론』 7권에 실린, 기록으로 남은 가장 오래된 알고리즘 가운데 하나다. 규칙은 하나다.
```text
gcd(a, b) = gcd(b, a mod b)
gcd(a, 0) = a
```
맞는 이유는 공약수 집합이 그대로이기 때문이다. `a = qb + r`일 때 d가 a와 b를 나누면 `r = a − qb`도 나누고, 거꾸로 d가 b와 r을 나누면 `a = qb + r`도 나눈다. 두 쌍의 공약수가 정확히 같으니 최대공약수도 같다. 그리고 나머지는 매번 줄어드므로 언젠가 0이 된다.

얼마나 빨리 끝날까? 단계 수를 세어 a ≤ n인 모든 쌍에서 가장 오래 걸리는 쌍을 찾아보자.
```python
def gcd_steps(a, b):
    steps = 0
    while b:
        a, b = b, a % b          # gcd(a, b) = gcd(b, a mod b)
        steps += 1
    return a, steps

print(gcd_steps(1071, 462))      # 1071 = 3²·7·17, 462 = 2·3·7·11

for n in (10, 100, 1000):
    best = max((gcd_steps(a, b)[1], a, b)
               for a in range(1, n + 1) for b in range(1, a))
    print(n, "최대 단계", best[0], "쌍", best[1:])
```
```text
(21, 3)
10 최대 단계 4 쌍 (8, 5)
100 최대 단계 9 쌍 (89, 55)
1000 최대 단계 14 쌍 (987, 610)
```
최악의 쌍은 모두 연속한 피보나치 수다. 피보나치 쌍에서는 몫이 매번 1이라 `(F(k+1), F(k)) → (F(k), F(k−1))`처럼 한 칸씩만 줄어들기 때문이다. 1844년 라메(Gabriel Lamé)는 k단계가 걸리는 가장 작은 쌍이 `(F(k+2), F(k+1))`임을 보였고, 피보나치 수는 황금비 φ ≈ 1.618의 거듭제곱으로 자라므로 단계 수는 `log_φ n`, 즉 작은 수의 10진 자릿수의 약 5배를 넘지 않는다. 직관적으로는 `a mod b < a/2`라서 두 단계마다 수가 절반 아래로 준다고 보면 된다. 피보나치 점화식 자체는 이산수학 4편 「수학적 귀납법과 재귀」에서 다뤘다.

## 확장 유클리드: 계수까지 구하기
**확장 유클리드 알고리즘**(extended Euclidean algorithm)은 g = gcd(a, b)와 함께 `ax + by = g`를 만족하는 정수 x, y를 찾는다. 이런 x, y가 항상 있다는 사실을 **베주 항등식**(Bézout's identity)이라 한다. 손으로는 호제법의 나눗셈을 적은 다음 아래에서부터 거꾸로 대입한다.
```text
40 = 5·7 + 5    →  5 = 40 − 5·7
 7 = 1·5 + 2    →  2 = 7 − 1·5
 5 = 2·2 + 1    →  1 = 5 − 2·2
1 = 5 − 2·(7 − 5) = 3·5 − 2·7
  = 3·(40 − 5·7) − 2·7
  = 3·40 − 17·7
```
그래서 `7 × (−17) ≡ 1 (mod 40)`이고, −17을 40으로 나눈 나머지 23이 역원이다. 재귀로 쓰면 이 대입이 그대로 코드가 된다. `gcd(b, a mod b)`에 대한 해 (x₁, y₁)을 알면, `a mod b = a − (a//b)·b`를 대입해 정리한 `(y₁, x₁ − (a//b)·y₁)`이 (a, b)에 대한 해다.
```python
def ext_gcd(a, b):
    """g = gcd(a, b)와 a·x + b·y = g인 (x, y)를 돌려준다."""
    if b == 0:
        return a, 1, 0
    g, x1, y1 = ext_gcd(b, a % b)       # b·x1 + (a mod b)·y1 = g
    return g, y1, x1 - (a // b) * y1   # a mod b = a − (a//b)·b 대입

def ext_gcd_iter(a, b):
    x0, y0, x1, y1 = 1, 0, 0, 1        # 불변식: a0·x + b0·y = 현재 값
    while b:
        q = a // b
        a, b = b, a - q * b
        x0, x1 = x1, x0 - q * x1
        y0, y1 = y1, y0 - q * y1
    return a, x0, y0

print(ext_gcd(40, 7), ext_gcd_iter(40, 7))
print(ext_gcd(1071, 462))
```
```text
(1, 3, -17) (1, 3, -17)
(21, -3, 7)
```
반복형은 "지금 들고 있는 두 수가 각각 원래 a, b의 정수 결합으로 몇 배인가"를 (x0, y0), (x1, y1)에 들고 다닌다. 두 수에 하는 연산(`a − q·b`)을 계수에도 똑같이 하므로 불변식이 유지되고, 끝에 남은 g의 계수가 답이다. 재귀 깊이도 단계 수와 같아 log 수준이라 걱정할 필요가 없다.

## ax + by = c: 해가 있을 조건과 모든 해
좌변은 항상 g의 배수이므로 **g가 c를 나눌 때만** 해가 있다. 나눈다면 `ax₀ + by₀ = g`의 양변에 c/g를 곱해 해 하나를 얻는다. 나머지 해는 a·(b/g)와 b·(a/g)가 같다는 데서 나온다.
```text
x = x₀·(c/g) + k·(b/g)
y = y₀·(c/g) − k·(a/g)     (k는 정수)
```
x는 b/g 간격으로만 움직이므로, x를 b/g로 나눈 나머지를 취하면 x ≥ 0인 가장 작은 해가 된다. "x를 0부터 b − 1까지 다 넣어 보기"와 대조하자.
```python
import random

def ext_gcd(a, b):
    if b == 0:
        return a, 1, 0
    g, x1, y1 = ext_gcd(b, a % b)
    return g, y1, x1 - (a // b) * y1

def solve(a, b, c):
    """a·x + b·y = c에서 x ≥ 0이 가장 작은 해, 없으면 None."""
    g, x0, y0 = ext_gcd(a, b)
    if c % g:
        return None                    # g가 c를 나눠야 해가 있다
    step = b // g                      # x는 b/g씩 움직일 수 있다
    x = (x0 * (c // g)) % step
    return x, (c - a * x) // b

def solve_brute(a, b, c):
    for x in range(b):                 # x를 b로 나눈 나머지만 보면 충분
        if (c - a * x) % b == 0:
            return x, (c - a * x) // b
    return None

print(solve(6, 15, 39), solve(6, 15, 40))
rng = random.Random(1)
for _ in range(500):
    a, b = rng.randint(1, 60), rng.randint(1, 60)
    c = rng.randint(-200, 200)
    assert solve(a, b, c) == solve_brute(a, b, c), (a, b, c)
print("무작위 500개 비교: 모두 일치")
```
```text
(4, 1) None
무작위 500개 비교: 모두 일치
```
6과 15의 최대공약수는 3이라 39는 되고(6·4 + 15·1) 40은 안 된다.

## 모듈러 역원
`ax ≡ 1 (mod m)`은 `ax + my = 1`이므로, **gcd(a, m) = 1일 때만** 역원이 있고 확장 유클리드의 x가 곧 역원이다. 파이썬 3.8부터는 `pow(a, -1, m)`이 같은 일을 하고, 역원이 없으면 `ValueError`를 낸다. 작은 법은 완전 탐색과, 10¹⁸까지의 큰 법은 `pow`와 대조한다.
```python
import random

def ext_gcd(a, b):
    if b == 0:
        return a, 1, 0
    g, x1, y1 = ext_gcd(b, a % b)
    return g, y1, x1 - (a // b) * y1

def mod_inv(a, m):
    g, x, _ = ext_gcd(a % m, m)
    if g != 1:
        raise ValueError(f"gcd({a}, {m}) = {g}: 역원 없음")
    return x % m                       # 음수일 수 있으니 [0, m)으로

def inv_brute(a, m):
    return next((x for x in range(m) if a * x % m == 1), None)

def pow_inv(a, m):
    return pow(a, -1, m)

def try_inv(f, a, m):
    try:
        return f(a, m)
    except ValueError:
        return None

print(mod_inv(7, 40), mod_inv(3, 10**9 + 7), pow(3, -1, 10**9 + 7))
try:
    pow(6, -1, 15)
except ValueError as e:
    print("pow:", e)

rng = random.Random(7)
for _ in range(500):
    m, a = rng.randint(2, 300), rng.randint(1, 10**6)
    assert try_inv(mod_inv, a, m) == inv_brute(a, m)
    M = rng.randint(2, 10**18)
    A = rng.randint(1, M - 1)
    assert try_inv(mod_inv, A, M) == try_inv(pow_inv, A, M)
print("무작위 500개 비교: 모두 일치")
```
```text
23 333333336 333333336
pow: base is not invertible for the given modulus
무작위 500개 비교: 모두 일치
```
3의 역원 333,333,336은 `3 × 333333336 = 1,000,000,008 ≡ 1`이다. 법이 소수라면 페르마 소정리로 `a^(p−2) mod p`를 계산해도 역원이 나오는데, 이 방법과 팩토리얼 역원 표는 5편에서 다룬다.

## 자주 하는 실수와 변형
- **음수 나머지**: x가 음수로 나오는 것이 정상이다. C++·자바에서는 `%`가 음수를 돌려주므로 `(x % m + m) % m`으로 바로잡는다.
- **역원이 없는 경우**: 법이 소수가 아니면(예: 10⁹, 2⁶⁴) 역원이 없을 수 있다. gcd를 먼저 확인한다.
- **선형 합동식** `ax ≡ b (mod m)`: g = gcd(a, m)가 b를 나눌 때 해가 법 m 안에 정확히 g개 있다. 양변을 g로 나눈 뒤 역원을 곱한다.
- **범위 안의 해 개수**: "x, y가 모두 0 이상인 해는 몇 개인가"는 위의 일반해에서 k의 범위를 부등식으로 구하면 된다.
- **최소공배수**: `lcm(a, b) = a // gcd(a, b) * b`. 나누기를 먼저 해야 다른 언어에서 오버플로를 덜 겪는다.

## 복잡도
| 방법 | 시간 | 근거 |
|---|---|---|
| 역원 완전 탐색 | O(m) | x를 모두 시도 |
| 유클리드 호제법 | O(log min(a, b)) | 두 단계마다 절반 이하 |
| 확장 유클리드 | O(log min(a, b)) | 같은 단계 + 계수 갱신 |

공간은 반복형이 O(1), 재귀형이 O(log min(a, b))의 호출 스택이다. 수가 아주 크면 한 단계의 나눗셈 비용도 자릿수에 따라 늘지만, 2⁶⁴ 미만의 수에서는 최악인 피보나치 쌍 `(F(93), F(92))`도 91단계면 끝난다.

## 어디에 쓰이나
- 이산수학 12편 「수 체계와 모듈러 연산: 2진수에서 해시까지」: 그 글의 합동 연산에 빠져 있던 나눗셈을, 법과 서로소인 수에 한해 역원 곱하기로 채운다.
- RSA 암호(1977년 리베스트·샤미르·애들먼): 공개 지수 e에 대해 개인 지수 `d = e⁻¹ mod φ(n)`을 확장 유클리드로 구한다. φ는 2편, 거듭제곱은 3편에서 다룬다.
- 4편 「중국인의 나머지 정리」: 서로 다른 법의 합동식을 하나로 합칠 때 확장 유클리드가 계수를 만들어 준다.
- 이산수학 4편 「수학적 귀납법과 재귀」: 라메의 단계 수 상한은 그 글의 피보나치 점화식과 강한 귀납법으로 증명한다.

## 정리
- 유클리드 호제법은 공약수 집합이 변하지 않는다는 사실 하나로 맞고, 최악인 연속 피보나치 쌍에서도 자릿수의 약 5배 안에 끝난다.
- 확장 유클리드는 같은 과정에서 `ax + by = gcd(a, b)`의 계수를 함께 들고 다닌다.
- `ax + by = c`는 gcd가 c를 나눌 때만 풀리고, 해는 b/g 간격으로 무한히 많다.
- 모듈러 역원은 gcd(a, m) = 1일 때만 있으며, 확장 유클리드나 `pow(a, -1, m)`으로 O(log m)에 구한다.
